# BotsTalk v0.3.0 发版对照报告

## 结论

**有条件发版**：核心功能链路（协议 v1.2 task_event 帧、网关 tasks 表、router 任务钩子、REST 5 端点、WS 端到端生命周期、Web 派活面板）已具备可运行证据（单元测试 + HTTP 集成测试 17 例 + WS 端到端 2 例 + tsc 通过），但 DoD 六大类中「可观测性」「数据（备份恢复/密钥校验/多用户）」「安全（依赖扫描/限流熔断）」「部署运维（Docker 实跑/滚动更新/运维手册验证）」「可靠性（失败注入）」多处未通过或未验证。因此不可按 DoD 判定为「可发版」；若发版须以「限定内部/单 lobby 场景 + 明确已知限制」为前提，故为有条件发版。

## 已知限制

1. Docker 镜像未实跑（本机无 daemon）。排期建议：下一版本在具备 daemon 的环境完成镜像构建与 compose 起停实测并留证。
2. 失败注入测试未写。排期建议：下一版本对派活、任务落库、WS 推送三条关键路径补失败注入用例。
3. 结构化日志/request_id 未做。排期建议：下一版本落地 request_id 全链路透传与结构化日志。
4. Prometheus 指标未做。排期建议：下一版本接入指标端点并定义关键指标。
5. 告警规则未做。排期建议：下一版本基于指标落地基础告警规则。
6. 备份恢复未实测（一键恢复脚本没有）。排期建议：下一版本先补一键恢复脚本，再做备份→恢复实测。
7. 依赖扫描未做。排期建议：下一版本接入依赖扫描并纳入 CI 门禁。
8. 限流熔断未做。排期建议：下一版本对 REST 与 WS 入口补限流、超时、熔断。
9. 多房间未做（单 lobby）。排期建议：下一版本评估多房间需求，同步确定 tenant/user 模型。
10. 滚动更新未验证。排期建议：下一版本给出零停机方案，或明确写出可接受的停机窗口与限制。
