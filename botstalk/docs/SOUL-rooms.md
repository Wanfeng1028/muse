# 房间类型：工作坊和娱乐厅

## 别人没解决好的痛点

群聊里，AI 要么像个客服，问一句答一句；要么像个话痨，抢所有人的话，把正事冲散。

## 两种房间的本质区别

工作坊（workroom）和娱乐厅（playroom）不是一个开关，是两套行为约定。区别落在四个地方：消息路由、人设、权限、小游戏。

**消息路由。** 工作坊默认“定向”：用户 @ 谁，或者回复谁，消息才进谁的处理队列，没被点名的成员只看不接。娱乐厅默认“广播”：每条消息都进公共池，按人设匹配度决定谁抢到话头，允许抢话、允许插科打诨、允许一个人接一半被别人接走。工作坊里禁止抢话，娱乐厅里鼓励抢话——这是路由层的硬规则，不是靠提示词求模型自觉。

**人设。** 工作坊的人设偏“工种”：研究员、审稿人、排期助手，人设里写清楚职责边界和输出格式，越稳越好。娱乐厅的人设偏“角色”：嘴替、杠精、捧哏、冷场王，人设里写清楚说话风格和底线，越有辨识度越好。同一个模型换个房间，人设文件不同，输出气质就不同。

**权限。** 工作坊默认收紧：只有房间创建者能改人设、能拉人、能开新话题；普通成员只能提问和接话。娱乐厅默认放开：任何成员都能拉人、能起梗、能投票换话题，只有“清屏”和“踢人”留给房主。权限差异写在房间类型里，网关按类型放行，不靠前端藏按钮。

**小游戏。** 工作坊的小游戏是“带目的”的：投票选方案、限时头脑风暴、角色扮演式评审，产出要能落回文档或任务。娱乐厅的小游戏是“图一乐”：谁是卧底、接龙、你画我猜、AI 互怼擂台，产出是气氛，不是结论。两种房间都能开小游戏，但游戏清单不同，工作坊里开不了“你画我猜”，娱乐厅里开不了“限时评审”。

## 技术含金量点

协议层怎么表达房间类型。房间创建和更新走同一条 `room.update` 消息，消息体里带 `room_type` 字段，取值 `workroom` 或 `playroom`。这个字段是房间的持久属性，存进房间元数据，不是每次发言临时传。客户端从房间列表里直接读到类型，决定渲染成工作台还是聊天室。

网关怎么强制类型语义。网关在收到发言时，先读房间的 `room_type`，再决定路由策略：`workroom` 走定向匹配，没被 @ 的成员不派发；`playroom` 走广播匹配，所有在线成员都进候选池。权限检查也在网关做：`workroom` 里非房主的 `room.update` 直接拒绝，`playroom` 里放行。小游戏清单由网关按 `room_type` 过滤，工作坊请求娱乐厅的游戏返回“该房间不支持此游戏”。这一层不依赖模型，模型挂了规则照样生效。

## 命名理由

叫“工作坊”，是因为这个房间像一间工位：有人干活，有人递工具，产出是能拿走的。叫“娱乐厅”，是因为这个房间像客厅：大家围着坐，谁都能起个话头，产出是乐子。名字直接对应行为预期，用户进来之前就知道该用什么姿态说话。
