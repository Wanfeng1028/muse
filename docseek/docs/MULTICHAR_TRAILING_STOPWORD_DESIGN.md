# 多字 token 尾字停用词剥离设计

> 状态：**未实现，仅设计**
> 适用范围：查询解析阶段的 token 规范化（query_parser.cpp）

## 1. 背景与现状

当前停用词过滤只处理一种情况：**整个 token 恰好是单字停用词**。

实现入口为 `isSingleCharStopword`，其语义是「token 本身长度为 1 且该字在单字停用词集合中」，
命中则该 token 被整体丢弃。

这一策略无法覆盖下面这类 token：

- `新的了` —— 尾部是停用字 `了`
- `苹果的` —— 尾部是停用字 `的`

## 2. 问题与风险

jieba 的切分结果依赖词典，同一段输入可能得到不同粒度：

| 输入 | 可能切分 A | 可能切分 B |
| --- | --- | --- |
| `苹果的` | `["苹果", "的"]`（已处理） | `["苹果的"]`（未处理） |
| `新的了` | `["新", "的", "了"]`（已处理） | `["新的了"]`（未处理） |

切分 A 中，`的` / `了` 作为独立单字 token，会被 `isSingleCharStopword` 过滤掉，行为正确。
切分 B 中，停用字黏着在多字 token 尾部，现有逻辑完全放行，导致：

1. **召回噪声**：`苹果的` 与 `苹果` 被视为不同 term，索引/检索无法对齐。
2. **一致性缺失**：同一语义的查询，因词典差异产生不同检索结果，行为不可预期。

## 3. 设计方案

### 3.1 新增 token 规范化函数

引入 `stripTrailingStopword(token)`，语义定义如下：

1. 若 `token` 长度 **不大于 1**，原样返回（单字场景交由 `isSingleCharStopword` 处理）。
2. 若 `token` 长度大于 1，且**尾字**属于单字停用词集合：
   - 剥离尾字；
   - 若剥离后剩余部分非空，则剩余部分重新参与检索（继续走后续流程）；
   - 若剥离后为空，则丢弃该 token。
3. 若尾字不属于单字停用词集合，原样返回。

该函数是**纯函数**：不修改入参，返回规范化结果（可能为空，表示丢弃）。

### 3.2 边界约束

- **只剥尾字**：不剥首字，也不剥中间字。
  例：`不了` 的 `不` 位于首字，**不剥离**；`办不了` 只考虑尾字 `了`。
- **`不` 字永不剥离**：`不` 作为否定词承载语义，任何位置都不得剥离。
  因此单字停用词集合用于「尾字剥离」时，必须显式排除 `不`。
- **不做递归剥离**：一次规范化只剥离一个尾字，避免 `新的了的` 这类输入被过度裁剪，
  也避免与后续流程产生循环依赖。是否需要多轮剥离由上层决定，本设计不承诺。

### 3.3 与 singleCharStopwords 的关系

两层过滤，职责不同：

| 层次 | 位置 | 作用对象 | 行为 |
| --- | --- | --- | --- |
| 第一层：入口过滤 | `isSingleCharStopword` | 单字 token | 整体丢弃 |
| 第二层：token 规范化 | `stripTrailingStopword` | 多字 token | 剥离尾字后保留剩余部分 |

顺序上，先做单字入口过滤，再做多字尾字剥离。
两者共用同一份单字停用词集合，但**尾字剥离需排除 `不`**，二者集合不完全等价。

## 4. 用例

### 4.1 正例（应当剥离尾字）

| 输入 token | 尾字 | 剥离后 | 说明 |
| --- | --- | --- | --- |
| `苹果的` | `的` | `苹果` | 常见名词 + 结构助词 |
| `新的了` | `了` | `新的` | 剥离后仍为多字，继续参与检索 |
| `数据的` | `的` | `数据` | 尾字助词剥离 |
| `跑得快` | `快` | `跑得` | 尾字为停用字时按规则剥离 |
| `完成了` | `了` | `完成` | 动词 + 时态助词 |

### 4.2 反例（不应当剥离）

| 输入 token | 尾字 | 结果 | 原因 |
| --- | --- | --- | --- |
| `不了` | `了` | 不剥离 | `不` 位于首字，规则只剥尾字；且 `不` 永不剥离 |
| `苹果` | `果` | 不剥离 | 尾字非停用字 |
| `不` | `不` | 不剥离 | 长度为 1，且 `不` 永不剥离 |

## 5. 实现位置建议

**状态：未实现，仅设计。**

建议在 `query_parser.cpp` 的 token 规范化点接入：

1. 在 query_parser.cpp 中新增 `stripTrailingStopword`（建议置于 `isSingleCharStopword` 附近，
   便于共用单字停用词集合）。
2. 在切分结果遍历过程中，对每个 token 依次执行：
   - 先 `isSingleCharStopword` 判断，命中则丢弃；
   - 否则调用 `stripTrailingStopword`，按返回结果决定保留或丢弃。
3. 尾字剥离所用的停用字集合，需在单字停用词集合基础上排除 `不`。

具体函数签名与接入点需以 query_parser.cpp 实际代码为准，本设计不预先固化签名。

## 6. 未决问题
