# docseek 发版对照报告：/api/search boost 尾字符非法返回 400

## 1. 改动摘要
- **改动文件**：`/api/search` 的 `title_boost` 与 `phrase_boost` 解析逻辑。
- **改动内容**：将 boost 参数的解析改为使用带 `pos` 的 `stod`，并要求 `pos == value.size()`。若尾字符非法（即存在未消费的尾部字符），接口直接返回 400 错误，错误文案保持不变。
- **范围控制**：既有的范围校验逻辑（小于 0、大于 1000）与 `limit` 参数的 `pos` 校验逻辑一字未动，确保不引入无关行为变更。

## 2. 验收范围
1. **新测试验证**：`tests/test_serve_r2_errparam.cpp` 新增 `BoostTrailingGarbage` 测试用例（`title_boost=1x`、`phrase_boost=2y` 各返回 400 且 body 包含对应文案）；既有 `TitleBoostNonNumeric` 与 `BoostsOutOfRange` 用例不受影响。
2. **靶向合跑测试**：基于上述新增及既有相关用例进行定向编译与运行。
3. **真实服务冒烟测试**：针对实际部署的服务实例进行尾字符非法参数的冒烟验证。
4. **全量 ctest 回归**：进行系统级全量测试回归验证。
实测结果：靶向 ServeErrParamR2 5/5 全绿（含新测 BoostTrailingGarbage）；真实服务冒烟（18471 端口，2 文档小库，真 serve 进程）4/4：title_boost=1x 与 phrase_boost=2y 各返回 400 且 body 含对应文案，title_boost=5 与 1.5 各返回 200，冒烟后服务已停、端口复查已关。全量 ctest 本轮未跑。
