# 分词方案设计注记

## 1. 背景：为什么要换

docseek 是 C++17 的本地全文检索 CLI，用 SQLite FTS5，底线是**单二进制分发**；而此前用的 cppjieba 在运行时需要加载 `jieba.dict.utf8` 等 4 个词典文件（约 10MB+），和这条底线直接冲突。

## 2. 三个候选方案

- **方案一：SQLite FTS5 `unicode61` + 自实现 CJK 二元切分（Bigram）** —— 写入索引前把 CJK 连续片段按相邻两字（overlapping bigram）切开，纯机械切分，不用任何词典。
- **方案二：cppjieba 静态词典内嵌 + 精简词典** —— 构建期把 4 个词典文件用 `xxd`/`bin2c` 嵌进二进制，运行时从内存流喂给 cppjieba，效果和现网一致，但体积要涨。
- **方案三：TinySegmenter 风格纯统计切分** —— 字符 n-gram 特征 + 极小的分类器模型（常量数组嵌进二进制），逐字判断「这里要不要切」，同样不依赖词典。

### 对比表

| 维度 | 方案一 Bigram + FTS5 | 方案二 cppjieba 静态内嵌 | 方案三 TinySegmenter 风格 |
|---|---|---|---|
| 检索效果（召回/精度） | 召回极高 / 精度偏低 | 召回高 / 精度高 | 召回中高 / 精度中等 |
| 二进制体积增量 | ≈ 0 | ≈ 10–12 MB（精简后 5–7 MB） | ≈ 50–200 KB |
| 构建复杂度 | 极低 | 中等（需 xxd/bin2c 步骤） | 低到中 |
| 许可证 | MIT（自研） | MIT（cppjieba） | BSD-2-Clause / MIT（自研） |
| 维护状态 | 自维护，逻辑稳定 | cppjieba 上游活跃度一般，但代码成熟 | 原版 TinySegmenter 停更；自研版自维护 |

## 3. 拍板结论：选方案一（自研 bigram）

2026-10-20 决策：新增自研 bigram 分词器（`src/bigram_tokenizer.cpp`），零词典依赖、零第三方依赖；jieba 分词器保留不动，作为可切换的另一选项。

三条理由：

1. **零依赖、单二进制** —— 纯逻辑代码，不读任何外部文件，不引入第三方库，单二进制底线不再被词典文件破坏。
2. **2–8 字中文短语召回最好** —— bigram 是纯机械切分，任意 2 字窗口都建索引，2 字以上短语只要连续出现必命中，几乎不会因分词错误漏检，正好对上「查询多为 2–8 字中文短语、偏好高召回」的实际场景。
3. **工程代价最低** —— 没有构建期转换步骤，没有离线训练流程，直接写进 docseek 的 tokenizer 适配层即可。

## 4. bigram 分词器的精确行为

FTS5 tokenizer 名 `"bigram"`，token 带字节起止偏移；查询侧的 `bigramCutForSearch` 与索引侧保持一致。

具体行为：

- **CJK 按 overlapping bigram 切分**：相邻两字成一个 token，窗口重叠；长度为奇数时，末尾留一个单字 token。
- **ASCII 字母数字按词切分**：连续字母数字整段作为一个 token，统一转小写。
- **数字串整体保护**：数字串连同其中的 `.`、`,` 以及 `%`/`％` 一起整体保护，不被拆开。
- **内嵌约 40 个单字中文停用词**：只过滤单字 token 和由两个停用字组成的 bigram，不做更激进的过滤。
- **专名附加（只增不减）**：地名后缀（省/市/区/县/镇/乡/村/路/街/道/号/楼）前 1–5 字成段；百家姓首字后 1–2 字成姓名；这些附加 token 用 `FTS5_TOKEN_COLOCATED` 标记，只增加不删除，不破坏原有 bigram 覆盖。

切分示例（示意）：

1. `全文检索` → `全文` / `文检` / `检索`（4 字，3 个重叠 bigram）
2. `数据库` → `数据` / `据库` / `库`（3 字，奇数字尾留单字）
3. `SQLite 版本 3.45%` → `sqlite` / `版本` / `3.45%`（ASCII 小写整词、CJK bigram、数字串带 `%` 整体保护）

## 5. 已知局限与回退

- **索引膨胀约 2–3×** —— 这是 bigram 机械切分的固有代价，属于存储问题，不影响二进制体积。
- **精度靠排序和约束收敛** —— bigram 噪声命中多，需要靠 FTS5 的 BM25 排序，加上短语查询（`"..."`）和 `phrase` 邻近约束来压噪声。
- **jieba 分词器保留** —— 精度敏感、能接受额外词典文件的场景，可以切回 jieba 分词器；两个分词器共存，按需切换。
