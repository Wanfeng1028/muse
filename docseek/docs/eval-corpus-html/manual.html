DocSeek Operator Manual

This manual describes the backup and restore workflows for DocSeek deployments. It assumes you have shell access to the host running the index service and that the docseek CLI is on your PATH.

Creating a backup

Use the docseek backup command to snapshot the index and its metadata. By default, output is written to /var/lib/docseek/backups.

docseek backup --target /mnt/backups --compress gzip --retain 7
  • --target sets the destination directory.
  • --compress accepts gzip or zstd.
  • --retain keeps the N most recent archives and prunes older ones.

Restoring from a backup

Restore operations require the service to be stopped first, otherwise the index lock will reject the write.

systemctl stop docseek
docseek restore --source /mnt/backups/docseek-2024-06-01.tar.gz --verify
systemctl start docseek

The --verify flag recomputes checksums for every shard before swapping the live index… if any shard fails, the restore aborts and the previous index remains untouched.

Verification checklist

  • Confirm the service reports status: healthy after restart.
  • Run docseek query --selftest and check for zero errors.
  • Compare document counts against the pre-backup snapshot.
