## 差异化命题
现有 AI MV 全是散件拼凑：Suno 作曲、剪映手动剪，创作者在四五个工具间搬运素材、对时间轴。drama-factory AI MV 模式把作词到成片收进一个 Run，让编排、暂停、重试、审批、成本统计都发生在同一条生命周期里。

## 技术含金量
- **歌词-画面时间轴对齐**：作曲 Agent 产出带 LRC 时间戳的音频，分镜 Agent 按行切段，每段画面时长直接由该行起止时间驱动，杜绝人工对轨。
- **多 Agent 编排的暂停/重试/审批**：作词、作曲、分镜、视频生成各自是 Run 里的一个步骤，任何一步可暂停改 prompt、单独重试，或等人工审批歌词后再放行作曲。
- **BYOK 作曲渠道抽象**：MiniMax music-3.0 与备用渠道统一封装为 Composer Provider 接口，渠道不可用时按 Run 配置切换，不写死单一供应商。
- **SRT 字幕烧录**：LRC 转 SRT 后由 ffmpeg 在剪辑步骤烧录，字幕时间与音频波形对齐，无需导出到第三方工具。
- **分镜-视频映射**：每个分镜条目携带目标模型（wan2.5 或 BYOK 视频源）与时长约束，生成失败只回滚该镜头，不重跑整支 MV。

## 视觉概念
mv.html 沿用中性灰黑体系：深灰底、细边框分区，左侧 Run 时间线竖向排列作词/作曲/分镜/生成/剪辑/质检六个节点，右侧主区按当前步骤切换——歌词编辑器、波形条、分镜网格、视频预览。颜色只用于状态语义：进行中、已暂停、失败、已归档，不用于装饰。图标一律线性 SVG，尺寸与文字基线对齐。

## 命名理由
"AI MV"直指交付物本身：MV 是行业与用户都认的成品形态，不用二次解释。"AI"标出生成方式，区别于传统拍摄剪辑。四个字不掺"工坊""平台"这类容器词，也不承诺工具集，只声明一件事——这里产出的是一支 MV。
