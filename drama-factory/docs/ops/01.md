# 剧坊-运维手册-备份恢复

本文写清楚剧坊（drama-factory）怎么备份、怎么恢复。按顺序照着做，出错就按“排查”那节查。

## 一、备份对象有哪些

剧坊是 Spring Boot 项目，跑起来要备份的东西分三块：

1. MySQL 数据库，库名 `drama_factory`。这是主数据，剧本、剧集、分镜、角色、任务记录都在里面。
2. 上传文件目录。配置项在 `application.yml` 里的 `drama.upload.path`，默认是 `/data/drama-factory/upload`。用户传的封面图、配音文件、视频片段都在这。
3. 配置文件。`application.yml`、`application-prod.yml`，还有日志配置 `logback-spring.xml`。这些不进 Git 的话要单独存。

Redis 不用备份。剧坊用 Redis 只做缓存和分布式锁，重启后数据能重建。真丢了顶多第一次请求慢一点。

## 二、备份频率和保留

- 数据库：每天凌晨 3 点全量备份一次，保留 14 天。
- 上传目录：每天凌晨 4 点增量备份一次，每周日凌晨 4 点做一次全量，全量保留 4 周。
- 配置文件：每次改动后手动备份一次，保留最近 10 个版本。

备份文件统一放 `/data/backup/drama-factory/`，按日期建子目录，比如 `/data/backup/drama-factory/2024-06-01/`。

## 三、数据库备份操作

### 3.1 手动全量备份

登录到数据库所在机器，执行：

```bash
mkdir -p /data/backup/drama-factory/$(date +%F)
mysqldump -h 127.0.0.1 -P 3306 -u drama_user -p \
  --single-transaction \
  --routines \
  --triggers \
  --set-gtid-purged=OFF \
  drama_factory \
  | gzip > /data/backup/drama-factory/$(date +%F)/drama_factory.sql.gz
```

`--single-transaction` 保证 InnoDB 表备份时不锁表，线上跑不影响业务。`--routines` 和 `--triggers` 把存储过程和触发器一起带走，漏了恢复时会缺东西。

### 3.2 写进 crontab

用 `crontab -e` 加两行：

```cron
0 3 * * * /usr/bin/mysqldump -h 127.0.0.1 -P 3306 -u drama_user -p'你的密码' --single-transaction --routines --triggers --set-gtid-purged=OFF drama_factory | gzip > /data/backup/drama-factory/$(date +\%F)/drama_factory.sql.gz
30 3 * * * find /data/backup/drama-factory -name 'drama_factory.sql.gz' -mtime +14 -delete
```

注意 crontab 里的 `%` 要写成 `\%`，不然会被当成换行。

密码写在 crontab 里不安全，建议改用 `/root/.my.cnf`：

```ini
[client]
user=drama_user
password=你的密码
host=127.0.0.1
port=3306
```

然后 crontab 命令里去掉 `-u` 和 `-p` 参数。

## 四、上传目录备份操作

用 rsync 做增量，全量就是不带 `--delete` 的第一次同步。

```bash
rsync -avz --delete \
  /data/drama-factory/upload/ \
  /data/backup/drama-factory/upload-current/
```

`--delete` 的意思是源目录删了的文件，备份目录也删。如果怕误删想留历史，去掉这个参数，改成每天往日期目录里拷一份：

```bash
rsync -avz /data/drama-factory/upload/ /data/backup/drama-factory/$(date +%F)/upload/
```

## 五、恢复操作

### 5.1 恢复数据库

先停应用，别让新数据写进来：

```bash
systemctl stop drama-factory
```

然后建库、导数据：

```bash
mysql -h 127.0.0.1 -P 3306 -u root -p -e "DROP DATABASE IF EXISTS drama_factory; CREATE DATABASE drama_factory DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"
gunzip < /data/backup/drama-factory/2024-06-01/drama_factory.sql.gz | mysql -h 127.0.0.1 -P 3306 -u root -p drama_factory
```

导完检查表数量和数据量：

```bash
mysql -h 127.0.0.1 -P 3306 -u drama_user -p -e "USE drama_factory; SHOW TABLES; SELECT COUNT(*) FROM drama_script;"
```

`drama_script` 是剧本表，数字对得上说明主数据回来了。

### 5.2 恢复上传目录

```bash
rsync -avz --delete /data/backup/drama-factory/2024-06-01/upload/ /data/drama-factory/upload/
chown -R drama:drama /data/drama-factory/upload
```

`chown` 这步不能省，权限不对应用读不了文件，页面上的图片和视频会 404。

### 5.3 恢复配置文件

从备份目录拷回：

```bash
cp /data/backup/drama-factory/config/application-prod.yml /opt/drama-factory/config/application-prod.yml
```

改完确认数据库连接、Redis 地址、`drama.upload.path` 三项对不对，再启动：

```bash
systemctl start drama-factory
```

启动后看日志确认没报错：

```bash
tail -f /opt/drama-factory/logs/drama-factory.log
```

看到 `Started DramaFactoryApplication` 就是起来了。

## 六、验证备份能不能用

备份不验证等于没备份。每周挑一个备份文件，在测试库上恢复一遍，跑下面这个接口确认服务正常：

```
GET /api/v1/script/list?page=1&size=10
```

返回 JSON 里 `code` 是 200、`data` 里有记录，就算通过。接口路径以项目里 `ScriptController` 的 `@RequestMapping` 为准，改过就按改后的写。

## 七、出问题怎么排查

- 备份文件是 0 字节：多半是 mysqldump 认证失败，手动跑一次看报错。
- 恢复后表是空的：检查 `gunzip` 管道后面有没有加库名，漏了会导到默认库。
- 上传文件 404：先看 `drama.upload.path` 指向哪，再看目录属主是不是 `drama:drama`。
- 启动报数据库连不上：核对 `application-prod.yml` 里 `spring.datasource.url` 的库名和端口。
- 定时任务没跑：`grep CRON /var/log/syslog` 看 crontab 有没有报错，重点看 `%` 有没有转义。

## 八、注意事项

1. 恢复前一定先停应用，边写边恢复会把数据搞乱。
2. 备份文件别和应用放同一块盘，盘挂了两个一起没。
3. 密码不要写进脚本明文，用 `.my.cnf` 或环境变量。
4. 每次恢复完，手工点几个页面看看，别只看日志。
