# Drama Factory 前端 UI 与交互审查报告

- 审查日期：2026-10-14
- 审查方式：浏览器逐页实机渲染（15/15 页面，1280×960 桌面视口）+ 实机操作验证（点击 / 键盘 / 主题 / 折叠）+ HTML/CSS/JS 源码定位 + 接口异常路径实测
- 审查范围：全部前端页面与交互（不含后端逻辑）
- 结论：未做任何代码修复，仅提交问题清单供排期

---

## 一、高严重度（明显缺陷，建议优先处理）

### 1. 无友好错误页，未捕获路由直接抛原始 500 JSON

- 现象：访问不存在的静态路径（如 `/foo.html`）返回 `{"status":500,"error":"Internal Server Error","message":"No static resource foo.html.","timestamp":...,"requestId":...}`，原始 JSON 直接暴露给用户，含 timestamp、requestId 等内部信息。
- 实测：`GET /foo.html -> HTTP 500`；`GET /api/nope -> HTTP 500`。
- 影响：用户输错 URL 时看到裸错误体，无 404 页、无兜底跳回首页，体验差且泄露内部结构。
- 建议：配置全局错误页（自定义 error 页面或统一兜底重定向首页）。

### 2. 浏览器标签页品牌名不统一

- 现象：15 个页面中 7 个 `<title>` 后缀为「AI 短剧工坊」（index/chat/storyboard/tasks/finals/pipeline/qc），8 个为「Drama Factory」（runs/usage/agents/images/music/avatar/settings/run-detail）。
- 影响：同一产品两套品牌名，浏览器标签、书签、历史记录中命名混乱。

### 3. 当前页标题顶栏与内容区重复（且个别不一致）

- 现象：所有页面 topbar-title 与 `page-head h1` 两处显示同名标题；qc 页 topbar 显示「成片库」而 h1 为「成片质检」，settings 页 topbar「设置」而 h1「设置中心」。
- 原因：`shell.js` 的 `currentId()` 将 `qc.html` 映射为 `finals`（成片库）、`run-detail.html` 映射为 `runs`，topbar 显示映射后名称。
- 建议：topbar 去掉当前页名（保留全局搜索/快捷键），或统一映射关系。

## 二、中严重度（体验与布局）

### 4. 首页主区域大段空白

- 「上下文 · 暂无项目」与快捷指令按钮之间约 370–400px 空白；聊天记录区为空时无占位高度。
- 影响：视觉失衡；叠加三步引导条后页面总高 1035px，超出 960px 视口（见 §五-1）。

### 5. 两套导航并存

- 顶部遗留 Bootstrap navbar（控制台首页/分镜板/任务队列/成片库/生产看板/AI 对话，旧版）与左侧 shell 侧边栏（13 项）功能重叠；顶部 navbar 主体被 CSS 隐藏后仍残留当前页名文本。
- 建议：清理旧导航，统一由侧边栏承担导航。

### 6. 空状态文案与样式不统一

- 各页空态各写一套：「当前分镜下没有任务」「还没有运行，创建第一条 Run 吧」「还没有剧集数据」「暂无用量数据，先跑一次运行吧」「请先选择项目和剧集」等，无统一空态组件。

### 7. 中英文混用 + 内部参数裸露

- runs 页「创建第一条 Run 吧」；设置页直接展示 `deepseek.base-url`、`deepseek.model`、`drama.video.provider`、`harness.qc.manual-approval`、`drama.video.max-attempts` 等配置 key 及「需重启」标签；Agent 机队页展示「修改 settings.json 中 drama.video.provider 即可运行时切换」。
- 建议：面向终端用户时使用中文描述性文案，配置 key 折叠到高级区域。

### 8. 供应商内部细节暴露给终端用户

- 首页/AI 对话页提示「对话会消耗你的 DeepSeek API 额度（微信 ChatAPI）」；chat 页 label「目标剧集(确认落库用)」——内部实现说明直接上 UI。

### 9. 任务队列筛选控件间距不均

- 项目→剧集 264px、剧集→分镜 196px，同排控件间距不一致。

### 10. 用量统计占位符不统一

- 「累计 Token — / 累计费用约 —」用「—」，但「视频任务 0 / 运行 0」用数字，风格割裂。

## 四、交互问题（实机操作验证）

### 15. 命令面板「操作」分组首屏不可见
- Ctrl+K 面板打开后 13 条页面命令占满 `cmd-panel`（max-height 60vh），6 条操作命令（新建分镜/从剧本生成分镜/提交本集全部任务/生成成片/打开 AI 对话/新建运行）在列表下方需滚动才可见，用户感知不到存在操作命令。

### 16. 「打开 AI 对话」快捷键标注与行为冲突
- 该命令条目 kbd 标注 ⌘K/Ctrl+K（`shell.js` 取 `modK()`），但 Ctrl+K 实际是命令面板自身的开关——在面板里按 Ctrl+K 只会关闭面板，不会跳转 AI 对话。

### 17. 操作分组命令无快捷键提示
- 页面分组 6 条命令带 `G H / G C / G S / G T / G F / G P` 快捷键，操作分组 6 条命令均无 kbd 提示，信息密度不一致。

### 18. 「添加分镜」按钮无项目/剧集校验
- 「AI 生成剧本」「全部提交」「查看剧本」均有「请先选择剧集」拦截（`storyboard.js`），唯独「添加分镜」`openForm()` 直接展开表单，与同排按钮行为不一致。

### 19. 首页新建面板双重展开
- 点「+ 新建」先展开面板，面板内「新建项目/新建剧集」还要各自再点「展开」才显示表单，两层展开才到表单；且展开后页面超出视口。

### 20. 命令面板打开 AI 对话的入口语义混乱
- 全局快捷键 Ctrl+K 是命令面板开关，「打开 AI 对话」在面板内出现但无独立快捷键，两条路径行为不一致（详见 #16）。

## 五、一屏显示问题（能一屏放下就不要滚动）

### 21. 首页空态下仍可能超出一屏（1035px）
- 三步引导条显示时页面总高 1035px > 960px 视口，「最近动态」被挤出屏幕；点击「+ 新建」展开面板后进一步溢出。根因是「上下文」与快捷指令之间约 370px 空白间距；引导条关闭后 927px 可放下但底部距视口边缘仅 33px，非常局促。

### 22. Agent 机队页内容堆叠超出一屏（1047px）
- 顶部两行技术说明（约 120px）+ 6 组供应商卡片（视频/图片/音乐/TTS 语音/数字人/编剧）纵向堆叠，底部「编剧」组落在视口外。建议精简顶部说明、压缩卡片间距或分组折叠。

### 23. 命令面板操作命令需滚动可见
- 同 #15，操作分组被页面分组挤出首屏。

## 六、反馈机制不统一（同一产品 ≥4 种形态）

| 页面 | 反馈形态 | 备注 |
| --- | --- | --- |
| index/chat/storyboard/pipeline/qc | Bootstrap toast（workspace.js） | `text-bg-danger` 硬编码红色，无成功态；创建项目成功无提示 |
| images/music/avatar | byok.js toast → 兜底 `alert()` | 失败提示退化为原生 alert 弹窗 |
| runs/run-detail | 自绘 `#toast-host` toast | 独立实现 |
| agents/settings | 动态创建 fallback 提示元素 | 运行时插入 |
| tasks/finals/usage | 页面内 alert 区 / hint 文本 | 无 toast |

- 建议：抽一个全局统一的 toast 组件（含 success/error/info 三态），所有页面接入。
