# AC Director 权利与发布指南

这份指南解决的是发布前的权利边界、来源证明和包完整性。它不能替代当地律师对商标、版权、合同、肖像权、数据保护或模型服务条款的意见。

## 推荐的发布分层

AC Director 当前采用混合方案：脚本和机器合同使用 Apache-2.0；原创指南、提示词、生产框架和案例文字使用 CC BY-NC-ND 4.0。这样可以让别人安装、运行和改进确定性工具，同时限制未经许可的商业化改写和“换名出售整套方法”。这不是 OSI 意义上的完整开源；如果你把“开源”作为产品承诺，应改用 Apache-2.0 或 CC BY-SA 4.0，并接受商业改编和再分发带来的控制减少。

## 发布前必须保留的证据

- 原始创作材料：草稿、设计记录、版本时间线、测试记录和首次公开时间；
- 权利来源：自己创作的文件、获得授权的外部文件、第三方许可证、引用范围和排除范围；
- 包身份：版本号、发布日期、清单、ZIP SHA-256、打包命令和完整性测试结果；
- 贡献记录：贡献者署名、DCO/CLA 状态、每个外部提交的许可证；
- 品牌证据：AC Director、Acheng Director、acheng-director 的首次公开使用、域名、代码仓库和发布页面；
- 媒体边界：哪些只是提示词和规划，哪些是用户或模型生成的真实媒体，哪些素材仍需人工确认。

## 第三方与模型风险

第三方 skill、模型名称、镜头目录、字体、图片、音频、案例图、训练数据和用户上传内容不能因为出现在一个 ZIP 里就变成 Acheng 的资产。逐项保留原许可证；如果来源不明，删除、替换或把该文件标为不可发布。模型输出还要遵守服务商条款、肖像和商标限制，AC Director 不替用户取得这些权利。

## 公开仓库的最低配置

至少放在仓库根目录：`LICENSE`、`LICENSE-SCOPE.md`、`LICENSE-DOCS.md`、`NOTICE`、`TRADEMARKS.md`、`CONTRIBUTING.md`、`SECURITY.md` 和本指南。发布 ZIP 还要附 SHA-256 清单；仓库标签、包内版本和发布说明必须一致。
