# 115｜按决策位置使用专业引导

本层帮助宿主把一次宽泛判断拆成有输入、有分支、有落点的小任务；不新增生产字段、第二套状态、额外审批或另一轮问卷。原有工序用于减轻单次推理与输出负担、保存完整产物并明确模块交接，不宣称突破模型能力或保证艺术质量。硬规范继续以生产合同、字段 owner 和既有脚本为准。

## 使用顺序

1. 先锁定当前版本、用户已确认内容和最早缺失阶段，只加载该模块入口及其决策指南。指南中的案例只解释方法，人物、道具、时长、镜头不得自动进入新项目。
2. 在指南中选择与当前困难吻合的一节；依次读取该节指定输入并执行分支。已完成且输入未变化的决定直接沿用，不重复答题。
3. 先用已有条件排除不适用选项，再按该节给出的来源查看少量相关条目。不要求遍历全库、每镜比较两个方案、每次采用新花样或展开全部轨道。
4. 把结果写回本模块原有字段。在现有回包 evidence 中仅记录可复核的输入来源、采用结果、必要取舍和对应字段；无需另建思考记录或展示逐步内部推理。
5. 下游消费已提交的字段与完整产物；机器可算的时间、编号、哈希交给原检查。缺少决定性事实时将具体缺项交回 owner，只有需要用户选择、素材或权限才询问用户。

## 当前阶段路由

| 当前位置 | 仅读此指南中的相关节 | 完成标志 |
|---|---|---|
| 剧情因果、知情或人物选择尚未成立 | [story](decisions/story.md) | 已确认的变化、选择和代价落在原剧本字段 |
| 不确定拍什么、从哪看、是否运动 | [shots](decisions/shots.md) | 必须可见事件、观察点和路径已确定 |
| 情绪抽象、反应套路或动作断因果 | [performance](decisions/performance.md) | 一条适用且可见的表演／动作链 |
| 不清楚先做哪张图、该参考什么 | [assets](decisions/assets.md) | 资产依赖、角色／状态和逐图用途明确 |
| 视效盖住动作或尺度没有参照 | [effects](decisions/effects.md) | 起因、可见结果、作用范围与尾态可读 |
| 人物图、关键帧到 H3 的引用未落实 | [model](decisions/model.md) | 同源正文、真实媒体和逐项上传映射 |
| 跨镜状态或版本冲突、恢复续写 | [continuity](decisions/continuity.md) | 有事件依据的承接与当前版本证据 |

资产链与模型链的接点仍由 [114](114-reference-binding-delivery-v4.3.6.md) 定义。参考手册说明如何决策；JSON 索引保存条目与权属；真实图片／视频保留视觉证据；production 保存唯一生产事实。不要在指南中复制维护另一份素材编号、批准状态或规范阈值。

## 具体问题如何加载

各指南的相关节已接入用户资料中筛选改写的 Q01–Q36；群戏、动画变形、材质落点、风格/曝光、声音、累积状态有专门小节。先按遇到的缺口选择位置，再读取它链接的一道题；题卡给出需取输入、两个局部问题、条件分支、原字段和停止条件。已能按原指南完成时不必打开题卡。

也可按位置检索：python scripts/director_library.py questions --module performance --case P1。默认只给两张卡，remaining_ids 只在缺口仍未解决时继续。工具不代替判断，不要求回答所有题。七份 Markdown 问题视图由唯一 JSON 索引生成，避免人读一套、机器读另一套。

图像材质/风格的具体步骤、媒介适配、字段到最终正文的落点见 [116视觉资料库](116-visual-reference-library.md)。检查执行和交付的问题接在 model M3/M4、continuity K3/K4 及模块回包处，继续复用原门禁；不另建一张自填 YAML 验收表。
