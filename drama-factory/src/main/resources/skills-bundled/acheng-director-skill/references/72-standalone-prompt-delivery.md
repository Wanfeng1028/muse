# 72｜独立提示词与模型交付边界

资产图和逐段视频提示词是视频生产分支的主要交付。每一次生成请求都是新上下文：只可依赖本次完整正文和本次实际上传素材。内部登记、聊天记录、上一段文本、技能知识库都不是生成模型隐含可见的输入。

## 代号必须消解，不能直接丢给模型

| 内部写法 | 对外交付必须包含 |
|---|---|
| A–I、M01/F01等身材编号 | 本项目已确认的年龄、身高／比例、骨架和体量分布、面部、姿态及支撑；编号含义查来源，不按字母猜 |
| I性格、人格分类 | 当前可见行为，例如凝视目标、呼吸节奏、肩颈张力、手势、语气；身材不决定人格 |
| E001/O001、EX节拍ID | 当前镜头可见的具体表演、对象、先后顺序和持续时间 |
| Previs 052、运镜编号 | 具体机位、移动类型、方向、幅度、速度、追踪对象，不能只译出索引名 |
| CHAR／S01／KF／ASSET ID | 人物具体外观、地点空间、明确画面和道具；文件名和管理清单可保留ID |
| D2、trauma phase 1、服装v3 | 本段可见裂口、缺损、包扎、受限关节、衣服颜色／形制／损伤；不让模型推断编号 |
| VisualBible、同上、沿用前段 | 在本条重新写明媒介、色板、主光、空间、身份和初态 |
| A/B/C故事线、配方名、七层力学名 | 实际发生的动作与可見后果；分析标签留在制作卡 |

代码允许内部 `prompt_bindings` 把 `{{LU_LOOK}}` 这类显式占位符展开为完整自然语言。绑定缺失、循环、展开后仍有常见代号会阻止导出；不存在把“A身材”随意替换为一个固定体型的全局表。注册ID、配方表和历史原文保留用于检索，不是最终提示词。

合法引用与内部缩写要区分：H3 的 `<Subject 1>`、`<Picture 1>`、`(S1)` 必须按指南保留；图像正文 `Reference image 1` 由上传清单绑定。用户原对白及实际画面文字作为字面内容保留。机器扫描不等于能理解所有自然语言：主导演还要对每条最终正文做脱离上下文阅读，发现任意未说明的人名、代号、简称或“照前面”依赖时补全再交付。

## GPT Image 2 / 2.5 出口

每项资产交付标题／用途、参考图状态、上传清单和一个完整自然语言 prompt。正文含可见主体身份、单一相位、构图、媒介、灯光材料和必要约束；用完整语句，不输出内部YAML、检索编号或一串风格代号。用户默认看到的资产结果只显示资产名称，以及源数据存在时的状态版本／资产版本；完整正文在`.image.txt`，参考图职责在`UPLOAD.md`和`index.json`。最终正文可中文或英文；台词、标识原文照录。不要把七步表本身当成最终提示词。

资产 `reference_policy` 必须显式为 `none` 或 `required`。纯原创首次设计可为none；已经有确认人物而要求保持身份、源图修改、角色进场景、依赖分镜构图等情况按真实依赖设required。每张图登记 `image`（从1起的上传顺序）、`file`、`role`、`subject`、`preserve`、`exclude`。正文展开用途和作用对象；清单给实际文件。需要几张就列几张，不将未知路径伪装为完成。可选图建议放正文外，不写成已上传的引用。

文件路径不会自动上传给OpenAI。GUI中按清单上传；API客户端把文件作为真实图像输入，并把`.image.txt`作为prompt。文本生成与带图生成／编辑须选择当前入口支持的方式。`GENERATE/EDIT/REBUILD/MIXED` 是制作意图，不是OpenAI端点字段。

2026-09-20核对的[OpenAI图像生成参考](https://developers.openai.com/api/reference/cli/resources/images/methods/generate)接受自然语言prompt，GPT图像模型prompt上限为32000字符；列出的模型包括 `gpt-image-2`、`gpt-image-2.5-sunburst`、`gpt-image-2.5-flare`。不把`gpt-image-2.5`简称冒充已确认API ID；本技能输出兼容的文本，不代选账号入口。图片作为独立输入的方式见[OpenAI图像生成指南](https://developers.openai.com/api/docs/guides/image-generation)。尺寸、质量等写到执行设置，不堆进正文或套其他模型专用语法。

`compile_assets.py`执行资产钩子、绑定展开、代号与引用检查，导出`.image.txt`、`UPLOAD.md`、`index.json`及实际参考图副本。缺图、未知参考编号、缺最终prompt、未展开绑定都会失败。无须图的纯文字资产明确显示“参考图不需要”。

## H3 出口

始终加载已安装 `h3-prompt-writing` 并读所需base/ref指南。模板不能覆盖指南；最终仍是四种基础模式三字段或Ref2VA六字段，不加自创字段。 

有真实参考图、角色、场景、动作或风格资产时，Ref2VA 是首选模式。每个 Ref2VA Segment 必须输出完整六字段；`detailed_description` 按本段时长与复杂度动态计算最低词数（默认 10 秒段为 2,000）与目标词数（默认约 2,400），极限值 2900 词硬性封顶（处于 2200-2900 词区间，彻底剔除无上限输出）。每个镜头独立写出外观、空间位置、朝向、光线、起始状态、触发事实、动作因果、微动作、微表情、接触／受力、相机路径、声音时序与尾态。不能用“同上”“沿用前段”、摘要或参考图标签替代这些事实。

Segment 必须登记 `mode`、`mode_lock` 和 `mode_selection_reason`；续写或升级不得静默更换模式。H3-only 请求不自动启动 STYLE_MOTHER 或资产生成。宿主达到单次输出上限时，按字段或镜头边界提交 partial 并保存游标，后续从完整句子继续，不能降低详细度。

每段重建自己的定义集合：从本段shots找出出现角色和场景，读取其 `prompt_description`（完整英文外观／空间），放入本段实际描述；每镜消费 `state_description`（英文当前伤势／道具／空间状态），再编排动作、表演和声音。v3.2 还要求每个镜头明确写出屏幕位置、光线、起始接触点、触发事实、按时间顺序的动作与反应、摄影机方向／路径／幅度／速度、声音来源与时序，以及镜尾保持状态；目标、策略和潜台词必须转成可见眼神、呼吸、姿态、手势、面部和声线行为。状态文字必须与 `state_in` 账本及确认资产一致，自动校验不能代替这一语义核对。用户只给代号时，导演先根据真值源写展开描述，不能把代号写入这些字段。

本段重新定义不意味着角色换人。稳定身份用 character_id/姓名跨段关联；`(Sx)` 按每次独立请求首次发声分配，段内保持，不要求跨段相同。Subject 和媒体标签也在每段局部定义，清单关联稳定身份。T2VA 不保证跨段同脸；模式变更需用户授权。

启用`acting_design`时，正文还必须把人物目标、社交策略、潜台词、触发事实、可见动作单元、预备/重音/跟随/收势、声线节拍和切镜承接展开成自然语言。不要把“灵动、夸张、有个性”当作替代；每个动作都要能从触发事实和对白节拍解释，并留下下一镜可继承的尾态。

H3脚本在G8检查最终完整文本的已知内部ID、常见代号、未展开绑定、英文章节、引用和字段。输出`.h3.txt`不含内部帧账本、文件路径或操作说明；`UPLOAD.md`单独列本段模式、时长、上传文件和用途。首尾帧素材必须真是对应单帧，正文写清连续运动路径；整张16格表仅作Ref2VA规划参考。

## 最终接收检查

检查实际导出的文本，不只检查结构数据：逐条独立阅读、逐项对照上传图、核对身份／左右／道具／伤势、核对每段起止与对白。禁止删掉主体描述来“通过代号检查”。历史来源原文中的旧代号不修改，且不得直接作为可提交prompt复制出去。遇到用户必须保留的画面文字或对白中含代号，保留其字面内容，不能让lint擅自改台词。

## 生图与视频模型引用标记规范（@图片N 与 Reference image N）

面向 GPT Image 2/2.5 或多模态生图平台交付提示词时，严禁使用模型不可见的内部变量名（如 `STYLE_MOTHER`、`CHAR_LU` 等）。必须统一映射为：
1. **中文标记**：`@图片1`、`@图片2` 或 `参考图1`、`参考图2`；
2. **英文标记**：`Reference image 1`、`Reference image 2` 或 `@image1`；
3. **上传助手匹配**：提示词中引用的每一个 `@图片N`，必须在资产卡上传助手中有明确真实文件相对应；槽位 1 默认为风格母图（`role: style`），后续槽位为身份图（`role: identity`）或场景底板（`role: layout`）。
