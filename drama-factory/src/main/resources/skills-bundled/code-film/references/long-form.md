# 长片：3 分钟以上怎么构思和设计

短片靠密度，长片靠**结构和持续的好奇心**。长片不可能像短片一样每秒都有新花样，观众也受不了。长片的难点在于：怎么让观众在几分钟甚至几十分钟里一直想看下去，以及怎么在很多镜头里保持统一又不单调。

## 1. 长片和短片的区别

| | 短片 | 长片 |
|---|---|---|
| 驱动力 | 冲击力、节奏、一个点子 | 一个贯穿始终的问题或旅程 |
| 节奏单位 | 拍、小节 | 段落、章节 |
| 镜头 | 多、短、每个都精雕 | 少而长，镜头内部有丰富的运动和变化 |
| 视觉 | 可以每个镜头都不一样 | 一套可以复用的视觉系统和「场景」 |
| 声音 | 一首音乐贯穿 | 每章不同的音乐，大量旁白，有静默段落 |
| 风险 | 做得不够惊艳 | 中间塌掉、观众走神、风格前后不一 |

## 2. 构思：长片的五根支柱

**① 一个核心问题**
长片必须有一个观众真正想知道答案的问题，它是整部片子的发动机。
- 「为什么天空是蓝的，而夕阳是红的？」
- 「一个 AI 能不能理解人类说的『温暖』？」
- 「这家公司是怎么从 3 个人走到今天的？」
答案要到结尾才完整给出，中间每一章都给出一部分答案，同时引出新的小问题。

**② 一个向导**
观众需要一个「跟着走」的对象：一个讲述者（旁白的人格）、一个角色、一个物体（一粒光子的旅行）、甚至一个图形（一个一直在画面里的小圆点）。向导让长片有了连续性。

**③ 一条旅程**
长片最好的结构是「移动」：从小到大、从过去到现在、从问题到答案、从表面到深处、从一个地方到另一个地方。
- 尺度之旅：从一个原子一路拉远到宇宙（经典的「十的次方」结构）。
- 时间之旅：沿时间线往前走。
- 深入之旅：一层一层往里剥。
- 地理之旅：从一个地点到另一个地点。

**④ 视觉母题**
选两三个在全片反复出现的视觉元素（一个形状、一个颜色、一个动作、一个构图），每次出现时意义都有一点变化。母题让长片有「整体感」，还能在结尾形成强烈的回声。

**⑤ 章节**
把片子切成 3 到 7 个章节，每章 1 到 3 分钟。每一章都是一个完整的小弧线：**自己的钩子、自己的推进、自己的小高潮、一个引向下一章的问题。**

## 3. 长片的结构模板

- **章节式**：片头 → 第一章 → 第二章 → …… → 结论 → 片尾。每章前有章节卡（2 到 3 秒）。
- **串珠式**：几个独立的小故事，由一个共同的主题串起来，最后汇合。
- **旅程式**：沿着一条路径（尺度、时间、空间）前进，每一站是一章。
- **问题树**：一个大问题拆成几个小问题，逐个解答，最后合成大答案。
- **双线交织**：两条线交替推进（比如数据和人、过去和现在），在高潮处交汇。
- **书挡式**：开头和结尾是同一个场景，中间是整段旅程，结尾时同一个场景有了新的意义。

## 4. 宏观节奏

- **每 45 到 90 秒一次「打断」**：新的视觉环境、一个惊人的事实、一个问题、一段音乐变化、一个幽默的点。观众的注意力在这个时间尺度上会自然下降，需要被重新唤起。
- **章节之间有呼吸**：章节卡、一段纯音乐、一个安静的长镜头。
- **每章的色调、音乐、节奏可以不同**，但都在同一个视觉系统之内。比如每章换一个强调色，字体和版式不变。
- **信息密度要控制**：科普长片，每 30 到 60 秒最多引入一个新概念，引入新概念前先回顾一下前一个。
- **全片的张力曲线**：整体上升，但每章内部也有起伏，像一条锯齿形向上的线。最大的高潮在最后一两章。

## 5. 长片的镜头设计

长片不能靠大量切镜，而要靠**镜头内部的变化**：

- **一镜到底式讲解**：所有内容在一张巨大的世界画布上，虚拟摄像机在上面持续移动。每到一处，元素逐步出现、变化、连接。一个「镜头」可以持续一两分钟，但一直有东西在发生。
- **渐进构建**：一张复杂的图，在几分钟里一点一点画出来。观众看着它长大，理解也随之加深。结尾拉远看到完整的图，是非常强的收尾。
- **场景（布景）复用**：设计几个可以反复回来的「场景」，比如一个实验室、一张地图、一条时间轴。每次回来都有新的东西。观众会对它们产生熟悉感，就像电视节目的演播室。
- **变换视角**：同一个东西，全景、局部、剖面、俯视、数据视图，轮流展示。
- **动作多样性预算**：列出全片会用到的动画类型，确保同一种入场方式不会连续出现太多次。

## 6. 长片的声音

- **旁白是长片的主干**，通常是必要的。旁白的人格要鲜明、一致。
- **每章可以有自己的配乐**，章节之间用渐变或静默过渡。一首音乐循环几分钟会让人厌烦。
- **留出没有音乐的段落**，只有旁白和环境音。这会让下一次音乐进来时更有力量。
- 音效比短片更稀疏，只在关键时刻使用。

## 7. 生产流程

长片的最大风险是「做到一半发现风格不对，要全部重来」。所以：

1. **总纲**（模板见 `assets/templates/long-form-bible.template.md`）：核心问题、向导、旅程、母题、章节表、视觉系统、声音系统、总时长。→ 用户确认。
2. **完整文案**：全部旁白和屏幕文字逐字定稿。→ 用户确认。
3. **竖切样片**：选一个最有代表性的章节（通常不是第一章，而是最复杂的一章），从头到尾做到成片质量，包括配音、音乐、音效。→ 用户确认。**这一步决定全片的风格和质量标准。**
4. **铺开**：其余章节按样片的标准制作。共用 `theme.ts` 和组件库，每章是一个独立的 Remotion 合成（Composition），有自己的 `storyboard` 文件。
5. **分章渲染**：每章单独渲染，编码参数完全一致（分辨率、帧率、编码器、像素格式、音频采样率）。
6. **拼接**：

   ```bash
   # chapters.txt 里每行一个：file 'ch01.mp4'
   ffmpeg -f concat -safe 0 -i chapters.txt -c copy full_raw.mp4
   python <skill>/scripts/finalize.py full_raw.mp4 full.mp4
   ```
7. **整片自检**：缩略图墙看全片的色彩和节奏变化，`qa_video.py` 检查冻帧和静音，请用户完整看一遍。

## 8. 长片工程结构

```
src/
├── Root.tsx               每章一个 Composition，另外一个 Full 合成用于整体预览
├── theme.ts               全片共用
├── components/            全片共用
├── chapters/
│   ├── ch01/storyboard.json
│   ├── ch01/scenes/...
│   ├── ch02/...
```

多个 Agent 可以并行制作不同章节，但前提是风格已经由竖切样片锁定，并且有一个「总导演」负责最后的统一检查：字体、颜色、动效参数、音量、转场方式是否全片一致。

## 9. 长片自检

- [ ] 核心问题在开头 30 秒内被提出，结尾被完整回答。
- [ ] 每一章都有自己的钩子和小高潮，章末留下一个问题。
- [ ] 每 45 到 90 秒有一次打断。
- [ ] 视觉母题出现了至少三次，结尾有回声。
- [ ] 各章风格统一（同一套 `theme.ts`），又有可识别的变化。
- [ ] 音乐不单调，有静默段落。
- [ ] 各章编码参数一致，拼接处没有跳帧或音频爆音。
