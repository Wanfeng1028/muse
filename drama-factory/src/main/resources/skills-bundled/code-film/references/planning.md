# 规划：把故事变成施工图

规划阶段的目标：**写代码时不再需要做任何创作决定，只做翻译。** 规划得越细，执行越稳，返工越少。能力一般的模型尤其要把这一步做足。

## 1. 规划的产物

| 产物 | 位置 | 作用 |
|---|---|---|
| 策划书 | `docs/brief.md` | 立意、结构、情绪曲线、文案、风格方向、声音方案（模板见 `assets/templates/brief.template.md`） |
| 分镜表 | `docs/brief.md` 里的表格 | 给人看：每个镜头的时间、画面、文字、声音、运镜、转场 |
| 分镜数据 | `src/storyboard.json` | 给代码看：唯一事实来源 |
| 关键帧施工图 | `docs/brief.md` 或单独文件 | 复杂镜头的逐帧动作表 |
| 视觉系统 | `src/theme.ts` | 颜色、字体、字号、动效参数、质感 |
| 风格帧 | `out/style/*.png` | 3 到 5 张关键画面静帧 |
| 动态预演 | `out/draft.mp4` | 只验证节奏和时间 |

## 2. 时间网格：先定尺子

**所有时间都用帧表示，所有动作都落在网格上。**

- 有音乐：用 `analyze_music.py` 得到的 BPM 和节拍位置。
- 没有音乐：也要按情绪选一个 BPM 当网格。60 到 80 抒情，90 到 110 叙述，120 到 130 活力，140 以上燃。之后选配乐时，找 BPM 相同或成倍数的曲子。
- 每拍帧数 = 帧率 × 60 ÷ BPM。30fps 下：60 BPM 是 30 帧，90 BPM 是 20 帧，120 BPM 是 15 帧，128 BPM 约 14.06 帧（非整数时按实际节拍时间取整，不要累积误差）。
- 四拍一小节，四小节或八小节一个乐句。**大的段落切换放在乐句边界，镜头切换放在拍上，重要揭示放在小节第一拍。**

30fps 速查：0.1 秒 = 3 帧，0.2 秒 = 6 帧，0.5 秒 = 15 帧，1 秒 = 30 帧。

## 3. 分镜表：给人看的版本

每个镜头一行，包含这些列：

| 列 | 内容 |
|---|---|
| 镜号 | s01、s02……插入镜头用 s03a |
| 时间 | 起止时间（秒）和帧数，或者「第几小节第几拍」 |
| 段落 / 张力 | 属于哪一幕，张力值 0 到 10 |
| 画面 | 画面里有什么，主角是谁，怎么动。要具体到能照着画 |
| 屏幕文字 | 逐字写出 |
| 旁白 | 逐字写出 |
| 声音 | 音乐状态（进入、铺底、抽空、爆发）和音效事件 |
| 运镜 | 固定、推、拉、摇、移、甩、跟随 |
| 转场 | 这个镜头怎么切到下一个 |
| 实现 | 用哪个场景组件，关键技术点，风险 |

画面描述的好坏对比：
- 差：「展示太阳的数据」
- 好：「黑底，等宽字体，数据从上往下逐行刷出：质量、温度、距离、年龄。每行出现时伴随一声 tick，刷完后整体停住 1 秒」

## 4. storyboard.json：给代码看的版本

模板工程读取的格式如下（字段含义见注释，JSON 里不能写注释，这里只是说明）：

```jsonc
{
  "meta": {
    "title": "我从未见过太阳",
    "fps": 30, "width": 1920, "height": 1080,
    "durationInFrames": 2700,
    "bpm": 72,                     // 可选：时间网格
    "beatOffsetFrames": 0,         // 可选：第一拍所在帧
    "music": "music/bgm.wav",      // 可选：public 下的相对路径
    "musicVolume": 0.8,
    "musicStartFrame": 0
  },
  "shots": [
    {
      "id": "s01",
      "from": 0,                   // 起始帧（全片坐标）
      "duration": 180,             // 持续帧数
      "scene": "Statement",        // scenes/index.ts 里注册的组件名
      "section": "起",
      "intensity": 2,              // 张力 0 到 10
      "text": ["太阳"],            // 屏幕上要读的文字，用于阅读时间检查
      "transitionOut": "cut",      // cut / fade / match / zoom / whip / wipe ……
      "props": { "text": "太阳", "technique": "type" },
      "events": [                  // 音效事件，at 是镜头内的相对帧
        { "at": 20, "sfx": "tick" },
        { "at": 150, "sfx": "riser", "align": "end" }
      ],
      "note": "光标先闪 20 帧再开始打字"
    }
  ]
}
```

规则：
- 镜头首尾相接，不留空档、不重叠。需要重叠的转场在场景组件内部实现，或者给镜头加 `"overlapOk": true`。
- `durationInFrames` 必须等于最后一个镜头的结束帧。
- 写完跑 `python <skill>/scripts/check_storyboard.py src/storyboard.json --sfx-manifest public/sfx/manifest.json`，把错误全部清零，警告逐条确认。

## 5. 每个镜头拆成「进、停、出」

每个镜头内部都有三段：
- **进**：主体入场，约占 20% 到 30%。
- **停**：让观众看清、读完，约占 50% 到 60%。停的时候也要有微动（见 `rhythm.md`）。
- **出**：退场，约占 10% 到 20%，或者直接硬切，不做退场。

**动画预算**：每个镜头只有一个「主角动作」，其他元素是配角，或者干脆不动。主角动作要落在拍子上。

## 6. 关键帧施工图

主角动作复杂、元素多、要和音效精确配合的镜头，写一张逐帧动作表。表写清楚了，写代码只是翻译。

示例：标题镜头，120 BPM（一拍 15 帧），共 4 拍 60 帧。

| 帧 | 元素 | 动作 | 曲线 | 音效 |
|---|---|---|---|---|
| 0 到 12 | 主标题 | 从下方 60px 遮罩升起，透明度 0 到 1 | 缓出 expo | whoosh（峰值对准第 6 帧） |
| 12 | 主标题 | 落定 | 弹簧，轻微回弹 | hit |
| 8 到 20 | 副标题 | 逐字模糊入场，每字间隔 2 帧 | 缓出 | 无 |
| 20 到 50 | 整体 | 缓慢放大 1.00 到 1.02 | 线性 | 无 |
| 50 到 58 | 整体 | 向上 20px 并淡出 | 缓入 | 无 |
| 55 | 下一镜 | 已经开始入场（和本镜重叠 3 帧） | | |

## 7. 视觉系统：先定规矩再画

在 `src/theme.ts` 里写死这些东西，所有镜头只从这里取值：
- **颜色**：背景色、前景色、弱化色、强调色（一个就够），以及它们的语义（比如「太阳」这个概念全片都用强调色）。
- **字体**：展示字体、正文字体、等宽字体，最多两种加一种等宽。
- **字号阶梯**：展示、标题、正文、注释四级，按画幅定具体数值（见 `typography.md`）。
- **网格与安全区**：页边距、栏数、竖屏的遮挡区。
- **动效参数**：入场帧数、退场帧数、重叠帧数、错峰间隔、默认缓动和弹簧。
- **质感**：颗粒强度、暗角强度、是否有辉光、色差、黑边。

## 8. 风格帧

风格帧是「长什么样」的定稿，不涉及动画。
- 挑 3 到 5 个最能代表全片的镜头：开场、高潮、结尾，外加一两个特别的。
- 把这些镜头做到「静止时完全是成品」的程度，用 `npx remotion still Film out/style/s05.png --frame=<停的阶段的某一帧>` 渲染。
- 给用户看的时候，说明配色、字体、质感的选择理由，和立意的关系。

风格帧通过之后，视觉系统就冻结了。后面再改颜色和字体，要回到这一关重新确认。

## 9. 动态预演（animatic）

动态预演是「怎么动、什么时候动」的定稿，不追求好看。
- 所有镜头按分镜的时间跑通：可以是灰色方块、占位文字、最简单的淡入淡出。
- 必须带上音乐（或节拍器）和主要音效位置，因为节奏只能在有声音时判断。
- 用 `npm run draft` 出半分辨率版本，渲染快。
- 给用户看的时候，请他只关注：总时长、每个镜头长短、切点和音乐的配合、高潮位置。

- [ ] 时间网格确定，切点都在拍上（`check_storyboard.py` 无拍点警告，或者警告都有理由）。
- [ ] 每个文字镜头的时长够读完。
- [ ] 张力曲线有起伏，高潮位置合理。
- [ ] 同一种镜头、同一种入场方式没有连续重复 3 次以上。
- [ ] 转场种类不超过 3 种，硬切是默认值。
- [ ] 每个镜头都知道用哪个组件实现，风险点已经标出。
