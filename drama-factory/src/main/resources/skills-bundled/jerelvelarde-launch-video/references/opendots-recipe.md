# OpenDots launch recipe

Use this reference for an OpenDots launch or a conversation-to-workspace story. The local production film was built with Canvas/JavaScript and real recordings; `OpenDotsLaunch` is a new 32-second Remotion adaptation with synthetic UI, not the original film source.

| Beat | Purpose | Starter surface |
| --- | --- | --- |
| Reveal | Establish one useful outcome | Title and concise premise |
| Conversation | Show the request and agent response | Synthetic conversation card |
| Approval | Make the decision visible | Draft, approval press, saving state |
| Page | Show where the result lives | Saved workspace Page |
| Channels | Explain routing without a logo wall | Shared connector geometry |
| Devices | Keep the result legible across screens | Mock desktop and phone |
| Integration | Give developers a concrete entry point | Disclosed pseudocode |
| CTA | Tell the viewer what to do next | Replaceable launch/repository URL |

Use current product evidence for Page creation, approvals, computer tools, channels, customization, and deployment claims. Replace pseudocode with a verified snippet before presenting it as setup instructions. Channel labels in the starter are generic; a logo is not evidence that an integration works.

For Slack proof, use the `slack-demo-video` skill if available, or the starter's `SlackThread`. Keep a clean full-frame UI export for the editor and add branding in the film composition. Disclose authored replies, progress, receipts, and reactions in notes. Use real capture when the user requests a live integration demonstration.

For actual product clips, preserve the full recorded viewport when requested. Enlarge UI before capture by choosing a responsive CSS viewport and suitable device pixel ratio; verify that text, controls, and computer output remain readable. Contain footage within panels without distorting its aspect ratio. Do not use camera cropping as evidence that the source UI was enlarged.

Inventory acquisition cadence separately from output fps. A 15 fps capture in a 30 fps film contains repeated frames. High device pixel ratio does not improve screenshots already embedded by the application. Document shortened navigation, stitched holds, speed changes, and any upscaled editor copies. Never replace failed or missing output with authored success and call it a recording.

Make the package useful to a human editor: active source list, lockfile, raw demo assets, approved masters, review poster, original audio and rights, frame timeline, and media verification. Keep accepted revisions until a replacement has passed decode and visual review. Historical revisions belong in an archive rather than in the active scene import graph.
