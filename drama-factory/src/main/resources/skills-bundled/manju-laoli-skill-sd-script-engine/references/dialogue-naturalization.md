**本引擎管用词与句法**（说什么词、怎么断句、怎么称呼）。两者正交，可叠加。

### 0.4 三条总则（贯穿全文）

1. **口语化 ≠ 加废话。** 目标是"像人说"，不是"变啰嗦"。与 `six-stage-pipeline.md` §6.8「对白丰富但不注水」严格一致。
2. **口语化 ≠ 拉低身份。** 书生变糙、杀手变话痨都是**人物崩**，不是拟人化。粗人糙话、书生引典、杀手惜字（`dialogue-doctor-7d.md:11`）。
3. **台词是服务剧情的工具，不是必须套用的模板**（总原则，见 `dialogue-speed-check.md` §一·补三 末）。宣判段、静场留白段**本就该"不口语"**——过站时须显式标注段落意图，不得硬掰。

## 一、 称呼系统（★ 本包空白 · 最高优先）

> **背景**：这是用户最直接的诉求（"增加点拟人的称呼，更加口语化"）。在本引擎建立之前，全包"称呼系统"仅出现 **1 次**（`six-stage-pipeline.md:419` 人物声音卡里的一个字段名），**没有任何定义、变体、示例或台账**。本节补此空白。

### 1.1 称呼不是"一个词"，是四个变量的函数

任何一个称呼 = **身份轴 × 关系轴 × 场合轴 × 情绪轴**。四者任一变化，称呼就该变化。

| 变量 | 取值示例 |
|---|---|
| **身份轴** | 尊/平/卑（决定敬语层级）、职业、年龄差 |
| **关系轴** | 生疏 / 熟识 / 亲密 / 决裂 / 旧情 / 上下级 |
| **场合轴** | 公开（有第三方在场）/ 私密 |
| **情绪轴** | 平静 / 动情 / 恼火 / 示弱 / 挑衅 |

**机械化最典型的症状之一**：全剧用同一个称呼——不管什么场合、什么情绪、关系走到哪一步，永远"李总""少爷""师父"。**那不是简洁，是没写。**

### 1.2 称呼变体矩阵（对同一对象的七种叫法）

以「一个角色对另一个角色」为行，示范四轴变化：

| 情境 | 该用什么 | 现代都市示例 | 古装示例 |
|---|---|---|---|
| **公开·正式·尊** | 职务/尊称全称 | "陈总监" | "陈大人""陈将军" |
| **私下·熟识** | 简省称呼 | "老陈" | "陈兄""老爷" |
| **亲密/动情** | 昵称、去姓、加小称 | "陈默""阿默" | "阿默""默郎" |
| **示弱/求人** | 升格敬称（故意拉开或拉近） | "陈总，您看……" | "大人，小人斗胆……" |
| **恼火/决裂** | 降格、直呼全名、去敬语 | "陈默！"（连名带姓） | "陈默！"（喝名） |
| **挑衅/敌意** | 贬称、外号、反讽敬称 | "陈大总监"（讽） | "陈大人好大的官威" |
| **划清界线** | 退回生疏称呼 | 从"老陈"退回"陈总监" | 从"兄"退回"大人" |

> **写作提示**：**称呼的"降格"和"退回"比"升格"更有戏**。关系破裂时，一句从"老陈"切回"陈总监"，比写一句"我们完了"更有力——因为观众能直接听出来。

### 1.3 三条铁律

1. **一致性铁律**：同一角色对同一对象，**在同一关系阶段的称呼必须稳定**，跨集不得漂移。要变，必须有**事件触发**并在台账登记。
2. **称呼是"体温计"，不是"推进器"**（与 `episode-planning.md:456` 一致）：
   > 关系弧必须通过共同经历、试探、保护、背叛、拒绝或修复推进。**不能只用称呼变化或旁白宣布关系升级。**
   称呼变化**只能反映**关系状态，**不能替代**事件。只改称呼不改行为 = 无效推进，标记 `ADDRESS_ONLY_SHIFT`。
3. **称呼要有区分度**：两个不同角色对**同一个**对象，称呼应不同（一个叫"爸"，一个叫"老李"，一个叫"李队"）——这是**关系位置的免费标记**。

### 1.4 产出物：`ADDRESS_LEDGER`（称呼台账 · 阶段⑤ 硬产出）

阶段③ 建卡时填写"初始关系"，阶段⑤ 逐集更新"称呼状态"：

```yaml
ADDRESS_LEDGER:
  - speaker: "沈砚"        # 说话人
    target: "陈默"         # 被称呼者
    relation_stage: "初识/生疏"       # 关系阶段
    address_now: "陈先生"              # 本阶段用的称呼
    history:                           # 变化轨迹（必须每次都有触发事件）
      - episode: "EP003"
        address: "陈先生"
        trigger: "初次见面，公开场合"
      - episode: "EP011"
        address: "老陈"
        trigger: "共同熬过危局，私下交谈"
    forbidden: ["陈总"]                # 本关系阶段绝不该出现的称呼（防穿越）
```

**过站检查**：逐集比对 `address_now` 与上集是否一致；不一致则必须有 `trigger`。
**机检**：`ADDRESS_LEDGER` 存在性 → 见 §八。

## 二、 书面语 → 口语（★ 先分题材，口径不同）

### 2.1 ⚠️ 关键前提：古装和现代，"书面"不是同一个东西

| 题材 | 什么算"机械化" | 什么**不算** |
|---|---|---|
| **现代/都市/悬疑** | 书面连接词、公文腔、完整长句、被动句 | 日常口语词、语气词、半截话 |
| **古装/年代** | **现代书面语混入**（"经济损失""逻辑漏洞""情绪价值"） | **文言简炼是风格，不是病灶** |

> **⛔ 最容易犯的错**：拿现代口语标准去改古装台词，把"臣不敢"改成"我不敢啦"。
> `dialogue-doctor-7d.md:14` 的病灶定义是**"古装戏冒出现代词"**——**不是"古装戏不够口语"**。

### 2.2 现代赛道：绝对禁用表（A 类 · 出现即标记）

以下虚词在**现代剧的口语台词**里不会出现，出现即为书面腔泄漏：

```
是否   因此   从而   鉴于   予以   加以   可否   何以
颇为   甚为   以及   然而   由于   进行   予以   兹
```

> **判定口径**：只查**台词文本**内，不查画面段/叙述段（古装剧本的场景描述可以用书面语）。
> **替换示例**：`是否 → 是不是`｜`因此 → 所以/这么说`｜`以及 → 还有`｜`由于 → 因为`｜`进行 + 名词 → 直接用动词`（"进行了一次检查"→"查了一遍"）

### 2.3 古装赛道：违和现代词表（B 类 · 出现即标记）

```
逻辑   数据   机制   效率   系统   项目   团队   版本   反馈   状态
维度   定位   复盘   闭环   赋能   抓手   颗粒度   情绪价值   经济损失
沟通   心理   压力   节奏（作抽象义时）   关系（作抽象义时）
```

> 依据 `dialogue-doctor-7d.md:14`「古装戏冒出'经济损失/逻辑漏洞'等现代词」。
> **边界**：`节奏`/`关系` 等词在古装里**作具体义**（"击鼓的节奏""父子关系"）可用，只有**现代抽象义**违和——判定看语境，不只看词。

### 2.4 通用：长句拆解（句式层）

机械化的第三种形态是**句法**，不是词汇：

| 症状 | 处方 |
|---|---|
| 成对关联词（"因为……所以……"、"虽然……但是……"） | 口语里**后半截常常不说**——"因为下雨了"后面直接接行动 |
| 完整主谓宾、无一处省略 | **删主语**（口语大量省略："吃了吗？""早说啊"） |
| 被动句（"被……所……"） | 改主动 |
| 一句话说完才停 | **插入停顿点**（逗号/破折号/省略号至少一处） |

## 三、 「撒碎屑」四法（把书面句掰成人话）

> **来源**：`short-drama-director/references/acting-direction.md:267` 坏表演图鉴第 8 条「**台词太干净**——街头角色说着书面长句 → **撒碎屑：打断、掉尾、重复**」。
> ⚠️ **标注纪律**：`acting-direction.md` 头部声明其示范句均为 `【待验证·未实拍】`（来源为粉丝投稿、本包未实拍验证）。**本节把原来的 6 个字展开为可执行手法**，示范句因此同样标 `【待验证·未实拍】`，**不得写成 ✅ 正例、不得进机检修复建议文案**。

### 3.1 打断（自己打断自己）

人说话会改口、会推翻自己半句。

- ❌ "我本来是想告诉你这件事的，但后来我觉得还是不要说了。"
- ✅ ~【待验证·未实拍】~"我本来想跟你说——算了。"

**用法**：用于**犹豫、隐瞒、动摇**的人物状态。**不宜每场都用**（谁老改口谁就像结巴）。

### 3.2 掉尾（说一半不说了）

把关键信息**留在沉默里**，由对方的反应补齐。

- ❌ "你要是敢动她一根头发，我绝对不会放过你。"
- ✅ ~【待验证·未实拍】~"你要是敢动她——"（后半句用眼神和手里的动作说）

**用法**：**威胁、诀别、说不出口的告白**。与 §六 的"金句留白"配合。

### 3.3 重复（口吃式重复 / 回声）

- ❌ "你说什么？我没听清。"
- ✅ ~【待验证·未实拍】~"你、你说什么？"

**用法**：**受冲击、难以置信、慌乱**。重复**只重复关键词**，不要重复整句。

### 3.4 语气词与垫词（★ 机械化最有效的解药）

书面句最明显的特征就是**一个语气词都没有**。中文口语的颗粒感大量来自句尾助词与垫词：

| 类别 | 词 | 功能 |
|---|---|---|
| 句尾助词 | 啊 吧 呢 嘛 呗 啦 呀 哦 咯 罢了 而已 | 缓和/确认/反问/无所谓 |
| 前置垫词 | 那什么 这个 我说 你听我说 得了 行吧 | 起话头/争取时间 |
| 应答词 | 嗯 唉 哎 嘿 哟 啧 | 情绪色彩 |
| 程度垫词 | 特别 贼 巨 超 老（老远了） | 替代"非常/十分" |

**示例**：
- ❌ "我知道了，你不用担心。"
- ✅ ~【待验证·未实拍】~"知道了知道了，你操那心干嘛呀。"

### 3.5 借物说话 / 答非所问（潜台词通道）

用**手边的东西**代替直接表态——这也是七维维度2「潜台词层级」的落地手法。

- ❌（拒绝表白）"对不起，我不能接受你的感情。"
- ✅ ~【待验证·未实拍】~"（把杯子推回去）……茶凉了。"

与 `dialogue-doctor-7d.md:12` 的示例「茶凉了，换杯热的再上路吧」同源。

## 四、 机械化认症表（反例库）

> 用途：**写完以后扫一遍**，命中即改。这是"体检"侧，与 §三 的"生成"侧配对使用。

| # | 症状 | 表现 | 处方 |
|---|---|---|---|
| 1 | **等长句** | 每句字数接近、结构一致 | 长短交错；长句后必接短句 |
| 2 | **零语气词** | 整段对话没有一个"啊/吧/呢/嘛" | 按 §三·4 补（注意场合） |
| 3 | **全完整句** | 每句主谓宾齐全、无人省略 | 删主语、掉尾、打断 |
| 4 | **人人同口吻** | 把角色名遮住认不出谁在说 | 建**角色特征词表**（每人 3~5 个专属用词） |
| 5 | **信息均匀分配** | 像轮流念资料，你一句我一句对等 | 制造**信息差**：一方知道得多，一方在猜 |
| 6 | **说明式对白** | 向观众交代背景（"我是你师兄，当年……"） | 改为动作/反应呈现（七维维度5） |
| 7 | **书面连接词** | "因此""是否""以及" | 查 §二 禁用表 |
| 8 | **情绪结果词** | "我很愤怒""他很伤心" | 情绪用行为和潜台词体现，不直说 |
| 9 | **全员敬语/全员粗口** | 无差别礼貌或表演型粗野 | 按身份轴分层（§1.1） |
| 10 | **复读** | 同一句台词在相邻集原样重复 | 见 `six-stage-pipeline.md` `KEY_LINE_OVERUSE` |

## 五、 同口吻识别法（自检工具）

写完一场戏，做三个测试：

| 测试 | 做法 | 判定 |
|---|---|---|
| **遮挡名测试** | 把角色名遮住，只看台词 | 认不出谁在说 → **不合格**（七维维度1 红线） |
| **句长方差测试** | 统计同一角色连续 5 句的字数 | 标准差 < 2 字 → 语境单一，考虑长短交错 |
| **专属词测试** | 每角色列出 3~5 个"只有他会用"的词 | 列不出 → 角色没立住 |

> 与 `story-bible-and-ip.md` §1.8 `PERFORMANCE_AND_VOICE` 的"角色语言指纹"呼应——**特征词要落进声音卡，不能只停在脑子里**。

## 六、 台词拟人化过站（执行流程 · 阶段⑤硬产出）

### 6.1 触发时机

**阶段⑤ 逐集十道主编工序 · 第 8 道「台词改写」之前**（`six-stage-pipeline.md` §6.9 第 8 条）。

### 6.2 四步过站

| 步 | 动作 | 产出 |
|---|---|---|
| **1** | **读台账**：调出 `ADDRESS_LEDGER`（§1.4）+ 各角色 `PERFORMANCE_AND_VOICE`（§1.8） | — |
| **2** | **逐句诊断**：按 §四 认症表扫全篇 | 问题句清单 |
| **3** | **逐句重写**：按 §二（词汇）+ §三（撒碎屑）+ §一（称呼）改写 | 改写后正文 |
| **4** | **回签**：标注改了哪些句、依据哪一条、是否触碰人物身份 | 过站卡 |

### 6.3 过站卡（输出契约）

```markdown
【原句】"我是否应该告诉你这件事？"
【改写】"我吧……想跟你说个事儿。"
【依据】
  ① 词汇禁用：`是否` → 口语不出现（§2.2）
  ② 撒碎屑·前置垫词：加"我吧"起话头（§3.4）
  ③ 掉尾：不把话说完，留给对方追问（§3.2）
【人物校验】符合"沈砚·犹豫不决"的语言指纹 ✅
```

### 6.4 ⛔ 段落豁免（不许硬掰）

以下段落**豁免过站**，但须在段首显式标注意图：

| 段落类型 | 标注写法 |
|---|---|
| 宣判/压迫/长镜头静场 | `【本段为静场宣判段·刻意书面】` |
| 权威人物的官腔（**人物设定如此**） | `【本段官腔为人设·非缺陷】` |
| 古装文言对白（题材语体） | `【本段为文言体·题材要求】` |

> **判准**：这段"不口语"，是**剧情需要**还是**作者没写**？前者豁免，后者过站。

## 七、 边界与禁令

1. **不注水**：口语化不得增加无效信息。与 `six-stage-pipeline.md` §6.8「对白丰富但不注水」一致；仍须通过**逐句删除测试**。
2. **不破身份**：粗人糙话≠全员糙话；书生引典≠全员文绉绉。见 §0.4·2。
3. **不改事件、不改因果、不改人物设定**：本引擎只改**台词的表达层**。任何需要改事件才能说通的台词，回 `six-stage-pipeline.md` §6.9 重做剧情。
4. **下游不越权**：P3 分镜 / P4 投喂的铁律是「**台词逐字保留、不得删改**」（`dialogue-speed-check.md` §一·补二）。**下游只能报，不能改**——改台词必须回阶段⑤ 过站。
5. **示范句标注纪律**：凡源自 `acting-direction.md` 手法（§三）的示范句，一律标 `【待验证·未实拍】`，实拍通过后方可回收为正式正例（依 `model-adapters.md` §5.0.5）。
6. **不新增字段**：称呼与语言指纹写入既有的声音卡与台账，**不新增七段式字段、不改投喂稿结构**。

## 八、 机检口径

> **诚实边界**：**"有没有人味"无法机检。** 本节能机检的是**可判定的子集**，用于**下游兜底探测**（补上 R5 缺失的反馈回路），不能替代人工过站。

### 8.1 可机检（下游 · `validate_prompt.py` C28 系列）

| 码 | 判定 | 级别 |
|---|---|---|
| `C28a` | 台词文本出现**现代书面虚词**（§2.2 A 类表） | WARN |
| `C28b` | 对话段台词 ≥40 字且**语气词数为 0** | WARN |
| `C28c` | 单句 ≥20 字且句内**无任何停顿标点** | WARN |

- **只报不改**：下游铁律「台词逐字保留」→ C28 是**提示**，触发**回阶段⑤ 过站**，不是自动改写。
- **赛道③ 豁免**：解说类旁白（VO）本就是书面叙事语体，`--track 3` 时 C28 整体豁免。

### 8.2 不可机检（人工过站负责）

称呼是否得体、潜台词是否成立、撒碎屑是否自然、是否破人物身份——**一律人工**。

### 8.3 剧本层登记项（非机检，但必须落盘）

`ADDRESS_LEDGER`（§1.4）与 §6.3 过站卡 —— 由阶段⑤ 产出，供圆桌审核抽查。
