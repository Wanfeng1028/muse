# 图像生成使用指南

> 参考来源：OpenAI GPT Image 文档、FLUX/BFL API 文档

## 快速参考卡

```
FLUX 分辨率：    1920x1088 (16:9) | 1088x1920 (9:16) ——必须是 16 的倍数
最大总像素：     4 百万像素（宽 x 高）
一致性方案：     用主视觉图作为后续帧的 input_image
风格系统：       从主题 + 受众 + 基调推导，再按场景适配
批量策略：       主视觉用最高质量 → klein 迭代 → pro 最终输出
```

## 视频帧分辨率

所有 FLUX 尺寸**必须是 16 的倍数**。最大总像素为 4MP。

| 目标 | FLUX 分辨率 | 费用（FLUX.2 pro） |
|------|-------------|---------------------|
| YouTube 16:9 | `1920x1088` | $0.03/张 |
| YouTube 4K | `3840x2160` | 需要 pro/max |
| TikTok/Reels 9:16 | `1088x1920` | $0.03/张 |
| 方形 1:1 | `1024x1024` | $0.03/张 |
| 缩略图 | `1280x720` | $0.03/张 |

## 维持视觉一致性

最大挑战：让 8-12 张生成图像看起来属于同一个视频。

### 策略一——共享视觉系统（始终使用）

先为项目定义一套共享视觉系统，再按场景适配。捕获项目的：

- 主导情绪与质感，
- 色调方向，
- 光照偏好，
- 渲染媒介，
- 角色/环境一致性锚点。

剧本的 `image_prompt_prefix` 是素材来源，不是逐字粘贴到每个提示词中的内容。将其提炼为更短的、适配场景的锚点。

### 策略二——主视觉参考图（推荐）

1. 以最高质量生成一张"主视觉"图（`FLUX.2 [max]`，$0.07）
2. 将其作为所有后续帧的 `input_image`：

```
帧 1：T2I 详细提示词 → hero.png
帧 2：I2I 以 hero.png + "相同风格，镜头右移展示……"
帧 3：I2I 以 hero.png + "相同风格，放大……"
```

FLUX.2 支持最多 4 张参考图（klein）或 8 张（pro/max/flex）。按编号引用："图 1 中的角色在图 2 的环境中。"

### 策略三——种子锁定

在相似提示词间使用相同的 `seed` 参数。能产生相似构图，但对提示词变化很敏感——作为补充手段而非主要策略。

## 提示词构建——三段式上下文方法

**不要**把剧本的 `image_prompt_prefix` 逐字复制到每个提示词中。那正是所有场景看起来一样的原因。相反，从三个上下文层次构建每个提示词：

### 第一段：场景专属风格方向（来自 shot_language + texture_keywords）

用场景的 `shot_language` 字段设定镜头与光照：
```
[景别，来自 shot_language.shot_size，如"中特写"]。
[光照，来自 shot_language.lighting_key，如"黄金时刻暖光"]。
[景深，来自 shot_language.depth_of_field，如"浅景深带散景"]。
[质感，来自 scene.texture_keywords，如"胶片颗粒、暖色调"]。
```

如果场景没有 shot_language，回退到下方模板。

### 第二段：剧本一致性锚点（适配，非逐字）

提取剧本视觉语言的**精髓**——不要复制前缀。例如：
- 剧本写"干净、极简插画，柔和阴影，低饱和色调" → 适配为："低饱和色调，柔和阴影"
- 剧本写"大胆扁平动态图形，鲜艳渐变" → 适配为："鲜艳扁平风格"

锚点保持场景视觉连贯，但不使它们完全相同。

### 第三段：场景描述

场景的实际内容。要具体——用具体细节替换泛泛的词语。

**差：** "一个人在现代办公室使用电脑"
**好：** "软件开发者坐在昏暗的家庭办公室，显示器蓝光映在眼镜上，桌上散落着能量饮料和便利贴"

### 完整提示词示例（有 shot_language）

```
中特写，黄金时刻暖光，浅景深。
低饱和大地色调，柔和阴影。
养蜂人穿白色防护服提起滴着蜂蜜的巢框，
午后阳光照在金色液滴上，薰衣草田在背景中虚化。
胶片颗粒，暖琥珀色调。
16:9 宽高比。
```

### 回退模板（无 shot_language 时）

```
[从剧本适配的风格锚点——5-10 个词，非完整前缀]。
[场景描述：具体主体、动作、环境]。
[光照：黄金时刻 / 阴天 / 影棚柔光箱 / 戏剧侧光]。
[构图：广角 / 中景 / 特写 / 俯拍 / 等距]。
[相机：使用 [相机] 搭配 [镜头] 光圈 [光圈值]]（仅限照片写实风格）。
16:9 宽高比。
```

### 使用 lib/shot_prompt_builder.py

以编程方式构建提示词时，使用镜头提示词构建器自动完成三段式方法：

```python
from lib.shot_prompt_builder import build_shot_prompt
prompt = build_shot_prompt(scene, style_context=playbook_data)
```

该函数将结构化的 shot_language 字段转换为自然语言提示词，针对图像/视频生成提供商优化。

## 批量生成策略

| 阶段 | 模型 | 单张费用 | 用途 |
|------|------|----------|------|
| 1. 风格指南 | FLUX.2 [max] | $0.07 | 一张主视觉图，最高质量 |
| 2. 故事板迭代 | FLUX.2 [klein] 9B | $0.015 | 规划期间的快速变体 |
| 3. 最终帧 | FLUX.2 [pro] | $0.03 | 以主视觉为参考重新生成最终版 |

**速率限制：** 最多 24 个并发请求。据此安排管线。

**8 张图解释视频预算：** $0.07（主视觉）+ $0.12（8x klein 迭代）+ $0.24（8x pro 最终）= 约 $0.43

## 常见陷阱

1. **图中文字**——AI 图像生成器对文字不可靠。绝不在提示词中包含文字；在合成阶段以叠加方式添加文字
2. **手和手指**——AI 图像模型仍然处理不好。避免需要详细手部姿势的提示词
3. **角色不一致**——没有参考图时，同一角色每次看起来都不同。始终使用主视觉参考策略
4. **过度提示**——冗长复杂的提示词产生不可预测的结果。控制在 2-3 句话
5. **过度统一提示词**——把完全相同的风格短语强行塞进每个提示词会让场景看起来千篇一律。保持视觉系统一致，但让每个场景表达自己的主体、镜头和情绪节拍

## 在 OpenMontage 中的应用

在素材阶段使用 `image_selector` 工具时：

1. **先设计视觉系统**——从提案或自定义剧本中提取：情绪、色调、质感、动态能量
2. **先生成主视觉图**，用最高质量，作为其他所有图的参考
3. **16:9 视频帧使用 `1920x1088`**（FLUX 的 16 倍数要求）
4. **绝不在图像中要求文字**——在合成阶段添加文字叠加
5. **预算检查**——生成前估算总图像费用；超预算时切换到本地 diffusers
6. **规划期间用 klein 迭代**，用 pro 定稿
7. **提示词保持 2-3 句话**——场景专属镜头/光照 + 适配的视觉锚点 + 具体主体
8. **匹配场景规划**——每张图对应脚本中的特定场景
