# Creative brief — script, storyboard, visual language

Produces three artifacts: **one core claim + a per-shot copy table + the visual language + a
storyboard table.** Everything here exists to serve dimension A (narrative) and C (visual design)
of the acceptance rubric.

## Core claim

One sentence, and a positioning line that carries through the whole film. Structure the film as
**pain → turn → product → evidence → CTA** — not the order of your website's navigation.

Test the hook against this: does the **first 3 seconds** answer "why should I care?" in the
**audience's own words**? If it uses internal product vocabulary, rewrite it in the language a user
would actually say out loud.

> Worked example (generic): a draft hook described a phenomenon — viewers nodded but felt nothing.
> It only worked after being rewritten as the user's own complaint. **This class of fix comes from
> real audience language, not from self-review.**

## Per-shot copy table

For each shot: time range, what's on screen, and the line.

- One shot does exactly one job.
- Any shot that can't be traced back to the core claim gets cut — that is how you tell a promo from
  a feature tour.
- Keep copy short enough to read at the shot's pace; if a line needs two reads, it's a shot too long.

## Visual language

Start from the product's **existing design system** rather than inventing a look:

- Colors, borders, shadows, type families already used by the product.
- Type scale **scaled up for video** — body text that works at web size is invisible on video.
- A minimum of 3 layers per frame (background treatment / main content / foreground detail).
- At least two focal points per frame; anchor content to edges and divisions, avoid centered floating.
- Light backgrounds still need texture so the frame doesn't read as "not loaded yet".

## Motion additions (what "not enough motion" usually means)

When someone says the edit feels flat, the fix is usually these, not more effects:

- A **visible cursor** that moves, clicks, and shows press feedback — the difference between "a
  screenshot animating" and "someone actually using it".
- Click ripples / small press scale on targets.
- **Real typing** (characters appearing one at a time), not text that just appears.
- Panels sliding in with slight perspective, not plain cross-fades.
- Data flowing in (transcript lines appearing with a cursor blink).
- Stronger **push-ins** on the key control (zoom 1.25–1.6×), with easing.

Pacing: steadier music and **bigger, fewer** actions beat a pile of small ones. Leave 0.3–0.5s after
each click for the reaction to read.
