# 音画工作流：从候选到可用的声音时间轴

## 先知道证据能支持什么

进入新会话时检查现有工具是否能实际接收/听取音频。导出音频、显示播放器、解码成功都不等于模型听过。具备音频输入时可按片段描述听到的层次；只有信号计算时限于非零信号、能量、频谱变化、重复周期与时间邻近。不要把2026-09-27的工具限制固化为永远不能听音。

把结果分为四类：

| 类别 | 可做什么 | 不能自动推导什么 |
|---|---|---|
| `measured_candidate` | 保存频谱突起或周期，跳转试听 | 点击/鼓点名称、主拍、刻意卡点 |
| `listening_confirmed` | 有实际试听/音频输入支持的分类或时间点，记录确认范围 | 作者软件、分轨、没有证据的意图 |
| `user_confirmed` | 用户选择的节拍层级、音效或对齐点 | 超出用户确认的其他段落 |
| `designed` | 为新片自己设计声音用途和位置，可直接做初稿 | 把新设计描述成原片事实 |

自动候选可以进入初稿，但始终保留候选身份。用户没有要求声音的静音片不必强行配乐。

## 选择时间轴的驱动关系

- **配乐主导**：试听选定片段、节拍单位与起始相位，再建立锚点网格。重要出现、切换、结果落定可用强拍；连续动作和阅读不必每拍变化。
- **动作主导**：先把抓取、拖动、接收、完成等视觉事件做清楚，再安排瞬态与持续声音。短点击适合确认感、持续扫动适合运动感只是创作选项，不能据画面断言参考片有这些音效。
- **旁白主导**：先有可核对的旁白时间，按语义组显露画面。配乐与音效避让重要语句，保留必要停顿。

先做基本节奏和声音层级，再加更多声音。每个声音应有用途；声音密度不等于高级感。

## 信号辅助与节奏选择

[scripts/analyze_audio.py](../scripts/analyze_audio.py) 的用法见[音轨CLI](audio-analysis-cli.md)。只在需要测量时运行。

1. 确认有无音轨，再看原声道是否非零。Mono为零但原声道非零可能是相位抵消，不能说视频静音。
2. 对全片或目标段落看能量、声音突起和周期候选。重复周期不是音乐主拍；还存在半倍、双倍、三倍与其他分组。按局部稳定性和可听证据选择，不能只取全局最大值。
3. 比较视觉事件区间与候选位置。附近出现峰值只意味着邻近，候选密集时很容易巧合；没有候选也不证明没有可听的弱声。
4. 时间轴统一到容器起点，保留音轨/视频实际PTS和剪辑映射。首PTS不相同就先解决映射；不要人为增加固定AAC延时。
5. 约10ms分析步长、约46ms窗和0.1s视觉抽帧具有不同含义。文字结论按证据精度取整，不制造毫秒级同步保证。

原始研究中，Nils副本各声道是数字零；Cloudflare前段75/150 BPM对应周期稳定，但未裁定主拍。完整案例仅供理解歧义，不是未来配乐默认速度。

### 有BPM仍需要相位

设选择的拍长为 `beat_s = 60 / bpm`，已确认的某拍在 `phase_s`：

`beat_time(n) = phase_s + n * beat_s`

每个拍点都独立换成 `Math.round(beat_time(n) * fps)`。不要把四舍五入的单拍帧长反复相加，否则非整数帧周期会累计漂移。8秒窗口识别出某个BPM并没有提供相位或强拍分组。

按用户目标可有轻微抢拍/拖拍，但这是创作选择，记录偏移并在原速听看。不要自动把所有对象吸附到最近声音峰。

## Cue 表与帧换算

先分清三个时间轴：参考视频的容器时间、目标成片的composition时间、所用音效文件的源时间。参考片9.43秒附近的候选用于理解动作与声音关系；改编为8秒新片时，按新分镜重新选择`target_s`，不能直接复制参考片秒数。`source_anchor_s`则来自实际选用的音效文件；裁切和变速的映射必须显式保留。

[示例cue表](../assets/cue-sheet.example.json)只包含原创设计位置，示例音效文件不随包提供；实际制作时替换成可用素材。复杂镜头用表，小修改可以只写少量事件，不必创建大工程。

素材状态另记`asset_status`：`planned`表示待制作/选择，`provided`表示调用者已提供路径，缺省为`not_checked`。可在表顶层设默认，也可逐cue覆盖；`provided`不等于脚本已检查文件。编译输出始终保留`asset_files_checked=false`，不能把时序可用说成素材已可播放。

每个cue记录：`id`、`asset`、`verification`、`target_s`、`source_in_s`、`source_anchor_s`、`source_out_s`、`playback_rate`和`note`。

- `target_s`：希望素材锚点落在全片哪一秒。
- `source_in_s` / `source_out_s`：保留源文件中的哪一段。
- `source_anchor_s`：音效文件里实际起音或重音的源时间；必须位于保留区间。
- `verification`：上表四种状态之一。`designed`表示自己的设计，不等于试听确认。

连续时间关系：

```text
clip_start_s = target_s - (source_anchor_s - source_in_s) / playback_rate
clip_end_s   = clip_start_s + (source_out_s - source_in_s) / playback_rate
```

再独立量化起点、源裁切与持续帧数，报告锚点的帧量化误差。起点为负、超出成片末尾、锚点被裁掉等情况应修改设计或明确使用有意预卷，不能悄悄钳制到零破坏对齐。

```bash
python3 <skill-dir>/scripts/compile_cues.py \
  --input <project>/cue-sheet.json --out <project>/cue-frames.json
```

`--out`是新的JSON文件，已有派生文件仅在显式`--overwrite`时覆盖，源cue表不会被替换。默认检测到`measured_candidate`会解释并停止帧编译；用`--include-candidates`可显式输出带候选标记的草稿。这是工具区分结果身份，不是要求用户每次审批。已设计的声音可以继续渲染初稿。

编译只验证时序与数据，不试听、不查资产授权、不核对文件存在，也不保证峰值/响度。输出保存源秒数和`clip_start_frame`、`source_trim_before_frame`、`source_duration_frames`、`output_duration_frames`等，方便适配项目API。

在Remotion中可用`Sequence`定位音频，音频组件裁切源区间并设置播放速率。当前官方[Audio](https://www.remotion.dev/docs/media/audio)的`durationInFrames`按源帧定义，外层Sequence按输出时间定义；核验工程版本，避免重复缩放时间。若修改播放速率，要重新核对起音和音高行为。

## 混音与最终确认

分别管理配乐、人声和音效；试听决定层级，必要时在关键语句下降低其他轨音量。RMS有助于比较同一片段的数字能量，但不是LUFS或主观响度；浮点解码峰值超过0dBFS也不能直接证明源视频削波。需要平台规范时再测对应指标。

渲染带前摇和尾音的核对片段，原速确认后再看慢速误差。听觉不可用时，完成可检查的时序、图像和媒体输出，准确注明“声音类型/主拍/混音未试听”，提供可播放结果或时间点。不要把这个限制扩张为停止所有制作。

方法背景：[起音检测](https://librosa.org/doc/0.11.0/onset.html)、[节拍跟踪的分阶段方法](https://librosa.org/doc/0.11.0/generated/librosa.beat.beat_track.html)。随包脚本是信号候选分析，不是完整动态规划beat tracker。
