# 参考片取证：把真实画面转为可实现状态

只在用户提供新参考、要精确复刻或现有证据不足时使用。本技能已经有可直接调用的镜头配方；不要把每次制作变成十条视频的大型研究。

## 拿到能看见的媒体

先检查已提供文件、当前工程资产和已存在的本地缓存。网页可打开、帖子文字可读、封面可见都不等于已看过视频。记录原帖URL、下载/读取日期、媒体哈希、版本/清晰度及音视频参数。若只能取得部分内容，就把观察范围写明。

2026-09-27的取证经验可作一次有界尝试：

- X原帖页面失败时，公开嵌入接口 `https://cdn.syndication.twimg.com/tweet-result?id=<POST_ID>&lang=en&token=1` 曾返回`mediaDetails[].video_info.variants`。只有接口实际返回可用媒体才沿返回的地址读取；接口可能改变，不保证成功。取得对应MP4后核对帖ID与媒体信息，不凭搜索摘要认定视频内容。
- B站旧`html5player.html?cid=...`地址可能失效。通过官方页面/公开元数据找到BV及分P，并逐个核对`pages[].cid`。CID必须精确匹配；投稿总标题的8K、时长等不代表该P。签名媒体URL会过期。
- 用户指定已登录浏览器时，遵从当前会话要求。遇到登录、验证或媒体不可取得，停止在可确认的证据边界，说明需要的文件/信息，同时完成不依赖媒体的分镜工作。

下载参考副本用于本地分析与后续回看；不要将它当作新作品可直接分发的资产。

## 时间基准

保留`format.start_time`、音轨首解码PTS、视频首解码PTS及实际帧PTS。以同一容器起点比较音画；任何重新剪切、变速或转码都要显式记录时间映射。音频尾部比视频长几十毫秒不意味着整条轨道错位。不要猜测统一AAC延时并手动补偿。

FFprobe显示的是媒体信息，不是原作者工程帧率。变帧率媒体不可用“第n张=第n/fps秒”替代实际PTS。

## 从概览到关键镜头

先覆盖全片稀疏取样，识别叙事段落与重复对象；只对决定制作方法的动作加密取样。可从1–2秒概览、0.1–0.2秒局部开始，按动作速度调整，记录实际采样点。

使用 [sample_frames.py说明](frame-sampling-cli.md)。相邻两帧只能给事件区间，不能据此反推出精确贝塞尔曲线、弹簧参数或软件。不可把有时间标签的联系表称为全片逐帧检查。

每个关键动作提炼四种信息：

| 信息 | 有用的记录 |
|---|---|
| 可观察状态 | 标签在框外；边框亮起；标签缩小；状态文字可读 |
| 时间证据 | 4.13秒帧未见，4.20秒帧可见，因此事件在此区间 |
| 连续关系 | 相同图标、颜色、中心或路径方向贯穿前后状态 |
| 制作方案 | 在共享父层插值矩形并单独揭示文本；这是重建方案，非原作者源码 |

区分主画面与作者加上的分镜/章节条；是否保留这类调试层取决于交付目标。

## 有效的分析交付

给出可回看时间段、少量关键帧、对象状态与建议实现。将“看到的”“测得的”“推测的”“本次自行设计的”明确分开。没有实际看过的部分保持未核验；不要用可读的帖文或作者自述填补画面观察。
