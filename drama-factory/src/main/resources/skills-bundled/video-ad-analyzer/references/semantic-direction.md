# 대사 기반 연출과 Seedance 변환

재창작/프롬프트 요청에 사용한다. 최종 결과는 복사해 사용할 수 있는 Seedance 프롬프트이며, 원본 분석과 연출 계획은 이를 뒷받침한다. 분석만 요청된 경우 새 대본을 임의로 만들지 않는다.

## 세 층을 분리한다

1. **원본 관찰:** 원본 대사, 컷, 행동, 실제 또는 추정 시각과 증거. 기존 `analysis.json` 규격을 유지한다.
2. **새 광고 설계:** 새 제품·대상·멘트에 맞춘 대본과 연출 관계. 원본과 다른 내용은 여기에만 기록한다.
3. **최종 프롬프트:** 새 대사와 연출을 자연어로 풀어쓴 Seedance 입력. 내부 관계 ID나 Hypit 문법은 모델이 해석하는 API 문법으로 취급하지 않는다.

원본의 초 단위 위치는 증거를 찾는 주소다. 새 대본의 의미와 연기가 새 영상의 진행을 결정한다. 총 길이가 지정되어 있으면 발화량, 호흡, 무언 시연, 반응 시간을 함께 고려한다. 원본과 새 대사의 길이 비율만으로 모든 컷을 늘이거나 줄이지 않는다.

## 원본의 관계 기록

분석 문서에 아래 열을 사용한다. 시간은 원본 JSON의 ID로 추적하고, 필요한 경우 해당 구간을 함께 적는다.

`관계 ID | 원본 대사·숏 ID | 관찰된 연결 | 추론한 역할 | 근거·불확실성`

- **발화 단위:** 하나의 설명·질문/답변·주장을 이루는 덩어리. 컷이나 문장 개수와 독립적이다.
- **구간 연결:** 어떤 말을 하는 동안 보조 화면이나 시연을 보여주는가.
- **순간 연결:** 어떤 구절의 시작/끝 또는 행동 완료 시점에 공개·전환·반응이 일어나는가.
- 동일한 구절이 반복되면 대사 ID와 몇 번째 등장인지로 구별한다. 단어 시각을 모르면 문장/구절 수준 관계만 기록한다.
- ASR 텍스트와 추정 시간을 원본과 대조한다. 정렬은 잘못 인식한 제품명을 올바른 말로 고쳐주는 절차가 아니다. 전사 수정 후 필요한 구간을 다시 정렬한다.
- 발화에 겹친 화면 변화라는 관찰과, 그 말을 강조하기 위한 편집이라는 해석을 분리한다. 보이는 사람에게 음성 화자 ID를 근거 없이 배정하지 않는다.

## 새 대본과 연출 계획

`단위 ID | 새 대사·화자·언어·발화 방식 | 연결 구절/사건과 시점 | 화면·행동·전환 | 원본 관계 ID 또는 새 제안`

대사에는 실제 발화할 말만 쓴다. 카메라·시각·스타일 지시는 별도 열에 둔다. 연결은 예를 들어 `해당 구절 시작`, `해당 설명 동안`, `질문 완료 후`, `제품을 내려놓은 뒤`처럼 명시한다. 새 대본을 수정하면 인용 구절과 연결도 갱신한다. 원본 관계를 유지할 수 없으면 삭제/대체 이유를 짧게 남긴다.

제품명만 치환하지 않는다. 예를 들어 텀블러 누수 시연을 가계부 앱 광고로 바꿀 때는 '의심을 시연으로 해소한다'는 역할을 유지할 수 있지만, 실제 행동은 영수증 촬영과 정리 결과 제시로 달라져야 한다. 이는 형식 설명용 가상 사례이며 새 제품이 해당 기능을 갖췄다는 근거가 있어야 실제 프롬프트에 쓴다.

발화가 화면을 가로질러 이어지면 목소리 유지와 화면 변경을 따로 쓴다. 듣는 사람의 표정, 발화 뒤 침묵, 무언 시연은 별도 연기 시간으로 고려한다. 의미 연결이 없는 음악 컷이나 정해진 엔드카드 길이는 해당 기준을 유지한다.

길이는 생성 전에는 추정치다. 자연스러운 발화·시연이 지정 길이에 들어가지 않으면, 개작 허용 범위에서 줄이거나 여러 클립으로 나눈다. 사용자가 고정한 문구·총 길이·단일 클립 조건이 충돌하면 충돌을 명시하고 필요한 선택을 확인한다. 정확한 문구를 몰래 생략하거나 무리한 속도로 읽히지 않는다.

## Seedance 프롬프트 작성

이 모음에서는 형제 폴더의 `sd25-pe`를 사용해 Seedance 2.5 최종 문법을 작성하고, 새 연출 계획을 입력으로 전달한다. 독립 설치에서는 호스트의 사용 가능한 스킬 목록에서 같은 이름을 찾는다. 고정된 다른 PC의 경로를 의존성으로 만들지 않는다. 사용할 수 없어도 아래 규칙으로 작성할 수 있다.

- 인물·제품·장소, 필요한 참조 자산의 역할, 사건 순서, 최종 상태를 간결하게 정의한다. 제공되지 않은 이미지/음성 참조를 존재하는 것처럼 번호로 지정하지 않는다.
- 연출 문장은 사용자의 언어나 요청한 프롬프트 언어와 관계없이 항상 영어로 작성한다. 대사와 화면 속 문구(간판·라벨·앱 화면 등)는 영어로 번역하지 않고 실제로 들리거나 보일 언어 그대로 인용한다(한국어 대사는 한국어, 일본어 대사는 일본어). 새로 쓴 대사도 같다. 대사에는 화자·언어·말투·화면 내 발화/내레이션을 붙인다. 최종 프롬프트의 대사는 새 대본과 일치해야 한다.
- `As she says "…"`, `During his explanation of …`, `After the question ends …`처럼 새 대사와 화면을 연결한다. 내부 ID는 실제 대사 인용이나 구체적 사건으로 변환한다. 행동에 따른 물건 소유·손 상태·화면 방향을 유지한다.
- 타임스탬프는 필요할 때만 새 대본 기준으로 설계한다. 원본 시간을 새 영상에 강제하지 않는다. 총 길이·비율 등의 실행 설정은 프롬프트 밖에 적고, 현재 사용하는 모델/서비스의 지원 조건을 확인한다. 특정 모델의 최대 길이를 이 문서에 고정하지 않는다.
- 한 발화 단위 안에 여러 컷이 있을 수 있다. 클립 분할은 의미 흐름, 생성 제약, 연속성으로 결정한다. 분할 시 연결 상태와 이어지는 음성 처리를 계획한다.
- 자막·그래픽·정확한 UI 합성이 필요하면 프롬프트와 별도로 후편집 항목을 적는다. 실제 생성·합성을 하지 않았다면 완성되었다고 말하지 않는다.

다음은 가상 앱 광고의 표현 예시다. 실제 원본 관찰이나 모델 실행 결과가 아니다.

```text
The presenter says in Korean, “영수증은 사진만 찍으세요.”
As she says “사진만”, cut to a close-up of her phone photographing
a receipt. Her voice continues over the demonstration.
She continues, “그러면 지출 내역이 이렇게 정리돼요.”
Reveal the categorized expense list as she says “이렇게”.
Hold the result long enough to read, then return to the presenter.
```

## 산출물과 확인 범위

파일로 제공하면 원본 관찰은 `analysis.json`/`analysis.md`, 새 대본과 관계는 `creative-plan.md`, 최종 입력은 `seedance-prompt.md`로 분리할 수 있다. 짧은 결과는 응답 안에서 구분해도 된다. 모두 스킬 폴더 밖에 저장한다.

- 기존 `check_analysis.py`는 원본 JSON의 시간·참조만 검사한다. 새 대본의 적합성, 관계의 의미, 프롬프트 동기화는 검사하지 않는다.
- 사람이 읽는 관계 표의 원본 ID가 실제 분석에 있는지, 인용한 구절이 해당 대사에 있는지, 새 프롬프트가 새 대본을 정확히 보존하는지 대조한다.
- 음성이 미확인인 원본에서 관계를 상상해 복원하지 않는다. 새 대사 창작을 요청받았다면 별도 창작으로 진행하고 원본의 대사 패턴을 재현했다고 표현하지 않는다.
- 자연어 지시는 생성 의도이며 정확한 동기화 보장이 아니다. 실제 생성 음성을 대본과 정렬해야 실제 시각을 얻을 수 있다. 생성 영상에 이미 들어간 잘못된 행동·컷은 정렬만으로 고쳐지지 않으며 재생성이나 편집이 필요할 수 있다.
