# 导演方法:怎么判断一镜好不好

这份文档回答一个具体问题:分镜写完了、样帧也渲出来了,怎么看这一镜是"能用"还是"必须重做"。不是审美空话,是几条可以直接对着素材打勾的标准,外加两个可复用的具体技法。

## 故事:钩子和信息承诺

- 开场 1-2 秒必须让观众知道"看下去能得到什么",不是"这条视频是关于什么"。前者是具体承诺(省多少时间、解决什么问题、看到什么效果),后者是话题标签,留不住人。
- 钩子里立的承诺,后面必须兑现,而且兑现的时间点要在观众记性还在的时候(通常是钩子后 15-30 秒内出现第一次呼应),不要等到片尾才回收——中途弃看的人根本等不到。
- 一镜一个信息点。如果一个镜头同时想交代"这是什么 + 为什么重要 + 怎么用",观众三个都记不住;拆成三镜,每镜一个记忆点,比硬塞进一镜再靠语速补救更有效。

## 节奏:信息密度、留白、停顿

- 信息密度不是越高越好,是要有节奏地起伏:密集信息段(讲清楚一个概念/一个步骤)后面跟一个短暂的"消化拍"(慢下来的镜头、一句总结、一个纯氛围的转场),再进入下一段密集信息。全程匀速灌信息,观众的注意力会在中段全面崩溃,不会均匀下降。
- 留白和静音不是"没做完",是主动工具。关键结论说完后停 0.3-0.5 秒再切下一镜,给观众一个"这句话很重要"的信号;背景音乐在强调句前后短暂减弱(甚至半秒静音)比加音效更能让观众竖起耳朵——见 `audio/xlaudio` 的 ducking 机制。
- 停顿怎么剪:不是所有停顿都要剪掉。呼吸、转折前的短暂停顿(通常 <0.3s)是口语的自然节奏,剪掉反而显得赶;真正要剪的是"气口"——想词、卡壳、无意义的填充音("嗯""那个")前后的停滞,这类停顿剪不干净,观众会觉得整条视频"拖沓、没剪辑过"。具体规则和参数见 `references/editing.md` 的删停顿部分,但耳朵判断优先于参数:听一遍成片,凡是让你想按快进的地方,就是该剪的地方。

## 镜头:签名镜头、转场、不要同套路连用

- **签名镜头**:一条片子挑 1-2 个"记忆点"镜头狠做(比如全片最重的运动模糊+冲击感只用在一个关键数字上,其余镜头克制),而不是每个镜头都想着"炫技"。如果每一镜都是视觉高潮,观众的感官会麻木,反而记不住哪个是重点;稀缺性本身就是强调。
- **转场按风格设计,不要照搬默认硬切**:风格切换(换背景、换视觉语言、换场景)这类"大动作"转场,如果用跟内容转场一样的硬切,观众会觉得画面"跳了一下"、缺乏预告——尤其风格差异越大(比如从真人实拍切到纯图形卡片),越需要一个过渡动效(扫光、擦除、翻页、色板扫过)来交代"接下来风格要变了"。纯内容内部的镜头切换(同风格下,换一张卡片、换一句话)才适合硬切,硬切在这里是干脆,不是偷懒。
- **同一套路不连用**:同一个转场效果、同一个强调手法(比如"关键词弹出+加粗"),用第二次观众会觉得眼熟,用第三次会觉得视频在"复读自己"。一条 2-3 分钟的视频里,同一个具体转场效果最多出现 2 次,且不要相邻;需要多次强调关键词时,交替用不同的强调手法(放大、高亮底、色彩变化),而不是重复同一个动效。
- **构图比例要经得起"这是不是很怪"的第一反应**:任何缩小真人比例、给真人加遮挡物/道具框(桌子、边框、前景遮挡)的构图,渲出来第一件事是退远看一眼整体轮廓——如果视觉上读起来像"身体被截断""头被框切掉"这类不祥联想,不管本意是什么,观众的第一反应会盖过你想传达的信息,必须重新调整比例或裁切线,不能靠"看惯了就好"说服自己。

## 人物:不消失、不压脸

- 人物不消失和不压脸/不压嘴是硬性 QA 规则(见 `SKILL.md` 固定规则、`references/qa.md`),这里补充两条容易漏掉的软性判断:
  - **风格化处理不能改变人物的基本可读性**:把真人合成进某个视觉风格(杂志封面、海报、卡片)时,人物本身的颜色/质感要保持自然(除非分镜明确要求做旧/单色的怀旧效果),不要因为背景变成某种滤镜/纸质/暗色调,就顺手把人物也套上同一层处理——观众认脸靠的是正常肤色和五官对比度,人物一旦被背景风格"传染"变灰变暗,会显得像贴上去的死气贴纸,而不是这个人真的站在那个场景里。
  - **暗色/低调风格要保留人物的可读层次**:发布会风、夜景、暗调这类背景全黑或接近全黑的风格,容易为了"高级感"把整体亮度压得过低——结果人物的面部细节、轮廓边缘都糊在暗部里,观众要眯眼才能看清。做法是背景可以纯黑到深灰,但人物身上要留一道边缘光/轮廓光,把人从背景里"抠"出一层亮度差,而不是让人物和背景融成同一片黑。

## 自检:看一遍样片/成片按什么顺序查

渲出来的东西,按这个顺序过一遍,比想到哪查到哪更不容易漏项:

1. **声音先行**:先只听不看(或者放到很小声只留大意),判断信息密度和节奏是否舒服、气口是否剪干净、强调句前后有没有必要的停顿。声音层面的问题比画面问题更容易被"看着还行"掩盖过去。
2. **缩略图/整体轮廓**:把播放头拖到每个镜头的中间帧,退远看缩略图大小,检查构图有没有"看一眼就觉得怪"的问题(截断感、比例失衡、遮挡显脏)——这一步专门用来抓上面"构图比例"那条,细看反而容易习惯化。
3. **逐镜看信息密度**:确认每一镜确实只在讲一个信息点,没有为了赶时长硬塞进第二个概念。
4. **转场检查**:风格转场有没有用足够的过渡动效;同一转场/强调手法有没有连续出现或全片用了 3 次以上。
5. **人物检查**:每一处真人上镜的画面,人脸是否清晰可读、颜色是否自然、暗部是否吃掉了轮廓;任何全屏图形/卡片镜头,检查连续无人时长有没有超过 3 秒。
6. **QA 门禁**:最后才跑 `qa.check` / `qa.pixel_qa`(见 `references/qa.md`)——机器检查压脸、压字幕带、空卡片这类可以量化的硬规则,前 5 步是机器查不出来的"观感"问题,顺序不能反过来(先跑 QA 会让人误以为通过=没问题了,跳过前面的主观判断)。

## 技法卡:两个具体做法

### 反相混合的角标/HUD 文字(已实现,但中灰底上会失效)

**做法**:角标、HUD 文字(章节号、进度条标签、右侧小字这类不带底卡的极简文字)相对底片做 `difference` 混合。白字落在亮底上变暗,落在暗底上保持亮,不用为每种背景单独调颜色。

**用法**:分镜里给镜头加 `"invert": true`。目前只有 `chapter_tag` 声明了支持(组件导出 `invert = true`),别的组件写了会在解析时报错,和 `"layer": "behind"` 同时写也报错。这类镜头单独渲成 `overlay_invert.mov`,在人前图形(L3)之后、统一收尾(L5)之前合成,所以总在人和其他图形上面。组件在这一路只画纯白墨,层级靠不透明度区分(编号和中文 1.0,英文小标和右侧小字 0.6,进度底轨 0.3),不画辉光;引擎在这一路关掉 flash、暗角和 bloom,保留 fade。普通镜头的 `chapter_tag` 输出不变。示例:`python3 -m render build examples/invert_hud/storyboard.json`(同一帧上下两个角标,上普通、下反相,底片依次是亮底、暗底、中灰、黑到白渐变)。

**公式**(W3C 可分离混合的 difference,写成预乘形式,`render/composite.py` 的 `premul_diff()`):

```
out = bg·(1−a) + a·|bg − C| = bg·(1−a) + |bg·a − O|      (O = a·C,预乘 rgb)
ffmpeg:maskedmerge(black, bg, a) 得到 bg·a,与 O 做 blend=difference,
       再加上 maskedmerge(bg, black, a) 得到的 bg·(1−a)(blend=addition)
```

不透明白字 a=1 时输出就是 255−bg。a≈0 但 rgb>0 的辉光像素在这个公式下退化成加法,和普通图层一样。用随机底色加随机预乘前景(含半透明、a=0 带 rgb 的辉光像素)跑这段滤镜链,和 numpy 按公式算的结果比,最大误差 1/255。

**为什么不用别的写法**:
- 只把 `premul_over()` 最后一步的 `addition` 换成 `difference`,算出来是 |bg·(1−a) − O|。不透明白字 a=1、O=1 时恒等于 1,永远是白字,根本没有反相。
- `grainextract`(A−B+0.5):黑底白字得 −0.5,截成 0,字直接消失。
- `exclusion`:预乘形式下拆不开,只在 a 为 0 或 1 时成立,抗锯齿边缘会算错。
- 在组件里设 `ctx.globalCompositeOperation = 'difference'`:引擎画的是全透明叠加层,底片到合成阶段才进来,这样只会和同一张画布上先画的图形做差。

**实测**(`examples/invert_hud` 成片抽帧,文字墨迹像素与框外一圈底色的 WCAG 对比度,正文可读的常用门槛是 4.5:1):

| 底色 | 普通白字 | 反相角标 |
|---|---|---|
| 亮底 #F0F0F0 | 1.14 | 16.8 |
| 暗底 #101010 | 19.0 | 16.6 |
| 中灰 #808080 | 3.95 | 1.01 |

**中灰死区**:白墨反相后显示 255−bg,底色越接近中灰,字和底越接近。按灰阶值(sRGB 8 位)算,反相角标在底色 73–182 之间低于 4.5:1,88–167 之间低于 3:1,128 附近几乎看不见;普通白字在底色 ≥119 时低于 4.5:1。两者在 119–182 一段都不够,肤色、灰墙、阴天天空、浅木桌面常落在这里。所以不能说"任何背景都可读"。

**什么时候用**:
- 角标底下的亮度会变(推拉镜头、切场景、人走过),或者底片整体偏亮(白墙、白纸、亮屏幕)时用 `invert`。
- 角标所在区域以中灰为主时不要用 `invert`,改回"纸条字幕"那套思路:给文字垫半透明底色块或够粗的描边,用固定对比度保证可读(见 `SKILL.md` 固定规则)。拿不准就先抽一帧,看角标区域的灰度是否大多落在 70–180。
- 底片一直是暗的,普通白字已经够清楚(19:1),换成 `invert` 反而略降(16.6:1),没必要。

### 粒子聚成文字

**做法**:一批粒子从随机位置(或从画面边缘、从某个源点)飞向一个目标——目标不是一个点,而是采样自一段文字轮廓的一批点,粒子各自飞到自己分配到的采样点,聚拢的瞬间正好拼出这段文字的形状。比单纯的文字淡入更有"信息从无序汇聚成结论"的视觉隐喻,适合强调总结句、最终数字、品牌词这类"压轴文字"。

**采样文字轮廓的做法**:把文字画到一张离屏 canvas 上,取 `ImageData`,按固定步长(比如每隔 3-4 像素)扫描,挑出 alpha 大于某个阈值(说明这个像素在文字的"墨"范围内)的像素坐标,就是这批目标点;点数按粒子数量做等距或随机抽样(点太多会看起来像实心块,不如稀疏一点更像"粒子聚拢")。

```js
// 伪代码:采样一段文字的轮廓点(离屏 canvas + getImageData)
function textPoints(str, font, x, y, opts = {}) {
  const step = opts.step ?? 4;                 // 采样步长(像素),越小点越密
  const cv = new OffscreenCanvas(W, H);         // 覆盖文字可能占的整块区域
  const c = cv.getContext('2d');
  c.font = font; c.textBaseline = 'alphabetic'; c.fillStyle = '#fff';
  c.fillText(str, x, y);
  const { data } = c.getImageData(0, 0, W, H);
  const pts = [];
  for (let py = 0; py < H; py += step)
    for (let px = 0; px < W; px += step)
      if (data[(py * W + px) * 4 + 3] > 128) pts.push({ x: px, y: py });
  return pts;                                   // 目标点数组,交给下面的汇聚函数
}

// 伪代码:粒子从各自随机起点飞向分配到的目标点,tau = 汇聚动画进度 0..1
function converge(ctx, glow, tau, particles, targets) {
  const e = easeOutCubic(clamp01(tau));         // 快出慢入,汇聚感更强
  particles.forEach((p, i) => {
    const t = targets[i % targets.length];      // 粒子数多于目标点时循环分配
    const x = lerp(p.x0, t.x, e) + jitter(p.seed, tau);  // 加一点噪声,不要走直线太机械
    const y = lerp(p.y0, t.y, e) + jitter(p.seed + 1, tau);
    const a = tau < 0.08 ? tau / 0.08 : 1;       // 粒子先淡入再飞,不要一开始就满屏亮点
    drawSprite(ctx, dot(p.color), x, y, p.r, a);
    if (glow) drawSprite(glow, dot(p.glowColor), x, y, p.r * 3, a * 0.6);
  });
}
```

**接进这套引擎的位置**:`engine/particles.js` 已经有 `sparks()`(定向火花)和 `dust()`(漂浮浮尘)两个同类的"纯函数,输入时间和参数、画一批点"的例子,新加一个 `textPoints()`(采样目标点,可离线算好存进组件参数,不用每帧重算)和 `converge()`(按目标点画粒子)可以直接照这两个函数的写法补进同一个文件——粒子飞行是一次性动画,不需要循环漂浮,逻辑比 `dust()` 还简单。真要接成一个正式组件(带 `mbSocket` / QA bbox),参考 `components/kinetic_keyword.js` 的组件契约(`id`/`role`/`params`/`draw`/`bbox`/`mbSamples`)包一层。
