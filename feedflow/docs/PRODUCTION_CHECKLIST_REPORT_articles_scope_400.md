# feedflow 靶向范围发版对照报告 (articles scope 400)

## 一、 改动摘要
- **接口**：`GET /api/articles`
- **改动内容**：当查询参数 `scope` 传入非法值时，逻辑由原本的“静默回落至 `unread`”调整为直接返回 HTTP 400 状态码，响应体错误信息为 `"scope 非法"`。
- **保持不变**：请求中缺省 `scope` 参数或传入空串（`""`）时，仍默认按 `unread` 处理；接口的其余参数及原有业务逻辑一字不动。

## 二、 验收范围

### 1. 靶向测试
- **scope 非法拦截测试**：旧的回落测试用例已删除/改名，断言逻辑同步更新为校验接口正确返回 400 状态码。
- **既有回归测试**：验证合法的 `scope` 取值以及分页相关测试用例均未受影响，表现正常。

### 2. 真实服务冒烟
- 真实服务冒烟（18471 端口，隔离库，FEEDFLOW_NO_SCHEDULER=1）：scope=illegal 返回 400 且 error 为“scope 非法”、scope=all 与无参及空串均 200，4/4 通过，冒烟后服务已停、端口复查已关。

## 四、 已知限制
- 当前接口中，针对 `feed_id` 和 `folder_id` 的非法值处理逻辑仍保持原样（经 `_int_arg` 处理，视为不过滤条件），该部分不在本轮发版的改动范围内。
- 全量测试套件本轮未跑（只跑靶向 2 文件 27 例）；mark_all_read 的 scope 回落仍在，不在本轮范围。
