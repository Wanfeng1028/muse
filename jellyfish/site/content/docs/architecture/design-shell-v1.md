# 前端外壳设计层 v1：生产台账

## 现状（已生效）

- 文件：`front/src/design-v1.css`，由 `front/src/App.tsx` 在 `App.css` 之后引用，层叠顺序上压过 `App.css`。
- 本层只覆盖，不改原样式表与任何 JS，不改页面职责：分镜编辑页仍负责“准备”，分镜工作室仍负责“生成”，任务中心仍只展示通用任务信息。
- 9 条规则全部为 GLM-5.3 收窄三段输出原文拼接（每段 3 条），编排只做了拼接与导入顺序核对，未改动规则本身。

## 视觉逻辑

- 纸面暖白 `#fafaf7`、墨色文字 `#1e293b`、单主色赭石 `#c2410c` 只作信号（选中、焦点、左缘）。
- 分隔一律 1px 细线 `#e5e7eb`，全部左对齐，系统无衬线字体，不引入外来字体，不用渐变、不加阴影。
- 侧栏选中项：淡赭石底 `#fff7ed` + 左侧 3px 赭石实线 + 赭石加粗文字，不用整块深色底。
- 面包屑 13px 次级墨色，最后一项墨色加粗。

## 已知事实与保留

- 原 `App.css` 里的紫渐变 `.app-header` 是死代码：全项目没有任何组件使用 `.app-header`、`.feature-grid`、`.feature-card`。本层把它压成平色，万一将来有人用也不会再出紫渐变；原文件本轮未动。
- `MainLayout.tsx` 的 Content 内联样式（padding 5、背景 token）本层不覆盖，属既存结构，留待后续轮处理。
- Ant Design 5 的 CSS-in-JS 哈希类选择器优先级高于本层普通类选择器时，部分规则可能被主题 token 盖过；本轮截图验收以计算样式为准，如实记录，不宣称“全部生效”。

## 验收实证（2026-10-25）

- `pnpm exec tsc --noEmit` 全洁；`vite build` 通过（设计层颜色已打进产物 CSS）。
- 截图链路：Chromium 152 的 LNA 会拦 `127.0.0.1` 直访（加旗标也拦，与此前各项目结论一致），截图走 `goto + 路由代理`老路：页面请求全部由 Playwright 路由从本地 `dist/` 履行，不走浏览器网络；应用为 `VITE_USE_MOCK=true` 构建，项目列表来自项目自带 mock 数据（`mocks/data.ts`），后端 `localhost:8000` 的任务/流程/分镜接口请求失败（后端未跑），不影响项目列表渲染，如实记录。
- 计算样式实证（1440x900 视口，项目列表页）：侧栏背景 `rgb(250,250,247)`、侧栏右缘 `1px solid rgb(229,231,235)`、选中项背景 `rgb(255,247,237)`、选中文字与左缘 `rgb(194,65,12)` 3px、顶栏背景与下缘同侧栏值，全部与设计值一致。
- 关键修正：第一版截图实测发现侧栏/顶栏背景与边线仍是 antd 默认白与 `#f0f0f0`，根因是 `MainLayout.tsx` 的内联样式（`token.colorBgContainer` 与 `token.colorBorderSecondary`）优先级高于样式表，本层规则落不上。编排机械改动：侧栏与顶栏 4 处内联样式值改为设计值（背景 `#fafaf7`、边线 `#e5e7eb`），逻辑与结构未动；改后重测计算样式全部对上。卡片内部的蓝色按钮与进度条是既存页面样式，本轮未动。
- 截图：`docs/img/shell-v1.png`（项目列表页，5 张真实 mock 项目卡，无重叠，视口撑满）。

## 第二轮补充：任务中心面板（2026-10-25）

- 机械改动（编排，无逻辑变化）：`TaskCenter.tsx` 的面板 Card 的 `shadow-lg` 改为语义类 `task-center-panel`，悬浮按钮的 `shadow-lg` 删除；职责未变，面板仍只展示通用任务信息。
- 设计层追加 3 条规则（GLM-5.3 收窄一段出正文，原文）：面板白底、1px 细线 `#e5e7eb`、圆角 6px；标题墨色 14px 加粗；内容区内边距 12px 16px。
- 计算样式实证：面板背景 `rgb(255,255,255)`、边线 `1px solid rgb(229,231,235)`、圆角 6px、阴影 `none`，全部对上。
- 截图：`docs/img/taskcenter-v1.png`（面板展开于项目列表页之上；面板内“当前没有任务记录”是 mock 下真实的无运行任务状态，身后项目列表为真实 mock 项目数据）。
