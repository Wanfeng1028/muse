# 发版对照报告 v1.35.0（linkshort，2026-10-28 深耕轮）

**范围句**：本次发版仅修改 `handleStatsHourly` 函数以收紧 `GET /api/stats/hourly` 的 `link_id` 参数校验逻辑；`days`、`geo`、`geo.csv` 及 `parseIntDefault` 保持一字不动；无新依赖、无新增端点、无 UI 改动，视觉验收不适用。

## 可靠性
- `link_id` 校验逻辑收紧，严格遵循严格整数校验规范。缺省或空串时，默认值仍为 0（全局统计）；非整数（如 `abc`、`1.5`、`1x`）一律返回 400 且错误体逐字为 `{"error": "link_id 非法"}`；负数（如既有测试锁定的 `link_id=-5`）仍钳制为 0 并正常返回 200，确保服务行为稳定可靠。

## 可观测性
- 非整数非法参数返回统一的 400 状态码及明确的 JSON 错误体，便于调用方与运维人员精准定位与排查问题。

## 数据与状态
- 非法 `link_id` 请求被严格拦截，避免错误的 link_id 进入业务逻辑导致异常数据查询或状态污染；负数正确钳制为 0，有效保护底层数据查询逻辑免受越界或脏数据影响。

## 部署运维
- 全量 `go test ./...` 14 个包全绿；`go vet` 检查全洁；改动文件 `gofmt` 格式全洁。
- 真实服务冒烟后环境已彻底清理：冒烟服务进程已停止、18483 测试端口已关闭、冒烟测试二进制文件已删除，无环境状态残留。

## 安全与健壮性
- 完善了 API 接口的入参合法性校验，通过严格拦截畸形 `link_id`（如非整数类型），显著提升了接口对恶意或错误入参的抗风险能力与整体健壮性。

## 可维护性
- 代码改动遵循高内聚低耦合原则，仅聚焦 `handleStatsHourly` 校验逻辑的梳理与收窄，未引入任何新增依赖或新增端点。
- 新增 `internal/handler/stats_hourly_linkid_validation_test.go` 提供 6 例专项测试，原有 hourly 基本测试、days 回落测试、负 linkID 测试及 days 校验测试全绿，保障了后续代码演进时的可测试性与可维护性。

## 真实服务冒烟
- 在 18483 端口基于 `:memory:` 内存库完成真实服务冒烟验证：无 key 返回 401；`link_id=abc` 与 `1.5` 均返回 400 且错误体逐字为 `{"error": "link_id 非法"}`；`link_id=-5` 返回 200；不带参数返回 200。冒烟测试结果与预期完全一致。

## 结论
- v1.35.0 版本所有改动聚焦明确，测试覆盖完善，静态检查全洁，真实服务冒烟验证通过且环境清理完毕，满足生产发版标准，准予发布。
