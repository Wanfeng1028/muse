# 房间类型 API 参考

这篇文档说清楚房间类型（RoomType）相关的接口怎么调，参数长什么样，报错怎么处理。看完你应该能自己把 workroom 和 playroom 用起来。

## 房间类型是什么

房间创建的时候要指定 `type`，取值只有两个：`'workroom'` 和 `'playroom'`。不传就默认 `'workroom'`。

- workroom：干活用的房间，默认人数上限 50。
- playroom：玩游戏的房间，默认人数上限 200。

两个类型的核心区别在权限。playroom 里发 `intent=task` 的消息会被直接拒掉，返回 `ROOM_TYPE_FORBIDDEN`。workroom 没这个限制。

数据库里，`rooms` 表加了列 `type TEXT NOT NULL DEFAULT 'workroom'`，`room_members` 表加了列 `persona_role TEXT`，新建了 `game_sessions` 表存游戏状态。

## 改房间类型

```
POST /api/rooms/:id/type
```

请求体：

```json
{ "type": "playroom" }
```

`type` 字段必填，只接受 `'workroom'` 或 `'playroom'`，传别的值会被拒。

返回成功时给房间的最新信息，失败时给错误码。改类型这个操作只有房间创建者能做，别人调会拿到权限错误。

## 看房间统计

```
GET /api/rooms/:id/stats
```

不用请求体。返回房间当前的人数、类型、成员构成这些数据。调用者必须是房间成员，否则拿不到。

典型返回结构里会有 `type`、`member_count`、`max_members` 这些字段，前端拿这个决定要不要禁用“邀请”按钮。

## 给成员设 persona

```
POST /api/rooms/:id/persona
```

请求体：

```json
{ "persona_id": "persona_123", "role": "host" }
```

`persona_id` 是这个人格的 id，`role` 写进 `room_members.persona_role` 列。一个人在同一房间里只有一个 persona_role，重复调会覆盖。

## 错误码

`ROOM_TYPE_FORBIDDEN`：在 playroom 里发 `intent=task` 的消息时返回。HTTP 状态码 400，响应体是：

```json
{ "error": "ROOM_TYPE_FORBIDDEN" }
```

前端收到这个就别重试了，说明房间类型不允许这个操作，要么换房间，要么别发 task。

## WebSocket 帧

协议版本升到了 v1.3。新增两种帧类型：`game_action` 和 `game_state`。

payload 形状：

```json
{
  "game": "string",
  "seat": "string",
  "action": {},
  "state": {},
  "state_hash": "string"
}
```

- `game`：游戏标识，必填。
- `seat`：座位号，可选。
- `action`：玩家动作，发 `game_action` 时用。
- `state`：游戏状态，发 `game_state` 时用。
- `state_hash`：状态哈希，用来对状态做校验，可选。

旧客户端不认识这两种帧，直接忽略就行，不会崩。服务端广播 `game_state` 有节流，默认 500 毫秒一次，由环境变量 `GAME_BROADCAST_THROTTLE_MS` 控制。

## 环境变量

这几个变量启动时读，值非法就直接起不来（fail-fast），不会带着错配置跑：

- `ROOM_MAX_MEMBERS_WORKROOM`：workroom 人数上限，默认 50。
- `ROOM_MAX_MEMBERS_PLAYROOM`：playroom 人数上限，默认 200。
- `GAME_BROADCAST_THROTTLE_MS`：游戏状态广播节流毫秒数，默认 500。

部署的时候检查一遍这三个值，写错数字或者写负数是启动阶段就会报错，不会等到运行中才出问题。

## 游戏会话

`game_sessions` 表结构：

```
id TEXT PRIMARY KEY,
room_id TEXT NOT NULL,
game TEXT NOT NULL,
phase TEXT NOT NULL DEFAULT 'lobby',
state TEXT NOT NULL DEFAULT '{}',
updated_at INTEGER NOT NULL
```

`phase` 表示游戏阶段，初始是 `'lobby'`。`state` 存序列化后的状态，默认空对象。`updated_at` 是最后更新时间戳。一个房间可以有多个游戏会话，用 `id` 区分。

调用方拿会话状态的时候，结合 WS 的 `game_state` 帧和 REST 查询一起用，避免状态对不上。
