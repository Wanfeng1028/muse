# 房间类型 FAQ

这份 FAQ 讲清楚 workroom 和 playroom 的区别、怎么切、切错了会怎样。所有接口和字段名都按 v1.3 协议来，旧客户端可以继续用。

## 房间类型到底是啥

每个房间创建时都会带一个 type，取值只有两个：`workroom` 和 `playroom`。不写的话默认是 `workroom`。

- workroom：干活用的房间。适合开会、写东西、跑任务。
- playroom：玩用的房间。适合桌游、你画我猜这类带游戏状态的场景。

类型存在 rooms 表的 type 列里，是 `TEXT NOT NULL DEFAULT 'workroom'`，所以老房间升级后自动就是 workroom。

## 两种房间有什么实际差别

目前有两个硬差别：

1. 人数上限不同。workroom 走 `ROOM_MAX_MEMBERS_WORKROOM`，默认 50；playroom 走 `ROOM_MAX_MEMBERS_PLAYROOM`，默认 200。这两个是环境变量，启动时如果值不合法（比如写成负数或者空字符串），进程会直接 fail-fast，不会带着坏配置跑起来。
2. 消息限制不同。在 playroom 里，如果有人发 intent=task 的消息，服务端会拒掉，返回 HTTP 400，body 是 `{"error":"ROOM_TYPE_FORBIDDEN"}`。workroom 不受这条限制。

playroom 还会用到游戏相关的表和帧，下面单独讲。

## 怎么改房间类型

用这个接口：

```
POST /api/rooms/:id/type
{ "type": "playroom" }
```

把 `:id` 换成真实房间 id，body 里的 type 填 `workroom` 或 `playroom`。改完以后新的人数上限和消息规则立刻生效。

## 房间统计怎么看

```
GET /api/rooms/:id/stats
```

返回这个房间的统计信息，用来在界面上显示当前人数、消息数之类。具体字段以实际返回为准，不要在前端写死。

## persona 和 role 是什么

room_members 表新增了一列 `persona_role TEXT`。给某个成员设置 persona 和角色用：

```
POST /api/rooms/:id/persona
{ "persona_id": "xxx", "role": "xxx" }
```

persona_id 是 persona 的标识，role 是这个成员在这个房间里扮演的角色。这一列允许为空，没设置就是 NULL。

## playroom 里的游戏状态怎么走

playroom 用一张新表 game_sessions 存游戏进度：

```
game_sessions(
  id TEXT PRIMARY KEY,
  room_id TEXT NOT NULL,
  game TEXT NOT NULL,
  phase TEXT NOT NULL DEFAULT 'lobby',
  state TEXT NOT NULL DEFAULT '{}',
  updated_at INTEGER NOT NULL
)
```

phase 默认是 `lobby`，state 默认是空对象字符串 `'{}'`，updated_at 是毫秒时间戳。

WebSocket 这边新增了两种帧类型：`game_action` 和 `game_state`。payload 形状是：

```
{ "game": string, "seat"?: string, "action"?: unknown, "state"?: unknown, "state_hash"?: string }
```

- game_action：客户端发过来的动作，带上 game、seat、action。
- game_state：服务端广播的状态，带上 game、state、state_hash。

广播有节流，由 `GAME_BROADCAST_THROTTLE_MS` 控制，默认 500 毫秒。同样，这个值不合法的话启动就 fail-fast。

## 旧客户端会不会挂

不会。旧客户端收到不认识的帧类型（比如 game_action、game_state）直接忽略就行，协议版本号升到了 v1.3，但字段是加法式的，没有删改已有字段。

## 常见错误

- 在 playroom 里发 intent=task：返回 400，`{"error":"ROOM_TYPE_FORBIDDEN"}`。要么换到 workroom，要么别发 task。
- 启动报配置错误：检查 `ROOM_MAX_MEMBERS_WORKROOM`、`ROOM_MAX_MEMBERS_PLAYROOM`、`GAME_BROADCAST_THROTTLE_MS` 三个环境变量，必须是合法数字。
- 改类型接口报错：确认 `:id` 是存在的房间，type 只能是 `workroom` 或 `playroom`。

## 一句话总结

要干活选 workroom，要玩游戏选 playroom。类型能改，人数上限和 task 限制跟着变。游戏状态走 game_sessions 表和 game_action / game_state 两种帧。旧客户端不用动。
