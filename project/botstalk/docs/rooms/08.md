# 房间类型-ADR 架构决策

## 背景

BotsTalk 原来只有一种房间。所有房间都能拉人、发消息、跑任务。用下来发现两个问题。

第一个问题是容量。一个房间里塞 50 个人和塞 200 个人，对服务器的压力完全不一样。任务型房间人一多，消息乱、上下文乱，谁都看不清谁在说什么。但娱乐型房间就是要人多才热闹。

第二个问题是行为边界。任务型房间里，有人发一条 intent=task 的消息，系统要去调度、要去执行。娱乐型房间不应该有这种东西。可原来的实现里，房间不区分用途，所有消息都按同一套逻辑走。结果就是娱乐房间里也能触发任务，任务房间里也混着闲聊。

我们要把这两种场景拆开，让房间在创建时就明确自己是干什么的。

## 决策

引入房间类型，用 `RoomType = 'workroom' | 'playroom'` 表示。创建房间时指定 type，不指定就默认 `workroom`。

数据库层面：

- `rooms` 表新增列 `type TEXT NOT NULL DEFAULT 'workroom'`。
- `room_members` 表新增列 `persona_role TEXT`。
- 新表 `game_sessions`，结构是 `game_sessions(id TEXT PRIMARY KEY, room_id TEXT NOT NULL, game TEXT NOT NULL, phase TEXT NOT NULL DEFAULT 'lobby', state TEXT NOT NULL DEFAULT '{}', updated_at INTEGER NOT NULL)`。

REST 接口层面新增三个：

- `POST /api/rooms/:id/type`，请求体 `{type}`，用来改房间类型。
- `GET /api/rooms/:id/stats`，查房间统计。
- `POST /api/rooms/:id/persona`，请求体 `{persona_id, role}`，给成员分配角色。

错误处理上，`playroom` 里如果有人发 `intent=task` 的消息，直接拒绝，返回 HTTP 400，JSON 体是 `{error:"ROOM_TYPE_FORBIDDEN"}`。这个错误码是契约的一部分，客户端要能识别。

WebSocket 层面新增两种帧类型：`game_action` 和 `game_state`。payload 形状统一为 `{game: string, seat?: string, action?: unknown, state?: unknown, state_hash?: string}`。

环境变量新增三个：

- `ROOM_MAX_MEMBERS_WORKROOM`，默认 50。
- `ROOM_MAX_MEMBERS_PLAYROOM`，默认 200。
- `GAME_BROADCAST_THROTTLE_MS`，默认 500。

这三个值如果非法，启动时直接 fail-fast，不要带着错配置跑起来。

兼容性上，旧客户端会忽略不认识的帧类型，所以新增 `game_action` / `game_state` 不会把它们打挂。协议版本从原来的升到 v1.3。

## 为什么不走别的路

考虑过用标签代替类型。给房间打多个标签，比如「任务」「娱乐」「游戏」。问题是标签是开放的，谁都能加，代码里没法穷举判断。类型是封闭集合，判断起来干净。

也考虑过让客户端自己管行为边界，服务端不拦。但娱乐房间触发任务这种事，一旦发生就是脏数据、脏调度，事后清理成本比当场拦下来高得多。服务端必须有一道硬闸。

还考虑过把游戏状态塞进房间现有的字段里。不行。游戏有局、有阶段、有状态快照，跟房间本身的生命周期不是一回事。单独一张 `game_sessions` 表，`phase` 管阶段、`state` 存快照、`updated_at` 管时序，职责清楚。

## 后果

好处是边界明确。任务房间只干任务的事，娱乐房间只干娱乐的事。容量上限按类型分开配，服务端压力可控。游戏状态有独立存储，不会污染房间数据。

代价是协议升了版本，需要客户端配合升级才能用新能力。另外 `rooms` 表加了列，老数据默认都是 `workroom`，如果需要把某些房间改成 `playroom`，得显式调 `POST /api/rooms/:id/type`。

还有一个要盯的点：`GAME_BROADCAST_THROTTLE_MS` 默认 500 毫秒。如果某个游戏的节奏比这个快，广播会被合并，客户端看到的状态刷新会滞后。到时候按具体游戏调这个值，别在代码里写死。

## 落地检查清单

- `rooms.type` 默认值必须是 `workroom`，不能是空。
- `playroom` 拦 `intent=task` 的返回体，字段名必须是 `error`，值必须是 `ROOM_TYPE_FORBIDDEN`。
- 三个环境变量非法时启动失败，不能静默降级。
- 旧客户端收到 `game_action` / `game_state` 要能忽略，不能崩。
- 协议版本标记为 v1.3。
