# HTML 提取模块设计注记

模块：`HtmlExtractor`，头文件 `include/docseek/html_extractor.h`，实现 `src/html_extractor.cpp`。

技术栈：纯 C++17，零第三方依赖（iconv 属于 glibc 系统调用，不算第三方库）。

本文只讲这个模块怎么干活、边界在哪。性能相关的数字没实测过的地方一律写“以实测为准”。

## 1. 目标与非目标

### 1.1 目标

- 从 HTML 字节流里抽出可索引的正文文本，供 Indexer 建索引。
- 抽 `<title>` 和 `<meta name="description">`，title 后面会作为文档标题入库。
- 自己搞定编码识别与解码：BOM、`<meta charset>`、常见中文编码规范化，最后统一产出 UTF-8。
- 处理 HTML 实体，把 `&amp;` 这类还原成字符。
- 剔除脚本、样式、注释、DOCTYPE、处理指令，这些内容不该进正文。
- 接口对调用方友好：`extractFromBytes` 是 `noexcept`，失败不抛异常，返回空串让上游回落。

### 1.2 非目标

- 不执行 JavaScript。动态渲染出来的内容拿不到，只能看到静态 HTML。
- 不跟随 meta 刷新/跳转。
- 不做完整的 HTML 语法校验，也不构建 DOM 树。就是个线性扫描器。
- 不做正文抽取算法（比如 Readability 那种“找出文章主体”），块级标签全保留，换行规则统一处理。
- 不负责文件读取、不解压、不管网络。输入就是一段字节或一段已经 UTF-8 的字符串。

## 2. 管线

从字节到文本分四步：探测编码 → 解码成 UTF-8 → 提取文本 → 失败回落。

```
                 ┌──────────────────────────┐
   原始字节 ───▶ │ detectCharset            │
                 │ BOM → meta charset →     │
                 │ 默认 UTF-8               │
                 └────────────┬─────────────┘
                              │ 编码名
                              ▼
                 ┌──────────────────────────┐
                 │ decodeToUtf8             │
                 │ 规范化编码名 →           │
                 │ UTF-16 手写转换 /        │
                 │ 其余走 iconv             │
                 └────────────┬─────────────┘
                              │ UTF-8 字符串
                              ▼
                 ┌──────────────────────────┐
                 │ 提取                     │
                 │ 剔 script/style/noscript │
                 │ 剔注释/DOCTYPE/PI        │
                 │ 取 title / meta desc     │
                 │ 块级标签换行             │
                 │ 实体还原                 │
                 │ 空白折叠                 │
                 └────────────┬─────────────┘
                              │
                     ┌────────┴────────┐
                     │ 正文非空？       │
                     └────┬───────┬────┘
                       是 │       │ 否
                          ▼       ▼
                      返回文本   返回空串
                                 （上游回落原始字节
                                  + warn 日志）
```

主入口三个：

- `extractFromBytes`：探测 + 解码 + 提取一条龙，`noexcept`。给 Indexer 用的就是这个。
- `extract`：输入已经是 UTF-8 的情况，跳过探测和解码。
- `detectCharset` / `decodeToUtf8`：拆开单独用也行，方便测试和复用。

## 3. 提取规则表

| 对象 | 处理方式 |
| --- | --- |
| `<script>` / `<style>` / `<noscript>` | 整段剔除，标签和内容都不留。未闭合的 `<script>` 会一直吞到输入结尾 |
| `<title>` | 提取内容，作为文档标题来源 |
| `<meta name="description">` | 提取 content |
| 块级标签 | 触发换行。连续换行最多压成 2 个 |
| 行内标签 | 不换行，只把标签本身去掉，内容接在前后文之间 |
| 注释 `<!-- -->` | 剔除 |
| DOCTYPE | 剔除 |
| 处理指令 `<? ?>` | 剔除 |
| 实体 | 数字、hex、40+ 命名实体，见下 |
| 首尾空白 | 去掉 |
| 连续空白 | 折叠成一个空格 |

块级标签清单（触发换行）：`p` `div` `h1`–`h6` `br` `li` `ul` `ol` `table` `tr` `td` `blockquote` `pre` `section` `article` `header` `footer` `nav` `aside` `main` `hr` 等。

换行压缩规则：不管中间夹了多少个块级标签，连续换行最多保留 2 个。这样段落之间有空行，但不会出现一大片空行。

实体规则：

- 数字实体（`&#123;`）和 hex 实体（`&#x1F600;`）都支持。
- 命名实体 40 多个，覆盖 `amp` `lt` `gt` `quot` `apos` `nbsp` `copy` `reg` `trade` `hellip` `mdash` `ndash`、引号类、货币类、分数类等。
- 必须分号结尾，大小写不敏感。
- 非法实体原样保留，不做猜测。比如 `&notanentity;` 就照原样输出。

## 4. 编码策略

探测顺序：

1. BOM。UTF-8 BOM、UTF-16LE BOM、UTF-16BE BOM 直接认。
2. 前 8KB 内找 `<meta charset>` 或 `<meta http-equiv="Content-Type" content="...; charset=xxx">`。
3. 都没有，默认 UTF-8。

注意：charset 探测只看前 8KB，meta 标签在这之后就不认了。

编码名规范化映射：

| 输入写法 | 规范化为 |
| --- | --- |
| `gbk` | `GB18030` |
| `gb2312` | `GB18030` |
| 其它大小写/别名变体 | 按同一套规则统一到标准名 |

解码路径：

- UTF-8：直接用。
- UTF-16LE / UTF-16BE：手写转换，包含代理对处理。这条路径不依赖 iconv。
- 其它编码：走 iconv。iconv 失败返回空串，交给上游回落。

UTF-16 手写转换是为了两件事：一是含 NUL 的 UTF-16 内容不会被误判成二进制（这个坑 Indexer 那边踩过），二是不用为了 UTF-16 单独拉依赖。

## 5. Indexer 集成与回落策略

- 默认扩展名包含 `.html` 和 `.htm`。
- UTF-16 内容里含 NUL，不再被误判为二进制文件。
- 提取失败或正文为空：回落到原始字节，同时打 warn 日志。日志 `module=indexer`，字段带 `path` 和 `charset`。
- title 入库为文档标题。

回落的意图：宁可索引到一堆标签噪音，也不要让这个文件在索引里彻底消失。warn 日志用来事后排查是哪个文件、什么编码出的问题。

## 6. 已知限制

- 不执行 JS。动态渲染的页面只能拿到静态 HTML，正文可能大量缺失。
- meta 刷新/跳转不跟随。
- 极端病态嵌套：扫描本身是线性的、无递归，不会栈溢出，但输出可能很大。受 `maxFileBytes`（默认 5MB）保护。
- charset 探测只看前 8KB，meta 声明在更后面的位置就不生效。
- 未闭合 `<script>` 会吞到结尾，这是规则不是 bug，但遇到残缺 HTML 时正文会被吃掉一块。
- 实体表是固定 40+ 个，没覆盖到的命名实体原样保留。
- 性能数字未实测，以实测为准。
