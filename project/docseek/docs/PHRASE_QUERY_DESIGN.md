# 引号短语查询设计（GAP-PHRASE-001）

## 1. 问题陈述

当前 `src/query_parser.cpp` 的 `extractPhrases` 已实现引号短语解析，支持三种引号形式：

- 直引号 `"..."`
- 直角引号 `「...」`
- 弯引号 `“...”`

`extractPhrases` 返回两部分：`phrases`（提取出的短语文本列表）与 `rest`（去掉短语后剩余的查询串）。

但 `Searcher::search` / `Searcher::searchQuestion` 从不调用 `extractPhrases`，走的是自有的 `splitTokens` + `buildMatchQuery` 路径。

实测行为：

- `search '"人工智能"'`（带引号）：恒返回 0 hits。
- `search '人工智能'`（不带引号）：正常命中 1 篇。

即引号被当作普通查询字符送进分词与 FTS5 MATCH，导致带引号的查询无法命中。这是产品缺口 GAP-PHRASE-001。

本文档定义引号短语查询的检索流程、排序规则与边界条件。

## 2. 为什么不用 FTS5 phrase 语法

FTS5 原生支持 `"phrase"` 邻接查询语法，但本引擎不采用，原因：

- 索引侧使用 `CutForSearch` 切词，会对同一段文本产生重叠词元（overlapping tokens）。
- FTS5 的短语邻接语义依赖词元在索引中的位置邻接关系，重叠词元会破坏这种邻接假设，导致短语匹配结果不可靠（漏召回或误召回）。

因此短语匹配改为「后过滤」：先按现有机制召回候选，再在候选上做连续子串包含判断。判断使用 `containsFolded(hay, needle)`，它做 ASCII 大小写折叠后的子串判断，`src/searcher.cpp` 已有该函数。

## 3. 检索流程（分步）

`Searcher::search` 与 `Searcher::searchQuestion` 都要接入本流程。以 `search` 为例：

1. 调用 `extractPhrases(query)`，得到 `phrases` 与 `rest`。
2. 若 `phrases` 为空：完全退化为现有行为，不做任何短语后过滤。
3. 若 `phrases` 非空：
   a. 若 `rest` 非空：`rest` 按现有三阶段正常检索，得到候选 hits：
      - 阶段 1：AND 精确匹配。
      - 阶段 2：token 数 >= 2 时 OR 回退。
      - 阶段 3：结果为空时子串召回回退（中文单字 OR 粗筛 + `substringRecallPass` 精验）。
   b. 若 `rest` 为空（纯短语查询）：跳过阶段 1 / 阶段 2，直接用短语文本自身的 `expandTokenOrQuery` 做 OR 召回候选；若无候选，则走阶段 3 子串召回回退。
4. 后过滤：对候选 hits，只保留满足以下条件的 hit —— `title` 与 `getContentById(doc_id)` 取回的原文中，按 `containsFolded` 连续包含**每一个**短语。
   - 「每一个」指 AND 语义：所有短语都必须命中。
   - 判断范围是 title 与原文，任一命中即可（OR 语义在「title 或原文」这一层）。
5. 后过滤发生在三阶段之后、`rerankHits` 之前。

短语只做包含判断，不再对短语本身分词。

## 4. 排序规则

命中的短语参与排序加成：

- 在 `rerankHits` 中，对每个命中的短语加一次 `phraseBoost`（默认 2.0）。
- `rerankHits` 已有短语加成逻辑：去空白后的连续查询串出现在 title / snippet 时 +`phraseBoost`。
- 去重规则：同一段文本命中同一短语，只计一次加成，不重复累加；现有「去空白连续查询串」加成与新增「引号短语」加成分别独立计算，各自按其命中条件加成一次，二者可叠加，但同类内不重复。

## 5. 边界条件表

| 情形 | 行为 |
| --- | --- |
| 未闭合引号，如 `"人工智能` | 按普通字符处理，交由 `extractPhrases` 现有行为决定，不视为短语 |
| 空短语 `""` | 忽略，不加入 `phrases` |
| 引号内只有空白 | 忽略，不加入 `phrases` |
| 纯短语查询（`rest` 为空） | 跳过阶段 1 / 阶段 2，用短语文本 `expandTokenOrQuery` 做 OR 召回，无候选则走阶段 3 |
| 短语 + 普通词混合 | `rest` 走现有三阶段，短语做后过滤 |
| 短语在 title 命中、原文未命中 | 该 hit 保留 |
| 短语在原文命中、title 未命中 | 该 hit 保留 |
| 多短语 | AND 语义，全部命中才保留 |
| `phrases` 为空 | 完全退化为现有行为 |

## 6. 与现有阶段的交互

- 短语后过滤发生在三阶段检索完成之后、`rerankHits` 之前。
- `rest` 为空时，阶段 1（AND 精确）与阶段 2（OR 回退）被跳过；阶段 3（子串召回回退）在短语自身 OR 召回无候选时仍可使用。
- `rest` 非空时，三阶段行为不变，仅在输出前追加短语后过滤。
- `searchQuestion` 与 `search` 共用同一套短语处理逻辑，接入点一致。
- `rerankHits` 的短语加成在过滤之后生效，保证只对已通过过滤的 hit 计分。

## 7. 测试计划要点

- 纯短语命中：`search '"人工智能"'` 应命中不带引号时命中的同一篇。
- 三种引号形式：`"..."`、`「...」`、`“...”` 行为一致。
- 未闭合引号：`search '"人工智能'` 不当作短语，退化为普通查询行为。
- 空短语：`search '""'` 与 `search '"" 人工智能'` 不产生空短语过滤。
- 短语 + 普通词混合：验证 `rest` 三阶段正常且短语后过滤生效。
- 多短语 AND：构造一篇只含其中一个短语的文档，验证其被过滤掉。
- title 命中 / 原文命中：分别构造只在一处命中的文档，验证均保留。
- 排序加成：验证命中短语的 hit 分数高于未命中短语但其余条件相同的 hit。
- 去重：同一短语在一篇文档的 title 与原文都出现，加成只计一次。
- 纯短语无候选：构造索引中无相关词的纯短语查询，验证走子串召回回退路径。
- `searchQuestion` 与 `search` 对上述用例行为一致。
