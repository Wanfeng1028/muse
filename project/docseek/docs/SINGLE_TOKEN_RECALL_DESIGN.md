# 单空白词查询召回放宽设计

## 1. 问题陈述

### 1.1 现象

单空白词查询（splitTokens 后只有 1 个 token 的查询，如"考研数学一"）在 AND 无结果时，不会进入阶段 2 的 OR 回退，直接跳到阶段 3。

实测用例：`tests/test_tokenizer_long.cpp` 中的 `TokenizerLong.ShortAndLongCoexist`（当前已 `GTEST_SKIP`）。

- 文档内容："数学是基础，考研数学一是重点，中华人民共和国是考点"
- 查询："考研数学一"
- 结果：0 hits

### 1.2 根因链

根因是**查询侧与索引侧的切词粒度不对齐**，且阶段 2 的 OR 回退对单 token 查询不生效：

1. 查询侧：`expandTokenOrQuery` 把"考研数学一"展开为 AND 组 `AND(考研, 数学, 一)`。
2. 索引侧：同一文档中"考研数学一是重点"被切成 `考研 / 数学 / 一是`，其中包含"一是"但**不含单字"一"**。
3. 结果：查询要求 AND 命中 `考研`、`数学`、`一`，而索引里只有 `考研`、`数学`，`一` 缺失，AND 恒为 0，阶段 2 无法召回。
4. 阶段 2 的 OR 回退条件是 `hits.empty() && tokens.size() >= 2`。由于该查询 `tokens.size() == 1`，条件不成立，OR 回退被跳过，直接进入阶段 3。
5. 阶段 3 的子串召回：粗筛 `buildSubstringRecallQuery` 把中文 token 拆单字 OR，已能召回候选；但精验 `substringRecallPass` 要求原文按 `CutForSearch` 切词后逐个包含查询词，在粒度不对齐时（原文切成"一是"、查询要"一"）同样兜不住。

因此，单 token 查询在这条链路上既拿不到阶段 2 的 OR 回退，又过不了阶段 3 的精验，最终 0 hits。

## 2. 为什么放宽 OR 而不是改索引

问题本质是**查询词粒度与索引切词粒度不一致**，有两种修法：

- 改索引：调整索引侧切词策略，使"考研数学一是重点"这类文本在索引里也能产出单字"一"。
- 放宽召回：在阶段 2 对单 token 查询启用 OR 回退。

选择放宽召回的理由：

1. 索引切词策略是全局的，改它会影响所有查询的召回与排序行为，回归面极大，且会改变已有索引的语义与存储，代价高、风险不可控。
2. 阶段 3 的粗筛已经证明"把中文 token 拆单字 OR"能召回候选，说明放宽粒度到 OR 是可行且已被验证的方向；缺的只是阶段 2 的"放宽 AND 为 OR"的语义。
3. 放宽召回只影响查询路径，不动索引数据，可回滚、可灰度、可用评测集量化。
4. 粒度不对齐是查询侧与索引侧的天然矛盾，靠"索引迁就查询"无法穷举；在召回阶段做 OR 放宽是更通用的兜底。

## 3. 新旧条件对比

### 3.1 阶段 2（`Searcher::search`）

- 旧：`hits.empty() && tokens.size() >= 2`
  - 单 token 查询 AND 无结果时，OR 回退被跳过。
- 新：`hits.empty() && !tokens.empty()`
  - 单 token 查询 AND 无结果时，也执行 OR 回退。

对单 token 查询，OR 回退的语义是：把 `expandTokenOrQuery` 生成的 AND 组改为 OR 连接，即**同一 token 内各词组之间用 OR**。

预期：query "考研数学一" -> `OR(考研, 数学, 一是/一...)`，命中文档（文档含 `考研`、`数学`）。

### 3.2 阶段 2（`searchQuestion`）

- `searchQuestion` 的阶段 2 本就是"恒执行 OR 并集"（在 `tokens.size() >= 2` 前提下）。
- 同样放宽到单 token：让单 token 查询也走 OR 并集路径，与 `Searcher::search` 的放宽保持一致。

### 3.3 阶段 3

不变。阶段 3 的粗筛与精验逻辑维持现状，作为 OR 回退之后的补充召回路径。

## 4. 噪音风险与排序兜底

### 4.1 风险

单 token OR 会放宽召回条件：原本 AND 要求全部词组命中，改为 OR 后只要命中任一词组即可召回，可能引入噪音文档。尤其当查询包含多个词组、而其中某个词组是常见词时，召回集会明显变大。

### 4.2 兜底

- 用现有的 `rerankHits` 排序压住噪音：OR 召回只负责"把候选捞进来"，最终顺序由 `rerankHits` 决定，命中词组更多、更相关的文档排在前列。
- 召回放宽 + 排序收紧，是召回率与准确率的常规分工：放宽阶段保证不漏，排序阶段保证不乱。

### 4.3 监控

以评测集 v07/v08/v09 的指标变化为准，若召回率提升伴随准确率显著下降，需重新评估 OR 回退的触发范围（例如仅在 token 内词组数超过阈值时才放宽）。

## 5. 回归验证要求

改动后必须跑评测集 **v07 / v08 / v09 全量**，对比改动前后的召回与排序指标：

1. 确认目标用例：`TokenizerLong.ShortAndLongCoexist` 对应的查询"考研数学一"能召回目标文档（去掉 `GTEST_SKIP` 后应通过）。
2. 确认 v07 / v08 / v09 全量指标无回退：重点看准确率类指标是否因噪音召回而下降。
3. 若某评测集出现明显回退，记录回退样本，定位是哪些单 token 查询触发了 OR 放宽、召回了哪些噪音文档，再决定是否需要收窄触发条件。
4. 回归需覆盖 `Searcher::search` 与 `searchQuestion` 两条路径，确保阶段 2 的放宽在两处行为一致。
