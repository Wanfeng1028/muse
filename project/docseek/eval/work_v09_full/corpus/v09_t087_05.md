# 用 GitHub Actions 自动备份博客文章

博客文章是我最不想丢的东西。虽然源码在 git 仓库里，但万一仓库出问题，或者我误删了分支，还是得有额外的备份。我用 GitHub Actions 做了一个每天自动备份的流程。

## 为什么不用网盘同步

网盘同步看起来简单，但有几个问题。一是同步冲突，我在两台电脑上改文章，网盘经常生成一堆冲突副本。二是网盘不会保留历史版本，误删了找不回来。用 git 仓库加定时打包，版本清清楚楚。

## 工作流怎么写

在仓库的 .github/workflows 目录下新建一个 backup.yml。触发器用 schedule，cron 表达式设成每天凌晨三点。步骤很简单：检出代码，打包 content 目录，上传成 artifact。

```yaml
name: backup
on:
  schedule:
    - cron: '0 3 * * *'
jobs:
  backup:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: tar -czf blog-content.tar.gz content
      - uses: actions/upload-artifact@v4
        with:
          name: blog-backup
          path: blog-content.tar.gz
```

## 备份到哪里

Artifact 默认保留九十天，对我来说够用了。如果你想长期保存，可以在工作流里加一步，把打包好的文件传到对象存储，比如 Cloudflare R2 或者阿里云 OSS。

## 恢复的时候怎么做

下载 artifact 里的压缩包，解压之后把 content 目录覆盖回仓库就行。因为每次备份都是完整打包，不依赖增量，恢复起来没有心智负担。

## 一点提醒

GitHub Actions 的定时任务不是精确到分钟的，高峰期可能会延迟几十分钟。对备份来说这无所谓，不用太在意。
