# 发版对照报告：步骤日志 offset 参数收紧（drama-factory）

| 验收项 | 结论 | 理由 |
| --- | --- | --- |
| 可靠性 | 改进 | 控制器入口拦截非法的负数 offset 并返回明确的 400 状态码，避免了调用方传错参数被静默钳制而无法发现的问题。 |
| 可观测性 | 无变化 | 未新增日志/指标；参数非法时抛出的异常经全局处理器统一处理，HTTP 400 响应结构与既有保持一致。 |
| 数据与状态 | 无变化 | 核心逻辑未动，仅收紧了控制器入口的参数校验，合法值行为及底层数据读取状态完全保持一致。 |
| 部署与运维 | 无变化 | 无 schema 变更、无版本号升级、无 UI 变更，前端逻辑不受影响，无需额外的部署运维操作。 |
| 安全与健壮性 | 改进 | 通过在控制器边界增加负数与非整数参数的严格校验，提升了 API 接口的安全性与抗异常输入的健壮性。 |
| 可维护性 | 改进 | 将参数校验前置至 API 边界并保留底层防御性代码，降低了未来排查调用方参数问题的时间成本。 |

## 已知限制

- 本轮未运行全量测试套件，仅定向运行了 RunLogsOffsetValidationTest、RunControllerTest、RunLogServiceTest、RunLogServiceDeepTest。
- 未做真实服务 HTTP 冒烟验证，HTTP 400 映射依赖全局异常处理器既有行为。
- 无 UI 变更，不适用视觉验收。
