# v3.1 灵动表演补强审查

## 结论

用户提供的提示词之所以生动，不是因为形容词更多，而是因为它把参考资产、人物社会目标、即时触发、微动作、对白切分、硬切、声线和尾态写成一条可播放的因果链。它同时提供了“保留什么”和“不要引入什么”，因此模型的自由度集中在表演幅度，而不是身份、空间或对白事实。

v3.1 将这套方法泛化为可选的 `shots[].performance.acting_design` 与 `segments[].motion_profile`：

- `acting_design`：目标、策略、潜台词、触发、稳定个性签名、动作单元、对白锚点、预备/重音/跟随/收势、声线节拍、切点承接、连续入/出状态和排除项。
- `motion_profile`：媒介、帧率、曝光方式、时间原则、镜头原则、调度原则、声音原则和剪辑风格。
- `performance_liveliness`：只对显式启用的镜头生效；校验对白锚点必须是真实原文子串、动作窗口必须在本镜内、跨切声音必须有真实`utterance_id`、段级运动规则必须存在。
- H3编译：把上述字段展开为自然语言，保留中文对白在`<d>`中；不把`S1`、角色内部ID、身材/性格代号或“沿用上一段”写进模型正文。

## 当前证据

- 五套生产数据全部通过 `audit_storyboard_quality.py`。
- 20个技能合同测试通过，其中新增5个测试覆盖有效编译、缺失社会逻辑、对白锚点、动作/切点窗口和跨切声音边界。
- `validate_director_contract.py` 通过：132条运镜、100条原始情绪、100条增补配方、七模块、五种H3模式、19段视频正文、16个图像设计、13个可直接提交图像提示词和3个显式草案。
- 文戏样例的 H3 正文已实际包含 `Motion language`、`Immediate objective`、动作单元、运动弧、对白停顿/重读和连续性尾态。

## 不宣称的部分

机器门只能证明提示词结构、来源和时间关系完整，不能证明生成视频一定自然。角色脸部稳定、个性是否讨喜、动作是否过量、声线是否真正保持、硬切是否顺滑，仍需在真实生成后逐帧和听音验收。多人同时有决定性反应时，当前合同要求拆镜或显式建立多个可追踪节拍，不宣称一个镜头能自动融合任意多人的心理过程。
