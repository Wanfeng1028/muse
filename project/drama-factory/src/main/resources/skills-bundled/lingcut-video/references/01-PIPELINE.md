# 完整流水线 —— 从剧本到成片（12 个阶段）

> 这是全流程的**总纲**。每一阶段都指向对应的参考文件。

---

## 全景图

```
 ①  读剧本，做结构化拆解
 ②  定角色 / 场景 / 道具（生成定板图，逐张审阅）
 ③  写分镜表（镜号 / 时长 / 景别 / 画面 / 声音）
 ④  建画布骨架（角色 / 场景 / 道具 / 镜头图 / 镜头视频）
 ⑤  生成分镜图（逐张审阅）
 ⑥  生成视频（逐条 QA）
 ⑦  配音 + 旁白（音色全片统一）
 ⑧  发现问题的返工循环 ★这部分最花时间
 ⑨  逐章拼接
 ⑩  混旁白
 ⑪  拼三卷 → 全片
 ⑫  交付（剪辑工作台 + 发布）
```

---

## ① 读剧本，做结构化拆解

**不要用站点自带的「剧本分析」**（质量差，只写角色名）。

自己产出结构化 JSON：

```json
{
  "characters": [
    { "name": "老先生", "visual_prompt": "<颜色/材质/年龄/特征写死>",
      "voice_desc": "<音色描述，锁定不换>" }
  ],
  "scenes": [{ "name": "老街", "environment_prompt": "...", "elements": ["..."] }],
  "props": [{ "name": "信纸", "visual_prompt": "..." }],
  "shots": [
    { "id": "B01", "unit": "第一章", "dur": 8, "size": "远景",
      "camera": "固定", "scene": "老街",
      "cast": ["老先生"], "action": "...", "light": "...",
      "speaker": null, "dialogue": null }
  ]
}
```

**★ 关键：每个镜头都要有全局唯一的镜号**（`A01`…`T09`）。
这个编号会在**几百个文件**里用一辈子 —— 文件名、报告问题、返工都靠它。

推荐编号体系：
```
A      楔子
B~F    一至五章
G~N    六至十三章
O~S    十四至十八章
T      尾声
```

## ② 定角色 / 场景 / 道具

**先出定板图，逐张看图确认，再往下走。** 这一步错了后面全废。

```
角色定板：纯灰白背景，无场景无道具干扰，多视图角色表
         （正面脸 / 全身正面 / 全身背面 / 手部特写）
         ★ 瞳孔必须是深褐色到近黑色，不能是蓝色
         ★ 必须写实电影质感，皮肤有真实纹理，避免塑料感

场景定板：环境全貌 + 6~10 个可辨识元素
道具定板：见 05-ASSETS.md 的「基底法」
```

**★ 定板图不能直接当视频参考** —— 要先裁成**大头照 + 全身照**（不要用三视图，
官方实测三视图会加剧漂移）。

---

## ③ 写分镜表

**用 Markdown 表格**，一镜一行：

```markdown
| 镜 | 时长 | 景别 · 机位 | 画面 | 声音 |
|---|---|---|---|---|
| **B05** | 9s | 中景 · 侧面 | 老先生抬眼：「老三又没回来？」<br>屠户瓮声瓮气：「捎话就行。说家里都好…」 | 对白 |
```

**★ 画面列里的「」引号 = 台词**，声音列注明类型（对白 / 静 / 旁白 / 音效）。

**这份分镜表是后面的「标准答案」** —— 所有 QA 都拿它对照。

**写分镜表时就要算时长**：
```
台词字数 ÷ 3.5 ≈ 需要秒数
+ 每个动作节拍 0.8~1.5s
超过 12s → 标记为「需要拆镜」
```

---

## ④ 建画布骨架

```
角色 y=0 | 场景 y=700 | 道具 y=1400 | 音频 y=2100 | 镜头图 y=2800 | 视频 y=3500
水平间距 650
```

用引擎 API 建节点：
```js
const img = eng.addNode('image', x, 2800);
eng.updateNodeData(img, { name: '[一·1章 B01] 老街未醒 [图]', entityType:'frame',
  model:'gpt-image-2.5', aspectRatio:'16:9', resolution:'1K', count:'1',
  prompt: '...' });
```

**★ 命名规范**：`[卷·章 镜号] 内容 [图/视频]`
这个 `name` 字段是后面**批量下载、重拼、找节点**的唯一依据。

**★ 命名必须自己写 `data.entityName`**，因为画布可能会把 `name` 重置成
「图片节点 N」——**留着 `entityName` 当备份**。

## ⑤ 生成分镜图，逐张审阅

```js
eng.selectNode(id); await sleep(1300);
// 把提示词打进 contenteditable（★不是只改 data！）
const ce = [...document.querySelectorAll('[contenteditable="true"]')]
  .find(e => e.getBoundingClientRect().width > 300);
ce.focus();
const s = getSelection(), r = document.createRange();
r.selectNodeContents(ce); s.removeAllRanges(); s.addRange(r);
document.execCommand('delete', false, null);
document.execCommand('insertText', false, prompt);
// 点 ↑
[...document.querySelectorAll('button')].find(b => b.textContent.trim() === '↑').click();
```

**⚠️ 提示词必须从 UI 的 `contenteditable` 打进去，只改节点数据不生效。**

**图可并行**（一次 6~11 张，40 秒左右）。

**生成完必须下载 + 拼联系表 + `read_image` 真的看图。不要跳过。**

## ⑥ 生成视频，逐条 QA

**时长选择**（免费模型）：
```
对白句数 × 1.3s + 节拍数 × 0.8~1.5s
可选 5 / 8 / 10 / 12
```

**逐帧 QA**（每 0.5 秒抽帧）：
```bash
ffmpeg -i v.mp4 -vf "fps=2" -q:v 3 frames/f_%03d.jpg
python scripts/contact_sheet.py frames out.jpg 5
```

核对清单：
- 人物是否同一个人？表情是"活"的还是定格？
- **口型和配音对得上吗？有没有模型自己编的台词？**
- 有无多余字幕 / 水印 / 双胞胎？
- 动作是否连贯？运镜是否在节拍处停下？

**⚠️ 免费模型的 API 轮询用服务端任务表，不要信 `generating` 标志**
（见 10-TROUBLESHOOTING.md 第六节）。

## ⑦ 配音 + 旁白

**对白**：走画布音频节点（让视频模型跟着配音走，而不是自己造声音）。

**旁白**：走 LibTV（`libtv-voice` skill），
**按章生成整条**，拼片时按章混进去。

详见 `07-AUDIO.md`。

## ⑧ ★ 返工循环（最花时间的一段）

**用户会一章一章地看，然后报告问题。** 常见 6 类：

| 类别 | 现象 | 参考 |
|---|---|---|
| **A 台词缺失/不全** | 分镜表有台词，提示词里没写 | 本文件第三节 |
| **B 台词归属错** | A 的话给 B 说了 | 10-TROUBLESHOOTING 第八节 |
| **C 声音性别错** | 画面里没人，模型配错 | 同上 |
| **D 特写图不对** | 所有信长一样 / 字看不清 | `05-ASSETS.md` |
| **E 时长不够** | 台词赶 / 被砍 | `04-LONGSHOT.md` |
| **F 人物引用错** | 用了别的角色定板 | 本文件第二节 |

**★ 建立自动审计**：把「分镜表」和「画布 JSON」逐镜比对，自动找出
①缺台词 ②台词不全 ③没写声音方向 ④缺专用特写图。

**实测效果**：186 镜逐字比对，找出 66 处缺陷，最后收敛到 6 处。

**★ 修复流程**：改提示词 → 重生成 → 替换本地 → 重拼。**每修一批就重拼一次**，
否则成片会一直是旧的。

## ⑨⑩⑪ 拼接 / 混音 / 拼卷

详见 `08-ASSEMBLY.md`。

```
逐镜规范化 → concat → 逐章成片
逐章成片 + 该章旁白 → 混音 → 带旁白的章节
章节 concat → 三卷
三卷 concat → 全片
```

**必须核对**：`全片时长 ≈ 各章之和`（差 < 0.5s），否则有漏镜或时长膨胀。

## 时间分配参考（实测 25 分钟成片）

| 阶段 | 占比 |
|---|---|
| ①②③ 剧本/定板/分镜 | 10% |
| ④⑤⑥ 生成 | 25% |
| ⑦ 配音 | 5% |
| **⑧ 返工循环** | **45%** ★ 最花时间 |
| ⑨⑩⑪ 拼接 | 10% |
| ⑫ 交付 | 5% |

**结论：预算要给返工留一大半。第一次生成的东西一定有一堆问题。**

## 铁律总表

1. **画面里不写情绪名词，只写动作链**（"很悲伤" → 面瘫脸）
2. **台词必须进提示词**，不写模型就自己编
3. **台词必须标归属**（谁说的），逐条 ①②③④
4. **每帧重复角色外貌关键词**，不能只写名字
5. **永远不要写「静止/不动/定格」** → 会真的定格
6. **单物体特写必须加「单一画面，不要拼贴」**
7. **提示词必须从 UI 的 contenteditable 打进去**
8. **改画布数据要用引擎 `updateNodeData`**，不要直接 PUT
9. **限流 ≤5 次/分钟（含失败），节流 13 秒**
10. **内容被拒 → 换措辞，不删剧情**
11. **付费前必须报备**
12. **覆盖成片前必须备份**
13. **每次 QA 都要真的看图/听声音，不要"应该没问题"**
14. **每次做完把新经验写回 PLAYBOOK**
