# FeedFlow 真实负载验证报告（2026-10-16）


## 测试方法


- 数据规模：2 订阅 × 10 文章 = 20 篇（Phase 2 种子）
- 零网络：RSS 条目不含 `<link>`，`extract_text` 无 link 时直接使用 description；`feed_url` 全部指向本地 RSS 文件路径，`fetch_feed` 对本地路径直接 feedparser 解析。
- feeds 表通过 `db.get_conn` 直接 SQL 插入（不调用 `store.create_feed`，避免其内部可能走网络）。
- 抓取基准调用 `fetch_feed(..., timeout=5, retries=0, extract_timeout=1)`，避免任何网络等待。

### 诚实边界（必读）


- **Phase 2 种子走 bulk 路径**（`executemany` 批量 INSERT + 批量 `UPDATE ... cluster_id = id`），等价于真实批量导入/回填场景，**不等价于单篇实时插入**。单篇实时插入成本（含 cluster 扫描）在 Phase 3 单独实测。
- 追加条目数自动降级判定：单篇 insert_article 探测 102.7ms <= 200ms，追加条目为 20。
- Phase 2 simhash 计算为实测：累计 0.29s，占总种子耗时 53.3%。

**诚实边界**：零网络（file:// RSS）；fixture 直插 SQL；B 的超时是在 10 万规模 + 8 线程争用下的真实表现，
