# kaoyan-os v1.8.0「多用户支持」生产级 Definition of Done 对照报告

> 对照标准：`PRODUCTION_CHECKLIST.md`（muse 仓库统一标准，全量执行）
> 版本：v1.8.0 「多用户支持」
> 报告日期：2026-10-19（本轮）
> 结论口径：**通过 / 未通过 / 不适用+理由**；未验证项一律标注“未验证”，不作为通过。
> 依据范围：本轮已知代码事实 —— `auth.ts`（会话 / bcrypt / 限流）、`db.ts`（migrateToMultiUser）、路由层 user 隔离、vitest 测试。

---

## 0. 版本范围摘要

- 新增 `users` / `sessions` 表
- bcrypt 密码哈希
- Cookie 会话：`kaoyan_session`，有效期 30 天，空闲 24h 续期
- 登录限流
- auth 全局钩子：除 `/api/auth/*` 外全部接口要求登录
- 所有业务表加 `user_id` 列，经 `migrateToMultiUser` 从单用户老库迁移，历史数据归属 `local` 保留用户
- 备份导出 / 导入按用户隔离

## 1. 可靠性

### 1.1 测试金字塔：单元 + 集成 + 端到端全量，关键路径有失败注入测试
- 结论：**未通过（部分覆盖，已知限制）**
- 现状：
  - 已有 vitest 单元 / 集成测试覆盖 auth（会话、bcrypt、限流）与多用户迁移（`migrateToMultiUser`）、路由 user 隔离。
  - 端到端（E2E，真实进程 + 真实 HTTP + 真实 SQLite 文件）测试未在本轮验证。
  - 关键路径失败注入测试（如 bcrypt 抛错、SQLite 写失败、会话表损坏、限流存储异常）未验证。
- 排期 / 限制：
  - v1.8.1 补 E2E 冒烟（登录 → 业务读写 → 登出 → 越权访问 401）。
  - v1.8.2 补失败注入：bcrypt 异常、DB 写失败、会话过期边界。
- 已知限制：当前“测试通过”仅代表单元 / 集成层通过，不代表 E2E 生产可用。

### 1.2 错误处理策略明确：重试（带退避）、降级、幂等，写进文档
- 结论：**未通过（已知限制）**
- 现状：
  - auth 层对登录失败返回明确错误，限流触发返回限流错误。
  - 未验证：DB 写失败重试 / 退避策略、下游降级路径、写接口幂等键设计。
- 排期：
  - v1.8.2 在 `docs/ERROR_HANDLING.md` 明确：可重试错误分类、退避参数、幂等边界（哪些接口幂等、哪些不幂等）。
- 已知限制：v1.8.0 不承诺写接口幂等；客户端重试需自行去重。

### 1.3 数据库迁移版本化（即使 SQLite），支持升级路径说明
- 结论：**通过**
- 依据：
  - `db.ts` 内 `migrateToMultiUser` 实现了从单用户老库到多用户结构的迁移，历史数据归属 `local` 保留用户，业务表补 `user_id` 列。
  - 迁移为显式函数式迁移，随代码版本走。
- 备注：迁移的“版本号表 / schema_version 表”是否落地未在本轮验证；如仅靠函数式判断，属于轻量版本化，可接受但建议补 schema_version 记录。

### 1.4 健康检查端点 + 就绪探针 + 优雅关闭
- 结论：**未验证（已知限制）**
- 现状：本轮代码事实未包含 `/healthz` / `/readyz` 端点，也未验证 Fastify 优雅关闭（`onClose` / SIGTERM 处理）。
- 排期：
  - v1.8.1 增加 `/healthz`（进程存活）与 `/readyz`（DB 可读 + 迁移完成）。
  - v1.8.1 补 SIGTERM/SIGINT 优雅关闭：停止接收新请求、等待在途请求、关闭 SQLite。
- 已知限制：v1.8.0 不支持就绪探针与优雅关闭。

## 3. 数据与状态

### 3.1 自动备份 + 一键恢复流程（写进运维手册，实测过）
- 结论：**未通过（已知限制）**
- 现状：
  - 备份导出 / 导入按用户隔离已实现（业务能力层）。
  - 自动备份调度、一键恢复脚本、实测恢复演练未验证。
- 排期：
  - v1.8.1 提供 `scripts/backup.sh`（SQLite 在线备份 API 或文件级备份）与 `scripts/restore.sh`。
  - v1.8.2 完成一次实测恢复演练并记录结果。
- 已知限制：v1.8.0 的“备份”仅指用户数据导出，不含整库自动备份。

### 3.2 敏感数据处理策略明确（存什么、怎么存、怎么删）
- 结论：**通过（部分）**
- 依据：
  - 密码经 bcrypt 哈希存储，不存明文。
  - 会话通过 `kaoyan_session` cookie 承载，服务端 `sessions` 表可失效。
- 缺口：
  - 密码哈希 cost 参数、会话 token 是否可撤销 / 旋转策略未在本轮验证。
  - 账号删除时关联业务数据的级联删除 / 匿名化策略未验证。
- 排期：v1.8.1 在 `docs/SECURITY.md` 明确：存储字段清单、哈希算法与 cost、会话撤销、账号删除数据处置。

### 3.3 配置与密钥完全分离，环境变量化，启动时校验必填项
- 结论：**未验证（已知限制）**
- 现状：未验证是否存在启动期必填环境变量校验（如会话密钥、DB 路径）。
- 排期：v1.8.1 增加启动配置校验，缺失必填项直接 fail fast 并打印缺失键名。

### 3.4 单用户项目也按多用户、长期运行设计：tenant/user 概念落地
- 结论：**通过**
- 依据：
  - 新增 `users` / `sessions` 表。
  - 所有业务表加 `user_id` 列。
  - `migrateToMultiUser` 完成老库迁移，历史数据归属 `local` 保留用户。
  - 路由层做 user 隔离；备份导出 / 导入按用户隔离。
- 备注：当前为单租户多用户（无 tenant 维度），符合本项目定位；如需多租户再评估。

## 9. 发版结论

- **v1.8.0 功能层结论**：多用户核心能力（users / sessions / bcrypt / cookie 会话 / 登录限流 / 全局 auth 钩子 / 业务表 `user_id` / `migrateToMultiUser` / 备份按用户隔离）**已实现并具备单元 + 集成测试覆盖**。
- **生产级结论**：按 muse 全量 DoD，v1.8.0 **不满足生产级基础要求**。主要缺口集中在：可观测性、告警、备份自动化、运维手册、E2E、失败注入、真实负载与故障演练、文档同步。
- **发版建议**：
  - 若定位为“内部 / 小范围试用”，可发 v1.8.0，但必须同步发布 `CHANGELOG.md` 与 `docs/UPGRADE_v1.8.0.md`，并在 `PROJECTS.md` 登记本报告。
  - 若定位为“对外生产可用”，**不建议直接发 v1.8.0**；先完成 v1.8.1 的 P0 项：健康检查 / 优雅关闭、结构化日志 + request_id、启动配置校验、Docker Compose + 运维手册、备份 / 恢复脚本、CHANGELOG + 升级指南。
