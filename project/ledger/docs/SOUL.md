# 钱迹 Ledger · SOUL

## 一句话差异化命题

别的记账 App 把账单 CSV 丢给你，然后让你一条一条选分类；钱迹 v2.0 反过来——账单导进来，系统先自己猜，猜不中的才排进"侦探队列"，你只需要点头或改一下，它顺手记住下次不再问。**不让你记账，让账单自己认领。**

## 技术含金量点

- **三路分类匹配是叠加优先级而不是投票**：关键词规则（用户显式意志）> 历史习惯学习（同一收款方过去被归到哪）> 候选建议（金额/时间/摘要模糊相似）。规则冲突时谁赢、学习结果怎么不覆盖规则，这套优先级本身就是要写清楚的产品逻辑，不是调个模型就完事。
- **认领即学习，且学习是可回退的**：用户点一次"这是餐饮"，系统要决定是记成一次性偏好还是提成规则，还要能撤销——不能让一次误点污染以后的自动分类。
- **转账识别靠"对方是不是自己"**：从流水里认出对手方账户名，跟用户已有账户比对，命中就建议转成内部转账而不是记一笔支出，避免收支虚增。
- **指纹去重**：同一份账单重复导入、或支付宝/微信/银行三份流水有交集时，靠交易时间+金额+对手方+摘要生成的指纹判重，同时要允许"确实有两笔一模一样的"这种真实情况。
- **列映射向导要能存成模板**：每家银行 CSV 表头都不一样，映射一次存下来，下次同一家银行直接套模板，这是把"一次性麻烦"变成"一次性解决"的关键。

## 视觉概念

侦探主题不是换套皮肤，是让"待认领"这件事在界面上有存在感：侦探队列用暖黄便签纸质感（像贴在案卷上的线索条），每条待认领流水下面摆三张候选卡片，选中即盖章归案；已自动匹配的流水是低饱和的"已结案"灰绿，一眼扫过去知道哪些还需要你动手。配色走旧档案室——牛皮纸米黄、墨绿、暗红印章色，不用紫渐变，不做 hero 大图。一句话视觉逻辑：**让用户一眼看出"还剩几条要我管"，而不是一眼看出"这个 App 好漂亮"。**

## 命名理由

"银行账单侦探"——用户导进来的 CSV 是"案发现场"（一堆没头没尾的流水），系统是侦探（负责推断每笔钱花在哪），用户是警长（侦探给结论，警长拍板）。叫侦探而不是叫"智能分类"，是因为智能分类听起来像黑盒，侦探听起来像"它在替我干活，但决定权还在我手上"——这正是三路匹配 + 侦探队列的设计本意。

## 自查

**亮点**
- "侦探队列"这个交互是真的少见：多数记账 App 要么全自动（错了你不知道）、要么全手动（累死），钱迹把"系统猜 + 人拍板 + 拍完就学"做成了一个闭环，而且界面上一眼能看出还剩多少要处理。
- 认领即学习、且可回退，解决的是"自动化越用越准"这件事的真实痛点，而不是嘴上说说。
- 转账识别防收支虚增，是个小但很实的细节，用过的人会懂。

**风险**
- 三路匹配的优先级规则如果第一次用就猜错，用户可能直接不信任自动分类，转头全手动——第一印象很关键，冷启动阶段（还没有历史习惯）的匹配质量可能撑不起"侦探"这个名字，得靠预置模板和关键词规则先兜底。
- 侦探队列如果一次涌进来 200 条待认领，用户还是会劝退，需要考虑批量认领和"先放着"的缓冲设计。
- 侦探主题如果做得太重（满屏牛皮纸+印章），会显得像玩具，记账工具本身还是要让人信任数字。
