# 插件权限

这份文档说清楚插件能申请哪些权限、装的时候会走什么流程，以及现在哪些东西其实还没做完。

## 权限目录

现在只认下面这三个权限 id。manifest 里写了别的 id，安装时一律按「未知权限」处理，界面按高风险显示。

| 权限 id | 中文描述 | 风险 |
| --- | --- | --- |
| `fs.read` | 能读取你的全部文件 | 中 |
| `fs.write` | 能修改、删除你的文件 | 高 |
| `settings.read` | 能读取你的偏好设置 | 低 |

风险等级的含义：

- 低：只读偏好设置这类东西，出问题影响面小。
- 中：能读到你的文件内容，泄露了很麻烦。
- 高：能改能删你的文件，出问题可能是数据丢了。

## 安装确认流程

用户在应用商店里选一个本地 zip，流程是这样的：

1. 选 zip 文件。
2. 前端把 zip 发到 `POST /api/plugins/preview`，后端只解析、不安装，返回 manifest JSON。解析失败返回 400 加纯文本中文错误。
3. 前端弹出确认框，标题是「安装前请确认权限」，显示插件名和版本、权限列表（每行是权限 id、中文描述、低/中/高风险徽标），底部提示「只安装你信任的插件」。
4. 用户点「取消」就什么都不装，关掉弹窗。
5. 用户点「确认安装」，前端把同一个 zip 发到 `POST /api/plugins/install`，后端做白名单校验并落盘，返回 200 加 manifest JSON。
6. 装完刷新列表。

失败信息显示在弹窗里的错误区，弹窗不自动关，用户可以重试或者取消。

## 诚实声明

说清楚现在做到哪一步，别让人误会：

- 已经做的：安装时按白名单校验权限 id，未知 id 直接拒掉；用户必须看过权限列表并点确认，才会真的装。
- 还没做的：运行时沙箱强制。也就是说插件装完之后，系统并不会在运行时拦住它去干权限之外的事。这部分排期在后续版本，做完之前请只装你信得过的插件。
- 声明式权限本身不等于安全边界，它只是个约定加上安装时的一道检查。

## 开发者 manifest 示例

manifest 里只能写上面表里的权限 id，写别的会被拒。

```json
{
  "id": "my-plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "entry": "index.js",
  "description": "一个示例插件",
  "icon": "puzzle",
  "permissions": ["settings.read"]
}
```

再比如一个要读写文件的插件：

```json
{
  "id": "file-tool",
  "name": "文件工具",
  "version": "0.2.0",
  "entry": "main.js",
  "description": "帮你批量处理文件",
  "icon": "folder",
  "permissions": ["fs.read", "fs.write"]
}
```

申请 `fs.write` 的时候想清楚，用户看到的是高风险徽标，很多人会因为这个不装。
