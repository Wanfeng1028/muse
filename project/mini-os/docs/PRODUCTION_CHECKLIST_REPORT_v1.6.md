## 1. 版本信息与范围

- [通过] 版本号：`Cargo.toml` 从 1.5.0 升到 1.6.0，语义化版本正确，这是加功能的小版本。
- [通过] 迁移 004：新增 `shares.share_type` 列，取值 `'file'|'dir'`，默认 `'file'`，带 `CHECK` 约束，`PRAGMA` 幂等写法，老数据自动落成 `'file'`，升级不丢数据。
- [通过] 目录分享建分享：`POST /api/shares` 接受 `{"type":"dir","path":"/目录"}`。目录不存在返 404、path 是文件返 400、跨用户返 404、非法 type 返 400、缺 path 返 400，五种情况都有对应状态码。
- [通过] 目录浏览：`GET /api/share/list?token=...&path=` 支持目录浏览。file 分享调它返 400、路径穿越返 403、不存在返 404、path 指向文件返 400。
- [通过] 树内下载：`GET /api/s/:token/download?path=相对路径` 能下目录树里的文件，file 分享走原来的行为没变。
- [通过] 前端：`share.html` 加了目录浏览 UI，有面包屑、文件夹点击进入、文件下载按钮，深色主题统一。
- [通过] 指标新增：Prometheus 加了 `http_request_duration_seconds` 直方图（11 档桶加 `+Inf`，带 `_sum`/`_count`），以及 `vfs_files_total`、`vfs_bytes_total`、`shares_total{type}` 三个 DB 实时 gauge。路由 label 做了归一化，没有 MatchedPath 的时候记 `unknown`。

## 8. 发版结论

通过的汇总一下：范围条全过，测试 117/117 全过，clippy 零警告，fmt 通过，依赖零新增，真服务冒烟全流程走通，视觉 4 张截图亲眼检查通过，文档三处同步。

未通过清单：

1. 基础告警规则——排期 v1.7。
2. Dependabot 依赖更新——等仓库根迁入 `.github/` 时配，用户侧待办。
3. 分享读接口限流——v1.7 评估。
4. v1.5 遗留：分布式限流、注册限流、密码策略、2FA——这版没动，继续挂。

已知限制：

1. 分享 token 无过期无撤销，发出去就长期有效，要撤销只能删分享记录。
2. 整树只读无细粒度授权，目录分享要么全给要么不给，没法只授权某个子目录。
3. gauge 在大库上抓取有开销，`/metrics` 每次都查 DB，库特别大的时候抓取会慢，v1.7 看要不要加缓存。

结论：这版可以发，未通过项都不阻塞上线，要么有排期要么是已知限制且声明清楚。
