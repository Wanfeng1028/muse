# 哨兵-备份恢复演练记录

这篇文档讲的是 sentinel 里备份恢复演练怎么记、记什么、记完放哪。所谓演练，就是定期把备份文件拿出来真恢复一次，别等真出事才发现备份是坏的。下面这些内容都是仓库里实际有的东西，照着做就行。

## 一、演练前要确认的配置项

sentinel 的备份恢复相关配置集中在 `sentinel/src/main/resources/application.properties`，里面跟演练直接相关的有这么几个：

- `sentinel.backup.dir`：备份文件放在哪个目录，默认是 `./data/backup`。演练时先看这个目录里有没有新文件。
- `sentinel.backup.retention.days`：备份保留多少天，默认 7 天。演练用的那份备份别是已经被清理的。
- `sentinel.restore.temp.dir`：恢复时先解压到哪个临时目录，默认 `./data/restore-tmp`。这个目录演练前要清空，不然会跟上次的残留混在一起。
- `sentinel.restore.verify.enabled`：恢复完要不要做校验，默认 `true`。演练时保持 `true`，不然恢复了个寂寞也不知道。

改完配置重启服务，配置才会生效。别在运行中改完就当生效了。

## 二、演练步骤

### 1. 挑一份备份

先看备份目录：

```
ls -lh ./data/backup
```

文件名格式是 `muse-backup-yyyyMMddHHmmss.tar.gz`，比如 `muse-backup-20240518103000.tar.gz`。挑最近一份，别挑快过期的。

### 2. 触发恢复

sentinel 提供了恢复接口，路径是 `POST /api/sentinel/restore`。请求体里带备份文件名：

```
curl -X POST http://localhost:8080/api/sentinel/restore \
  -H "Content-Type: application/json" \
  -d '{"backupFile":"muse-backup-20240518103000.tar.gz","verify":true}'
```

返回里会有 `taskId`，拿这个去查进度。

### 3. 查恢复状态

接口是 `GET /api/sentinel/restore/{taskId}`：

```
curl http://localhost:8080/api/sentinel/restore/12345
```

返回的 `status` 字段有几种值：`RUNNING` 表示还在跑，`SUCCESS` 表示成了，`FAILED` 表示挂了。挂了的话看 `message` 字段，里面写了失败原因。

### 4. 校验

如果配置里 `sentinel.restore.verify.enabled=true`，恢复完会自动跑校验。校验接口是 `GET /api/sentinel/restore/{taskId}/verify`：

```
curl http://localhost:8080/api/sentinel/restore/12345/verify
```

返回里 `passed` 为 `true` 才算真恢复成功。`passed` 为 `false` 时 `details` 里会列出哪些表或哪些文件对不上。

## 三、演练记录表

每次演练完，往 `sentinel/docs/restore-drill-log.md` 里加一行。表头是固定的：

| 演练日期 | 备份文件 | 恢复耗时(秒) | 校验结果 | 操作人 | 备注 |
|---------|---------|------------|---------|-------|------|

填的时候注意：

- 演练日期写实际做的日期，格式 `yyyy-MM-dd`。
- 备份文件写完整文件名，别简写。
- 恢复耗时从发恢复请求到 `status` 变 `SUCCESS` 或 `FAILED` 的秒数，失败了也记。
- 校验结果写 `通过` 或 `不通过`，不通过的在备注里写清楚哪对不上。
- 操作人写全名，别写花名。

## 四、常见问题

**恢复一直卡在 RUNNING 怎么办？**

先看 `sentinel.restore.temp.dir` 那个目录的磁盘空间。空间不够会卡住。再看服务日志里有没有报错，日志在 `logs/sentinel.log`。

**校验不通过但数据看着没问题？**

校验比的是恢复后的数据和备份里的元数据，不是肉眼看着像就行。`details` 里会写具体哪张表哪一行对不上，照着查。

**备份文件是空的？**

检查 `sentinel.backup.dir` 目录权限，还有备份任务是不是真在跑。备份任务的日志同样在 `logs/sentinel.log` 里搜 `BackupTask`。

## 五、演练频率

建议每个月做一次。生产环境改过数据结构、加过表之后，必须补一次演练。演练记录别删，留着追溯用。
