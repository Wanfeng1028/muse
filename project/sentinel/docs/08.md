# 哨兵-短信告警配置

这篇讲怎么让哨兵在发现故障时，给你手机发短信。

## 先搞清楚发短信要经过谁

哨兵自己不发短信。它把告警内容交给短信网关，由网关去对接运营商。现在支持两种网关：

- 阿里云短信
- 腾讯云短信

你要先在云厂商那边开通短信服务，拿到下面这几样东西，再去改哨兵的配置。没有这些，配置写了也没用。

阿里云需要：
- AccessKeyId
- AccessKeySecret
- SignName（短信签名）
- TemplateCode（模板编号）

腾讯云需要：
- SecretId
- SecretKey
- SdkAppId
- SignName
- TemplateId

## 配置文件在哪

默认路径是：

```
sentinel/config/sentinel.yaml
```

如果你启动时用 `-c` 指定了别的路径，就以你指定的为准。

## 配置怎么写

下面这段是阿里云的完整例子，直接抄过去改值就行：

```yaml
alert:
  sms:
    enabled: true
    provider: aliyun
    access_key_id: "LTAI5txxxxxxxxxxxx"
    access_key_secret: "xxxxxxxxxxxxxxxxxxxxxxxx"
    sign_name: "哨兵告警"
    template_code: "SMS_123456789"
    template_param: "{\"name\":\"${rule_name}\",\"value\":\"${metric_value}\"}"
    receivers:
      - "13800138000"
      - "13900139000"
    retry: 2
    timeout: 5
```

腾讯云把 provider 那段换掉：

```yaml
alert:
  sms:
    enabled: true
    provider: tencent
    secret_id: "AKIDxxxxxxxxxxxxxxxx"
    secret_key: "xxxxxxxxxxxxxxxx"
    sdk_app_id: "1400000000"
    sign_name: "哨兵告警"
    template_id: "1234567"
    template_param: "{\"1\":\"${rule_name}\",\"2\":\"${metric_value}\"}"
    receivers:
      - "13800138000"
    retry: 2
    timeout: 5
```

几个字段说明一下：

- `enabled`：改成 true 才会发。默认是 false，防止你调试的时候短信乱飞。
- `provider`：只能是 `aliyun` 或 `tencent`，写别的启动会报错。
- `template_param`：里面能用 `${rule_name}`、`${metric_value}`、`${host}`、`${time}` 四个变量，哨兵发之前会替换成真实值。模板里变量个数要跟你云厂商后台建的模板对上，对不上会发失败。
- `receivers`：手机号列表，一个一行。国际号码要带国家码，比如 `+8613800138000`。
- `retry`：发送失败重试几次，默认 2。
- `timeout`：单次请求超时秒数，默认 5。

## 什么时候会发

满足下面任一条件就触发：

- 规则里的 `level` 是 `critical` 或 `warning`
- 规则里显式写了 `notify: [sms]`

`info` 级别的规则默认不发短信，只记日志。如果你确实要发，在规则里加 `notify`：

```yaml
rules:
  - name: cpu_high
    expr: "cpu_usage > 90"
    level: warning
    notify:
      - sms
```

## 相关接口

哨兵提供了几个 HTTP 接口，用来查配置和手动测：

查当前短信配置（密钥字段会打码）：

```
GET /api/v1/alert/sms/config
```

改配置（改完立刻生效，不用重启）：

```
PUT /api/v1/alert/sms/config
```

发一条测试短信，用来验证配置对不对：

```
POST /api/v1/alert/sms/test
```

请求体：

```json
{
  "receiver": "13800138000"
}
```

返回成功：

```json
{
  "code": 0,
  "msg": "ok"
}
```

返回失败会带错误原因，比如签名不对、模板参数数量不匹配，按提示改配置。

## 命令行怎么用

查配置：

```
sentinel alert sms config get
```

改配置：

```
sentinel alert sms config set --provider aliyun --sign-name "哨兵告警" --template-code SMS_123456789
```

发测试短信：

```
sentinel alert sms test --receiver 13800138000
```

跑完看输出，成功会打印 `send ok`，失败会打印具体错误码和错误信息。

## 常见问题

**收不到短信，日志里也没报错**

先看 `enabled` 是不是 true。再看规则的 `level`，info 级别不会发。最后看 `receivers` 里手机号有没有写错。

**报签名不合法**

`sign_name` 必须跟你在云厂商后台申请的签名一字不差，包括中英文和括号。审核没过的签名用不了。

**报模板参数不匹配**

`template_param` 里的变量个数要跟后台模板里的占位符个数一致。阿里云模板里是 `${name}` 这种，腾讯云是 `{1}`、`{2}` 这种，别搞混。

**发送超时**

一般是网络问题。可以先把 `timeout` 调大试试，比如改成 10。如果还是超时，检查哨兵所在机器能不能访问短信服务的域名。

**同一个告警短时间收到好几条**

哨兵默认有静默期，同一条规则 5 分钟内只发一次。想改的话在规则里加 `silence: 600`，单位是秒。
