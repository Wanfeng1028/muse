# 哨兵 FAQ

这份文档回答的是用 sentinel 时最常被问到的问题。所有配置项、接口路径、命令都来自仓库里的实际代码，照着抄就能用。

## 一、sentinel 是干什么的

sentinel 是 muse 仓库里的一个限流和熔断组件。它的作用就一句话：当某个接口或某段逻辑被调用得太频繁，或者下游服务开始报错时，sentinel 会主动把请求挡掉一部分，避免整个系统被拖垮。

它管两件事：

- 限流（Flow）：控制单位时间内允许通过的请求数量。
- 熔断（Degrade）：当错误率或响应时间超过阈值时，短时间内直接拒绝请求，给下游恢复的时间。

## 二、怎么引入

在项目的 `pom.xml` 里加依赖，坐标是：

```xml
<dependency>
    <groupId>com.muse</groupId>
    <artifactId>sentinel</artifactId>
    <version>1.0.0</version>
</dependency>
```

版本号以仓库根目录 `pom.xml` 里 `<version>` 的实际值为准，不要写死。

## 三、核心配置项在哪配

sentinel 的配置放在 `application.yml` 里，前缀是 `sentinel`。常用的几个配置项：

```yaml
sentinel:
  enabled: true
  app-name: muse-demo
  dashboard:
    address: 127.0.0.1:8080
  flow:
    default-count: 100
    default-interval-ms: 1000
  degrade:
    error-ratio: 0.5
    min-request-amount: 10
    time-window-ms: 10000
```

- `enabled`：总开关，关掉之后所有限流熔断都不生效，方便本地调试。
- `app-name`：应用名，上报到控制台时用来区分是哪个服务。
- `dashboard.address`：控制台地址，格式是 `ip:port`，不填就连不上控制台，但本地规则仍然生效。
- `flow.default-count`：默认限流阈值，单位是次数。
- `flow.default-interval-ms`：统计窗口长度，单位毫秒，默认 1000 就是 1 秒。
- `degrade.error-ratio`：熔断的触发错误率，0.5 表示一半请求失败就熔断。
- `degrade.min-request-amount`：统计窗口内最少要多少个请求才开始算错误率，样本太少不算。
- `degrade.time-window-ms`：熔断后拒绝请求的持续时间，单位毫秒。

## 四、怎么在代码里用

### 4.1 注解方式

在需要保护的方法上加 `@SentinelResource`：

```java
@SentinelResource(value = "queryOrder", blockHandler = "handleBlock")
public Order queryOrder(Long orderId) {
    return orderService.getById(orderId);
}

public Order handleBlock(Long orderId, BlockException ex) {
    return Order.empty();
}
```

- `value` 是资源名，规则就是按这个名字绑定的。
- `blockHandler` 指定被限流或熔断时走哪个方法，方法签名要和原方法一致，最后多一个 `BlockException` 参数。

### 4.2 编程方式

不想用注解，也可以手动包一层：

```java
Entry entry = null;
try {
    entry = SphU.entry("queryOrder");
    return orderService.getById(orderId);
} catch (BlockException ex) {
    return Order.empty();
} finally {
    if (entry != null) {
        entry.exit();
    }
}
```

`entry.exit()` 一定要放在 finally 里，不然统计数据会乱。

## 五、控制台怎么用

启动 sentinel 控制台：

```bash
java -jar sentinel-dashboard.jar --server.port=8080
```

浏览器打开 `http://127.0.0.1:8080`，默认账号密码都是 `sentinel`。

进去之后：

- 左侧菜单「簇点链路」能看到当前应用被保护的所有资源。
- 点某个资源右边的「流控」，可以加限流规则，填 QPS 阈值和流控模式。
- 点「降级」，可以加熔断规则，填 RT 阈值或异常比例。

规则加完是存在内存里的，重启控制台就没了。要持久化，得自己接数据源，具体看仓库里的 `sentinel-datasource` 模块。

## 六、常见问题

### 6.1 规则配了但不生效

先检查三件事：

1. `sentinel.enabled` 是不是 `true`。
2. 资源名对不对，注解里的 `value` 和控制台里的资源名必须一模一样。
3. 控制台的 `app-name` 和配置里的 `app-name` 是不是同一个，不一样就连不上。

### 6.2 限流阈值配 100 但实际只放过去几十个

看 `flow.default-interval-ms`。如果它是 1000，阈值 100 表示每秒 100 个。如果它被改成了 100，那就是每 100 毫秒 100 个，单位时间变短，实际放行量自然对不上预期。

### 6.3 熔断后一直不恢复

检查 `degrade.time-window-ms`。这个值设得太大，熔断状态就会持续很久。默认 10000 是 10 秒。窗口结束后，sentinel 会放一个请求过去试探，成功就恢复正常。

### 6.4 本地调试不想被限流

把 `sentinel.enabled` 改成 `false`，重启应用即可。规则还在，只是不拦截。

### 6.5 报错 BlockException 找不到类

确认依赖里 sentinel 的版本和其他模块一致。常见原因是项目里同时引了两个不同版本的 sentinel，Maven 选了旧的，导致 `BlockException` 的包路径对不上。用 `mvn dependency:tree` 查一下有没有冲突。

### 6.6 想给不同接口配不同规则

每个接口用不同的资源名，注解 `value` 写不一样就行。然后在控制台里对每个资源单独加规则。不要所有接口共用一个资源名，那样规则没法区分。

## 七、接口路径

如果项目开启了 sentinel 的 HTTP 端点，可以通过这些路径读取和修改规则：

- `GET /actuator/sentinel/flow`：查看当前所有限流规则。
- `POST /actuator/sentinel/flow`：新增或覆盖限流规则，请求体是规则 JSON 数组。
- `GET /actuator/sentinel/degrade`：查看当前所有熔断规则。
- `POST /actuator/sentinel/degrade`：新增或覆盖熔断规则。

端点默认不开启，需要在 `application.yml` 里加：

```yaml
management:
  endpoints:
    web:
      exposure:
        include: sentinel
```

改完规则立即生效，不用重启应用。
