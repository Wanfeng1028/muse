
# VoxLoom 可靠性策略：重试 / 退避 / 降级 / 幂等

本文说明 VoxLoom v1.1 在失败场景下的真实行为，以及为什么这么设计。

## 1. 冲突检测

`EditPlan` 已有冲突检测，冲突时抛 `EditConflictException`。也就是说，当一次编辑计划和当前状态对不上（例如基于旧状态生成的计划），会被明确拒绝，而不是静默产生错误结果。

## 2. 重试与退避策略表

| 操作 | 是否重试 | 理由 |
| --- | --- | --- |
| ffmpeg / ffprobe 解码 | 否 | 纯函数、无副作用；失败直接报给用户重选文件 |
| 备份 zip 写入 | 否 | 失败记日志；自动备份不阻断编辑 |
| 日志写入 | 永不抛（at-least-once） | 写日志不能把业务带崩 |

### 工程判断

**不是所有操作都值得重试。** 重试只对「失败是暂时的、重试可能成功、且重试不会造成额外副作用」的操作有意义。

- 解码失败通常是文件本身的问题（格式不支持、文件损坏），重试同一个文件还是失败，不如让用户换文件。
- 备份写入失败通常是磁盘满或权限问题，立刻重试大概率还是失败，记日志让人去处理更合适。
- 日志写入用 at-least-once 语义：允许极端情况下丢日志，但绝不因为写日志失败而中断业务。

## 3. 降级策略

- **ffmpeg 缺失**：WAV 导入和演示模式仍然可用；错误信息给安装指引（`sudo apt install ffmpeg` / `brew install ffmpeg` / ffmpeg.org）。
- **自动备份失败**：记 Warning 日志，继续编辑，不阻断用户。
- **ffprobe 失败**：明确抛 `AudioFormatException`，**不静默猜格式**。猜错了用户会拿到错误结果，比直接报错更糟。

## 4. 幂等性

- `CreateBackup`：每次生成新 Id，可重入，重复调用不会互相覆盖。
- `Restore`：目标非空即拒绝，天然幂等——同一个备份恢复两次，第二次会被拒绝，不会产生半截状态。
- `DeleteSelected` / `WeakenFillers`：基于不可变 `AudioClip` 重渲染，可重复执行，结果一致。

## 5. 超时

| 操作 | 超时 |
| --- | --- |
| ffprobe | 30s |
| ffmpeg 解码 | 120s |
| ffmpeg 可用性探测 | 10s |

超时会杀掉整个进程树，避免 ffmpeg 子进程残留。
