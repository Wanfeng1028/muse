# second-brain 发版对照报告：review_queue_limit_400

## 改动摘要

- 改动接口：`GET /api/review/queue`。
- 行为变更：`limit` 参数为非数字时，由原来的静默回落默认值改为返回 HTTP 400，`error` 字段为 `limit 参数非法`。
- 未变更行为：`limit` 缺省或为空时仍默认为 `20`；钳制逻辑保持不变（`<= 0` 置 `20`，`> 200` 置 `200`）；store 层未做改动。

## 验收范围

### 1. 靶向测试

- 新增测试文件：`review_queue_limit_validation_test.go`。
- 子用例数量：7 个。
- 已覆盖断言：
  - 非数字输入 `abc`、`1.5`、`1x`：均期望 HTTP 400，且 `error` 为 `limit 参数非法`。
  - 不传 `limit`、`limit=2`、`limit=0`、`limit=999`：均期望 HTTP 200。
- 既有回归：`TestReviewQueueLimitBoundary`（`limit=2`/`0`/`999` 的 200 口径）不受影响。

### 2. 真实服务冒烟

- 冒烟项：对 `GET /api/review/queue` 发起真实请求，验证非数字 `limit` 返回 400，缺省/合法/钳制值返回 200。
- 冒烟结果：真实服务冒烟（18427 端口，隔离库）7/7：limit=abc/1.5/1x 均 400 且 error 为“limit 参数非法”、limit=2 与无参及 0/999 均 200，冒烟后服务已停、端口复查已关。

## 对照表

| 维度 | 结论 | 理由 |
|---|---|---|
| 可靠性 | 通过 | 非法 `limit` 从静默容错改为显式 400，行为可预期且不破坏合法请求。 |
| 可观测性 | 通过 | 新增 400 响应带明确 `error=limit 参数非法`，便于客户端与日志定位。 |
| 数据 | 通过 | 本轮不涉及持久化与 store 层变更，limit 仅影响响应截取。 |
| 部署 | 通过 | 仅后端路由参数校验调整，无独立部署物变化。 |
| 安全 | 通过 | 参数入口收紧可减少异常输入造成的不确定性行为。 |
| 可维护性 | 通过 | 非法输入显式失败优于隐式回落，降低后续维护歧义。 |

## 已知限制

- `trend`/`heatmap`/`digest` 中的 `days`/`n` 仍沿用 `parseIntDefault` 静默回落口径，不在本轮靶向范围内。
- 全量测试套件本轮未跑（只跑靶向 3 组）。
