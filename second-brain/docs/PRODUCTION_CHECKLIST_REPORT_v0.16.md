# v0.16.0「年度复习热力图」发版对照报告

## 变更清单

### 后端
- `store/`：把 `ReviewTrend` 的聚合逻辑抽成未导出函数 `reviewTrendCore`，`ReviewTrend`（钳制 7/60）和新增的 `ReviewHeatmap`（钳制 365/366）共用同一套核心逻辑；既有行为零变更。

### API
- 新增 `GET /api/review/heatmap?days=`（默认 365，上限 366），返回 `{days,heatmap:[{date,reviewed,added}]}`，日期升序、含今天；口径与既有 `/api/review/trend` 完全一致（UTC 日期、复习数按用户去重过滤、新增数全局）。

### 前端
- 复习统计页新增「年度热力图」区块：GitHub 贡献图样式（列=周、行=周一至周日、周一对齐补占位），颜色按当日复习数分 5 档（`#2b7de9` 色系），鼠标悬停显示大白话 tooltip；加载失败静默，不打断统计页其余功能。
- 修复：`renderHeatmap` 用 `hidden` 属性会被 `#heatmap{display:grid}` 覆盖（沿用 v0.2.0 教训），改用 `style.display` 控制。

### 测试
- store 层 4 例：默认天数 / 钳制边界 / 数据正确性 / 跨用户隔离与 Trend 一致性。
- API 层 3 例：默认 365 / 钳制 366 / 跨用户隔离。
- 修复：测试用固定假 today 导致 Added 断言错，改用真实 today。
- `go test ./...` 全量全绿；`go vet` 全洁；真实服务冒烟（365 行、首尾日期正确、days=400→366）；截图亲眼验收通过。

## 已知限制

- 日期按 UTC 口径划分，与 `/api/review/trend` 一致；用户若跨时区可能感觉"日切"偏移。
- 热力图不包含未来日期，最多返回到今天。
- `days` 上限 366，超过自动钳制为 366。

## 结论

可发版。所有测试全绿，冒烟与截图验收通过，既有行为零变更，无迁移/鉴权/备份风险。
