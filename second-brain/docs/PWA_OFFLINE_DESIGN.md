# 离线设计

## 缓存策略表

| 资源类型 | 策略 | 失败时行为 |
| --- | --- | --- |
| 应用壳（index.html、CSS、JS、manifest、图标） | Service Worker 预缓存 | 安装阶段单个资源失败则该资源不进缓存；后续请求回退到已有缓存或网络 |
| 导航请求（页面跳转） | 网络优先 | 网络失败回退缓存的 index.html，应用以壳 + 缓存数据启动 |
| GET API（笔记列表/详情/预览/反向链接/标签/统计/搜索/复习队列/复习统计/图谱） | stale-while-revalidate | 先返回缓存副本，后台发起网络请求更新缓存；无缓存且网络失败则返回错误，页面显示空态或错误提示 |
| 写操作（POST/PUT/DELETE） | 仅网络 | 网络失败不进入 SW 缓存逻辑，由页面端离线队列接管（见下节） |

## 离线写队列

入队时机：页面端检测到写操作（保存笔记、删除笔记、提交复习评分）失败或 `navigator.onLine === false` 时，将操作写入 IndexedDB 数据库 `sb-offline` 的对象存储 `queue`。每条记录含自增 id、操作类型、载荷、目标 URL、创建时间。

回放顺序：联网后按 id 升序逐条回放，保证与用户操作顺序一致。

失败处理：单条回放遇到网络失败则停止本次回放，保留该条及其后所有条目，等待下次触发；遇到 HTTP 4xx 则丢弃该条并继续回放下一条（视为该操作已无效）。回放不并发，同一时刻只有一个队列回放流程。

## 冲突策略

① 笔记编辑：服务端权威。离线期间对已有笔记的修改在回放时以 `PUT /api/notes/{id}` 整条覆盖，即最后写入胜出。判定以服务端 `updated_at` 为准。不做三方合并，不保留历史版本，用户若在两处（如两个标签页或设备，本产品不支持多设备，仅限同浏览器多标签）同时改同一笔记，后回放者覆盖先回放者。

② 离线新建笔记：回放时由服务端分配新 id。队列中没有客户端幂等键，因此无法在回放前预知最终 id。页面刷新后以服务端返回的 id 为准；离线期间本地持有的临时标识在回放完成后丢弃。若回放过程中页面仍打开，队列回放完成后触发一次列表刷新，用服务端数据替换本地临时视图。

③ 复习评分回放：`POST /api/review/{id}` 按评分推进 SM-2 状态，该接口非幂等——同一评分回放两次会推进两次。队列保证每条评分只回放一次（成功即从 `queue` 删除）。若回放失败则停止并保留该条，不会静默丢弃，也不会重复入队。用户需知悉：在回放成功前，该次复习不计入服务端统计；回放成功后统计才更新。

## 明确不支持

- 推送通知：不实现 Web Push，无 Service Worker push 事件处理。
- 后台同步（Background Sync）：不实现。iOS Safari 不支持该 API，且本产品不依赖后台唤醒。
- 多设备同步：不实现。本产品是单机单库（SQLite 单文件），无跨设备冲突解决机制，无账号体系。

## 降级行为

IndexedDB 不可用（如隐私模式、存储被禁用）时，离线队列退化为内存队列：写操作暂存于页面内存，页面刷新或关闭即丢失。此降级在初始化时检测并 `console.warn` 输出提示，不阻断应用其余功能。内存队列同样按入队顺序回放，失败处理逻辑与 IndexedDB 队列一致，但不保证跨页面生命周期的持久性。
