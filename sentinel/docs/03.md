# 哨兵静默规则指南

静默规则用来压掉已知的、重复的、暂时不想看的告警。比如某台机器在夜里跑批，CPU 一直飘高，你知道它没事，就可以在这个时间段把这条告警静默掉。静默不是删除规则，也不是关掉监控，它只是让命中的告警不再发通知。

## 静默和屏蔽的区别

静默（silence）是按时间生效的，到点自动失效。屏蔽（suppress）是长期生效的，得手动改配置。你要是只想临时安静一会儿，用静默；要是某个告警永远不想看，那应该去改告警规则本身，而不是堆一堆永久静默。

## 配置文件长什么样

静默规则放在 `sentinel/conf/silence.yaml` 里。一个规则大概是这样：

```yaml
silences:
  - name: nightly-batch-cpu
    enabled: true
    match:
      alertname: HighCpuUsage
      instance: 10.0.3.21:9100
      severity: warning
    startsAt: "2024-06-01T22:00:00+08:00"
    endsAt: "2024-06-02T06:00:00+08:00"
    createdBy: wanfeng
    comment: "夜里跑批，CPU 高是正常的"
```

几个字段说清楚：

- `name`：规则名，同一个文件里不能重名。
- `enabled`：布尔值，`false` 时这条规则不参与匹配，但配置还留着。
- `match`：匹配条件，键值对形式。键是告警里的标签名，值是标签值。所有键值对都命中才算匹配，是“与”的关系。
- `startsAt` / `endsAt`：生效时间，RFC3339 格式，必须带时区。`endsAt` 必须晚于 `startsAt`，否则加载时直接报错。
- `createdBy`：谁建的，方便追责。
- `comment`：写清楚为什么静默，别过俩月自己都忘了。

`match` 里的值支持精确匹配。如果你想一次静默多台机器，就写多条规则，别在一个值里塞逗号，那样匹配不上。

## 匹配是怎么走的

告警进来后，哨兵拿它的标签去跟每条 `enabled: true` 的静默规则比。先看当前时间在不在 `startsAt` 和 `endsAt` 之间，不在就直接跳过。在时间窗口内的，再逐条比 `match` 里的键值对。全部对上，这条告警就被静默，不进通知队列。

注意一点：告警的标签里没有 `match` 要求的某个键，算不匹配，不是算命中。比如规则要求 `instance: 10.0.3.21:9100`，告警里压根没 `instance` 这个标签，那就不静默。

## 命令行操作

哨兵提供 `sentinel-cli` 来管静默。常用几个：

查当前生效的静默：

```
sentinel-cli silence list --active
```

查全部静默，包括没生效和已过期的：

```
sentinel-cli silence list
```

临时加一条静默，两小时后失效：

```
sentinel-cli silence add \
  --name disk-tmp \
  --match alertname=DiskUsageHigh \
  --match instance=10.0.3.30:9100 \
  --duration 2h \
  --comment "在清日志，先别报"
```

删掉一条：

```
sentinel-cli silence delete --name disk-tmp
```

`--duration` 支持 `30m`、`2h`、`7d` 这种写法。用 `--duration` 就不用自己算 `endsAt`，CLI 会按当前时间加上去。要是你想指定绝对时间，就用 `--starts-at` 和 `--ends-at`，格式跟配置文件一样。

## HTTP API

哨兵对外开了静默相关的接口，默认监听 `127.0.0.1:9095`。

拉列表：

```
GET /api/v1/silences
```

带上 `?active=true` 只返回当前生效的。

建一条：

```
POST /api/v1/silences
Content-Type: application/json

{
  "name": "disk-tmp",
  "enabled": true,
  "match": {
    "alertname": "DiskUsageHigh",
    "instance": "10.0.3.30:9100"
  },
  "startsAt": "2024-06-01T10:00:00+08:00",
  "endsAt": "2024-06-01T12:00:00+08:00",
  "createdBy": "wanfeng",
  "comment": "在清日志，先别报"
}
```

删一条：

```
DELETE /api/v1/silences/disk-tmp
```

路径最后那段是规则名。名字里有特殊字符的先做 URL 编码。

## 几个坑

第一，时间一定带时区。写成 `2024-06-01T10:00:00` 不带 `+08:00`，哨兵按 UTC 解析，跟你想的差八小时。

第二，改完 `silence.yaml` 要重载配置，哨兵不会自己盯着文件变。重载命令：

```
sentinel-cli reload
```

第三，静默只影响通知，不影响告警的生成和存储。你在告警历史里还是能看到被静默的告警，只是没发出去。排查问题时别以为静默了就等于没发生。

第四，规则别堆太多。堆到几百条以后，匹配虽然还是毫秒级，但人已经看不懂了。定期用 `sentinel-cli silence list` 过一遍，过期的删掉。

第五，`match` 的值是精确匹配，不支持正则。要按前缀、正则匹配，那是告警路由（route）该干的事，不是静默。两者别混着用。
