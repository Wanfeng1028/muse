# 哨兵-订阅管理指南

这篇文档讲的是 sentinel 里的订阅管理。订阅就是让 sentinel 帮你盯着某个东西，出事了通知你。

## 订阅是什么

一条订阅记录包含这几个字段：

- `id`：订阅编号，创建时自动生成
- `name`：订阅名字，自己取，方便认
- `type`：订阅类型，决定盯的是什么
- `target`：订阅目标，比如某个服务名、某个 URL
- `enabled`：是否启用，true 开着，false 关着
- `created_at`：创建时间

目前支持的 `type` 有：

- `http`：盯一个 HTTP 地址，返回码不对或者超时就报警
- `tcp`：盯一个 TCP 端口通不通
- `metric`：盯一个指标，超过阈值报警

## 配置文件

sentinel 启动时读 `sentinel/config.yaml`。订阅相关的配置在 `subscriptions` 段下面。

```yaml
subscriptions:
  check_interval: 30s
  timeout: 5s
  retry: 2
  store_path: ./data/subscriptions.json
```

字段说明：

- `check_interval`：多久检查一次，写 30s 就是 30 秒查一遍
- `timeout`：单次检查等多久算超时
- `retry`：失败了重试几次
- `store_path`：订阅数据存哪个文件，重启后从这读

改完配置要重启 sentinel 才生效。

## 命令行操作

sentinel 提供 `sentinel sub` 命令管子订阅。

### 新建订阅

```
sentinel sub add --name "订单服务健康检查" --type http --target "http://order-svc:8080/health"
```

成功后返回新订阅的 `id`，比如 `sub_7f3a2b`。

### 列出订阅

```
sentinel sub list
```

输出每条订阅的 `id`、`name`、`type`、`target`、`enabled`。

想只看开着的：

```
sentinel sub list --enabled
```

### 查看单条

```
sentinel sub get sub_7f3a2b
```

### 启用和停用

```
sentinel sub enable sub_7f3a2b
sentinel sub disable sub_7f3a2b
```

停用后 sentinel 不再检查这条，但记录还在。

### 删除订阅

```
sentinel sub remove sub_7f3a2b
```

删了就没了，`store_path` 里对应记录也会去掉。

### 手动触发一次检查

```
sentinel sub check sub_7f3a2b
```

会立即跑一次检查，把结果打到终端，用来调试。

## HTTP API

sentinel 默认监听 `:9090`，订阅接口都挂在 `/api/v1/subscriptions` 下面。

### 创建

```
POST /api/v1/subscriptions
Content-Type: application/json

{
  "name": "订单服务健康检查",
  "type": "http",
  "target": "http://order-svc:8080/health",
  "enabled": true
}
```

返回：

```json
{
  "id": "sub_7f3a2b",
  "name": "订单服务健康检查",
  "type": "http",
  "target": "http://order-svc:8080/health",
  "enabled": true,
  "created_at": "2024-05-12T10:30:00Z"
}
```

### 列表

```
GET /api/v1/subscriptions
```

### 查单条

```
GET /api/v1/subscriptions/{id}
```

### 更新

```
PUT /api/v1/subscriptions/{id}
Content-Type: application/json

{
  "target": "http://order-svc:8081/health"
}
```

只传要改的字段，没传的保持原样。

### 删除

```
DELETE /api/v1/subscriptions/{id}
```

## 报警怎么出去

订阅触发报警后，sentinel 把消息发给 `notifiers` 里配的渠道。看 `sentinel/config.yaml`：

```yaml
notifiers:
  - name: ops-webhook
    type: webhook
    url: http://alert-hub:9000/hook
  - name: oncall-mail
    type: email
    smtp_host: smtp.example.com
    smtp_port: 587
    from: sentinel@example.com
    to:
      - oncall@example.com
```

每个订阅可以指定走哪个通知渠道，加 `notifier` 字段：

```
sentinel sub add --name "支付网关" --type tcp --target "pay-gw:8443" --notifier ops-webhook
```

不写 `notifier` 就走所有渠道。

## 常见问题

**订阅建了但不检查**

先看 `enabled` 是不是 true。再看 sentinel 进程是不是在跑，`check_interval` 是不是设得太大。

**重启后订阅没了**

检查 `store_path` 指向的文件是不是还在。如果路径配的是相对路径，注意 sentinel 的工作目录，别因为换目录读不到。

**想改检查频率**

这是全局的，改 `check_interval` 后重启。目前不支持单条订阅单独设频率。

**删了订阅还能收到报警吗**

不会。删除是直接从存储里去掉，下一轮检查就没这条了。

**报错说 target 格式不对**

`http` 类型的 `target` 必须带 `http://` 或 `https://`。`tcp` 类型写 `主机:端口`，别加协议头。
