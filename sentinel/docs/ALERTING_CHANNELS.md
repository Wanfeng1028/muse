# 告警通道说明

本文说明 sentinel 支持的四类告警通道，重点讲短信通道怎么配、怎么用、出问题怎么查。

## 1. 通道对比表

| 维度 | webhook | smtp | 企业微信 | sms |
| --- | --- | --- | --- | --- |
| 典型延迟 | 秒级（取决于对端接口） | 秒级到分钟级（取决于邮件服务商） | 秒级 | 秒级到分钟级（取决于运营商与阿里云） |
| 可靠性 | 取决于对端，需自行重试 | 一般，可能进垃圾箱 | 较高，群机器人稳定 | 高，强触达，手机短信直接到人 |
| 配置成本 | 低，填个 URL 就行 | 中，要配 SMTP 主机、账号、端口 | 低，填机器人 Webhook 即可 | 中，需在阿里云控制台申请签名、模板、AK |
| 费用 | 自建接口无额外费用 | 邮件服务商可能收费 | 一般免费 | 按条计费，价格以阿里云官网为准 |
| 适用场景 | 对接自有系统、工单、IM 网关 | 邮件通知、留档 | 团队群内通知 | 强触达、按条计费，适合核心故障叫醒 |

选型建议：日常通知走 webhook 或企业微信，重要故障加一路 sms 兜底。

## 2. 短信通道（sms）

### 2.1 工作原理

号码来源分两级：先看监控项自己的 `sms_phones`，有就用；没有就回退到全局 `SENTINEL_SMS_PHONES`。两者都为空时，sms 渠道直接跳过，不算错误。

发送器有两种：

- Mock 发送器：内存里记一条，不真发短信，每次调用打一条 Info 日志 "Mock 短信发送"。只用于演示和测试，不用于生产。
- 阿里云发送器：走阿里云 SendSms 接口，模板变量固定为 `${msg}`，模板必须定义这个变量。

正文格式示例：

```
【sentinel 告警】官网首页 宕机，目标 https://web.example.com，时间 2026-10-16T23:00:00Z，错误：连接超时
```

失败会重试一次，也就是总共 2 次尝试。

### 2.2 阿里云短信配置 step-by-step

1. 在阿里云短信控制台申请签名。签名就是短信开头那个方括号里的名字，需要审核通过才能用。
2. 创建短信模板，模板正文里必须定义 `${msg}` 变量，审核通过后拿到模板 CODE。
3. 绑定测试号码。测试阶段只有控制台里绑定过的号码才能收到短信。
4. 创建 AccessKey。在 RAM 里建一个子账号，给它短信发送权限，拿到 AccessKeyID 和 AccessKeySecret。
5. 填环境变量并启动。设置 `SENTINEL_SMS_MODE=aliyun`，再把 AK、签名、模板 CODE 都填上，缺一个启动就会报错退出。

### 2.3 环境变量表

| 变量名 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| SENTINEL_SMS_MODE | 否 | mock | 取值 mock 或 aliyun。mock 只做演示/测试，不真发 |
| SENTINEL_SMS_PHONES | 否 | 空 | 全局默认号码，逗号分隔。监控项 sms_phones 为空时回退到此 |
| SENTINEL_SMS_ACCESS_KEY_ID | aliyun 模式必填 | 空 | 阿里云 AccessKeyID |
| SENTINEL_SMS_ACCESS_KEY_SECRET | aliyun 模式必填 | 空 | 阿里云 AccessKeySecret |
| SENTINEL_SMS_SIGN_NAME | aliyun 模式必填 | 空 | 已审核通过的短信签名 |
| SENTINEL_SMS_TEMPLATE_CODE | aliyun 模式必填 | 空 | 已审核通过的模板 CODE，模板须定义 `${msg}` 变量 |

aliyun 模式下，AK ID、AK Secret、签名、模板 CODE 四项缺一，启动即报错退出。

### 2.4 监控项配置

在监控项的 `notify_channels` 里加上 `sms`，在 `sms_phones` 里填接收号码。前端监控表单里有对应的"短信告警"配置区，可以多选通知渠道并填号码。

API 示例：

```bash
curl -X POST http://localhost:8080/api/monitors \
  -H 'Content-Type: application/json' \
  -d '{
    "name": "官网首页",
    "url": "https://web.example.com",
    "notify_channels": ["webhook", "sms"],
    "sms_phones": "13800138000,13900139000"
  }'
```

`sms_phones` 里的号码格式非法时，接口返回 400。

### 2.5 Mock 演示模式

默认就是 mock 模式，不用配任何 AK。想验证链路通不通，把 `SENTINEL_SMS_MODE` 保持为 `mock`，触发一次告警，然后在日志里搜 "Mock 短信发送"。看到这条 Info 日志，说明号码解析、渠道调度、正文拼装都走通了。

注意：mock 只用于演示和测试，不真发短信，不能当生产用。生产要发真短信，必须切到 aliyun 模式并配齐四项。

### 2.6 费用与限流

- 短信按条计费，具体价格以阿里云官网为准。
- 签名和模板都要在阿里云控制台审核通过，没审核过发不出去。
- 阿里云 SendSms 单次最多 1000 个号码，本实现是逐个单发，所以没这个批量上限的问题。
- 发送失败会重试一次，总共 2 次尝试，重试也会按条计费。
- 建议正文控制在 70 字以内，超过一条长度会按多条计费。

### 2.7 故障排查表

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 启动报 "短信通道未配置：缺少阿里云 AccessKeyID/AccessKeySecret，请设置 SENTINEL_SMS_ACCESS_KEY_ID 与 SENTINEL_SMS_ACCESS_KEY_SECRET" | aliyun 模式下 AK 没填 | 补齐 AK ID 与 AK Secret，或先切回 mock |
| 号码非法，返回中文错误 | 号码不符合格式 | 用大陆 11 位（1[3-9] 开头）或国际格式（+ 开头，7~15 位数字） |
| 接口返回 400 | `sms_phones` 字段校验没过 | 检查号码格式与分隔符 |
| 阿里云返回无权限 | AK 没有短信发送权限 | 在 RAM 里给子账号加短信权限 |
| 阿里云返回模板变量缺失 | 模板里没定义 `${msg}` | 去控制台改模板，加上 `${msg}` 变量并重新审核 |

### 2.8 安全注意事项

- AK 只走环境变量，不要写进仓库、不要提交到代码里。
- 手机号属于个人信息，日志里不要打全量正文。当前实现只打 phone 与正文长度，不打完整内容。
- 签名和模板审核通过后别随意改，改了要重新审核。
- 给 AK 的权限尽量收窄，只给短信发送需要的权限。
