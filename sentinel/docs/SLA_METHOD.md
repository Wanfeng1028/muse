# SLA 月度统计口径

本文档描述 sentinel 月度 SLA 报告的计算口径，对应代码 `internal/store/profile.go` 中的 `MonthlySLA`。所有时间均按 UTC 处理，事件按 `started_at` 归属到对应月份。

## 1. uptime 口径

uptime 为区间内检查（checks 表）成功占比：

```
uptime_pct = ok 的检查数 / 区间内检查总数 * 100
```

其中区间为 `[月初 00:00:00 UTC, 次月初 00:00:00 UTC)`。当区间内没有任何检查记录时，`uptime_pct` 记为 100。

无检查月份记 100 的理由：缺少检查数据时无法观测到失败，将其记为 100 是保守的可用性声明，避免因监控缺失而对用户展示虚假的宕机。这是一个如实声明的假设，而非对真实可用性的证明。

## 2. TotalDowntimeSec 口径

`total_downtime_sec` 为区间内事件宕机时长之和，由两部分组成：

1. 已关闭事件：直接累加其 `downtime_sec`。
2. 未关闭事件：按查询时刻估算，即 `now - started_at`（UTC，取整秒，负值不计入）。该估算仅用于报告计算，不写回数据库。

`down_incidents` 为区间内开始的事件总数（含已关闭与未关闭）。

## 3. MTTR 口径

`mttr_sec` 为平均恢复时长，仅统计已关闭事件：

```
mttr_sec = 已关闭事件的 downtime_sec 之和 / 已关闭事件数量
```

未关闭事件不参与 MTTR。当区间内没有已关闭事件时，`mttr_sec` 为 0。

## 4. 故障严重程度分级

按单次事件的宕机时长分级：

| 级别 | 阈值 | 含义 |
| --- | --- | --- |
| P1 | >= 1800 秒 | 严重 |
| P2 | >= 300 秒且 < 1800 秒 | 中等 |
| P3 | < 300 秒 | 轻微 |

未关闭事件使用查询时刻估算的时长参与分级，不写回数据库。

阈值理由：300 秒（5 分钟）是常见的告警确认与初步响应窗口，超过该窗口的故障通常已影响真实用户；1800 秒（30 分钟）是常见的重大故障响应升级线，超过该时长的故障通常需要跨团队介入。

## 5. 时间与归属

- 所有时间均为 UTC。
- 事件按 `started_at` 归属月份，区间为 `[月初, 次月初)`。
- 月份参数非法（month < 1 或 month > 12）时返回错误。

## 6. 固定目标

`sla_target` 固定为 99.9。`met` 为 `uptime_pct >= sla_target`。
