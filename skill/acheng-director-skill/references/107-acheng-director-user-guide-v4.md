# Acheng Director 4.3.6｜完整用户使用指南（兼容引用副本）

4.3.6 的上传状态、同源绑定与逐段操作按[114 合同](114-reference-binding-delivery-v4.3.6.md)执行；当前完整用法以[根目录指南](../使用指南.md)为准。自动模式直接展示每段操作卡与正文链接，长文保留文件；交互模式展示当前段完整正文。缺图不等于无需参考，本地绑定不等于平台已上传。

> 当前用户直接使用的完整指南以包根目录的 `使用指南.md` 为准；本文件保留旧引用路径以兼容 4.x 合同。4.3 新增的动画／原画术语库见 `references/113-animation-art-terminology-library-v4.3.md`，Ref2VA 词数按片段时长与复杂度动态计算，默认 10 秒简单段最低 2,000、目标约 2,400 个英文词。

这份指南给用户直接复制提示词。模板中的 `[填写]` 换成你的项目内容；示例可以直接运行，也可以只替换题材、人物和场景。每次只选当前需要的模板，不要把所有模板一次粘贴给模型。

Acheng Director 的原则是：主导演统一真值，专业模块各自负责自己的事实，最后由主导演合并。提示词越明确地写出目标、范围、冻结事实、需要的模块和交付物，结果越完整，也越少出现“同上”“根据需要调整”或把未生成媒体说成已完成的问题。

## 先写这四件事

任何请求开头先写：

1. 这次要做什么：剧本、分镜、表演、动作、资产、场景、VFX、H3、Seedance、续作还是审计。
2. 哪些事实已经锁定：对白、剧情结果、角色外观、场景几何、镜头时间、伤势、道具所有权和参考图。
3. 哪些事实允许原创：没有提供的角色、场景、道具、风格和声音。
4. 要什么交付：`prompt_only` 局部包，还是 `full_production` 完整生产包。

默认写上：

```text
不要调用付费媒体模型。没有真实图像、视频或音频时，不要声称已经生成；visual_status=UNVERIFIED。
每个资产和每个视频段都必须脱离聊天独立可用，不使用“同上”“沿用前段”“见角色设定”“根据需要调整”。
```

## 功能触发词表

把下表中的词直接写进请求，能让 Acheng 选择正确的专业模块。

| 你的目标 | 建议写入的词 | 触发模块 |
| --- | --- | --- |
| 创作或修订剧本 | `剧本`、`分场`、`故事架构`、`人物弧光`、`对白润色` | story |
| 多线、悬疑、伏笔、知情差 | `多线`、`谁知道什么`、`伏笔回收`、`双时间线`、`跨集` | story + continuity |
| 文戏表演 | `文戏表演`、`潜台词`、`眼神呼吸肩线手势`、`因果表演链` | performance |
| 战斗或追逐 | `战斗编排`、`combat timing`、`受力`、`接触窗口`、`攻应果续` | performance + model |
| 分镜和镜头 | `分镜`、`ShotSpec`、`镜头路径`、`切镜`、`4–15秒分段` | shots |
| 角色、场景、道具、关键帧资产 | `资产计划`、`GPT Image`、`四视图`、`参考图上传清单` | assets |
| 场景美术 | `场景设计`、`环境概念图`、`背景板`、`空间结构`、`多视图场景`、`moodboard转场景` | scene-design + assets |
| 风格统一 | `STYLE_MOTHER`、`style_lock`、`统一媒介线条色板` | assets |
| VFX 或巨构 | `VFX`、`能量`、`天气`、`破坏`、`变形`、`巨构尺度证据` | effects |
| MiniMax H3 | `H3`、`T2VA`、`I2VA`、`FL2VA`、`L2VA`、`Ref2VA` | model + h3-prompt-writing |
| Seedance | `Seedance`、`同一时间轴自然语言视频提示词` | model |
| 跨场连续性 | `连续性账本`、`伤势`、`弹药`、`道具所有权`、`场景损坏` | continuity |
| 参考视频分析 | `拉片`、`deconstruct`、`逐帧证据`、`观察与推断分栏` | shots/performance/action |
| 质量检查 | `机器验收`、`交付完整性`、`人工验收边界`、`prompt audit` | audit |

Acheng 不会因为写了一个词就强制加载所有模块。它会按本次请求追加真正需要的模块；例如只有场景设计时，不会自动加入战斗或 performance。

## 高命中能力触发词包

下面这些不是装饰词，而是告诉 Acheng 必须展开哪一类专业事实。使用时不要只写一个形容词；把“触发词 + 必须展开的字段 + 校验要求”一起写进去。

| 想激活的能力 | 建议原样写入的触发词 | 必须要求模型展开 | 主要模块 |
| --- | --- | --- | --- |
| 角色灵动、微动作、微表情 | `角色灵动表演`、`微动作`、`微表情`、`acting_design`、`gaze`、`breath`、`shoulder`、`body_hands`、`dialogue`、`五轨表演` | 目标、社交策略、潜台词、触发事实、眼神轨迹、呼吸、肩颈、身体/手部、面部变化、对白节拍、预备/重音/跟随/收势、切镜承接和尾态 | performance + model |
| 打戏逻辑与因果 | `打戏逻辑链`、`打戏因果链`、`攻应果续`、`force_source`、`trajectory`、`contact`、`resistance`、`impact_hold`、`transfer`、`recoil` | 施力来源、轨迹、接触点、阻力、冲击停留、受力传递、反作用、攻击结果、下一拍权限 | performance + model |
| 战斗时序和速度 | `combat timing`、`direction_facts`、`speed_profile`、`approach`、`commit`、`contact`、`recovery`、`reset`、`合法慢动作接触窗口` | origin、target、屏幕方向、身体朝向、武器方向、支点、结果方向；支撑/加速/接触可读性/恢复；慢动作触发事实、时窗、比例、退出条件 | performance + shots + model |
| 空间位置和方向 | `空间位置关系`、`世界位置`、`屏幕坐标`、`身体朝向`、`视线方向`、`支点`、`武器方向`、`180度轴线`、`角色钉子`、`入口出口地标` | 每镜角色位置、可见占比、深度层、朝向、动线、轴线、相机位置、目标、路径、方向、遮挡和镜尾状态 | shots + performance + continuity |
| 镜头可执行性 | `镜头实际路径`、`景别`、`机位`、`焦段`、`运动类型`、`幅度`、`速度`、`追踪目标`、`切镜原因`、`尾态承接` | 相机在世界中的位置和朝向，运动路径、幅度、速度、焦点、切镜新增信息、下一镜如何接上 | shots + model |
| 场景美学和空间设计 | `场景美学`、`scene thesis`、`primary visual tension`、`spatial grammar`、`material grammar`、`human use`、`维护痕迹`、`文化逻辑`、`尺度锚点`、`氛围感` | 场景命题、主要视觉张力、空间语法、材质和老化、人类使用、入口出口、地标、前中后景、尺度、光源动机、色彩角色、空气和负空间 | scene-design + assets |
| Moodboard 和风格锁 | `moodboard provenance`、`STYLE_MOTHER`、`style_lock`、`媒介`、`线条`、`阴影`、`色板`、`材质响应`、`保留/排除` | 区分审美方向、身份事实、构图、动作、状态和光位；记录来源、批准状态和排除范围 | assets + scene-design |
| VFX 和巨构可信度 | `效果家族`、`来源`、`作用域`、`传播过程`、`终态残留`、`遮挡后果`、`巨构尺度证据`、`主形/机制/决定性事件` | 能量/流体/天气/破坏/变形/空间/光学的适用逻辑；至少两种独立尺度证据和深度关系 | effects |
| 连续性和守恒 | `连续性账本`、`state_in`、`state_out`、`before/after`、`伤势 Phase`、`弹药/能量守恒`、`道具所有权`、`场景损坏等级`、`天气状态` | 每个变化的来源镜头、前态、后态、原因、时间位置；不得凭“下一镜”恢复物品或伤势 | continuity |
| 交付质量和诚实边界 | `提醒校验逻辑`、`机器验收`、`人工验收边界`、`反省略`、`独立可用`、`路径/版本/SHA-256/evidence`、`prompt_status`、`visual_status` | 范围、最小完整单元、禁止 shorthand、证据、未决项、真实媒体状态和下一步 | audit + continuity |

### 高命中触发前缀

当你特别在意质量稳定性，可以把这段放在任务正文前面，再补项目内容：

```text
本次不是只要形容词，请按能力触发词展开成可执行事实。
启用：角色灵动表演、微动作、微表情、五轨表演、空间位置关系、身体朝向、镜头实际路径、场景美学、氛围感、连续性账本、提醒校验逻辑。
如果有打戏，再启用：打戏逻辑链、打戏因果链、攻应果续、direction_facts、speed_profile、approach、commit、contact、recovery、reset、force_source、trajectory、resistance、impact_hold、transfer、recoil、合法慢动作接触窗口。
每个触发词都必须落到字段、可见动作、镜头路径或验收证据，不能只在标题中出现。
```

### 高命中触发示例

```text
调用 performance、shots、model、continuity，并加载 h3-prompt-writing。
本镜启用：角色灵动表演、微动作、微表情、五轨表演、空间位置关系、身体朝向、镜头实际路径、打戏逻辑链、打戏因果链、提醒校验逻辑。
陆川在画面左侧，岑禾在右侧，180 度轴线不能越过。陆川先用余光看热像屏幕，再看岑禾伸出的手；呼吸停在半拍，右肩因伤下沉，左手松开钥匙环。岑禾先停手再接住钥匙，接触声成为切到断流锁的声音承接。
若加入推搡，必须写 force_source、trajectory、contact、resistance、impact_hold、transfer、recoil，并用 direction_facts 和 speed_profile 闭合 approach→commit→contact→recovery→reset。慢动作只能覆盖 contact 的可读时间窗。
请检查角色屏幕位置、朝向、视线、支点、相机路径、切镜原因、state_in/state_out、对白原文和下一镜尾态；输出完整可独立使用的 H3，不用“同上”。
```

## 1. 从零做完整短片

### 可填空模板

```text
使用 $acheng-director，执行 full-production。

项目类型：[原创动画 / 实拍风格化 / 游戏预告 / 广告 / 其他]
视觉媒介：[3D CG / 2D / 3渲2 / 定格 / 写实 / 其他]
题材和语气：[动作 / 悬疑 / 喜剧 / 浪漫 / 混合]
故事创意：[用 3–8 句写清主角、目标、阻力、代价和结局方向]
目标总时长：[例如 60 秒]
单段目标：[4–15 秒；如有偏好写 8–12 秒]
已锁定事实：[对白、角色、结局、参考图、场景几何；没有就写“无”]
允许原创：[角色 / 场景 / 道具 / 风格 / 声音]
资产模型：[GPT Image 2/2.5 或“请按当前入口输出兼容 prompt”]
视频模型：[MiniMax H3 / Seedance / 只做提示词]
本次明确需要的模块：[story, shots, performance, assets, model, continuity；按需增删]
本次不需要的模块：[combat / effects / scene-design / STYLE_MOTHER 等]
交付范围：[prompt_only / full_production]

请先输出能力触发图和导演总控台，再按 story → shots → performance → assets → model → continuity → audit 的实际依赖顺序交付。
每个角色、场景、镜头、资产和视频段都写完整可见事实；不要用内部代号替代正文。
没有参考图时先做原创设计；不调用付费生成；visual_status=UNVERIFIED。
```

### 完整示例

```text
使用 $acheng-director，执行 full-production。

项目类型：原创 3D 电影感动画
视觉媒介：写实材质、略带 3D 渲染质感
题材和语气：近未来悬疑，最后转为克制的关系和解
故事创意：夜班维修员陆川必须在停电前让最后一辆载有平民的运输车通过闸门。闸门由他独自撑住，但热像显示继续供电会烧毁破裂电芯。检修员岑禾要求他交出手动钥匙；他必须承认上次独断造成的事故，才能让两人共同完成断流和开闸。结尾车辆通过，钥匙留在两人共用的墙钩上。
目标总时长：60 秒
单段目标：8–12 秒
已锁定事实：陆川右腕受伤且功能受限；岑禾是检修员；结尾必须是车辆通过、钥匙不再由陆川独占；没有参考图。
允许原创：角色外观、机库、道具、灯光、声音。
资产模型：GPT Image 2/2.5 兼容提示词
视频模型：MiniMax H3 提示词
本次明确需要的模块：story, shots, performance, assets, model, continuity, audit
本次不需要的模块：战斗、VFX、STYLE_MOTHER、场景专业支路
交付范围：full_production

请先输出能力触发图和导演总控台，然后完整交付剧本、人物弧光、分镜、文戏表演、资产图提示词、逐段 H3、上传清单、连续性账本和机器验收。真实媒体未生成，visual_status=UNVERIFIED。
```

## 2. 剧本、分场和人物弧光

### 可填空模板

```text
调用 story 模块，执行 script/story 模式。

作品：[ ]
总时长或集数：[ ]
题材和终局约束：[ ]
角色：[姓名、关系、当下目标；没有就请原创]
已锁定对白：[逐字粘贴；没有就写无]
不能改变的事实：[ ]
希望强化的问题：[因果 / 人物选择 / 节奏 / 喜剧 / 悬疑 / 关系]

请输出：
1. 核心冲突和终局必须成立的事件；
2. 任意数量的剧情线，每拍标 primary_thread 和 secondary_threads；
3. 角色欲望、需要、误信、能力边界、关系债和可见行为证据；
4. 完整分场正文，包含起因、目标、阻力、选择、代价、结果、尾态和下一场原因；
5. 场景登记簿、伏笔/兑现表和知情事件；
6. 机器检查会用到的未决项和对白锁定项。

已有确认稿的部分不要重写；只修改我明确允许的范围。
```

### 完整示例

```text
调用 story 模块，执行 script/story 模式。

作品：《最后一车》
总时长：90 秒
终局约束：末车必须通过；破裂电芯不能继续并网；陆川必须主动把控制权交给岑禾；结尾用一个具体物件动作证明关系改变。
角色：陆川，维修员，习惯独自承担；岑禾，检修员，过去被陆川拒绝过一次接管。
不能改变的事实：陆川右腕受伤；对白“上次是我没听。现在你来。”必须逐字保留。
希望强化的问题：让 A 外部任务、B 关系冲突、C 电芯暗线互相改变，而不是三条平行事件。

请交付完整 90 秒分场正文、A/B/C 节拍、知情事件、伏笔回收、五阶段人物弧光、场景登记簿和尾态。不要为了适配视频窗口提前结束故事。
```

## 3. 多线、知情差、伏笔和跨集故事

### 可填空模板

```text
调用 story 和 continuity，执行 multi-line / serial 模式。

故事范围：[集数、总时长、播放顺序和故事时间]
线路数量：[任意数量；每条写持续问题]
人物和观众分别知道什么：[ ]
必须保留的误信：[ ]
伏笔：[铺设事实、表面解释、强化节点、兑现节点、兑现造成的选择变化]
倒叙或交叉剪辑：[ ]

请为每个 beat 写：beat_id、scene_id、story_time、primary_thread、secondary_threads、depends_on、goal、obstacle、choice、cost、result、setup/payoff、next_cause。
每个 knowledge event 写 holder、fact、before、after、evidence 和生效时点。
不允许角色提前知道尚未取得的事实；不允许用删除角色已经看见的信息来制造悬疑。
```

### 完整示例

```text
调用 story 和 continuity，执行 multi-line / serial 模式。

三集悬疑短剧，每集 60 秒。A 线：调查员寻找被删掉的港口维修记录。B 线：她和弟弟因父亲事故互相隐瞒。C 线：港口每天凌晨会自动恢复一段不存在的监控。
观众在第一集知道监控异常，但调查员只认为是系统故障；弟弟知道父亲曾进入维修塔，但不知道监控会恢复。
伏笔：第一集出现反复亮起的黄色检修灯；第二集灯光引导调查员避开错误入口；第三集灯光证明维修塔的备用电源仍被人为维护。
倒叙只允许出现在第二集，必须标 story_time，不得让人物在倒叙发生前使用其中信息。

请输出线路网络、知情表、每拍依赖、伏笔兑现和跨集连续性入口，不要只给主题分析。
```

## 4. 台词、人物声音和局部改稿

### 可填空模板

```text
调用 story，执行 character-dialogue-revision。

修改范围：[台词 / 潜台词 / 人物选择 / 节奏 / 可拍性]
原文：[粘贴需要修改的场次]
冻结：[结局、事实、对白、资产、时长中哪些不能动]
允许变化：[ ]
人物 A 的目标、策略、潜台词：[ ]
人物 B 的目标、策略、潜台词：[ ]

请先给出原位置和问题证据，再给完整修订文本和变更表。每句台词说明表面说法、真正想让对方做什么、对方可能听成什么；视频正文只保留可见行为、声线和原对白，不把分析标签写进 H3。
```

### 完整示例

```text
调用 story，执行 character-dialogue-revision。

只改 SC04 的人物选择和表演前置，不改对白、结局和时长。
原文：陆川握住钥匙说“上次是我没听。现在你来。”
问题：台词本身有效，但之前没有可见动作证明他真的放弃控制。
允许变化：视线、呼吸、手部动作、岑禾的反应和切镜点。
```

## 12. MiniMax H3 视频提示词

涉及 H3 时必须加载 `h3-prompt-writing` skill。scene、story、shots、performance 只提供事实，model 负责按 H3 合同编译。

### 模式选择

| 模式 | 适用情况 |
| --- | --- |
| T2VA | 没有参考帧，只用文字建立完整时间线 |
| I2VA | 有真实首帧，从首帧继续向前发展 |
| FL2VA | 有真实首帧和尾帧，描述两帧之间的连续路径 |
| L2VA | 有真实尾帧，让动作从合理前态收束到尾帧 |
| Ref2VA | 多类真实参考，需定义 Subject/Picture/Video/Audio 角色 |

Ref2VA 用于真实参考文件驱动任务；标签只对应真实上传文件，不能仅因有角色或场景定义就伪造参考标签。`detailed_description` 按时长与复杂度动态计算最低词数和目标词数：`minimum=max(2000, ceil(seconds×200))+complexity_addition`，`target=max(2400, ceil(seconds×240), minimum+200)`，极限值 2900 词硬性封顶（处于 2200-2900 词区间，剔除无上限输出）；默认 10 秒简单段最低 2,000、目标 2,400 个英文词。每个镜头都要展开主体外观、空间位置、朝向、光线、起始状态、触发事实、动作因果、微动作、微表情、接触／受力、相机路径、声音时序和尾态。若达到宿主单次输出上限，按字段和镜头续写并保留游标，不能摘要化、写“同上”或静默切换模式。

## 19. 推荐的最短交互方式

如果你不确定该用哪个模板，先发这一段，Acheng 会自己生成能力触发图并继续：

```text
使用 $acheng-director。
我的目标是：[一句话写想完成的事情]。

```

### 完整示例

```text
使用 $acheng-director。
我的目标是：把“一个维修员在停电前把最后一辆车送过闸门”的想法做成 45 秒悬疑动画。
```
