# 60｜图像资产、IM2 七步法与 16 格接触表

## 显式路由与输入权属

全生产必须先按[61全资产依赖](61-asset-dependency-production.md)建立需求、版本与制作顺序，再编译以下图像卡。局部资产请求可仅交该卡，但不得称全剧资产齐备。

本分支最终产物是可直接粘贴到GPT Image 2/2.5的完整自然语言提示词，遵守[独立提示词与上传合同](72-standalone-prompt-delivery.md)。每条明确无需参考图或必须上传的实际文件、顺序、用途与不继承项；不能只交七步分析表或代号。用 `compile_assets.py` 导出`.image.txt`和`UPLOAD.md`。

GitHub 仓库 `im2-image-skills` 在本机的技能名为 `im2-clean-image`，两者是同一来源链的仓库名与技能名，不是缺失的两个服务。资产请求显式记录 `contract:C/target:im2-clean-image/source_repository:im2-image-skills`。已安装版本存在时读其 SKILL 和当前任务所需 ref；无外部入口时本包 [原始七步与材质规范](sources/im2/upstream-skill.md) 提供完整本地规则，不假称已调用出图模型。

角色图、场景图、风格图、姿势图、构图图各自承担一个主要角色。身份权威不能被更漂亮的风格图覆盖；姿势图不能带入另一个人的脸。源图编辑先分类 EDIT／REBUILD／MIXED：局部材料修改可 EDIT；机位、拓扑、遮挡变化通常需要 REBUILD；MIXED 逐项列出耦合区域。

### 角色身份资产默认：四视图基准板

当资产卡的 `asset_kind` 或依赖计划的 `kind` 为 `character`，且没有明确指定其他视图布局时，默认生成一张单角色四视图身份基准板，按从左到右固定为：

1. 正面全身（front full-body）；
2. 背面全身（back full-body）；
3. 侧面全身（side-profile full-body）；
4. 正脸头肩近景（front-facing face close-up）。

前三格保持同一中立站姿、比例、服装、发型、光线和背景；第四格只放大正脸，用于锁定五官。四格是一个身份参考资产，不是四个独立人物，也不是动作关键帧。角色卡必须同时提供 `character_name` 与 `state_label`；名称、状态和版本写入 `ASSET_NAMES.txt`、`index.json` 与 `UPLOAD.md`，提示词会以自然语言声明它们，但明确禁止把标签文字渲染到图内。

【四视图去道具纯化原则】：人物四视图（Character Turnaround Sheet）是纯粹的人体骨架、五官相貌与服装版型基准板，**绝对禁止加入手持武器、繁复机械道具或大件外设**！双手必须保持空手自然中立下垂，严禁手持刀剑或摆出战斗攻击姿态，以防生图 AI 将武器细节与肢体融合成结构畸变。武器与关键道具必须单独生成独立的道具设计图（Prop Design Sheet）。
用户明确指定单视图、姿势图或其他布局时才覆盖默认四视图；场景、道具、特效和剧情关键帧不自动套用本规则。

图像事务写三段：CHANGE 是一个主要可见变化，PRESERVE EXACTLY 是已由源图证明的不变量，REBUILD 是因变化而必须重算的遮挡、接触影、反射或新露出的表面。“保持一致”是验收目标，不是假称生成模型像素精确保真。文字、徽标、注册几何和局部像素需严格一致时，用遮罩、合成、对齐比较或 3D 重建。

## 必须按顺序编译的七步

| 步骤 | 产出内容 | 示例 |
|---|---|---|
| 1 主体／身份／相位／场所 | 当前可见人物、数量、单一姿态和地点 | 两台维护机甲在机库斜板两侧，左机甲护臂接触右拳 |
| 2 媒介 | 用户选定的写实、赛璐璐、水墨或其他媒介 | 写实机械比例与可读的装甲叠层 |
| 3 相机／构图／层级 | 观察点、主形、视觉路径和静音区 | 35 mm 等效，1.6 m 高，接触点在右上三分位 |
| 4 光路／材料 | 光源—介质—受体，hero surfaces 及曝光 | 东墙灯经油雾照到护板边缘，漆面哑光、断口金属反光 |
| 5 信息密度衰减 | 焦点、支撑、静音及纵深变化 | 接触点细节清楚，后方桁架合并成三块低对比形体 |
| 6 受控细节 | 当前镜距可见且有归属的细节 | 划擦边缘少量露底，其他甲板保持连续大面 |
| 7 负向卫生 | 简短当前风险约束 | 避免错接肢体、统一塑料高光和重复微格 |

Hero surface 句式：`The [material] shows [response] under [source], with [local wear] at [visible scale]; [flat area] stays [matte/absorbing] while [edge] catches [highlight width/direction].` 必须用实际材料和部位填完，不以“物理正确”四字代替。

材质描述仍不具体时，在这一步进入[视觉与材质库](116-visual-reference-library.md)和 assets A5：锁实际物件、媒介、光源与镜距，再查局部条目。第4步写光源和表面差异，第6步限定可见尺度，完整 prompt 同步展开；不能仅添“丝绸”“PBR”或条目编号。已批准身份、颜色、干湿、磨损与风格锁不由资料库改写。关键帧按当前单一相位使用，不提前带入之后的损坏。

## 六项主配方与两个附加配方

下面六项是本版面向影视资产的主路由；原库还含商品／海报配方和 clean-slate 清洗模板，因此总资源不只六条。每个分支继承七步顺序，不能只复制最后的清洁词。

### 人像

锁定颅面转折、视线与同一身份，皮肤哑光主体上保留柔和高光，耳缘透光仅在光源支持处出现。微纹理只在当前近景分辨率可读的鼻翼和面颊，不在远景刷满毛孔。发丝合并成束，细丝留在受光边缘，衣料纹理随褶皱。焦点为脸与手势，背景保留安静色面。避免蜡皮、面部残影、重复毛孔噪点。

### 暗黑夜戏

先指出主光和可读暗部最低层，再把黑衣、黑金属、暗墙用高光宽度、色值和边缘差异分开。小范围轮廓光必须来自已有源，地面只在局部湿区反射。背景不铺满散景亮点和雾。失败时先修暗部层级，不提升全局曝光到灰。

### 奇幻高密

锁 3–7 个大形群与一至两个焦点簇，主体机制清楚后再配置符纹和结构。远处塔、云、山的内部细节递减，保留地标轮廓。石、金属、布、皮肤分别定义响应。纹样只在焦点法器或受力部位可读；不能满屏微型符号。

### 载具／硬表面

先轮廓、板厚、接缝、轮／足接地和承载。哑光与半光泽甲板依靠粗糙度和高光宽度区分，磨损只在手、足、气流、路面或真实碰撞区域。检修盖有铰链或拆装界面，管线有入口出口；不能用随机机械碎件掩盖功能断链。

### 国风水墨

指定干笔／湿墨边界、浓淡关系、留白和选定笔触方向。形体由轮廓、墨色面积和叠压表达；材质差异转译为吸墨、飞白和边缘软硬，不强塞照片镜面、PBR 参数或胶片颗粒。剑气连续笔势作为主干，墨滴仅在边缘出现。

### 同色调材质分离

同样黑色的皮革、钢板、布料，分别用柔和半光泽、窄方向高光、宽吸光面区分；再用接触阴影、温度微差和深度对比补足。不要为了可读擅自新增红蓝色块，不给所有物件描黑边。

### 商品／海报附加支路

保护文字／标识区域、结构比例和留白；英雄表面留真实细节，反射有视点与粗糙度依据，印刷或布局以确定性合成保证。这个分支不自动用于剧情关键帧。

### clean-slate 白板重建

当失败图已有残影、暗水印、重复纹理，回到干净已确认的身份／结构参考重写：保持主体、姿态、构图、媒介和色板，重建 3–7 个大形、材料分离、高光滚降和静音区。不能把失败图连续图生图十次堆出更重残留。“白板”指干净输入基线，不指必须白色背景。

完整英文配方保留在 [clean-prompt-recipes](sources/im2/references/clean-prompt-recipes.md)。

## 重场景四类结构锁与八变量排错

四类锁：相机／裁切／地平线；固定地标／开口／通行拓扑；前中后景占位／遮挡；板厚／支撑／地面接触／重心。源图不可见部位写 unknown，不假定背面结构。

| 真实失败 | 单次改动 | 冻结 |
|---|---|---|
| 地标漂移 | 一个地标的位置／数量锁 | 其余结构、材质、风格 |
| 开口像贴纸 | 现有开口内外值差 | 几何、全局曝光 |
| 支撑漂浮 | 实际接触处的接触影 | 轮廓、主光 |
| 荷载接头读不清 | 接头掠光或边缘分离 | 相机与承重结构 |
| 大面变鱼鳞 | 降低非焦点纹理频率 | 结构、色板、主光 |
| 全部像塑料 | 材料间粗糙度／高光宽度差 | 材料种类和主体比例 |
| 质量感变死黑 | 暗部最低可读层 | 厚度、光向、主体 |
| 接缝脏晕 | 限定 AO 至真实接触处 | 纹理、轮廓、颜色 |

每轮记录 source hash、失败证据、仅改变的一项、冻结项、实际模型设置、结果与剩余缺陷。这是八类诊断变量，不是必须运行八次昂贵生成。付费调用仍需当前任务授权。

## 负向卫生

【无文字无水印绝对红线】：所有资产图（四视图、场景图、道具图、关键帧）提示词末尾必须显式包含负向清洁约束：`Strict Clean Negative: no text, no words, no letters, no labels, no title text, no watermark, no signatures, no artist credits, no UI elements, no borders, clean background.` 生图 AI 极易在画面中擅自添加英文字母、设计图标题或水印标签，必须坚决杜绝。
先写清应出现的事实，再加少量当前风险类别。不能把旧失败角色、场所、武器、颜色塞入 no-list 反向召唤；不能正向写水墨，负向又禁 cartoon。需要同一角色时重新描述具体脸、体型和衣服，并绑定已确认身份图；“单一已登记身份”或“同脸骨相”本身不能作为最终身份描述。需要空手时写“可见空掌”；不要靠长串不相关禁词。保留 [完整负向卫生规范](sources/im2/references/negative-prompt-hygiene.md)。

## 五种场景／关键帧工作模式

STYLE MOTHER 建画法、材料和光色响应；ESTABLISHING 锁地点、地标、入口和世界光位；NARRATIVE 捕捉一个改变关系或认知的时刻；ACTION 选预备、接触或后分离的单一相位；CONTINUITY SERIES 按共同 VisualBible 产生逐镜组。原版标题称“四种”却列五种，本版统一为五种。

角色基准图中立，不消费剧情表情；关键帧只选 EX 一个相位，不把十秒表演压成五个同时动作。首尾帧若机位跨度大，先检查可达摄影路径和遮挡，不把“景别不得跨两级”当模型官方上限。

## 4×4 接触表完整合同

16 格从左到右、从上到下编号。每格从 production.shots 选一个 frame，注明 shot_id、姿态相位、相机、角色钉子、场景版本和可见道具。格数不决定切镜数；同一镜位的四个动作时刻保持该镜头摄影连续。

图像总画幅与单格画幅保持一致：四列四行等尺寸网格在无边距时继承同一宽高比；若单格 2.39:1，总图不能无说明地写 16:9，需另计边距和标题区域。编号放在格外边条，实际模型输入可裁单格；如输入整表，Ref2VA 明确它只控制分镜规划，输出是单一全屏视频，不能把网格纹理带入成片。

本包 contact-sheet 工具生成确定性灰模图及 PNG，角色块只代表位置和方向，不能当面部真值源。完整资产图提示词仍需七步法；实际图片生成未执行时明确记录状态。生成后核对 16 格没有合并、缺格、重号和错误切镜；文本提示“有16格”不能代替检查。


## 风格母图锚定参考在提示词中的注入标准与上传参考助手（Style Anchor Injection & Upload Assistant）

> **关键原则**：生图模型（如 GPT Image 2/2.5、Midjourney、Stable Diffusion 等）**无法理解抽象工程名称（如 `STYLE_MOTHER`）**，只能识别用户在交互界面中实际上传的图片标号（如 `@图片1`、`Reference image 1`）。  
> 因此，在生成每一项视觉资产图提示词时，必须严格遵守两项交付要求：
> 1. **资产图制作处必须附带【上传参考助手（Upload Assistant Guide）】**：清晰说明当前资产需上传几张参考图、每张图对应真实文件是什么、在提示词中对应 `@图片几`、各自的用途/保留项/排除项。
> 2. **提示词正文中必须使用生图 AI 可执行的标记**：显式写出 `参考@图片1（Reference image 1）`，并限定其只作为艺术风格参考，排除主体与几何污染。

### 上传参考助手标准卡格式

在交付每一个资产图提示词时，必须附带如下说明卡：

```markdown
### 📋 资产上传参考助手（Upload Assistant Guide）
- **本资产需上传参考图总数**：1 张（或多张）
- **槽位 1 / 提示词对应 `@图片1` (Reference image 1)**：
  - 必须上传文件：`STYLE_MOTHER.png`（风格母图）
  - 角色用途：`style`（视觉艺术风格与材质质感锚点）
  - 必须保留：媒介画风、线条质感、阴影分层、色板基调、材质响应、空气透视
  - 禁止继承：禁止继承母图的人物外貌、构图与环境几何
- **槽位 2 / 提示词对应 `@图片2` (Reference image 2)**（若为姿势/变体/关键帧）：
  - 必须上传文件：`CHAR_LU_WUJIU.png`（角色身份基准板）
  - 角色用途：`identity`（锁定人物脸型五官、体型骨架与装备）
```

### 提示词内风格锚定正文标准结构（中英文兼容）

```text
[Visual Style Anchor (视觉风格参考)]:
Use Reference image 1 (@图片1) as the authoritative visual style and artistic rendering anchor.
- PRESERVE FROM @图片1: Inherit the exact visual medium ([e.g. 2D anime cel / Hong Kong wuxia ink-brush]), line edge dynamics, shadow hierarchy, color palette balance, surface material response, and atmospheric depth.
- EXCLUDE FROM @图片1: Do NOT inherit any character identity, facial features, clothing details, scene geometry, camera layout, or pose from @图片1. Apply only the artistic rendering texture to this subject.
```
## 关键帧多图联动参考与上传助手规范（Keyframe Multi-Reference Guide）

关键帧（Keyframe）是一场戏剧化情节的瞬间定格，**绝对不能只引用单一风格图**！必须视场景、角色与道具的实际剧情需要，进行多图联动参考组合：

1. **组合逻辑视情况而定**：
   - 槽位 1 / 提示词 `@图片1` (Reference image 1)：`STYLE_MOTHER`（风格母图）——锁定全局艺术媒介、线条笔触、光色基调与空气透视；
   - 槽位 2 / 提示词 `@图片2` (Reference image 2)：`SCENE_xxx`（场景图）——锁定空间透视、建筑地标、开口与光路拓扑；
   - 槽位 3 / 提示词 `@图片3` (Reference image 3)：`CHAR_xxx`（角色 A 四视图）——锁定该角色的脸型五官、发型、体型与服装；
   - 槽位 4 / 提示词 `@图片4` (Reference image 4)：`CHAR_yyy`（角色 B 四视图）——若为对手戏，锁定另一角色的五官与服装；
   - 槽位 5 / 提示词 `@图片5` (Reference image 5)：`PROP_zzz`（核心道具图）——若本瞬间发生武器交锋或道具争夺，锁定该道具的外观机理。

2. **必须配套关键帧上传参考助手说明**：
   在输出每一个关键帧提示词时，必须在提示词上方输出清晰的上传指引卡，明确列出槽位 1~N 对应 `@图片1`~`@图片N` 的文件、用途、保留项与排除项。

3. **提示词正文必须使用生图 AI 可执行的标记**：
   生图 AI 无法理解抽象文件名称，必须在正文中明确指派 `@图片1`、`@图片2`、`@图片3` 的分工：
   - 声明：`参考@图片1的画风质感，参考@图片2的场景空间，参考@图片3的人物外貌...`
   - 结尾必须严格声明：`无文字、无水印、无标签（No text, no watermark, no labels）`。
