# 动作与打斗编译器

在打斗、追逐、坠落、逃生、体育、舞蹈、复杂递物/争夺、强环境交互，或普通文戏需要更清楚的动作因果时读取本文件。本文只提供动作语法，不改变 `00-visual-contract.md` 的固定画风。

## 核心原则

不要只写动作结果，要写结果如何发生。每个有效动作至少回答：谁从什么状态出发、以什么意图沿什么路径行动、接触或被处理的位置、人物与环境结果、尾态如何引出下一拍。

高动态不等于全程高速。可读性来自重心、轨迹、接触点、节奏落差、空间交换和余波。

## 动作拍合同

复杂打戏使用以下内部结构；没有证据的字段不要虚构致命伤或新能力：

```yaml
action_beat:
  id:
  attacker:
  attack_type:
  target:
  target_point:
  attack_intent:
  path:
  force_chain:
  defender_initial_state:
  response:
  contact_or_miss:
  character_result:
  environment_result:
  spatial_exchange:
  state_transition:
  next_beat_authority:
  visible_residual:
```

把它压缩成“一攻 → 一应 → 一果 → 一续”：

- 一攻：发起者、攻击类型、对象、目标点、攻击意图、路径和发力链；
- 一应：被攻击者起始状态、可达的应对方式和受力/导偏路径；
- 一果：命中、擦过、格挡、导偏或落空，以及人物结果和环境反馈；
- 一续：双方新位置、新状态与下一拍主动权。

## 发力链与接触

使用最短可信链条：

```text
支撑点/重心 -> 膝胯/躯干旋转 -> 肩臂/手腕/武器 -> 目标点/接触点 -> 反作用力
```

只写画面能辨认、会改变轨迹的环节。拳、脚、武器或投掷物必须有明确方向和目标点；格挡要写接触面、导偏方向和防守者如何稳住重心。攻击落空时写清为什么落空、最终打到哪里以及产生什么破绽，不能让动量凭空消失。

避免解剖过度和危险教程化细节。描述影视动作的可见力学与虚构结果，不给现实伤害操作建议。

## 空间拓扑

每场动作先建立：

- 核心轴线与双方屏幕方向；
- 起始距离、内外圈和高差；
- 路线、障碍、掩体和运动出口；
- 每拍结束后的双方坐标、朝向、武器手和视线；
- 角色入画/出画原因。

空间交换必须通过脚步、让线、贴身入圈、绕行、跳跃、遮挡转场或明确镜头跨轴完成。角色不在当前镜头时不要继续描述其姿态；远端角色仍在画面时保留体型比例、朝向和武器状态。

巨大/微小角色使用环境尺度参照，避免镜头切换后体型漂移。上一拍尾态必须成为下一拍起始状态，除非剧本明确瞬移或跳时。

## 节奏层次

从实际需要中选取相位，不强制每段齐全：

```text
观察/压迫 -> 微动作预备 -> 加速/接敌 -> 接触前可读点 ->
碰撞或轨迹改变 -> 极短停顿 -> 分离/回正 -> 余波/下一轮准备
```

- 预备让观众读懂意图；
- 加速体现位移和惯性；
- 接触点或导偏点保持清楚；
- 极短停顿只服务强碰撞或重要决定，不滥用冻结；
- 分离交代结果和新的攻守关系；
- 结尾有后续时保留余势，不做无依据终结定格。

速度坡度、慢动作、冲击帧和运动模糊都必须绑定具体接触或轨迹变化。不要用“120fps”代替动作设计。

## 摄影绑定

每次运镜绑定一个动作锚点：脚掌蹬地、身体换位、手伸向物体、武器前缘、接触点、受击肩线、滑行终点或余波核心。

选择焦段和景别时先问观众需要读什么：

- 空间与路线：广角全景/中全景；
- 发力、应对与双方距离：中景/全身景；
- 接触点、手部和表演反应：近景/特写；
- 微观爆点：短暂插入镜头后立即回到空间关系。

镜头可跟随、侧移、推进、后撤或受控震动，但不要同时叠加多个相互竞争的运动。越轴必须通过可见绕行、中性镜头、遮挡或动作匹配完成。

## 环境与特效

环境反馈服从力、材质和时间：脚步压开积水，刀刃改变雨线，撞击使灰尘/碎屑沿受力方向移动，衣发稍后跟随惯性，重物落地后产生二次坠落和回声。

特效只写来源、形状、方向、强度、接触对象和消散结果。物理反馈优先于无因能量光；角色轮廓、关节、武器轨迹和接触结果始终可读。不要用满屏粒子、残影或爆光掩盖动作缺口。

## 文戏与其它桥段

文戏复用因果骨架，不复用攻击强度：

```text
意图/触发 -> 起始状态 -> 最小动作路径 -> 对方/物体反馈 ->
关系或物理状态变化 -> 下一拍话语权/行动权 -> 可见残留
```

| 场景 | 编译重点 |
|---|---|
| 对话交锋 | 视线对象、停顿、谁先移开、听者反应、谁获得下一句主动权 |
| 递物/拒收/夺物 | 手的起点与路径、物体朝向、接触点、对方应对、最终归属与距离 |
| 拥抱/推开 | 接近路线、重心、手臂接触、接受/僵住/挣脱、衣料与呼吸残留 |
| 开门/落座/起身 | 支撑点、身体转向、道具避让、落定状态与下一动作出口 |
| 行走/追逐 | 起步、路线、障碍、抵达场景、尾帧继续方向 |
| 环境桥段 | 风雨灯门等触发源、对人物/道具的具体作用和消退过程 |

表演节拍来自 `performance-adapter.md`。例如对话中的“攻击意图”应改写为沟通意图，“被攻击者起始状态”改写为听者起始状态，“结果”改写为关系、注意力或道具状态变化；不要把文戏写成肢体冲突。

## 声音与交付规格

动作声音写呼吸、脚步、衣料、破风、接触、材质碎裂、环境底噪和空间回声。BGM 继承上游声音合同；只有明确 `soundtrack_policy: no_bgm` 时才输出无 BGM。

`target_delivery_fps: 120` 与 `target_mastering_resolution: 8k` 只能作为后期交付意图，是非模型保证；它们不能替代清楚的运动轨迹、补帧逻辑、快门/运动模糊选择或实际输出参数。

## 压缩与质量门禁

时间不足时先删装饰性特效和重复运镜，再缩短不改变状态的过渡；保留一攻一应一果一续、关键表演节拍和尾态。

交付前检查：

- 每拍主语、对象、意图、目标点和路径清楚；
- 发力链、被攻击者起始状态和应对在物理上可达；
- 接触/落空结果与环境反馈一致；
- 空间交换、轴线、武器手、伤势和尺度连续；
- 下一拍主动权来自上一拍结果；
- 节奏有可读落差，不是连续模糊；
- 摄影服务动作锚点；
- 特效不遮挡轮廓、关节和接触点；
- 文戏只使用降阶因果语法；
- 固定画风没有被动作模板覆盖。
