# Seedance 2.0 视频提示词编译器

在已确认分镜、ShotSpec、关键帧和可选 `expression_handoff` 需要转换为最终视频提示词执行包时读取本文件。目标模型固定为 Seedance 2.0。

## 官方能力边界

Seedance 2.0 官方页面说明其统一音视频架构支持文本、图像、音频和视频输入，并可控制表演、光影与镜头运动。因此把参考素材职责、角色表演、镜头动作和声场放进同一执行包，但仍需避免互相冲突。需要复核时访问 [ByteDance Seedance 2.0](https://seed.bytedance.com/en/seedance2_0)。

不要在 Skill 中假设某个宿主界面的固定附件上限、时长或专用符号。执行时读取当前 Seedance 入口能力，再填写 `generation_clip_duration`、比例、生成模式和实际引用标签。

## 请求元数据

```yaml
video_request:
  model: Seedance 2.0
  production_total_duration: ""
  generation_clip_duration: ""
  aspect_ratio: ""
  mode: text_to_video | image_to_video | multimodal_reference
  soundtrack_policy: inherit | no_bgm | specified_music
  target_mastering_resolution: null
  target_delivery_fps: null
```

`production_total_duration` 原样继承上游剧本。单次生成只覆盖一个连续片段；超长作品通过多个片段拼接，不压缩剧情。`target_mastering_resolution` 与 `target_delivery_fps` 是后期交付意图，不代表 Seedance 原生保证相应分辨率或帧率，不得写成已经实现的模型能力。

## 编译前输入

必须具备：

- 已确认的连续 storyboard 片段及全局唯一 `shot_id`；
- 片段绝对时间与相对时间映射；
- 每镜 ShotSpec 和前后镜头状态；
- 当前片段实际使用的关键帧及时间锚点；
- 角色/道具参考（仅在关键帧不足以锁定身份时传入）；
- 声音合同；
- 可选 EX→shot 映射。

缺分镜时不根据关键帧脑补动作；缺关键帧时按当前生产合同决定返回 frame 阶段，而不是静默退化；缺 `expression_handoff` 时只编译剧本已有可见动作并标记 `performance_input: screenplay_only`。

## 编译结构

按以下顺序输出：

1. `video_request` 元数据；
2. 参考素材列表和每项职责；
3. 全局不变量；
4. 连续动态时间线；
5. 表演/动作/摄影协同；
6. 台词、现场声和音乐策略；
7. 连续性与排除项；
8. 交付意图与未保证项。

### 参考素材

使用当前宿主实际提供的 `@图片N`、`@视频N`、`@音频N` 或等价标签，不创造不存在的语法。逐项声明：文件/资产 ID、职责、时间锚点、必须继承和不得继承的内容。

关键帧承担构图、身份、场景、道具状态与光位；文字仍需写清动作如何从上一锚点到下一锚点。不要逐字复述整张图，也不要只说“参考图片自然运动”。

### 全局不变量

只写整段始终不变的内容：

- 固定 cinematic 画风 DNA；
- 角色身份、体型、服装结构、武器和命名；
- 场景地标、世界光向、天气和轴线；
- 音乐策略与不可出现的文字；
- 本片段必须锁定的损伤、道具和环境状态。

局部动态信息不要在全局段提前堆叠，也不要在每个时间段重复全部不变量。

## 连续时间线

覆盖 `0.0s` 到 `generation_clip_duration`，时间段首尾相连且总和准确。普通叙事使用能表达清楚的 0.5–2 秒粒度；只有接触点、泄露瞬间、冲击帧或精确台词锚点需要 0.1 秒级划分。过细时间码会制造相互竞争的指令。

每段按需要填写：

```text
[时间段｜shot_id｜expression_beat_ids]
当前场景与位置：
起始状态：
触发/意图：
主体动作与对象反馈：
表演相位：
摄影与焦点：
环境/材质反馈：
声音：
尾态与下一段承接：
```

省略本段不需要的字段，不输出空标签。镜头切换、视角切换或越轴必须有视觉动机和承接方式。

## 表演编译

有 EX 映射时读取 `performance-adapter.md`，按下列顺序展开：

```text
state_in -> trigger -> leakage -> control_action -> residual -> continuity_out
```

- `prompt_ready_zh` 是首选动作底稿；按 `timing`、本镜头时间、景别和对象裁剪。
- `internal_state` 只解释选择，绝不直接写入画面。
- `visibility` 决定可用通道；远景不用眼睑/嘴角特写。
- `exclusions` 转入对应时间段或结尾限制。
- 多个 EX ID 分别标注人物和先后，不能写成同时发生的表情清单。
- 关键帧的 `selected_phase` 只是时间锚点；视频仍需生成相位之前和之后的连续过渡。

## 动作与摄影编译

普通动作也写起始状态、路径、接触/反馈和尾态。打斗、追逐、坠落、复杂群体调度或强环境交互必须再读取 `action-choreography-compiler.md`。

让摄影绑定动作锚点：跟随脚掌蹬地、手伸向道具、视线转移、武器接触、身体换位或环境结果。主体静止时镜头可移动；主体高速运动时不要同时堆叠无关的环绕、甩镜和变焦。始终说明画面主焦点、运动方向和镜头结束时的空间关系。

## 声音

Seedance 2.0 支持音视频联合生成，因此明确：

- 台词人物、对象、语气、时间段和口型可见条件；
- 呼吸、脚步、衣料、武器、碰撞、环境底噪和空间混响；
- `soundtrack_policy: inherit` 时服从上游声音合同；
- `no_bgm` 只在用户或上游明确要求时使用；
- `specified_music` 写清音乐进入/退出位置，不用音乐掩盖动作节奏。

官方展示同时存在 “no music” 和有背景音乐的示例，因此不得把无 BGM 当作模型通用默认。

## 连续性与排除项

结尾集中写最少必要硬约束：

- 人脸、体型、服装、武器、道具结构不漂移；
- 轴线、地标、世界光向、损伤和持有状态连续；
- 手、武器、接触点和地面关系清楚，无穿模；
- 没有用户要求时不生成字幕、文字、Logo、水印；
- 不出现无关角色、无因特效和无因环境破坏；
- 每张关键帧在声明的时间点被经过，不强迫整个视频冻结成静帧。

## 压缩规则

发生 token 或时长压力时按顺序压缩：

1. 删除重复画风与资产描述；
2. 合并同一动作的相邻时间段；
3. 删除不改变状态的装饰性微动作；
4. 减少非关键环境粒子；
5. 保留剧情因果、EX 顺序、接触结果、台词和尾态。

不得通过删除防守者应对、动作结果、表演控制相位或连续性状态来“压缩”。

## 交付门禁

- 相对时间完整覆盖单次生成片段；
- 每段能追溯到 `shot_id`，有表演时还能追溯到 EX ID；
- 参考素材职责互不冲突；
- 表演顺序、动作因果、镜头运动和声音同步；
- 总时长与单次生成时长没有混淆；
- 8K/120fps 只在交付意图中出现，并明确不是模型保证；
- 最终提示词只包含 Seedance 2.0 所需信息，没有其它模型或节点术语。
