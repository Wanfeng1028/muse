# v3.2 规范冲突裁决

本报告记录本轮对主 Skill、H3 基础指南、全参考指南、原盛唐资产规则和红猴子来源结构的统一裁决。历史来源原文保留，不把旧格式直接当成当前输出合同。

| 冲突 | 采用规则 | 原因与边界 |
|---|---|---|
| H3 固定三字段／六字段 vs. “多加负向字段更详细” | 仍只输出基础模式三字段或 Ref2VA 六字段；详尽要求写进各字段正文和每镜独立指令 | 保持已安装 `h3-prompt-writing` 的字段顺序，避免模型把自创字段当成输入参数 |
| 第一镜完整上下文、后镜只写动作 vs. 独立生成请求 | 每个镜头重新写主体外观、屏幕位置、场景地标、光线、初态、触发、动作反应、摄影机、声音和尾态 | 每段、每镜都可能被单独提交；上下文不能依赖上一镜或聊天记录 |
| `expression_handoff` 来源事实 vs. `acting_design` 镜头表现 | handoff 只拥有来源、锚点和排除项；acting_design 只把已确认事实变成可见动作、对白节拍和切点承接 | 防止表演支路改写剧情，也防止上游抽象情绪直接泄漏给模型 |
| 资产摘要 vs. 完整 GPT Image Prompt | `ASSET_NAMES.txt` 只展示资产名和可选 `state_version`／`asset_version`；`.image.txt` 保留完整自然语言正文；`UPLOAD.md`／`index.json` 保留参考图和状态 | 用户可见资产结果不被“提示词：”“状态：”“参考图：”干扰，同时不丢失可执行上传信息 |
| 盛唐固定画风 vs. 通用导演引擎 | 盛唐画风只在盛唐项目 brief 明确启用；通用项目从视觉总宪法和 brief 读取媒介、色彩、光路和材质 | 保留盛唐 skill 的资产依赖、命名、参考职责和独立 Prompt 原则，不污染其他题材 |
| GPT Image 参考图编号 vs. H3 `<Picture N>` 标签 | 图像正文使用实际上传顺序的 `Reference image N`；H3 使用指南规定的 `<Picture N>`／`<Subject N>` | 两套模型输入不是同一协议，禁止用 `[img0]`、资产 ID 或 H3 标签冒充真实上传 |
| 4–15 秒生成窗 vs. 示例固定时长 | 每段必须在当前适配器核实的 4–15 秒窗口内；示例可用 4、8、10、12、14 或 15 秒，不把 10 秒写成全局硬编码 | 时长是装箱约束，不是艺术规则；超窗必须在合法动作节点拆分 |
| 内部代号 vs. 模型正文 | 身材、人格、情绪、运镜、状态和资产 ID 只留在生产数据、索引和文件名；最终正文必须展开为年龄、比例、行为、机位、路径、速度、状态和后果 | 生成模型不会读取登记表或上一段提示词；未知代号必须报缺失，不能按字母猜 |

## 本轮可执行门

- H3 编译器为每个镜头写入独立详尽指令，并重新消费角色、场景和状态描述。
- H3 质量门拒绝未消费的角色／场景／初态，拒绝未使用的 Ref2VA Subject，并检查跨切对白来源完整性。
- 资产编译器生成名称纯净出口和完整执行清单；缺图仍标草案，不能假装可提交。
- 八套样例覆盖五种 H3 模式、动画／写实／喜剧／悬疑／巨构／动作等不同生产条件；真实出片质量仍需生成后人工验收。
