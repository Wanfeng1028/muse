# Acheng Director 4.3.8：功能消费链审查与修复

## 结论与评价

这个技能有真实工程价值，不能概括为“垃圾”。单一生产源、七个专业模块、按需素材库、分段输出、版本/哈希绑定、partial恢复和独立上传卡，都在解决长任务的信息丢失、输出上限、跨模块接力和引用歧义。问题出在部分连接：有些字段被检查却没有进入正文；有些批准、依赖和完成状态可以互相矛盾；部分示例继承了不属于自己的剧情事实。只增加问题或规范无法修复这些断点。

本次保留这些工序的原意，修复实际连接，并把专业判断放在局部决策处。工序降低遗漏和接力成本，不会凭空提高模型推理上限；门禁证明限定范围内的事实，不能证明影片必然优秀。

审查覆盖主入口、七模块权属和读取路由、附属整合、结构化目录及原媒体、工作流状态/提交、资产链、镜头/表演/视效/场记字段消费、H3最终格式和联合交付，以及八个生产示例。证据来自代码与合同交叉检查、复现错误、直接受影响测试、实际离线编译和最终包验收；没有调用生成模型，也没有把原文附带的指令当作用户授权。

## 用户强调的三条链

| 链路 | 原来的真实缺口 | 本版处理 | 仍需人/宿主确认 |
|---|---|---|---|
| 风格母版→资产图 | apply_to_kinds可以漏掉实际类型；lock与节点可批准不同文件；图像正文可写“末槽风格图”却没绑定指定母版；draft参数曾允许缺风格政策进入资产导出 | required策略覆盖实际类型；批准状态、版本、文件、哈希一致；每项适用资产直接依赖母版，指定版本的style引用只能在最后槽；两个编译入口与验收共同检查 | 母版实际有无身份/构图污染；生成资产是否保持画风。没有生成图组时不填视觉PASS |
| 身份/场景/道具/风格→关键帧 | DAG只证明已声明的边一致，不证明该镜需要的素材都进了关键帧 | 从显式shot_ids、消费镜头或镜头entity_id定位目标，检查其实际required_assets进入直接依赖及编号引用；风格另守母版门 | 尚无ShotSpec的孤立图，只验证已声明引用；自然语言漏写的物件仍需主导演盘点 |
| 批准媒体→H3→上传卡 | 资产图解析器可静默覆盖冲突路径/哈希；视觉Subject可以误引Audio；不同RIFF媒体可混用；改正文并重算自己的哈希缺少源数据再编译核对 | 拒绝重复字段冲突；Subject只用Picture/Video；类型检查统一；正式H3/图像在带production的验收中重新编译并逐字比较；保留分类编号、逐镜范围、版本、保留/排除及缺项 | 本地绑定不是平台上传；容器基础签名不是完整解码或轨道确认；真实视听一致性需要实际媒体 |

实际发现并修正的示例：SERIAL_SHOT_01要求铅笔/纸签，但ART_KEYFRAME_01没有ART_STATIONERY参考；本版补齐节点依赖、第五槽参考与目标正文。图片清单、资产正文和镜头需求现在同源，不再只在报告中列一个道具名称。

H3不用机械上传全部生产资产：一个已批准关键帧可能承担人物、场景和姿态的综合来源；Subject只提取所需身份，reference的anchor_shot_ids约束帧姿态作用范围。四视图身份板不是单一剧情关键帧；STYLE_MOTHER也不是每段H3的强制附件。上传助手分别输出“制作资产图”和“制作视频段”的卡，二者编号域独立。

## 各工序为什么保留、由谁消费

| 功能 | 作用和接收端 | 接受证据/边界 |
|---|---|---|
| 剧本、多线、知情、铺垫/回收 | story与script_scenes约束角色选择，shots将当前节拍变为镜头，performance继承表演来源 | story_contract核对声明的覆盖和因果；整份剧情不用塞进每段H3 |
| 132运镜与白模视频 | shots读取少量相关运动，写camera路径、视轴、光学与时序，编译器展开实际运动 | ID/索引和源文件核对；白模用于运动/构图，不提供人物美术身份；无需每镜强制两方案辩论 |
| 表情与因果表演 | 触发→策略→可见泄漏→动作/语气→尾态写入performance及handoff | 原来源、可见性、动作单元/台词、连续状态合同；不强制每镜五轨全开 |
| 战斗五阶段与受力链 | 支撑、轨迹、接触、传递、回收和速度写入combat，最终进入逐镜正文 | 整数帧闭合、阶段因果字段；不编造牛顿值，不规定所有物种都从脚底发力 |
| 条件视效与巨构 | effects按features选择family、源点、遮挡/残留及尺度证据 | 无对应现象则N/A；OPTIMIZE保留冻结过程和结果；效果不能吞掉接触和主体 |
| 场景设计支路 | assets按场景设计请求读取外部方法，将批准结果写回原场景/资产卡 | 支路没有第二份写权限；不因存在一个能力就让所有项目全跑 |
| 七步图像与事务 | 七步组织主体、媒介、构图、光材、密度、细节、当前风险，完整prompt是模型实际消费正文 | 七步和change/preserve/rebuild先验证；采用的资料必须落入prompt，不能只留在计划栏 |
| 风格/身份/状态资产DAG | 指定真实版本与制作顺序，指导上游图到下游图再到视频输入 | 计划不是图像，批准不能由文件存在推断；版本改动沿impact传播 |
| H3五种模式 | model依据现有素材与模式锁，编译三字段或六字段、局部标签与逐字对白 | 真实文件、范围、标签、台词、声音和磁盘字节联合验收；缺素材不静默转T2VA |
| 动画88术语 | 选择与当前任务有关的条目，展开为时间窗、可见事实、布局和QA | 所选ID必须有展开证据，并进入H3；词条本身不增加事实、不保证表现 |
| 提问36卡/32场景 | 问题在决策前触发，提供已有输入、两个具体问题、条件分支、原owner字段和完成条件 | 不开新审批，不要求输出思维链，已有答案且输入未变就复用 |
| 材质/视觉31条目 | JSON检索小候选，Markdown解释选择，按写实/赛璐璐/水墨等媒介表达 | MAT/OPT编号必须转成当前物体、光照、距离下可见的描述；不把器材/大师名当保证 |
| 场记与归档 | 初态、事件、尾态和冷档案防止回合/镜头遗忘，参考state_guards约束时间窗 | ammo/trauma/damage/prop是机器回放域；空间、干湿、心理等需明确镜头描述，不能冒充已有通用物理仿真 |
| 分段、partial、commit | 对抗单次输出上限；保留完整文本、当前游标和依赖顺序 | 只接受无未决项的完整提交；partial不完成节点；恢复回读原字节和最新未完游标 |
| 顾问与整合库 | 摄影/图像/H3已内化；提示词分析、推理框架、冷热记忆、归档等按明确特征启用 | 整合记录无生产写权限；安全/发布顾问不替用户授权、不引入后台代理或付费调用 |
| 人类交付视图/上传卡 | 把同一manifest变成能操作的卡片，长正文保留完整文件 | 同源回读，缺槽位不重排，不把草案、图像生成完成和平台上传混为一谈 |

## 其他修复及明确保留的设计

- 工作流四项已复现错误：accepted=false或有未决项仍能推进；model可提交普通文件并绕过依赖；同一artifact从partial转complete失败；恢复时旧complete覆盖新partial游标。修复后，接受状态、依赖、节点身份、H3联合包、幂等字节和恢复游标均有验收。
- 规划器补齐storyboard/performance/action/continuity等已有入口的路由，并拒绝未知意图、未知段ID与伪造completed_nodes；局部vfx或纯场景任务不被强制拉入不相关镜头/表演制作。
- 补齐缺失写入路由：assets管理风格锁/政策数据，shots登记required_assets/required_prop_ids，model接收动画术语选择和展开。没有新增owner。
- 阶段回包检查自己的合同，明确记录推迟的下游检查；避免H3尚未完成阻止合格的上游回包。最终整体验收继续保留。script/assets的交付CLI补上真正的阶段合同，audit入口运行真实生产审计。
- 编译器补接原本只检查或部分遗漏的sensor_basis、shutter_angle、人物屏幕位置/朝向/视线/持物、表演可见性/承接、VFX源点、尺度证据位置、声源/低频及场记事件/持有人。内部道具名称经prompt_bindings展开，不输出管理ID或猜译。
- 喜剧/悬疑示例清除从文戏复制来的陆川/岑禾、黄铜钥匙交接、右腕伤势与不相符的镜头/动作事实，并在各自真实场面中重建动作单元、场景和持物状态。相关生成脚本与当前样例同步修正。
- 已确认result_revision的原设计：它是写入dispatch_log前的数据摘要，文档明确如此；后续请求再计算完整文件摘要。不把这个有明确定义的非自引用摘要误判为缺陷。
- 计划绑定production revision是刻意的安全边界。生产源改变后宿主重新规划剩余工作；提交器不能悄悄将旧产物升级为新事实。非model提交回执只证明文件完整，专业阶段检查回执仍需宿主执行。

## 资料库形态与不增加的负担

推荐当前混合结构：Markdown负责工作方法、局部问题和例子；JSON负责稳定ID、筛选、适用/排除、原文出处和字段落点；实际图片/视频负责视觉参照；Python负责结构和一致性门。两份用户原文完整保留并校验哈希，提取条目是可执行整理，不是全文塞进主入口。

没有必要将这个规模改成外部数据库，也不宜把一切降成大篇Markdown：前者增加部署和同步成本，后者失去结构化检索与同源生成。默认检索两条、最多四条；不问泛化的“如何更高级”，而问当前能做出决定的对象、时机、遮挡、光照或状态。没有触发的卡不执行。

原硬门保留：确认的时长/模式/对白、权限边界、单一owner、图像七步、战斗阶段、Ref2VA详细度、partial和真实回执。问题库不再强迫拒绝前两稿、每8–12秒反转、固定毫秒/毫米微动、所有效果固液气全开或把YAML自填PASS当事实。

## 验收证据和剩余边界

实际最终状态以[包验收](package-acceptance-v4.3.8-final.json)、[完整测试日志](tests-v4.3.8.txt)和[完整性报告](upgrade-integrity-v4.3.8.json)为准。[工作流错误复现](workflow-reproductions-v4.3.8.json)保存的是修复前表现，不是当前状态。

本次最终离线验收：87项测试通过，8套生产案例通过包合同检查；重新编译23段H3（21段可上传、2段因真实参考媒体缺失保留草案）和19份资产提示词（16份可提交、3份关键帧因前置素材待生成保留草案）。这些草案是预期的阻断示例，没有补假图片、降级模式或伪造批准。程序与引用连接的最终差异已复核；原始媒体及来源字节保留范围见完整性报告。

正向验收包括：图像/视频/音频同段绑定、真实白模视频与本地WAV的文件复制/分类编号/H3正文/上传卡回读，以及库条目进入图像和H3正文。负向验收包括：风格漏覆盖、批准文件冲突、关键帧漏人物/场景/道具、版本/状态冲突、Audio冒充视觉身份、错误RIFF类型、重算哈希但丢失源指令、缺依赖完成、partial恢复等。测试媒体只用于工程验收。

本版没有实测弱模型与强模型的出片差异，没有实拍/生成后的身份、表演、碰撞和声学验收，没有实时平台上传。技能可提供更清晰的决策路径与最低工程保证；“完美影视”“格式在任何平台绝对有效”“100%没有幻觉”都不能由该包证明。保留这些边界，才能避免自证清单反过来制造虚假的确定性。
