# Acheng Director 4.3.8｜完整用户使用指南

## 4.3.8：问题跟着决策走，材质跟着物件走

七个模块的原决策入口已接入36张专业问题卡，按触发条件读取；每张只解决一个具体缺口，给出两个局部问题、分支和原字段落点。不会要求每个镜头回答36题，也不会新增公开scratchpad、自证账本或全套审核循环。详细位置和取舍见[4.3.8说明](UPGRADE-4.3.8.md)。

材质资料采用[Markdown手册](references/116-visual-reference-library.md)说明用法、JSON保存31个视觉条目，其中7种材质有写实/赛璐璐/水墨适配。库里的文字不是参考图：人物身份图、场景图、关键帧、STYLE_MOTHER与H3引用仍需实际媒体、批准版本和原有绑定链。

按实际缺口查询，例如：

    python scripts/director_library.py questions --module shots --case C5
    python scripts/director_library.py visuals --medium ink --surface silk

也可直接说“保持当前人物、场景、动作和批准画风，按材质资料库补清本镜丝绸与金属的可见差异；写回原字段并回读独立资产与H3正文”。材料、光位和状态必须沿用项目事实；库条目不会自动变成新道具、风雨、磨损或平台上传证据。没有对应缺口就不查库。

## 4.3.7：局部专业引导与资产参考图接力

严格工序继续承担拆小推理任务、分批完整输出、记录版本、恢复续作和模块权属的工作；这些机制减轻单次任务压力，不保证突破底座模型能力。新增的[专业决策指南](references/115-directed-decisions.md)只在当前模块遇到对应问题时读取：先找已有输入，再按具体分支确定做法，写回原字段。无需把七份指南全读完、逐题作答或新增自证 YAML。

资料库保持原来的混合结构：Markdown 解释适用条件与取舍，JSON 提供可检索条目和稳定编号，图片／视频提供视觉证据，脚本验证可计算的合同。新增引导放在各模块的决策入口，不在每个字段旁重复问一遍。

独立资产包现在为每项资产提供 ASSET_ID.upload.md；H3 包附带的资产提示词则配 ASSET_ID.asset-upload.md。两者都复制真实参考图片，并列出原始编号、来源、版本、用途、保留／排除与缺项。人物四视图提供一个人物的身份，状态图只在适用时间使用，单幅关键帧提供指定时刻构图；整张接触表不能直接冒充一个首帧。资产生成编号与每段 H3 编号分别核对。

缺图时保留完整草案和缺失槽位，不把后面的图前移补号，不把提示词文件当图片。图片存在、格式签名和哈希一致只证明本地引用成立；平台上传与生成后画面质量仍需真实证据。

重新核验独立资产包：

    python scripts/asset_delivery.py output/assets-revision-01 --production production.json

返回码 0 为本地资产输入合同通过，2 为草案不可提交，1 为文件或合同错误。H3 联合校验也会核验附带资产映射；结果中的 asset_prompt_delivery 单独报告资产状态，H3 各段是否可上传仍以各段状态为准。修改输入、图片或正文后导出新目录，不手改旧验收记录。

## 4.3.6：拿到 H3 后怎么操作

每份 H3 都有同段的 `SEG.upload.md`、`.delivery.json` 绑定快照及正文验收文件。自动模式在聊天直接展示逐段操作卡，完整长正文留文件；不能只给总 UPLOAD 链接。交互模式只交当前一段的完整正文和卡，未完成时保留游标。

先看状态：`DRAFT_MISSING_REFERENCES` 要先生成/提供并批准素材；`READY_TO_UPLOAD` 表示本地版本与文件检查通过，仍需在实际平台上传并核对标签。`NOT_UPLOADED` 不能被本地文件存在或机器 PASS 自动升级。只有明确 T2VA 且没有引用需求时才是无需上传。

卡片逐项给出真实媒体链接或未绑定、版本、Subject/说话人、用途、Shot/帧窗、保留/排除和下一步。`.image.txt` 是生成素材的指令，不是图片；一图可以覆盖多个对象，不要求一物一图。改素材版本、正文或标签后重新编译新目录，不沿用旧回执。

详细数据示例与命令见[逐段参考绑定与联合交付](references/114-reference-binding-delivery-v4.3.6.md)。这次升级不改变动态词数、详细创作、动作/微表演、STYLE_MOTHER、132 运镜与白模、场景支路或真实媒体验收边界。

这份指南给用户直接复制提示词。模板中的 `[填写]` 换成你的项目内容；示例可以直接运行，也可以只替换题材、人物和场景。每次只选当前需要的模板，不要把所有模板一次粘贴给模型。

名称约定：用户简称是 **Acheng Director**，作者署名是 **Acheng**，技术包名和实际调用标识是 `$acheng-director`。在发布、引用或反馈问题时，可以写成“Acheng Director（acheng-director） by Acheng”，避免简称、包名和作者身份混淆。

Acheng Director 的原则是：主导演统一真值，专业模块各自负责自己的事实，最后由主导演合并。提示词越明确地写出目标、范围、冻结事实、需要的模块和交付物，结果越完整，也越少出现“同上”“根据需要调整”或把未生成媒体说成已完成的问题。

## 先写这四件事

任何请求开头先写：

1. 这次要做什么：剧本、分镜、表演、动作、资产、场景、VFX、H3、Seedance、续作还是审计。
2. 哪些事实已经锁定：对白、剧情结果、角色外观、场景几何、镜头时间、伤势、道具所有权和参考图。
3. 哪些事实允许原创：没有提供的角色、场景、道具、风格和声音。
4. 要什么交付：`prompt_only` 局部包，还是 `full_production` 完整生产包。

默认写上：

```text
不要调用付费媒体模型。没有真实图像、视频或音频时，不要声称已经生成；visual_status=UNVERIFIED。
每个资产和每个视频段都必须脱离聊天独立可用，不使用“同上”“沿用前段”“见角色设定”“根据需要调整”。
```

## 2. 剧本、分场和人物弧光

### 可填空模板

```text
调用 story 模块，执行 script/story 模式。

作品：[ ]
总时长或集数：[ ]
题材和终局约束：[ ]
角色：[姓名、关系、当下目标；没有就请原创]
已锁定对白：[逐字粘贴；没有就写无]
不能改变的事实：[ ]
希望强化的问题：[因果 / 人物选择 / 节奏 / 喜剧 / 悬疑 / 关系]

请输出：
1. 核心冲突和终局必须成立的事件；
2. 任意数量的剧情线，每拍标 primary_thread 和 secondary_threads；
3. 角色欲望、需要、误信、能力边界、关系债和可见行为证据；
4. 完整分场正文，包含起因、目标、阻力、选择、代价、结果、尾态和下一场原因；
```

## 12. MiniMax H3 视频提示词

涉及 H3 时必须加载 `h3-prompt-writing` skill。scene、story、shots、performance 只提供事实，model 负责按 H3 合同编译。

### 模式选择

| 模式 | 适用情况 |
| --- | --- |
| T2VA | 没有参考帧，只用文字建立完整时间线 |
| I2VA | 有真实首帧，从首帧继续向前发展 |
| FL2VA | 有真实首帧和尾帧，描述两帧之间的连续路径 |
| L2VA | 有真实尾帧，让动作从合理前态收束到尾帧 |
| Ref2VA | 多类真实参考，需定义 Subject/Picture/Video/Audio 角色 |

Ref2VA 是有真实参考文件时的模式；标签只对应真实上传文件，不能仅因有角色或场景定义就伪造参考标签。`detailed_description` 按时长与复杂度动态计算最低词数和目标词数：`minimum=max(2000, ceil(seconds×200))+complexity_addition`，`target=max(2400, ceil(seconds×240), minimum+200)`，极限值 2900 词硬性封顶（处于 2200-2900 词区间，剔除无上限输出）；默认 10 秒简单段最低 2,000、目标 2,400 个英文词。每个镜头都要展开主体外观、空间位置、朝向、光线、起始状态、触发事实、动作因果、微动作、微表情、接触／受力、相机路径、声音时序和尾态。若达到宿主单次输出上限，按字段和镜头续写并保留游标，不能摘要化、写“同上”或静默切换模式。

### 可填空模板

```text

Segment：[ ]，时长：[4–15 秒]
本段起始状态：[角色、位置、朝向、道具、场景、光线]
```

## H3 提示词模板的动态详细度补充

下面统一适用于本指南中的 H3 模板与示例：Ref2VA 只有在真实参考文件存在并实际上传时才可使用；没有真实素材时按输入走 T2VA/I2VA/FL2VA/L2VA，不能因为原创了角色和场景就伪造 `<Subject>` 或 `<Picture>` 文件来源。Ref2VA 详细正文按时长、复杂度动态计算词数，不要把默认数值当作所有片段的统一长度：

```text
默认最低英文词数 = max(2000, ceil(片段秒数 × 200)) + 复杂度加成
默认目标英文词数 = max(2400, ceil(片段秒数 × 240), 最低词数 + 200)
```

复杂度加成由 combat、VFX/巨构、对白、说话人数、镜头数和参考数量计算，最多 600 词。默认简单 10 秒段是最低 2,000、目标 2,400；时间或复杂度增加，预算随之增加。词数只作最低密度门，不是质量替代：不能重复空话填充，也不能删掉角色位置、朝向、微动作、微表情、动作因果、镜头路径、声音和尾态来凑数。实际生成仍要经过真实模型和媒体人工检查。


默认数字 1 是自动文件批处理，适合 Antigravity IDE 中一次提交后持续生成；聊天直接展示逐段上传操作卡，并附 manifest、文件与验收结果，完整正文在工作区文件中。若你希望在聊天窗口看到长 H3 并即时修改，选择数字 2。`/goal` 只表示目标会跨回合保存，不能把“完成全部”理解成一次回复。

可直接复制的完整 `/goal` 模板见 [110-goal-multi-turn-delivery-v4.md](references/110-goal-multi-turn-delivery-v4.md)。其中的“Antigravity IDE 默认自动文件批处理模板”适合选择 `1`；“Antigravity IDE 交互制作模板”适合选择 `2`。

如果选择自动文件批处理模式（数字 1），再补上：

```text
请将每个 Segment 写入独立 `.h3.txt` 或对应资产合同文件，逐份提交并记录 SHA-256、input_revision、状态和 current_cursor。聊天直接展示逐段上传操作卡，并附 manifest、文件与验收结果、路径、哈希、未决项和 visual_status，不重复粘贴长正文；无法写文件时暂停并如实报告。
```

## 18. 最终复制前检查

把下面清单贴给模型，要求它在交付前执行一次：

```text
交付前检查：
- 本次范围和未覆盖范围是否写清；
- 剧本是否有起因、选择、代价、结果和尾态；
- 每条剧情线、知情事件和伏笔是否有证据；
- 每个镜头是否有整数帧、相机位置、路径、方向、速度、切镜原因和尾态；
- 文戏是否写出目标、策略、潜台词、触发、预备、重音、跟随、收势和可见行为；
- 战斗是否写出方向事实、速度曲线、接触、受力、反作用和下一拍；
- 每个资产是否有独立 prompt、参考策略、上传清单、版本和状态；
- 场景是否有边界、入口、出口、地标、动线、材质、光线和尺度；
- VFX 是否有来源、作用域、过程、终态和遮挡/尺度证据；
- H3/Seedance 是否使用正确模式、字段顺序、真实参考标签和逐段完整定义；
- 连续性是否从真实基线重放，伤势、道具、场景损坏和天气是否守恒；
- 是否错误使用“同上”“沿用前段”“根据需要调整”；
- 是否把机器 PASS 或 READY_TO_SUBMIT 写成真实媒体已经生成或人工通过；
- visual_status 在没有真实媒体人工验收时是否仍为 UNVERIFIED。
```

## 19. 推荐的最短交互方式

如果你不确定该用哪个模板，先发这一段，Acheng Director 会自己生成能力触发图并继续：

```text
使用 $acheng-director。
我的目标是：[一句话写想完成的事情]。
已有事实：[粘贴剧本/角色/镜头/资产/参考图；没有就写无]。
允许原创：[ ]。
本次希望交付：[剧本 / 分镜 / 表演 / 动作 / 资产 / 场景 / VFX / H3 / Seedance / 连续性 / 审计]
请先判断需要哪些专业模块，说明每个模块的职责和不需要加载的模块，然后直接开始。
每个产物必须独立可用；没有真实媒体时 visual_status=UNVERIFIED；不调用付费生成。
```

### 完整示例

```text
使用 $acheng-director。
我的目标是：把“一个维修员在停电前把最后一辆车送过闸门”的想法做成 45 秒悬疑动画。
已有事实：只有这句话；没有角色、场景、参考图或对白。
允许原创：角色、场景、道具、风格、对白和声音，但结尾必须是车辆通过、维修员把控制权交给同伴。
本次希望交付：完整剧本、人物弧光、分镜、文戏表演、场景和角色资产、逐段 H3、上传清单、连续性和机器验收。
请先选择交付方式并判断专业模块，说明职责后按模式推进；不要固定七段。STYLE_MOTHER 按多资产合同触发，combat timing 按真实动作触发，H3 模式按需求锁定；缺素材保留草案，不能静默退回 T2VA。
```

这套用法能让宿主模型把创意、专业模块和生产合同接在一起：用户只提供自己的想法，Acheng Director 负责选择模块、保持权属、展开事实、交付独立提示词，并诚实报告尚未生成或尚未人工验收的部分。
