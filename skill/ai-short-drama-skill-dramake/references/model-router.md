# 模型路由

先按所需能力选模型，再比较执行入口、价格、队列和用户偏好。模型系列只是实测起点；当前参数页/API/UI 才是参数真相。产品发布页说明“模型家族能做什么”，具体入口 schema 决定“这次调用能传什么”，两者不得混用。

## 运行时能力解析器

每个新项目，或模型卡超过 14 天未核验时：

1. 从用户实际入口列出模型，解析精确 model ID；
2. 获取输入 schema、必填字段、枚举、互斥模式和 prompt 上限；
3. 核对时长、分辨率、画幅、帧率、音频、各类参考数量/总时长，以及输入视频是否挤占输出时长；
4. 核对计费单位、队列、异步轮询/任务找回、上传可见性与保存期限；
5. 入口支持时先 `dry_run`，再做一个代表性低成本请求；
6. 把文档能力与实测观察分开记录，并附日期和来源。

不得从另一聚合平台、旧截图或同系列旧版本迁移精确参数。入口未暴露的能力，本次视为不可用。

| 需求 | 首个测试路线 | 原因 | 重点检查 |
|---|---|---|---|
| 20–30 秒剧情段 | Wan 3 类长段 I2V/R2V | 外部接缝少，可用原生音画 | 后半段身份、解剖、服装与画风漂移 |
| 丰富图/视频/音频参考 | Seedance 2.5 类 R2V | 多模态、编辑/续写能力 | 成本与参考过载 |
| 参考声线/对白修复 | Seedance 2.5 类音频感知路线 | 声线和节奏可进入生成 | 核实纯音频/混合参考规则 |
| 4–15 秒对白/过渡 | Seedance 2.0 类 | 短段多模态较可控 | 长片外部接缝更多 |
| 低成本测试与备选 | Seedance 2.0 Fast 类 | 迭代快、成本低 | 不能免除终片质检 |
| 4–15 秒高运动/首尾帧 | MiniMax H3 类 I2V/R2V | 适合选择性重点镜头 | 普通镜头全部使用不经济 |
| 5–15 秒多镜头/元素绑定 | Kling 3 Omni 类 | 多镜头、元素绑定与关键帧桥接可减少外部调用 | 子镜头过载、入口差异、内部切镜不可控 |
| 静态母版/关键帧 | 高保真图像生成或编辑模型 | 先锁身份、几何、地点和文字底板 | 拼版复制、错误母版传播到视频 |

截至 2026-08 的正式能力资料显示：Wan 3 支持最长 30 秒、多模态参考与原生音频；Seedance 2.5 支持单次最长 30 秒、扩展、灵活参考与编辑；Seedance 2.0 论文披露 4–15 秒原生音画；MiniMax H3 发布资料披露最长 15 秒、原生立体声和最高 2K；Kling 3.0 系列公开强调多镜头与元素绑定。实际入口可能只开放其中一部分，因此仍以运行时参数为准。

## Wan 3 参考驱动对白长段

当当前入口确实开放 Wan 3 类 `reference-to-video`、混合图/视频/音频参考和原生音频时，可把它作为 20–30 秒双人或多角色连续表演的首测路线：

1. 为每个常驻角色准备独立身份/服装定妆图，并在提示词中明确 `Image 1 → 角色 A`、`Image 2 → 角色 B`；
2. 需要动作和材质控制时添加短视频参考，给它唯一职责，例如毛发质感、运动方式或整体摄影介质，不让一条素材同时控制所有维度；
3. 从每个角色的声线母版裁出一段干净、无音乐、无混响的入口兼容音频，明确 `Audio 1 → 角色 A`、`Audio 2 → 角色 B`，禁止交叉绑定；
4. 一次编排完整连续场景和多轮对白，不按句拆请求；用时间节拍写清谁说、同时做什么、谁反应、下一状态是什么；
5. 原生音频提示明确“只包含对白、动作拟音和场景环境，无非叙事背景音乐、无歌声”，终片再统一铺一条后期音乐并重建环境连续性。

参考素材表达的是控制意图，不是保证。定妆图意图锁身份/服装，视频意图锁动作/材质/介质，音频意图锁声线/语气/节奏；必须用真实输出做身份、声线、口型、台词和动作 A/B 验收。

截至 2026-08-25，Wan 3 官方接口资料明确支持参考图、参考视频和参考音频混合输入、最长 30 秒输出、原生音频开关、720P 与 16:9 等档位；但参考模式与 `first_frame`/`last_frame` 模式互斥。若输入参考视频，官方接口还要求“输入视频总时长 + 输出时长 ≤ 30 秒”，所以带视频参考时不能同时假设仍可输出满 30 秒。需要角色/声线/自然表演时优先测试 R2V；需要严格首尾构图时改用首帧/首尾帧路线，不能在同一请求里两者都要。其他执行入口必须重新核实相同约束。

## 提交前八问

1. 原生支持多长？
2. 能否同时接收人物母版和已验收状态帧？
3. 首尾帧模式是否与其他参考互斥？
4. 图、视频和音频参考角色是否明确？
5. 是否生成对白/音频，能否关闭随机音乐？
6. 是否支持尾帧、编辑、续写或口型？
7. 哪些分辨率是原生，哪些是放大？
8. 当前价格、队列、重试与素材保存规则是什么？

另查：精确 model ID 是否仍可用；异步任务如何找回；prompt/params/refs/schema 任一变化是否会使确认失效。

为每个可用路线建立可编辑 [model-card.yaml](../assets/templates/model-card.yaml)。未知参数使用保守配置，不猜。

## 执行入口可替换

同一模型可能存在官方产品、API、聚合入口、网页端或 MCP。创意清单只表达能力需求，入口适配信息留在运行文件：

```yaml
needs:
  duration_seconds: 30
  aspect_ratio: 9:16
  native_audio: true
  reference_images: 2
  reference_audio: 1
  first_frame: false
  last_frame: false
  reference_frame_mode_compatibility: exclusive
  edit_or_extend: preferred
```

然后选择当前可用且满足条件的入口，不把核心 Skill 锁定到单一服务。

## 实测不是保证

- 某次 2026-08 实测中，Wan 3 普通 30 秒输出包含 2–4 次内部变化，减少外部接缝，但仍需 4–6 个时间节拍；
- 同项目中，尾帧串联改善下一段开头，但未阻止后半段服装/解剖漂移；
- Seedance 2.0 系列短段的原生音频仍需要终片声音连续性后期。

记录模型、入口、日期、设置和证据，重复结果后再调整路由。

## 可复用的公开工程模式

- 先完成角色母版和静态故事板，再让视频负责运动；主观长镜头不机械套用“每节拍一张图”。
- 把单镜头、多提示内部切镜和首尾关键帧桥接视为不同生产模式。
- 每次调用保存 prompt、模型版本、参考、参数、耗时、费用和输出清单，形成可恢复审计链。
- 提交前预览精确请求；请求体变化重新确认；超时先查历史再重提。

这些方法必须用项目真实输出验证，不能因写入流程就视为质量保证。
