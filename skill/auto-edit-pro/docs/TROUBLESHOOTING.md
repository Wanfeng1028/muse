# 排障

[返回 README](../README.md) · [使用说明](USAGE.md) · [提交问题](https://github.com/cytxnyu/chuanyuntian-auto-edit-pro/issues)

## 助手没有识别到 Skill

确认完整仓库位于助手的 Skills 目录，安装目录可名为 `auto-edit-pro`，实际触发名为 `auto-edit-pro`，其中保留 `SKILL.md`、`references/`、`scripts/` 和 `packages/`。在仓库目录执行 `npm ci` 后新开会话，并使用 `$auto-edit-pro` 调用；只复制一个 Markdown 文件不足以运行。

## 找不到 ffmpeg 或 ffprobe

在运行 Skill 的同一个终端检查：

```bash
node --version
ffmpeg -version
ffprobe -version
```

推荐 Node.js 24 LTS；确保两个 FFmpeg 可执行程序均在 PATH 中。路径含空格或中文时为 CLI 参数加引号，不要在输出目录参数中遗漏引号。

## 没有 SRT，或台词与视频不同步

先寻找与当前剪辑版本对应的字幕，不用旧版时间码勉强套用。缺失时先提出转写、原话确认与时间轴校对方案，等用户确认后再转写；CLI 不内置语音识别。改变原片或 SRT 后需重新执行 Gate A 并审批，输入哈希变化不能沿用旧批准。

## 第一次生成审核帧需要下载浏览器

Remotion 使用配套 Chrome Headless Shell 渲染；首次运行可能需要下载。等待下载完成并确认网络可达，后续会复用缓存。不要把浏览器下载失败描述为视频内容错误。

## HEVC 原片在浏览器中不显示

CLI 会创建连续的 H.264/AAC 制作代理，保留原顺序和时间轴，不是二次剪辑。检查源片与代理时长、音画同步；代理及最终音频可能重新编码，不保证原始音频字节一致。

## 显示“Gate C requires eight distinct semantic structures”

当前通用 Gate C 从八种不同结构中各抽取节拍 72% 的稳定帧，结构不足会报错。这尤其影响短片；4 秒合成 fixture 只用于 Gate A 自测。

不要为凑数扩写台词、冒充八种结构或跳过审片。先在 Gate A 说明短片与规则的冲突，约定并实现工程级抽帧审核策略后再继续。安装中的通用规则不会自动切成“6 张稳定帧＋2 张交接帧”。

## 为什么 B 完成后直接生成审核帧

这是当前流程：用户批准 Gate A 后，Gate B 自动进入 Gate C，无需第二次 B 到 C 的批准。它不代表最终导出已获批。只有用户明确要求本次仅准备输入时才添加 `--gate-b-only`；最终仍需 Gate D 明确批准与 `--render`。

## 字幕出现两层

源视频已有固定字幕时使用 `--captions burned-in`。`generated` 是根据 SRT 再画一层文字，不会自动识别并移除原字幕。发生有意遮挡时用准确关键词短暂接棒，随后恢复连续字幕；不要叠加第三层完整台词。

## 人物遮挡或互动不自然

全屏舞台允许有目的地遮挡人物，检查的是语义、时长、可读性与退场，而非一律缩回侧边。真实手势必须对照源帧；人物前后穿插必须使用同机位、同时间轴的透明人物层，检查头发和手指边缘。

没有透明人物层时采用前景覆盖等可验证布局，不把普通半透明原片称作抠像。本仓库不提供自动抠像或自动手部跟踪。

## 文字溢出、信息太密或数字显得像权威结论

先调整组件内容、字号、尺寸与停留时间，查看实际渲染帧和运动片段。数字须保留来源、个人体验或估算归属；没有证据素材时用论点或示意结构，不编造结果截图、Logo、用户评价或产品功能。

## 1080p 渲染过慢或超时

默认并发为 2。可用 `--concurrency 1` 降低内存压力；确有必要时增大 `--timeout`（毫秒，默认 120000）。先排查浏览器、解码和缺失素材，避免只盲目提高并发。调整配置后仍须执行真实成片验证。

## 为什么 --fps 60 没有把合成输出变成 60 帧

合成模式从视频探测画布、帧率和时长；`--width`、`--height`、`--fps` 用于没有视频时的 SRT-only 画布。若确实需要另一个输出规格，先确定转码与字幕时间轴策略，以固定的新输入版本重新开始方案审核。

## 透明 MOV 显示黑底

某些播放器用黑色显示透明区域，不能仅凭播放器背景判断 Alpha 已丢失。核对 ProRes 4444、Alpha 像素格式、采样 Alpha 变化以及无音轨，在剪辑软件里与底片叠加核验。不要把只含全不透明像素的文件当作透明交付。

## HyperFrames 与全屏舞台配置不兼容

当前 HyperFrames 适配器仅支持 legacy 布局与风格；混合风格全屏舞台与 Gate C/D 走 Remotion。切换渲染器时使用新的输出目录并重新检查方案。可选项目依赖固定 GSAP CDN 构建，离线使用需准备对应本地脚本并验证实际加载。

## 反馈问题需要哪些内容

请提供系统、Node.js/FFmpeg 版本、使用命令、当前 Gate、必要媒体参数、报错日志和最小复现。上传前移除密钥、登录数据、本地账号路径及私人视频；可以先用 [合成示例](EXAMPLES.md) 排查环境。
