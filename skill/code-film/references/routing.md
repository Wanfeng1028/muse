# 接单与拆解：拿到任务先想清楚走哪条路

## 1. 先把任务翻译成一张任务卡

不管用户说得多随意，先在心里（或 `docs/brief.md` 开头）填这张卡。填不出来的格子，就是要问用户的问题。

```
片名 / 主题：
用途与平台：        （抖音、视频号、B 站、小红书、官网、发布会大屏、PPT 内嵌……）
画幅 / 分辨率 / 帧率：
目标时长：
观众是谁：          （他们原来知道什么，看完应该多知道什么、多感受到什么）
一句话立意：        （第 1 步再定，这里先留空）
输入素材：          （文案、音乐、图片、视频、截图、数据、Logo、品牌色）
可用工具：          （纯代码 / 配音 AI / 音乐 AI / 生图 / 生视频）
声音方案：          （旁白 / 纯音乐 / 音乐加音效 / 纯音效 / 静默）
风格倾向：          （参考链接、形容词、禁忌）
工作模式：          陪跑（默认）/ 全自动
```

## 2. 按输入类型选路径

**A. 只有一个主题或一句话**（最常见，也最考功力）
故事先行：`story.md` 全流程 → 立意 → 结构 → 文案 → 分镜。创意是这条路的瓶颈，按 `story.md` 的方法先发散出至少 10 个角度，再收敛。

**B. 已经有文案或旁白稿**
不要急着排版。先按句拆开，给每句标上「情绪值」和「这句要画什么」。发现有句子画不出来，说明它太抽象，要和用户商量改写，或者为它设计一个视觉比喻。有旁白时，时间轴由配音决定（`ai-assets.md` 的配音部分）。

**C. 已经有音乐**
音乐先行：跑 `scripts/analyze_music.py`，读 `music-edit.md`。音乐的段落就是片子的幕，能量曲线就是画面密度曲线。故事要贴着音乐的结构去写，而不是反过来。

**D. 有一堆素材（图片、视频、截图、Logo）**
先盘点：每个素材是什么、质量如何、能承担什么叙事功能（开场、证据、高潮、结尾）。再找一条能把它们串起来的线。素材不够撑起结构时，用代码画面补（文字、图形、数据）。

**E. 有数据**
数据片的故事是「一个洞察」，而不是「一堆图表」。先从数据里找出最反直觉、最有冲击力的一个结论，整部片子只为它服务。其他数据是铺垫或证据。

**F. 有产品、网页或 App**
结构通常是「痛点 → 转机 → 方案演示 → 结果/愿景 → 行动号召」。真实界面截图是最好的素材，用虚拟摄像机在界面上推拉，比重画一遍界面可信得多。

**G. 批量或模板化**（同一个模板要出很多条）
先把「会变的东西」抽成参数（名字、数字、图片、颜色），设计一个 schema，再做一个样片给用户确认，最后批量渲染。重点检查极端数据：超长的名字、0 和超大的数字、缺图。

**H. 长片（3 分钟以上）**
读 `long-form.md`。先做总纲和章节表，再做一个章节的「竖切样片」验证风格，最后铺开。

多种输入同时出现时，优先级：**配音 > 音乐 > 文案 > 素材 > 主题**。越靠前的越刚性，要以它为骨架。

## 3. 按可用工具选做法

| 可用工具 | 做法 |
|---|---|
| 只能写代码 | 读 `pure-code.md`。选代码天生擅长的风格：文字、几何、字符、数据、粒子、生成艺术。音效和配乐用脚本合成 |
| 有配音 AI | 逐句生成配音 → `media_durations.py` 排时间 → 画面贴着句子走 |
| 有音乐 AI | 先写好音乐提示词（结构、BPM、时长、情绪走向），生成 3 到 4 首，用 `analyze_music.py` 挑结构最贴合的 |
| 有生图 AI | 生成意象、背景、拼贴元素、质感图，用代码让它动起来（推拉、视差、遮罩） |
| 有生视频 AI | 只用它做代码做不了的镜头（真人、自然、写实），代码负责标题、排版、转场、调色统一和节奏 |

详细用法见 `ai-assets.md`。原则：**AI 负责质感，代码负责秩序。** 工具调用失败或额度不够时，不要卡住，退回纯代码方案，并告诉用户换掉了什么。

## 4. 该问什么，不该问什么

只问「答案不同，做法就完全不同」的问题。每个问题都附上你的推荐，让用户可以一句「按你的来」就过。

值得问的：
- 发在哪、什么画幅（决定构图、字号、安全区，事后改代价巨大）
- 要不要旁白（决定时间轴由谁驱动）
- 有没有现成的音乐、素材、品牌规范
- 时长（决定结构和镜头数）
- 有没有明确的风格参考或禁忌

不值得问的（直接用默认值，在策划书里写明即可）：
- 帧率（默认 30；电影感用 24；UI 演示、游戏感用 60）
- 具体配色、字体（风格帧环节会给用户看）
- 转场、运镜细节（分镜环节会给用户看）

## 5. 时长预算

先按结构比例分配时长，再按节奏估算镜头数。下面是常规节奏下的参考值，快节奏 PV 可以翻倍，抒情片减半。

| 总时长 | 镜头数 | 结构建议 |
|---|---|---|
| 6 到 15 秒 | 4 到 10 | 钩子、爆点、落版。基本就是一个完整的乐句 |
| 15 到 30 秒 | 8 到 15 | 钩子、展开、高潮、落版 |
| 30 到 60 秒 | 12 到 25 | 三幕或起承转合 |
| 1 到 3 分钟 | 25 到 60 | 三幕加若干小起伏，每 20 到 30 秒一个新刺激 |
| 3 分钟以上 | 按章节算 | 见 `long-form.md` |

平台常用规格：

| 场景 | 画幅 | 分辨率 |
|---|---|---|
| B 站、YouTube、官网、大屏 | 16:9 | 1920×1080（或 3840×2160） |
| 抖音、视频号、快手、Reels | 9:16 | 1080×1920 |
| 小红书 | 3:4 或 9:16 | 1080×1440 / 1080×1920 |
| 信息流方图 | 1:1 或 4:5 | 1080×1080 / 1080×1350 |
| 电影感宽银幕 | 2.39:1 | 1920×1080 画面上下加黑边，或 1920×804 |

9:16 竖屏的安全区（约数，各平台略有差别）：顶部约 200 到 250px、底部约 350 到 450px 会被标题栏、文案、进度条遮挡，右侧约 150px 有点赞评论按钮。**关键文字和主体放在中间偏上的区域。**

## 6. 拆解完成的标志

能用三句话讲给别人听：
1. 这是一部什么片子，给谁看，多长。
2. 它想让观众感受到或明白什么（一句话立意）。
3. 它靠什么驱动时间（配音、音乐，还是节拍网格），用什么风格，素材从哪来。

讲不出来，就回到第 1 节继续问或继续想。
