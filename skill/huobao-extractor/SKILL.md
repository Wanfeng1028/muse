# 角色场景道具提取

本 skill 面向单集剧本的资产抽取环节：从当前集文本中识别出真正参与叙事的角色、场景与道具，按规范整理成结构化字段，去重后写入项目资产库并自动建立与本集的关联。

## 角色提取规范

角色字段与 `save_dedup_characters` 工具参数逐项对应：

- **name**（必填）：角色全名
- **role**：角色定位，取值为主角/配角/龙套
- **appearance**：样貌描写，篇幅控制在 300-500 字，覆盖性别、年龄感、五官、体态、气质。角色的性格特点不单独成项，必须转译为可被画面捕捉的外在气质与神态，一并写进样貌描写。例如"性格冷峻"应落笔为"眼神冷峻、表情克制、少有笑意"。
- **styling**：妆造，包含发型、服装、妆面、配饰等
- **description**：背景故事与人物关系，属于可选补充项

## 场景提取规范

场景字段与 `save_dedup_scenes` 工具参数逐项对应：

- **location**（必填）：具体场所名称
- **time**：时间段，例如 白天/黄昏/深夜。同一地点落在不同时段时，按新场景处理
- **prompt**：场景描述，交代空间结构、陈设、年代质感与关键视觉元素，只写纯背景，画面中不出现人物
- **lighting**：场景光影，说明光源、色调、明暗关系与整体氛围

## 道具提取规范

**核心原则：宁可少提，不要多提。** 道具属于高成本资产，需要单独生成白底单品图并供视频特写引用，因此只有剧情关键道具才值得提取。单集通常落在 **0-3 个**区间；若候选超过 3 个，按剧情重要性排序，只保留前 3 个。

一个道具必须**同时满足**以下两条，缺一不可：

1. **直接推动剧情**：该物品的出现、交接、损坏或被发现会引发情节转折，例如凶器、信物、关键文件、定情礼物、关键证据。
2. **值得单独生成图片**：后续分镜会为其安排特写镜头或让其反复出现，外观需要固定下来。

**判定三问**：对每个候选道具依次自问，任何一问答案为"否"即放弃提取。

- ① 把它删掉，剧情是否依然成立？→ 若成立则**不提取**，它只是道具式背景板。
- ② 它是否只是角色随手使用的日常物品（手机、筷子、水杯、香烟、雨伞）？→ 若是则**不提取**。
- ③ 它是否属于场景陈设的一部分（桌椅、灯具、门窗、挂画、餐具）？→ 若是则**不提取**，这类内容归入场景描述。

**不算道具的典型情形**：随手使用但不影响剧情走向的普通物品；场景陈设与家具；仅被提及一次且再无下文的物品；角色的常规穿戴（应归入角色妆造）。

若本集没有任何道具满足条件，**不要强行提取**，调用 `save_dedup_props` 时传入空数组即可。

道具字段与 `save_dedup_props` 工具参数逐项对应：

- **name**（必填）：道具名
- **type**：类型，例如 日常/武器/交通/装饰/文件
- **description**：物品外貌，只描写物品自身的物理外观，包括材质、颜色、形状、大小、新旧程度、磨损痕迹等；不要写剧情用途，也不要牵扯与角色或其他事物的关联

道具**不需要输出图片提示词**——道具的最终提示词由提示词生成 Agent 在生图前专门产出（白底单品规范）。

## 使用步骤

1. 调用 `read_script_for_extraction` 读取当前集剧本
2. 调用 `read_existing_characters` 查看项目已有角色以及当前集已关联角色
3. 调用 `read_existing_scenes` 查看项目已有场景以及当前集已关联场景
4. 调用 `read_existing_props` 查看项目已有道具以及当前集已关联道具
5. 只提取当前集真实涉及的角色、场景和道具
6. 调用 `save_dedup_characters` 保存角色，同时自动关联到当前集
7. 调用 `save_dedup_scenes` 保存场景，同时自动关联到当前集
8. 调用 `save_dedup_props` 保存道具，同时自动关联到当前集

## 当前集规则

- 工作目标是补齐"当前集"所需的角色、场景和道具，而非重扫整个项目
- 若某资产已存在于项目中但尚未关联到当前集，仍应复用该资产并把它关联到当前集
- 去重规则：角色与道具按名称精确匹配，场景按【地点+时间段】精确匹配；命中已有记录时优先复用，不要重复创建
- 近名去重：名称中带括号定位或别名时，按括号前的主体进行比较，例如「林小雨（主角）」与「林小雨」视为同一角色/道具，复用已有记录；`read_existing_characters` / `read_existing_props` 返回的 normalized_name 即归一化后的名字，场景的 normalized_location 同理，据此判断即可
