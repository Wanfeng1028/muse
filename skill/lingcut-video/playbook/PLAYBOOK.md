## 二、提示词技巧 ★ 这是质量的主要来源

> ### 🚨 范式警告（2026-09-30 重大更正）
>
> **LingCut 视频节点的底层模型是 MiniMax H3（海螺）**，有**官方固定语法**，
> 与 Seedance 2.0 的写法**互不兼容**。
>
> **正确做法：读 `references/H3-OFFICIAL.md`（109KB，官方字段完整覆盖），用 H3 范式。**
>
> 本节 2.1~2.6 是早期按 Seedance 范式写的，**已作废但保留**（踩坑记录）。
> **H3 要点见下方 2.0-H。**

### 2.0-H ★ H3 官方范式（当前唯一正确写法）

#### 三种模式，按连了几张参考图选

| 模式 | 何时用 | 结构 |
|---|---|---|
| **I2VA** | **只连 1 张图**（就是首帧） | 固定首行 + **三段式** |
| **Ref2VA** | 连了**多张图 / 角色图 / 音频**（**我们的默认情况**） | 固定首行 + **六段式** |
| FL2VA / L2VA | 锁首尾帧 / 只锁尾帧 | 各自固定首行 + 三段式 |

> 官方原话：**「不要因为有一张角色参考图就机械地选 I2VA。若图片只定义人物身份、
> 并不是第 0 秒的具体画面，应使用 Ref2VA 的 `<Subject N>` 关系。」**
> → 我们连了「分镜图 + 角色图 (+ 音频)」，**默认走 Ref2VA 六段式**。

#### Ref2VA 六段式（字段名与顺序不可自创）

```text
subject_definitions:
<Subject 1> is ... shown in <Picture N>: ... <Picture N> defines his face, hairstyle, build, wardrobe only.
<Subject 2> is the ... shown in <Picture 1>: ... <Picture 1> defines the room layout, light and atmosphere only.
<Picture 1> is the first frame of [Shot 1]: ...
<Audio 1> is the voice-timbre reference for <Subject 1> (S1).        ← 仅在有台词时

summary:
[reference generation + keyframe completion + audio reference] ... No dialogue is spoken in this shot.

retention_analysis:
<Subject 1> (appears in [Shot 1]): fully_preserved - ... are retained.
<Picture 1> ([Shot 1] first frame): fully_preserved - ... are retained.
<Audio 1>: reference - used only for the voice timbre of <Subject 1>.

detailed_description:
The target video is live-action, cinematic, at 24 fps, lit by ...
[Shot 1] The shot begins from <Picture 1> and holds one ... shot. <Subject 1> ...
<Subject 1> (S1) says in a low, slow voice: <d>[Chinese] 台词原文。</d> He closes his mouth naturally and ...
The camera pushes in with small amplitude at slow speed and stops ...; no cut occurs.

overall_soundscape:
<1~4 句环境声/物理动作声/非语言人声。不重复台词>

non_diegetic_music:
N/A    （有配乐才写；1~3 句，只写乐器/速度/节奏）
```

#### I2VA 固定首行（只连一张图时）

```text
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.
```

#### ★ 与 Seedance 的三处硬冲突（第一版翻车的真正原因）

| 项 | Seedance 范式（错） | H3 官方（对） |
|---|---|---|
| **时间** | 废弃精确秒数，用「镜头N」 | **必须**：`[Shot 1]` 不带时间戳；后续 `[Shot 2] At 00:05.000, the camera cuts to ...` |
| **语言/字段** | 中文板块 `【声音】【约束】` | **英文字段名 + 固定顺序**；中文只留在 `<d>[Chinese] 台词</d>` 与画面可见文字里 |
| **负面约束** | 写「不要 XXX」 | **H3 没有 negative conditioning**，「不要…」等于没写；改用 `<Subject N>` 单职责声明 + `retention_analysis` 逐项 `fully_preserved` |

#### 其它 H3 硬规则

- **一个 `[Shot 1]` 写完一次连续表演**。切镜必须带来新信息（新主体/空间/状态/视角），
  「只是从中景变近景」优先用 `Push In`，别浪费一个 Cut。**4 个以上镜头是官方点名的高风险区。**
- 运镜写成**英文自然动作句**，格式 `类型 + 幅度 + 速度`：
  `The camera pushes in with small amplitude at slow speed toward ...`
  官方词表：`Zoom In/Out`、`Push In/Pull Out`、`Pan Left/Right`、`Truck Left/Right`、
  `Tilt Up/Down`、`Pedestal Up/Down`、`Arc Shot`、`Tracking Shot`、`Static Shot`、
  `Shake Slightly/Strongly`、`POV`、`Roll Clockwise/Counterclockwise`；
  幅度 `with small/large amplitude`；速度 `at slow/fast speed`。中等幅度与常速可省略。
- 说话人：发声者用稳定 `(S1)`/`(S2)`，**从不发声的人不分配 ID**。
  身份/动作/语气写在 `<d>` **外**；`<d>` **内只放语言标签 + 用户原始台词**，逐字保留不改写。
  台词说完要写 `closes his mouth naturally`。
- 画外旁白固定用 `says in an off-screen voiceover`，并紧跟 `while his lips remain completely closed`。
- 画面可见文字放英文双引号内，原文逐字保留。
- 风格词写在 `[Shot 1]` 开头：`Live-action` / `Cinematic` / `2D-animated` / `3D CG` /
  `claymation` / `watercolor` / `vintage film`。
- **不要**把时长、画幅、抽象情绪词（「克制的疲惫」）、项目管理式括号写进正文。

> 完整规范、12 条官方范例、失败修正表、生成前审计清单：
> **`references/H3-OFFICIAL.md`**（尤其第 1、2、5、6、9 节）。

#### ⚠️⚠️ 音频/对白：LingCut 网关的重大限制（实测，2026-09-30）

**结论：LingCut 的音频节点只是「音色/口型参考」，模型不会把参考音频混进输出。
而且一旦提示词里写了台词 + 连了音频参考，模型连自己的音轨都不生成了。**

五版对照实测（第 5 镜，同一分镜图与连线）：

| 版本 | 提示词写法 | 动态范围 | 峰值 | 结果 |
|---|---|---|---|---|
| v1 | 中文，**无台词** | 44.8 dB | -21.3 dB | 模型**自编台词**（剧本里没有的话） |
| **v2** | 中文 + `{}` 台词 | **44.1 dB** | **-20.8 dB** | 有声，但非我们的配音 |
| v3 | 英文 Ref2VA 长版 + `<d>` | 20.8 dB | -41.4 dB | 嘴在动，**几乎无声** |
| h3B | 英文 Ref2VA 紧凑版 | 4.9 dB | -50.7 dB | 全静音 |
| h3C | 中文正文 + 英文字段 | 13.4 dB | -41.1 dB | 仍近乎无声 |

**正确做法：对白由我们自己在后期按时间轴混进去。**

```bash
node scripts/mix-dialogue.mjs <输入.mp4> <输出.mp4> <cues.json>
# cues.json: [{"file":".../line05.mp3","at":21.7,"gainDb":4}, ...]
```
实测：v3 成片（20.8 dB / -41.4 dB）混入 2 句对白后 → **37.4 dB / -14.0 dB**，人声准确落在 21.7s 与 26.6s。

**所以流程是**：
1. 提示词里**照写台词**（让模型对口型）
2. 音频节点**照连**（音色/口型参考）
3. **成片后用 `mix-dialogue.mjs` 把 MiniMax 配音按时间轴混入** ← 这才是最终声音

> 附带好处：音色完全由我们的 `voice_id` 决定，跨镜头绝对一致，且不受模型乱说话影响。

### 2.0 总纲（第一版翻车的两条根因）—— ⚠️ 以下为 Seedance 范式，已作废

> **画面里不写情绪名词，只写动作链；台词必须嵌进提示词。**

❌ 第一版写法：`……动作缓慢，肩膀微塌，神情疲惫。`（情绪名词 + 定格 + 无时间轴 + **台词完全没进提示词**）
→ 结果：**面瘫脸**；且模型自己编台词（小女孩说了剧本里根本没有的「爷爷，可以收留我们吗」）。

✅ 正确写法：拆「镜头N」时间轴 + 箭头链动作 + 台词用 `{}` 嵌在对应镜头 + 明确要求余韵。

### 2.1 十条铁律（详见 PERFORMANCE.md 第 1 节）

1. 首句固定 `画面无任何字幕。`
2. 每条提示词**只设一个「第一优先级」**
3. 情绪写成链：`先…→ 随后…→ 接着…→ 最后…`
4. **通道错开**：`视线/眼睑 → 眉 → 嘴/下颌 → 呼吸 → 头 → 肩 → 手 → 声音`
5. **台词按镜头嵌入**，`{}` 标注；【声音】块只写音效不堆台词
6. **删负面词**，改正向（「画面中无 XXX」）
7. 抽象词量化（`梦幻 = 低饱和 + 软光源 + 长焦压缩`）
8. 词序 = 优先级：主体 → 光影 → 抽象
9. 一镜一运镜，**运镜动完必须停**
10. 别太干净：加前景遮挡、剪杂色、剪情绪词

### 2.2 角色一致性：必须"写死"外貌，不能只写名字

> ❌ **踩坑（2026-09-30）**：站点自带的剧本分析生成的分镜提示词里只有角色**名字**
> （"深夜老城区面馆，老陈，老陈把筷子…"），结果模型自由发挥——
> 剧本写"洗得发白的**蓝布**围裙"，出图是**浅色**围裙；"右手虎口旧疤"也没了。

**规则**：
1. 每个角色先写一份 `visual_prompt`，**颜色/材质/年龄/特征写死**（"靛蓝色棉布围裙"而不是"围裙"）。
2. 每一帧提示词里**重复**该角色的关键外貌词，不要只写名字。
3. 再把角色参考图**连线**给视频节点——文字 + 图像双重约束。
4. **一致性锚**：`全片锁定面部比例、发际线、虎口旧疤、棉袄与围裙`

> ⚠️ 官方实测：**不要用人物三视图做视频参考**（模型会把不同角度当成多个主体，反而加剧漂移）。
> 用**大头照 + 全身照**。

### 2.3 角色参考图提示词模板

```
电影级写实人物设定图，纯中性灰背景，全身正面立姿。<年龄><性别>，<职业>。
<发型>，<面部特征>，<眼神>。身穿<服装，颜色写死>，<配饰/围裙，颜色+磨损写死>。
<手部/特殊标记>。光线均匀柔和，无强烈阴影。
超写实，可见毛孔与皮肤纹理，胡茬/发丝长短不一，柯达胶片质感，细腻颗粒，8K 超清细节，全身构图，主体居中。
```
要点：**纯中性灰背景 + 全身 + 正面 + 均匀光**，最容易当参考图用。

### 2.4 分镜图 / 视频提示词模板

**完整模板见 `references/PERFORMANCE.md` 第 8 节**，骨架：

```
画面无任何字幕。
<地点><时间><风格>，<时长>，<画幅>，<整体基调>

镜头1（本镜第一优先级：<这一拍最想让观众看到什么>）
<景别>，<机位>，<1 种运镜>。<场景交代>。<角色外貌关键词逐字重复>。
<具体动作过程：写到手/腿/头/肩背，标幅度与速度>。
<光线：方向+软硬+色温+光比+阴影行为>。<皮肤毛发的可控不完美>。<同步音效 <>>

镜头2 …（视线→眉→唇/颌→呼吸，通道错开）
镜头3 <角色>（<语气>）：{<台词>} …（说完要有余韵）

【声音】【参考】【约束】【一致性】
画面稳定不闪烁、光影细腻、电影质感
```

**关键注意**：
- 官方已不推荐在通用场景写精确秒数 → **改用「镜头N」**；只有口型/TTS 对齐才留 `0-X秒`
- 素材别用满上限，**推荐 4~5 个**（角色图 1~2 + 场景图 1 + 音视频 1~2）
- 一段 15s 对白控制在 3~4 句；**LingCut 免费模型只有 5/8/10/12s，建议 1~2 句**

### 2.5 场景 / 道具

- 场景：`电影级写实空镜，<地点>，画面中无人。` + 光源（方向/软硬/色温）+ **6~10 个环境元素 + 1 个移动细节** + 镜头语言
- 道具：`电影级写实静物特写，<物品>，<材质/颜色>。` + 光位 + `微距质感`

### 2.6 ★ 对白 · 口型 · 音色（第一版翻车点）

**台词必须进提示词**，用 `{}` 嵌在对应镜头：
```
镜头3
小满（怯生生，轻声，音量很小）：{我没有钱。}
她嘴唇微动，说话时眼神向一侧闪避，说完下唇轻轻收了一下。
```
无台词镜头要**正向**写明保持沉默：
```
【声音】环境音：雨声 + 锅内沸水声。人物保持沉默，嘴唇自然闭合。
```

**音色锁定三层**：
1. 每个角色固定一个 `voice_id`，**全片不换**
2. MiniMax 生成 → 七牛上传 → 建音频节点 → **连到视频节点**（让模型跟着我们的音频走）
3. 提示词里写音色描述作备份：`音色：58岁男性，中低音，语速慢，带一点沙哑`

**特殊符号**：音乐 `（）`｜音效 `<>`｜**台词 `{}`**｜字幕 `【】`

## 三、画布操作（LingCut 无限画布）

### 3.1 ★ 拿到引擎实例 = 一切的关键

应用没把引擎挂 window，但它在 React fiber 的 hook 里。**遍历拿到后，所有操作都变精确、可靠**：

```js
// 见 scripts/engine.js 的 findEngine()
engine.addNode(type, x, y)        // 精确坐标建节点，返回 id
engine.updateNodeData(id, data)   // 写 prompt/model/entityType/src…
engine.updateNodePosition(id,x,y)
engine.addConnection(srcId, tgtId)
engine.removeNode(id)
engine.selectNode(id)             // 选中后节点才渲染 DOM 控制面板
engine.getTransform() / setTransform(x, y, k)
engine.fitToView(120)
engine.toJSON()
engine.nodes / connections / nodeMap
```

> 验证：2026-09-30，用引擎一次建 21 个节点 + 15 条连线，零误差。

### 3.2 保存

`PUT /api/projects/{id}`，body `{canvas_data: JSON.stringify(engine.toJSON())}`。
**因为数据就是应用自己的内存状态，不会被应用回写覆盖。**

> ❌ 反面教训：直接改服务端 `canvas_data` 加连线，会被应用内存状态**覆盖掉**（2026-09-30 实测丢失连线）。

### 3.3 精确触发生成

```js
focusNode(id, 120, 60)   // setTransform 把节点摆到固定屏幕位置（k=1）
engine.selectNode(id)    // 渲染控制面板
// 然后点文本为 "↑" 的 button
```
生成状态轮询：`node.data.generating / genProgress / src / srcs / genError`。

### 3.4 布局约定（沿用用户既有习惯）

```
水平间距 650（节点宽 500 + 150 空隙）
垂直间距 700（节点高 280 + 420 空隙）

角色区   y=0       x=0, 650, 1300 …
场景区   y=700
道具区   y=1400
音频区   y=2100
分镜图区 y=2800
视频区   y=3500
脚本节点 右上角独立放置
```

### 3.5 ⚠️ 无头浏览器：画布不自动重绘

状态变了但 canvas 停在旧帧（**连续截图字节完全相同**）。
`setTransform` 之后必须强制重绘：
```js
canvas.dispatchEvent(new WheelEvent('wheel', {deltaY:-120, clientX:400, clientY:400, bubbles:true, cancelable:true}));
canvas.dispatchEvent(new WheelEvent('wheel', {deltaY: 120, clientX:400, clientY:400, bubbles:true, cancelable:true}));
```

### 3.6 ⚠️ 其他画布坑

- 有浮层 `div.fixed.inset-0.z-[195]`（快捷操作菜单背景）时，Playwright 点击会失败 → 先点掉

### 5.3 ffmpeg（拼接/抽帧用）

**Windows 上没有预装 ffmpeg。** 从 npmmirror 下载最快（GitHub 直连极慢）：
```
https://registry.npmmirror.com/-/binary/ffmpeg-static/b6.1.1/ffmpeg-win32-x64.gz
```
gunzip 后约 79MB。实测 12 秒下完（GitHub 直连 15 分钟没下完）。

**无损拼接**（前提：所有片段编码参数一致）：
```bash
ffmpeg -f concat -safe 0 -i concat.txt -c copy -movflags +faststart -y out.mp4
```
> `lingcut` 出的片统一为 h264 High / yuv420p / 1280x720 / 24fps / AAC 32kHz，
> **拼接过 6 条无需重编码**。
> ⚠️ 输出文件名避免纯 ASCII 之外的特殊字符，某些工具链会乱码；用户可读名字放最后再改。

### 5.3.1 ⚠️ ffmpeg 纯探测会返回退出码 1

`ffmpeg -i file.mp4`（只探测、不给输出文件）**正常结束时退出码是 1**。
用 `execFileSync` / `check=True` 会被当作失败抛异常。
**必须捕获异常再从 stderr 里解析**（ffmpeg 把 `Duration`/`Stream` 信息打到 stderr）。
```js
let probe = '';
try { probe = execFileSync(ffmpeg, ['-hide_banner','-i',file], {encoding:'utf8', stdio:['ignore','pipe','pipe']}); }
catch (e) { probe = String(e.stderr||'') + String(e.stdout||''); }
```
> 踩坑日期 2026-09-30：`scripts/concat.mjs` 因此崩过一次，已修复。

### 5.4 没有 ffmpeg 时如何"看"视频

用浏览器：`crossOrigin="anonymous"` + `<video>` seek + canvas `drawImage` + `toBlob`，
再上传七牛只回传 URL（**避免把 base64 灌进上下文**）。见 `scripts/extract-frames.js`。

### 8.5.1 ★★ 免费路可行：白模**截图**当图片参考（实测大幅提升）

**结论：白模视频喂不了免费模型，但白模截图可以，而且效果提升明显。**

实测（第 1 镜，老陈叠凳）：
- 输入 = 老陈角色图 + **白模截图**（2 图，免费 `lingcut`）
- 结果对比之前所有版本：

| 维度 | v1/v2/v3 | 白模截图版 |
|---|---|---|
| 环境 | 虚化背景，只有桌椅轮廓 | **完整面馆**：墙上中文菜单、价目牌、桌椅、米饭锅、调料罐、蒸汽 |
| 空间感 | 平，无纵深 | 明确纵深与透视 |
| 动作 | 弯腰幅度含糊 | **搬凳动作清晰**，直起腰后**露出笑容** |
| 镜头 | 晃 | 稳定中景 + 轻微推近 |

→ **原理**：白模截图给出了具体空间布局（墙/桌椅/机位高度），模型照这个几何壳子填细节。
正是「白模控制空间」那条在起作用——**不需要视频，一张截图就够**。

**所以免费流水线的最佳配置是**：
```
每个分镜视频节点连 3 张图：
  ① 分镜图（画面与光）
  ② 角色图（身份一致）
  ③ 白模截图（空间与构图）   ← 新增，免费额度 5 图内
```

**操作**：导演台摆好场景 → 选机位 → `截取` → 得到图片节点 → 连到分镜视频节点。

> ⚠️ 踩坑：批量改连线时不要用"排除某些 sourceId"的过滤写法，容易误删已有连线。
> 改完必须 `getInputData(shotId)` 复核 `images` 数量。

**成本**：0 元。**待验证**：白模截图能否约束**运镜**（大概率不能，运镜仍需视频参考 → 有偿模型）。

### 8.5.2 免费 `lingcut` 参考输入的真实限制（2026-09-30 严格实测）

| 项 | 官方宣称 | **实测结论** |
|---|---|---|
| **视频参考** | 未提 | ❌ **硬拒绝**：`HTTP 400 {"param":"videos","code":"unsupported_field"}`「当前模型（Lingcut）不支持视频参考输入」 |
| **图片参考** | 5 图 | ✅ **6 张被接受并成功出片** → **宣称值是建议，不是硬限制** |
| 音频参考 | 3 音频 | 未能测到上限（画布上只有 2 个音频节点） |
| 时长 | 5/8/10/12s | 一致 |
| 分辨率 | 720P | 一致（免费上限） |

> ⚠️ 超限请求是**秒返回 400**，所以测限制很便宜——先测边界再设计流程。

### 8.5.3 多张白模时间点帧：**目前看不出额外收益**（实测）

**做法**（已跑通）：导演台里点 `▶` 播放运镜，在指定时刻点 `截取`，就能拿到该时刻的白模画面。
实测取到 t=0（正面）与 t=1.2s 两张，连同分镜图+角色图共 4 图喂给免费模型。

**结果**：画质与「只加 1 张白模图」的版本**相当**，多出的时间点帧**没有肉眼可见的额外提升**。

**原因**：静态图只能表达「空间长什么样」，表达不了「时间上怎么变」。
→ **白模图的价值主要在「有 / 没有」之间**；要真正传时间维度（运镜），只能靠视频参考，而视频参考需要有偿模型。

**操作要点**：
- 截取必须在**舞台打开**状态下进行；生成新节点后舞台可能被关掉，需要重新进
- 播放 + 定时截取有时序竞态，建议一次只取一个时刻、取完复核节点数

### 8.5.4 白模 → 场景图 → 视频 的三段式（推荐工作流）

```
① 建模：导演台摆空间（脚本化精确坐标，全部刷灰白）
② 场景图：白模截图当参考 → gpt-image-2.5 生成"干净场景图"
   （白模给空间，提示词给材质/光线）
③ 视频：每个分镜节点连 3~4 张图
   分镜图 + 角色图 + 白模截图（构图）
```
白模视频（`录制运镜`）单独留着，等换有偿模型时直接用。

### 8.6 白模方法论（抄自外部资源，`prompt-library/whitemodel/`）

1. **白模控制空间、运动、时机、空间关系；参考图控制身份、材质、光线。**
   白模可以**极其简陋**——时间花在运镜和节奏上，不是建模上。
2. **提示词里的每个数字都必须从白模量出来**，不是抄设计稿、不是想出来的。
3. **每个参考素材必须声明「继承什么 / 不继承什么」**；漏掉「不继承」，模型会把参考里的一切都端过来。
4. ⚠️ **白模主体的颜色会渗进成片**（蓝人群白模 → 成片出现蓝面罩人群）。
   → **摆好场景后必须把假人/物体改成灰白**（属性面板有灰白黑色板）。
5. **机械验收通过 ≠ 画面正确**，渲完必须抽帧看。
6. **两个人以上，站位比动作重要**——镜头偏离两人中线时，世界坐标分得很开、画面上却可能完全重叠。
7. 先出**镜头表**让人在文字上改（改一行一秒），白模建完再改是几分钟。

## 九、配音音色：用中文描述生成 + 必须实测基频 ★

### 9.1 🚨 音色名完全不可信（实测踩坑）

给 58 岁男老板老陈选的是 `Chinese (Mandarin)_Gentle_Senior` ——
名字听着像「温和的老年男声」，**实测是女声**。

| 音频 | F0 中位数 | 判定 |
|---|---|---|
| 老陈「记账」（用 `Gentle_Senior`） | **262.3 Hz** | ❌ **女声**（成年男性应 100–140 Hz） |
| 小满「我没有钱」（用 `Soft_Girl`） | 285.7 Hz | ✅ 儿童女声 |

**用户是听出来的（「那个老头是一个女人的声音」）。**

> 规律：音色名里的 `Senior` / `Woman` / `Antie` / `Wise_Women` 都可能是**女声**，
> 名字没有任何可信度。**唯一可靠的办法是生成样本、测 F0。**（见 9.3）

### 9.2 ✅ 正确做法：`voice_design` 用中文自然语言描述

```bash
POST https://api.minimaxi.com/v1/voice_design
Authorization: Bearer <MINIMAX_KEY>
{ "prompt": "<中文音色描述>", "preview_text": "<试听文本>" }
→ { trial_audio: <hex mp3>, voice_id: "ttv-voice-<ts>-<id>", ... }
```

**返回的 `voice_id` 是持久的**，可直接塞进 `/v1/t2a_v2` 的 `voice_setting.voice_id` 复用。

实测两条描述与结果：

| 角色 | 中文描述 | 生成 voice_id | F0 | 判定 |
|---|---|---|---|---|
| 老陈 | 58岁中国男性，嗓音低沉沙哑，语速缓慢，带一点常年在灶台前熏出来的粗粝感和疲惫，说话克制不张扬 | `ttv-voice-...HFR4M2Zh` | **131.1 Hz** | ✅ 男声 |
| 小满 | 9岁中国女孩，声音清亮稚嫩，带一点怯生生的鼻音，轻声细语，句子末尾会微微发颤 | `ttv-voice-...46KFLe9g` | **280.7 Hz** | ✅ 儿童女声 |

**描述写法**：`年龄 + 性别 + 音色质感 + 语速 + 情绪/经历底色`，别只写「老年男声」。

### 9.3 必做质检：测基频 F0（`scripts/voice_gender.py`）

```bash
ffmpeg -i line.mp3 -ac 1 -ar 16000 line.wav
python scripts/voice_gender.py line.wav
```

自相关法估 F0，参考区间：
- 成年男声 ≈ 85–155 Hz
- 女性 ≈ 165–255 Hz
- 儿童 ≈ 250–400 Hz

**每个角色的配音生成后都要过这一步**，尤其男声角色。
改完音色要**重新上传到七牛并更新画布音频节点的 `src`** ——
只改本地文件，画布上还是旧音频（本项目的真实教训）。

### 9.3.1 ★★ 默认改用 edge-tts：免费、无限次（2026-10-01）

**用户反馈**：MiniMax 音色设计**按次收费，2 段音频花了约 20 元**，做短剧不可持续。

**替代方案：`edge-tts`**（微软 Edge 公开神经语音接口，**免费、无需 API key、无限次**）

```bash
pip install edge-tts                      # 已装 7.2.8
python scripts/tts-edge.py lines.json outDir
```
```json
[{ "file":"line05.mp3", "text":"我没有钱。", "voice":"zh-CN-XiaoyiNeural", "rate":"-12%" }]
```

**14 个中文音色，按实测 F0 标注**：

| 音色 | 性别 | F0 | 用途 |
|---|---|---|---|
| `zh-CN-YunjianNeural` | ♂ | 115–127 Hz | **成年/中老年男性**（rate-18% pitch-14Hz → 108 Hz，更像老人） |
| `zh-CN-YunxiNeural` | ♂ | 157–178 Hz | 青年男性 |
| `zh-CN-YunxiaNeural` | ♂ | —— | 少年 |
| `zh-CN-YunyangNeural` | ♂ | 143 Hz | **新闻播报腔，避开** |
| `zh-CN-XiaoxiaoNeural` | ♀ | 246 Hz | 成年女性 |
| `zh-CN-XiaoyiNeural` | ♀ | **326 Hz** | **少女/女童**（小女孩首选） |

> → **必须人耳试听挑音色**：批量生成候选样本（`_试听包`），让人挑，不要自己猜。

### 9.4 台词写法（用户实测结论）

**模型自己能说话，提示词里写「谁 + 怎么说的 + 说了什么」就够**：

```text
姥姥微笑说：对了，就是这个味。
老陈低声说：记账。
```

H3 官方那套 `<Subject 1> (S1) says in a low voice: <d>[Chinese] 记账。</d>` 更规范，
但**中文直述式（谁+动作+说：内容）同样能被识别**，且更不容易出错、更好读。
两者都保留，按场景选。

> ⚠️ 但**输出音轨仍然不包含对白**（音频节点只是口型/音色参考）——
> 成片对白依旧要用 `scripts/mix-dialogue.mjs` 在后期混入。这条没有改变。
