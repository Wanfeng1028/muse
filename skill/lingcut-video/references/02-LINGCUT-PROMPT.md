# LingCut 提示词规范（★权威 · 2026-10-01 实测确立）

> **本文件是 LingCut 视频节点提示词的唯一格式规范。**
> 用错格式会白白烧掉几小时和一堆试错 —— 见下方「走过的弯路」。
>
> ⚠️ **不要用 MiniMax H3 官方六段式英文长提示词。**
> `H3-OFFICIAL.md` 是官方规范没错，但 **LingCut 的 `lingcut` 免费模型不吃这一套**。
> 两者的差别见第四节实测对照。

---

## 一、★ 唯一正确的格式

```
[景别，运镜] 场景，在场人物，动作描述。氛围/光影/情绪说明
```

**四块**：
1. `[景别，运镜]` —— 方括号开头，景别 + 运镜方式
2. **场景** —— 在哪
3. **在场人物** —— 有谁（点名）
4. **动作描述** —— 干什么，**台词用中文引号写在动作里**
5. 氛围/光影/情绪 —— 收尾一句

### 范例（实测可用）

```
[全景，静态] 纯白虚空，一台打开的笔记本电脑放在画面正中，右边一个小像素咖啡杯
冒着细细热气。屏幕原本空白，忽然"啪"地弹出一双圆滚滚的卡通大眼睛…

[中景，低角度仰拍 15 度] 纯白虚空，小智站在打开的笔记本电脑键盘上，双臂高高举起
伸了个夸张的懒腰…它张嘴大声说："2026年10月1日，国庆节！本AI正式上岗第一天！"

[全景，斜侧 30 度] 纯白虚空，小智站在画面左侧，低头搓着两只小手…小智看着清单，
挑着眉、语速很快地说："今日目标——帮主人搞定所有任务，成为年度最佳打工人！"
```

### 长度

**100–200 字**。用户参考剧里是 56–85 字，我们的实测 142–203 字也正常。

| 长度 | 结果 |
|---|---|
| 3257 字（英文六段式）| ❌ 无效 |
| 137 字（中文无 @）| 🟡 有效 |
| **203 字（中文 + @）** | ✅ **最佳** |

## 二、★ `@` 引用参考图（关键功能）

**提示词里可以 `@` 指名引用已连接的参考图。这是让模型"照抄"而不是"大致参考"的唯一手段。**

### 编号规则

**按连接顺序自动编号**，属性面板「参考 (N)」直接显示：

| 标签 | 含义 |
|---|---|
| `@图1` `@图2` `@图3` … | 第 1/2/3 张**图片**（含分镜图、角色图、文字图）|
| `@音频1` | 第 1 段**音频** |
| `@视频1` | 第 1 段**视频** |

⚠️ 编号**取决于连线顺序**，不取决于节点名。**每次用前先在面板上核对「参考 (N)」的编号。**

### 用法

```
[全景，斜侧 30 度] 画面构图和机位严格参照 @图1，人物外形严格参照 @图2，
声音音色参照 @音频1。…画面右侧"啪"地弹出一张待办清单卡片，
卡片的样式、配色和上面的中文字严格照抄 @图3，稳稳悬在空中不再移动。
```

### 效果对照（实测）

| | 不加 `@` | **加 `@`** |
|---|---|---|
| 文字卡片 | 模型自己发挥尺寸/位置 | **尺寸/配色/位置/文字全部照抄参考图** |
| 角色形象 | 大致像 | 严格一致 |
| **嘴部动作** | 基本静止 | ✅ **有清晰开合（在说话）** |
| 音量 (mean) | -23.8 dB | -23.5 dB |

**结论：`@` 是这套流程里性价比最高的一个动作，必加。**

### 弯路④：把"静止/不动"写进提示词 → 画面被冻死

**错误做法**：想让角色演出"气绝/力竭/定格"的感觉，就写「说完彻底不动了」「画面定格」「静止」。

**实测结果**：模型**照字面执行**，把整段视频冻成**一张静图**
（10 帧逐帧比对**像素级完全相同**）→ 观众看到的是"视频卡死了"。

**正确做法**：**任何镜头都要写持续动作**。想表现"力竭"就用**细微动作**代替静止：

| ❌ 不要写 | ✅ 改写 |
|---|---|
| 说完彻底不动了 | 身体随**微弱呼吸轻轻一起一伏**，天线无力地晃了晃，一只手慢慢滑落 |
| 画面定格 | 镜头**缓慢推近一点点** |
| 静止不动 | **全程画面都在动，不要定格** |

**收尾句模板**：`全程画面都在动，不要定格。`

> 同类雷区：`保持不变` / `一动不动` / `凝固` / `定格`。
> **判据**：提示词里凡是描述"没有动作"的词，模型都会理解成"输出静帧"。

### 弯路⑤：台词后面还跟描述 → 描述被当成台词念出来

**错误做法**：把舞台提示写在引号**后面**。

```
它气若游丝地说："国庆……我恨你……" 说完彻底不动了。
                                    ↑ 这段被模型当台词一起念了
```

**实测后果**（Whisper ASR 逐字转出来的）：

```
模型实际说：  国庆，我恨你！说完彻底不动了！
剧本要求：    国庆……我恨你……
```

**这就是"穿帮"**：观众听到多出来的一句自我描述。

**正确做法：台词必须放在提示词的最后一句，后面不再跟任何描述。**

```
…它保持在原地，全程只有细微动作：身体随呼吸轻轻一起一伏，天线晃了晃，
一只短手慢慢滑落，镜头缓慢推近，画面不要定格。
它气若游丝地念出唯一一句台词："国庆……我恨你……"
                                    ↑ 到此结束，后面什么都不写
```

**自检**：**引号闭合之后，提示词就该结束了。** 引号后还有字 → 有被念出来的风险。

> 同理，**动作描述要放在台词前面**，不要放在后面。

## 五、⚠️ 节点字段坑（实测）

### 5.0 ★★ 提示词必须从 UI 打进去，不能只改节点数据

**这是踩过最贵的一个坑（白烧 0.30 元 + 一轮视频）。**

| 做法 | 结果 |
|---|---|
| `lc.setData(id, {prompt: '...'})` | ❌ **UI 不认**。节点的 React 组件有自己的 prompt 状态，提交时用它自己的（通常是空的）→ **模型自己编了一个"雪山湖泊"通用美景** |
| **选中节点 → 往 `contenteditable` 打 → 点 ↑** | ✅ **正确** |

**正确操作序列**（`contenteditable` 是个 DIV，占位符「描述你想要生成的画面内容，点击连线后的图片进行@」）：

```js
// 1) 画布上点中节点（引擎的 selectNode 不触发 UI 重渲染，必须真点画布）
// 2) 往 contenteditable 写字
const ce = [...document.querySelectorAll('[contenteditable="true"]')]
             .find(e => e.getBoundingClientRect().width > 300);
ce.focus();
const sel = getSelection(), r = document.createRange();
r.selectNodeContents(ce); sel.removeAllRanges(); sel.addRange(r);
document.execCommand('delete', false, null);
document.execCommand('insertText', false, PROMPT);   // ← 会触发 input 事件，React 收得到
// 3) 点面板上的 ↑ 按钮（它给【当前选中节点】生成）
//    注意：用 [...document.querySelectorAll('button')].find(b => b.textContent.trim() === '↑')
```

**⚠️ 四个附带结论：**
- **`data.prompt` 不会回写**。打完字 `data.prompt` 可能还是旧值 —— **这不代表没生效**，生成用的是 contenteditable 的内容。别拿 `data.prompt` 当验证依据。
- **生成期间输入框是禁用的**（`generating: true` 时打不进字）。要改提示词必须**先等生成结束**（5s 镜头约 2–3 分钟，10s 更久）。
- **`updateNodeData` 在打字之后调用会覆盖掉刚打的内容**（实测把新提示词顶回旧值）。
- **参考编号在面板上核对**：面板显示 `参考 (1) | @图1` —— 连好线就有编号。

### 5.0.1 时长档位只有 4 档

UI 下拉是 **5s / 8s / 10s / 12s**，没有 6s、7s。写别的值会被吞掉。
新建节点时 `duration` 数据字段有效，**已建节点改档位要走 UI 下拉**。

### 5.1 时长字段是 `duration`，不是 `seconds`

节点数据里**两个字段都存在**，但**只有 `duration` 生效**：

```json
{
  "seconds": "8",     ← ❌ 写了没用，引擎忽略
  "duration": "5s"    ← ✅ 引擎实际读的（字符串，带 "s" 后缀）
}
```

**写错字段的后果**：设了 8 秒，实际出片永远 5.18 秒 —— 而且**不报错**，很难发现。
台词长的镜头会因此挤得飞快。

**正确写法**：
```js
lc.setData(id, { duration: '8s' });   // 5s / 8s / 10s / 12s
```

### 5.2 出片实际时长

请求 5s → 实际 **5.18s**（多一帧）。其余档位同理略有出入，拼接前用 ffmpeg 核一遍。

### 5.3 台词长度与时长对照

| 台词字数 | 建议时长 | 语速 |
|---|---|---|
| ≤18 字 | 5s | 标准 |
| 19–24 字 | 5s 紧 / 8s 稳 | 偏快 |
| **25–40 字** | **8s** | 标准 |
| 40–60 字 | 10s 或**拆成两镜** | 8s 会过快 |

⚠️ **24 字是舒适上限**（`DRAMA-RULES.md` 第三节）。超过就改 `duration` 或拆镜。

## 六、音频与声音

### 3.1 声音从哪来

**两种来源，实测都有：**
1. **模型自己说** —— 提示词里写了中文台词（引号内），模型会念出来
2. **连接的音频** —— 音频节点提供音色/台词

> ⚠️ 网络上有说法"音频节点只做口型参考、模型不出声"，**这个说法在本项目实测中不成立**。
> 但**不要靠指标判断有没有人声** —— 见第五节。

### 3.2 音频节点用法

- 音频节点连接后，面板显示为 `@音频1`
- 提示词里写 `声音音色参照 @音频1`
- **音色确定**走 `libtv-voice` skill（LibTV `seed-audio-1.0`，1 积分/条）

### 3.3 台词写法

**直接写中文引号内，放在动作描述里：**

```
…它张嘴大声说："2026年10月1日，国庆节！本AI正式上岗第一天！"
…小智看着清单，挑着眉、语速很快地说："今日目标——帮主人搞定所有任务！"
…它扬起一只小手，短促有力地说："写祝福、跑数据、推电影——就这？三分钟搞定！"
```

**配合口型描述**（实测有效）：
- `说话时嘴巴清楚地一张一合`
- `嘴唇微动，仿佛默念"手要轻，心要诚"`
- `嘴唇微动，无声说着"尝尝不"`

## 四、⚠️ 走过的弯路（不要重犯）

### 弯路①：用 H3 官方六段式英文长提示词

**错误做法**：把 `H3-OFFICIAL.md` 的 Ref2VA 六段式英文结构直接投给 LingCut 的 `lingcut` 模型。

**实测结果**：

| 版本 | 提示词 | 音量 mean | 嘴部动作 |
|---|---|---|---|
| 英文六段式 | 3257 字 | -30.3 dB | ❌ 静止 |
| 中文短提示词 | 137 字 | -23.8 dB | 🟡 有动 |
| **中文 + @** | 203 字 | -23.5 dB | ✅ 清晰开合 |

**英文版响度低 7 dB、嘴不动、画面不照抄参考图。**
`H3-OFFICIAL.md` 只在**直连 MiniMax H3 API**时适用，走 LingCut 画布时**不用**。

### 弯路②：靠声学指标判断"有没有人声"

**错误做法**：用 `speech_band_ratio`（语音带能量占比）判断模型有没有说话。

**实测打脸**：一个纯音效的镜头被测出 **0.915（判为"极像人声"）**，
而真人说话的参考剧镜头只有 0.2–0.75。**这个指标在判断人声上不可靠。**

**正确做法**：**抽音轨出来给人听。** 指标只能看趋势（比如各版本响度对比），不能下"有没有说话"的结论。

```bash
# 抽模型原声给人听
ffmpeg -i 视频.mp4 -vn -ac 1 -ar 44100 -b:a 128k 原声.mp3
```

### 弯路③：没先看用户已做好的项目

**正确做法**：开工前先扒用户自己的成功项目 —— 提示词格式、节点连线、参数全部照抄。
`GET /api/projects` 列项目，`GET /api/projects/<id>` 取 `canvas_data`。

## 七、★ 穿帮的成因与修法（实测）

**判据：密集抽帧（每 1 秒一帧）逐帧看。** 只看首尾两帧会漏掉中间 1–2 秒的穿帮。

### 7.1 动作给太大 → 折颈 / 拉长手臂

**实测案例（A05 街口木桌老人）**：提示词写了「老人**缓慢磨墨**」（但这一镜按分镜只是静态建立镜头），
结果 1.0s 处**头几乎埋进桌子**（脖子折叠），2.0s 处**右臂异常伸长横过桌面**。

**成因**：给了一个**跨度过大的动作**，模型在衔接时自由发挥肢体。

**修法三步**：
1. **动作收窄**到分镜真正要的那一个（建立镜头就只要"坐着"）
2. **写清不变的锚点**：`头部和肩膀始终留在画面同一位置，不要低头趴到桌上，不要起身，手臂不要伸向画面外`
3. **用镜头运动保持画面活性**（因为不能写"静止"）：`镜头持续缓慢推近`

### 7.2 提示词提到什么东西 → 模型就造出什么东西

**实测案例**：同一镜我写了「**桌上纸角被风微微掀起**」→ 模型**凭空造了一张纸**，6s 处他拿了起来；
同时油灯暖光「分裂」成**第二盏灯 / 第二个火苗**。

**修法**：**加"禁止新增物品"的显式约束**，并把画面里该有什么列清楚：

```
画面里始终只有一盏油灯，不要出现第二盏灯或第二个火苗；
桌面上只有图中原有的砚台、毛笔和油灯，不要新增纸张或任何物品。
```

**修好后**：坐姿全程稳定、只有一盏灯、没有多余道具，镜头推近感还在。

### 7.3 通用收尾（推荐固定加上）

```
动作幅度极小，不要低头趴下，不要起身，手臂不要伸向画面外。
全程画面都在动，不要定格。
```

## 八、★ 声音（用户硬要求）

**不要音乐，可以有音效。** 所有视频提示词默认不带 BGM 描述；后期合成也不加背景音乐。

- **画面内音效**：写进提示词（脚步声、磨墨声、火苗声、翻纸声、街市人声、犬吠…）
- **本地镜头的音效**：用 ffmpeg 合成（见 `06-楔子视频/build_local_shots.py`）——
  折扇「啪」= 极短宽带噪声 + 指数衰减；醒木 = 320/780Hz 双音 + 10ms 衰减；闷鼓 = 低频正弦扫频 + 0.32s 衰减
- **音轨自检**：`ffmpeg -i x.mp4 -af volumedetect -f null -`，mean 在 −35～−20 dB 属正常音效范围
- ⚠️ 用 Python 写 WAV **必须用 `wave` 模块加文件头**，直接写裸 PCM 会让 ffmpeg 报
  `Invalid data found when processing input`
