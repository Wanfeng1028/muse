# 长镜头拆分 —— 尾帧接续法 ★★★

> **本文件是整个 skill 里最有价值的一招。**
> 它让**免费模型**做出**付费模型才能做的长镜头**，而且是无缝的。

---

## 一、问题

LingCut 免费模型（`lingcut`）的时长只有 **5 / 8 / 10 / 12 秒** 四档。

但剧本里经常需要：
- 20 秒的一镜到底（人物说完话 → 镜头拉远 → 全景）
- 14 秒的悬念镜（磨墨很久 → 抬眼 → 两句台词）
- 台词太长，12 秒装不下（中文正常语速 **3.5–4 字/秒**）

**硬凑的后果**：台词赶得像念稿，或者被砍掉半句。

---

## 二、解法：抽尾帧，当下一段的首帧

```
① 生成 A 段（12s，用免费模型）
② ffmpeg 抽 A 段的最后一帧 → PNG
③ 把 PNG 上传成画布上的一个新「图片节点」
④ 新建 B 段视频节点，把这张尾帧图接进去（= B 段的首帧参考）
⑤ 生成 B 段（5s / 8s / 10s）
⑥ A + B 规范化后用 concat 拼接
```

**为什么无缝**：B 段的首帧 = A 段的尾帧，视觉上是同一个画面的延续。
配合 B 段提示词开头的 `★【续接前一段】同一个镜头，画面风格/光线/人物位置必须完全一致`，
接缝基本看不出来（实测 12s→10s 的接缝肉眼无感）。

> **尾帧接续法让同样的效果成本为 0。**

## 四、脚本

`.` 见 `scripts/lingcut-split.mjs`（通用拆镜器）

```bash
node scripts/lingcut-split.mjs <镜头编号> <配置.json>
```

配置格式：

```json
{
  "durA": "12s",
  "durB": "8s",
  "nameB": "一·3章 D05b 老陈说三百封·续 [视频]",
  "promptA": "[中景，固定机位] …… ★台词（一字不差）：「前半段的台词」",
  "promptB": "★【续接前一段】同一个机位…… ★画面风格、光线、人物位置必须和前一段完全一致。★台词：「后半段的台词」"
}
```

脚本会自动：生成 A → 抽尾帧 → 建节点 → 上传 → 生成 B → 规范化 → concat → 替换本地文件。

## 五、提示词模板

### A 段（前半）

```
[景别，机位，运镜] <场景>。<人物外貌严格参照 @图N>。
<动作过程：写到手/腿/头/肩背，标幅度与速度>。
★台词（必须按照写下来的字，一字不差、清楚完整地说出来；
      用画面上这个人物自己的声音，不要旁白腔）：「<前半段台词>」
【电影感】<五条，见 02-PROMPT.md>
无配乐，只有音效：<…>。全程画面都在动，不要定格。
```

### B 段（后半）★ 关键在开头三句

```
★【续接前一段·同一个镜头】摄影机继续<与 A 段相同的运动>。
<人物> <动作>。
★画面风格、光线、人物位置、色调必须和前一段完全一致，
  是同一镜头的延续，不能像换了机位。
★台词（<节奏指示>）：「<后半段台词>」
【电影感】<与 A 段相同的五条>
无配乐，只有音效：<与 A 段相同>。全程画面都在动，不要定格。
```

## 六、★ 台词节奏指示（这是 A10 踩过的坑）

**问题**：28 个字塞进 5 秒 = 5.6 字/秒，听起来像赶场。

**解法**：在提示词里**明确写出停顿点**。

```
★台词必须一字不差、慢慢地说，不要赶。
  **节奏是：先沉默两秒**（只是抬眼、喉结动了一下），然后才开口；
  第一句：「写过。」——说完停半拍；
  第二句：「写过两次。」——说完停半拍；
  第三句：「第一次，把我老婆写死了。」——说完停顿更久一点；
  第四句：「第二次，我不敢了。」——说完之后画面再停留一秒，他不再说话。
  用这个人物自己的声音，<音色描述>，**不是念稿，语速要慢**。
```

**通用时长估算**：

| 内容 | 需要时长 |
|---|---|
| 中文台词 | **字数 ÷ 3.5 ~ 4** |
| 一个动作节拍（抬眼/转头/停手）| +0.8 ~ 1.5s |
| 沉默停顿 | +1 ~ 2s |

**总时长 > 12s 就拆镜。**

## 七、拼接规范化（必做，否则时长会膨胀）

```bash
ffmpeg -y -fflags +genpts -avoid_negative_ts make_zero -i <src> \
  -c:v libx264 -preset veryfast -crf 20 -r 24 -vf "scale=1280:720,setsar=1" \
  -pix_fmt yuv420p -c:a aac -ar 32000 -ac 2 <dst>
```

然后：

```bash
# list.txt
file 'A-n.mp4'
file 'B-n.mp4'

ffmpeg -y -f concat -safe 0 -i list.txt -c copy out.mp4
```

⚠️ **`list.txt` 必须是无 BOM 的 UTF-8**（PowerShell 的 `Set-Content -Encoding UTF8`
在 5.1 下会加 BOM，ffmpeg 报 `unknown keyword 'file'`）。
用 `[System.IO.File]::WriteAllLines($p, $lines, (New-Object System.Text.UTF8Encoding($false)))`。

## 八、什么时候**不**用尾帧接续

- 两段画面**本来就该切**（换个机位、换个场景）→ 直接两个镜头，不用拼
- 台词能装下（≤12s）→ 直接加时长到 10s/12s 就行，别过度设计
- 需要**真正的运动连续性**但预算够 → 可以考虑付费长镜

**判断标准：剧本写的是「同一个镜头里发生了什么」，才用尾帧接续。**

---

## 九、和「多段拼接」的区别（别搞混）

| | 尾帧接续 | 普通拼接 |
|---|---|---|
| 目的 | 假装是**一个**长镜头 | 就是**两个**镜头 |
| B 段首帧 | = A 段尾帧 | 独立生成 |
| B 段提示词 | 必须写「续接前一段、完全一致」| 正常写 |
| 接缝 | 要看不出 | 本来就该切 |
