# 交付 —— 从画布到「用户可以剪」★★

> 片子生成完了 ≠ 用户能用了。
> 用户要的是：**能看、能核对、能剪、能发。**
> 这一步做不好，前面全白费。

---

## 一、★ 从画布批量下载全部素材

**这是交付的起点，也是「离线审阅」的前提。**

`.probe/lingcut-download-all.mjs` 做三件事：

1. 拉 `/api/projects/<id>` 拿完整画布
2. 遍历所有节点，取 `data.src` / `selectedSrc`
3. 按**剧情顺序**重新编号下载

**文件名规则**（让排序 = 播放顺序）：
```
001_楔子 A02_油灯点亮.mp4
002_楔子 A03_州城城晨景.mp4
009_第一章 B01_老街未醒.mp4
041_第四章 E03_盯着信看.mp4
```

排序键：`单元顺序 → 镜号 → 图先于视频`

**输出**：
```
★网站最新/
├─ 读我-怎么看.txt     导航说明
├─ 视频/     NNN_单元 镜号_内容.mp4
└─ 图片/     000_资产_…
```

⚠️ **清空重下，不要增量下**。反复下载会产生 162 组重复文件（序号会变）。

## 二、★ 剪辑工作台（交付给用户的核心）

用户要在**自己的剪辑软件**里剪（剪映 / Premiere / DaVinci）。
给他一个**开箱即用**的目录：

```
★剪辑工作台/
├─ 读我-怎么剪.txt          ← 导航 + 每章镜头清单（带时间码）
├─ 01-新视频/               ← 按 卷→章 分好文件夹的逐镜视频
│   ├─ 卷1/ 00_楔子/ A01_全黑醒木.mp4 …
│   ├─ 卷1/ 01_第一章_老街未醒/ B01_… B11_…
│   ├─ 卷2/ …
│   └─ 卷3/ …
├─ 02-旧视频/               ← 修复前的版本，用于新旧对比
│   ├─ 逐镜旧版（从OSS拉回）/   和新视频一一对应，加【旧版】后缀
│   ├─ 旧版成片（重建）/        整章级的旧版
│   └─ v1素材/
├─ 03-音频/
│   ├─ 旁白-按章/           XX章_旁白.wav（每章整条）
│   └─LibTV旁白源文件/
├─ 04-成片参考/             ← 已经拼好的，剪的时候对着看
│   ├─ 00_全片_X分X秒.mp4
│   ├─ 卷一/卷二/卷三
│   └─ 分章（20个）/
└─ 05-素材图/               角色定板 / 场景 / 道具
```

**原则**：
- **新旧分开**（用户要对比时能立刻找到）
- **按卷/章分文件夹**（拖进剪辑软件自动成素材箱）
- **音频单独给**（用户可能要重新对）
- **参考成片一定要给**（这是校准的基准）

## 三、★ `读我-怎么剪.txt` 要写什么

这是**交付文档**，比成片本身还重要。

```
① 文件夹说明
② 建议的剪辑流程（5 步）
③ 输出规格（1280×720 · 24fps · H.264 · AAC 48kHz）
④ 每一章的完整镜头清单：
     0:00    4.00s   A01_全黑醒木
     0:04    5.18s   A02_油灯点亮
     ...
   章长: 1:27  (87.32s)   11 镜
⑤ 本次修复的重点镜头逐条标注：
     L11  ★★20秒长镜（尾帧接续：特写→中景→远景，全片最长镜）
     A10  ★楔子悬念钩子·22秒
     K02  ★案上有白布覆盖的遗体（可自行打码）
⑥ 音效说明（无 BGM，镜头自带环境音）
⑦ 新旧版本对照说明
```

**第 ④ 项的时间码由脚本生成**（读实际文件时长），不要手写。

## 四、★ 让用户能「报告问题」

用户看完会提问题。**必须让他能用最短的话定位到镜头**。

在交付文档里写：

```
发现问题直接说「序号 + 名字」，例如：
  「041 第四章 E03 那个镜头人物不对」
  「111 第十一章 L11 那段结尾不对」
  「A10 那句台词说得太快」
```

**并且**：全片的**镜号体系**要在文档里列清楚：

```
楔子          A01-A11      第一章 老街   B01-B11
第二章 小伙计  C01-C11      第三章 邮差     D01-D08
……（每个单元的字幕范围）
```

## 五、★ 旧版本恢复（画布快照 = 时间机器）

**问题**：用户改了镜头，覆盖了成片，后来问「上一版还在吗」。

**解法**：如果你曾经存过画布的 JSON 快照（`_tmp/canvas.json`），
里面就有**所有旧节点的 OSS URL**。

```
① 读旧快照 → 建 nodeId → 旧 src 的映射
② 拉当前画布 → 建 nodeId → 新 src 的映射
③ 对比，找出 src 变了的节点
④ 从 OSS 把这些旧版本下回来
⑤ 用旧版本 + 未变的镜头 + 旧时长的旁白 → 重建旧成片
```

**实测效果**：53 个改过的镜头全部拉回，重建的旧版成片
**1460.57s vs 原始 1458.36s（差 0.15%）**。

> ⚠️ 画布节点的 `srcs` 数组**不保留历史版本**（只有一个当前值），
> `history` / `versions` / `snapshots` 接口都是 404。
> **所以定期存画布 JSON 快照是唯一的恢复手段。**

## 六、抖音 / 短视频发布

### 6.1 文案结构

```
钩子（前两行，必须有悬念/反差）
↓
展开（3-5 行，把故事的核心冲突说清楚）
↓
话题标签（5-8 个）
```

**示例**：
```
他替人写了三十年的信。

全是假话。

只写过两次真话——
第一次，把他妻子写死了。
第二次，他儿子再也没回来。

#示例片名 #书信 #原创短剧 #古风 #AI短剧
```

### 6.2 封面

**只放两行，字要大**，用**最有钩子的那一帧**（不是片名字卡）。

### 6.3 ★ 时长策略

| 成片长度 | 抖音建议 |
|---|---|
| < 3 分钟 | 整条发 |
| 3–8 分钟 | **切成 2–3 集**，每集结尾留悬念 |
| > 8 分钟 | 先发 60 秒预告，引流到长视频；或切成多集 |

**7 分 22 秒直接发抖音，完播率会很低。**

### 6.4 前 3 秒决定生死

- ❌ 开头放片名 / 黑屏 / 字幕卡
- ✅ 直接上画面 + 那句最狠的话
- 技巧：把全片最悬念的镜头**提到开头**做"倒叙钩子"

### 6.5 话题标签

```
必带：作品名 + 核心关键词（各 1 个）
内容标签 3-4 个：#原创短剧 #古风 #AI短剧 #一封家书 #中式美学
流量标签 1-2 个：#短剧推荐 #原创

⚠️ 不要带 #影视剪辑 #解说（会被判搬运）
```

### 6.6 评论区引导

发完自己先留一条，制造"往下看"的动机：
> 「他第二次那句真话，是写给谁的？看到第五章就懂了。」

## 七、交付检查清单

- [ ] 从画布**全集**重下（不是零散目录）
- [ ] 文件名排序 = 剧情顺序
- [ ] 镜头清单按单元打印，**人工核对有没有漏镜**
- [ ] 成片时长 ≈ 各段之和（差 < 0.5s）
- [ ] **旧版本已备份**
- [ ] 剪辑工作台：新/旧/音频/参考/素材 五件套齐全
- [ ] `读我-怎么剪.txt` 有时间码 + 修复标注 + 报告问题的话术
- [ ] 交付文档里**没有凭据**（账号密码 / API key）
