# 场景导演 · 本地化配音管线

## 何时启用

当需要为每一个本地化交付物确定处理策略时启用本技能：时间轴如何对齐、可见说话动作如何应对、字幕如何排布、屏上文字如何处置。本阶段的核心决策是——保留原始剪辑、在露嘴段落做画面遮挡，还是尝试唇形同步。

## 参考输入

- `docs/localization-dubbing-best-practices.md`
- `skills/creative/video-editing.md`

## 流程

### 1. 逐交付物选定配音模式

从下列四种中挑选其一：

- `subtitle_only`：只出字幕，音频保持原声。
- `dub_audio_only`：只替换配音音轨，不做口型处理。
- `lip_synced`：做唇形同步，适用于对嘴型要求高的镜头。
- `hybrid_covered`：在口型明显不匹配、容易让观众出戏的段落，改用 B-roll、图形动画或文字覆盖来转移注意力。

每种交付物都必须显式指定一种模式，不允许留空。

### 2. 标注时间轴风险

逐场排查可能因下列原因产生时长漂移的段落：

- 语速过快；
- 法律条文类密集文本；
- 多人对话交叠；
- 快切剪辑；
- 面部特写中的可见嘴部动作。

把风险位置和风险类型记录下来，供后续排期与人工复核参考。

### 3. 梳理屏上语言依赖

登记所有包含下列元素的镜头：

- 界面 UI 文字；
- 下三分之一字幕条；
- 标题卡；
- 已经烧录进画面的字幕；
- 图表与标签。

对每一项判断是需要替换、遮挡还是保留原样。

### 4. 用元数据驱动多版本规划

推荐写入以下元数据键：

- `dub_mode_map`：交付物到配音模式的映射。
- `timing_risk_map`：时间轴风险位置与成因。
- `on_screen_text_replacement_map`：屏上文字的替换/遮挡方案。
- `language_variant_notes`：各语言版本的补充说明。

### 5. 质量门

- 每个交付物都已明确本地化处理方式；
- 时间轴风险已全部标注；
- 唇形同步的使用是有选择的，而非一刀切；
- 文字替换需求没有被掩盖或遗漏。

## 常见坑

- 想当然认为配音音轨能严丝合缝贴合原片时长。
- 不分镜头一律上唇形同步，浪费成本且未必必要。
- 直到合成阶段才想起画面里还有烧录文字没处理。

## 人工审批门（强制）

本阶段以人工审批为门禁（`human_approval_default: true`）。复核通过后：以 `status="awaiting_human"` 写入检查点，展示摘要（Backlot 看板会渲染产物），然后**结束本轮回复**。不得在同一轮里启动下一阶段。审批按门逐个生效——此前某次的"继续"不覆盖本门。
