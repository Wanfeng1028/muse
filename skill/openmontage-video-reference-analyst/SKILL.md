# 视频参考分析师（Video Reference Analyst）

当用户提供视频 URL（YouTube、Shorts、Instagram、TikTok 或任意链接）或本地视频文件作为**参考**时使用本技能——含义是“给我做一个类似的”，而不是“帮我剪这段素材”。

如果用户说“剪辑这个视频”或“剪成片段”，应改走素材主导的流水线（clip-factory、talking-head、hybrid）。本技能针对的是**参考驱动**的制作。

## 触发信号

命中以下情况时触发：

- 用户粘贴 YouTube / Shorts / Instagram / TikTok 链接
- 用户说“类似这个”“受这个启发”“这种风格”“和这个差不多”
- 用户上传视频并说“我想要一个像这样的”
- 用户说“我看到这个视频，想做类似的东西”

不要触发的情况：

- 用户提供素材并说“剪辑这个”或“剪成片段” → 走 source_media_review
- 用户提供音频并说“给这段做个视频” → 标准流水线
- 用户只想要转录文本 → 直接使用 TranscriptFetcher

## 协议

### 第 1 步：分析参考

以 `analysis_depth: "standard"` 运行 VideoAnalyzer：

```python
video_analyzer.execute({
    "source": "<url or path>",
    "analysis_depth": "standard",
    "max_keyframes": 20
})
```

读取返回的 VideoAnalysisBrief。在继续之前先向用户做一次汇报。这不是原始数据倾倒，而是一次对话式的解读，并且必须按五个维度组织，以便下游阶段能直接取用字段：

```
“我看过这个视频了。以下是我的观察：

**内容：** [两句话概括视频讲什么]
**风格：** [一句话——节奏、视觉处理、能量感]
**结构：** [X 个场景 / 共 Y 秒，节奏风格]
**动态：** [M 个场景中 N 个是动态片段 / 动画静帧 / 静态图片。
本片使用 [AI 生成视频片段 / 带平移缩放的静帧 / 混合]。]

**五维拆解（按镜头或镜头组）：**
- Subject（主体）：[类型、数量、属性；跨镜头的主体变化：出现/消失/切换/复杂交替；或 N/A]
- Subject Motion（主体运动）：[按时间顺序的动作；交互；或 N/A]
- Scene（场景）：[叠加层（文字/图形）单独列出；视角（航拍/过肩/微距等）；环境；时间；动态]
- Spatial Framing（空间构图）：[景别；主体位置；景深；相对高度；如何变化]
- Camera（摄影机）：[播放速度；镜头；高度；角度；焦点/景深；稳定性；运动]

**它为什么成立：** [2-3 个具体要点——钩子手法、节奏、视觉转场、旁白风格]

现在让我看看在你当前的配置下能做些什么……”
```

上面的五维块是 `proposal-director`、`script-director`、`scene-director` 会读取的**规范形式**。不要把它折回散文，保留标签。

**动态分类是关键。** VideoAnalysisBrief 现在包含每个场景的 `motion_type`（"motion_clip"、"animated_still"、"static_image"）与 `flow_variance`。据此判断制作路径：

- 大多数场景是 `motion_clip` → 参考使用了**视频生成**（Kling、MiniMax 等）→ 围绕视频生成工具规划，而不是图像生成。
- 大多数场景是 `animated_still` → 参考使用了**静帧 + Ken Burns / 平移缩放** → 图像生成 + Remotion/FFmpeg 合成更合适。
- 混合情况 → 记录哪些段落用动态、哪些用静帧。

**永远不要猜测**参考用的是图像还是视频。读 `motion_type` 字段。判断错误会导致提出错误的流水线与错误的工具路径。

**视觉分析：** 在展示结构数据之后，亲自检查抽取的关键帧。你是多模态模型——查看关键帧图像并丰富 VideoAnalysisBrief，补充：

- 每帧描述（主体、文字、构图、色彩）
- 跨帧视觉连续性与风格一致性
- 类型归类与制作质量评估
- 主色提取（跨关键帧的主导颜色）
- 若存在屏幕文字，记录字体风格
- 顺序关键帧之间可见的转场模式

用这些视觉观察更新 brief 的 `content_analysis`、`style_profile` 与 `replication_guidance` 字段。工具提供结构，你的视觉提供理解，这才让分析真正全面。

### 五维结构化输出（强制）

分析报告必须按 CMU/Harvard CHAI 研究的**五个维度**拆解参考视频（也是 `skills/creative/video-gen-prompting.md` 中使用的规范结构）。仅有叙述性总结已不足够——下游阶段（提案、剧本、scene-director）会直接消费五维形式，不再重新解析散文。

**决策树式标注策略。** 对每个检测到的镜头，依次走完五个维度：

> - **Subject：** 类型、属性（数量、年龄、角色、服装、显著特征）、多主体消歧、跨镜头变化（出现/消失/切换/复杂交替）。
> - **Subject Motion：** 按时间顺序的动作；群体/交互模式（并行、顺序、反应式）；移动 vs 手势 vs 面部。
> - **Scene：** **叠加层单独列出**（文字、下三分之一、图形、水印——作为独立图层说明，不要并入环境）+ 视角（航拍、过肩、微距、俯视、行车记录、FPV、手持、固定机位）+ 环境 + 时间 + 动态（天气、粒子、人群移动）。
> - **Spatial Framing：** 景别（ECU/CU/MS/WS/EWS）、主体在画面中的位置、景深（前景/中景/背景使用）、相对高度（高于/平于/低于主体）——以及当机位或主体移动时这些如何**变化**。
> - **Camera：** 播放速度（实时/慢动作/延时）、镜头畸变（宽银幕、鱼眼、移轴）、高度（地面/眼平/俯视）、角度（仰/俯/荷兰角）、焦点/景深（拉焦、深焦、浅焦）、稳定性（锁定/手持/稳定器）、运动（推/拉/摇/俯仰/移动/横移/升降/环绕）。

> 若某项不适用，**明确标为 N/A**（例如“Subject：N/A——纯风景镜头”或“Scene 叠加层：N/A——无图形”）。**静默省略是分析员最常见的失误**，会导致下游提示词含糊不清。

原语定义与各维度的规范词表参见 `skills/creative/video-gen-prompting.md`。

### 第 2 步：能力审计

运行标准预检：

```bash
# 发现工具并打印支持包络
python -c "from tools.tool_registry import registry; import json; registry.discover(); print(json.dumps(registry.support_envelope(), indent=2))"

# 打印可用的提供商菜单
python -c "from tools.tool_registry import registry; import json; registry.discover(); print(json.dumps(registry.provider_menu(), indent=2))"

# 打印能力目录
python -c "from tools.tool_registry import registry; import json; registry.discover(); print(json.dumps(registry.capability_catalog(), indent=2))"
```

将参考视频的需求映射到可用能力：

```
参考需求                你的能力                     差距
──────────────────      ──────────────────────      ──────────
视频片段（科幻）        视频生成：0/12 已配置       缺密钥则被阻塞
旁白（低沉男声）        TTS：ElevenLabs 可用         就绪
背景音乐                音乐：MusicGen 可用          就绪
合成引擎                Remotion：可用               就绪
                        HyperFrames：可用            就绪
                        FFmpeg：可用                 就绪（仅独立操作）
```

**合成引擎选择：** Remotion 与 HyperFrames 是并行、不分等级的合成运行时——不要在此处预先锁定。两者都可用时，`AGENT_GUIDE.md` 中的“同时呈现两个合成运行时（硬性规则）”关卡生效：在提案阶段向用户呈现两个选项及取舍，等待明确批准后再锁定 `render_runtime`。静默选择默认值是禁止的。FFmpeg 在此流程中不是合成运行时——它保留用于合成管线之外的独立操作（裁剪、转码、烧字幕）。

诚实对待差距。如果需要视频生成但不可用，要说清楚：

```
“这个参考使用了生成的科幻素材。目前你还没有配置任何视频生成提供商。可选路径：

• 按 `provider_menu()` 推荐的网关或提供商密钥添加视频生成能力
• 若有多个提供商可选，总结各自取舍并基于用户简述推荐一个
• 不使用视频生成 → 我改用库存素材 + Remotion 动画
  （感觉不同，但仍可行）

你倾向哪一种？”
```

对每个不可用工具，从注册表读取 install_instructions——**不要硬编码**密钥名、提供商名或安装 URL。

### 第 3 步：提出关键问题

在提案之前，收集 VideoAnalysisBrief 无法提供的信息：

1. “你的版本要旁白，还是纯画面配乐？”
2. **若需要旁白：现在就锁定音频架构。** 询问：
   “故事该怎么讲？选项：
   • **单一旁白** —— 一个声音讲完整故事（像 Pixar 短片）
   • **角色对白** —— 角色互相说话，无旁白
   • **旁白 + 角色声音** —— 旁白推进故事，角色偶尔有台词”
   这个决定影响剧本、配音选角与预算。必须在提案前解决——不要推迟到剧本或合成阶段。
3. “你的视频要多长？参考是 [X] 秒。”
4. “有特定主题/题材吗，还是我沿参考的主题发挥？”
5. “参考里有什么你特别爱或特别不想要的？”

不要一次全问。先问最关键的缺口。如果用户第一条消息已答了部分问题，跳过它们。

### 第 3b 步：轻量研究

**此步是强制性的。** 即使有清晰的参考视频和用户方向，代理也必须在提出概念前做有针对性的研究。不要跳过此步只依赖参考分析和你自己的知识。

研究范围（保持聚焦——这不是完整的 research-director 阶段）：

1. **内容图景：** 搜索 3-5 个与用户目标相似的现有视频。什么做得好？什么被做烂了？哪些角度还新鲜？让你的提案扎根于真实存在的内容，而不是你的想象。

2. **风格/技术研究：** 搜索与制作路径相关的最佳实践：
   - 若走 AI 视频生成：哪些模型最适合这个题材？已知的提示模式？角色一致性技巧？
   - 若走动画：哪些动画风格适配这类内容？
   - 若参考有独特技法：它是如何实现的？

3. **主题研究：** 若用户主题含事实内容（科学、历史、原理类），收集 3-5 个具体数据点或事实，让视频更有意思。即使是娱乐/喜剧视频，也研究同类内容为何吸引人（套路、钩子、回报结构）。

**如何呈现：** 不要把原始研究倒出来。把发现编织进提案：

- “我看了类似频道——大多数食物拟人视频都用 X，所以我们用 Y 的反转会更突出”
- “Kling 在 [特定技法] 下处理拟人角色效果很好”
- “表现最好的 60 秒喜剧短片都采用三段结构：铺垫、升级、意外回报”

**时间预算：** 2-3 分钟网络搜索。这是一次轻量通过，不是深度调查。完整的 research-director 阶段若有需要会在流水线内部稍后运行。

### 第 4 步：创意提案（2-3 个变体）

强制要求：代理绝不能提出复制品。参考是灵感，不是模板。每个提案必须有明确的创意差异化。

每个变体使用以下结构：

```
## 选项 [A/B/C]：“[标题]”

**受其启发：** [保留自参考的部分——节奏、结构、语气]
**创意转折：** [改变的部分——角度、主题、视觉处理、钩子]

**视觉方案：**
- 剧本： [最接近的匹配 + 定制]
- 视觉处理： [视觉如何制作——哪些工具、哪些提供商]
- 合成： [Remotion（可用时为默认）/ FFmpeg（仅兜底）]
- 动效： [视频生成片段 / Remotion 弹簧动画作用于静帧 / 等]
- 片段时长策略： [最大化单片段时长以降低 API 调用与成本。
  多数提供商支持 5 秒和 10 秒片段。优先 10 秒，并在叙事连贯时合并
  相邻场景为单片段。60 秒视频需要 6×10 秒而非 12×5 秒——一半成本、
  更少剪切、更顺滑的运动。]

**音频方案：**
- 音频架构： [单一旁白 / 角色对白 / 旁白 + 角色]
- 配音选角： [每个角色的声音名 + ID——旁白、角色 A 等]
- TTS 提供商： [通过 tts_selector 预检从可用提供商中选择——
  Google Chirp3-HD（性价比最佳：近乎免费、富有表现力、24kHz）、
  ElevenLabs（仅声音克隆）、OpenAI gpt-4o-mini-tts（适合 instructions 参数）、
  Piper（离线/免费）。不要硬编码提供商——运行预检确认已配置的选项并推荐最佳可用者。
  **默认推荐：Google Chirp3-HD**，除非需要声音克隆。]
- 音乐： [曲库曲目 / 生成 / 无]
- 声音设计： [任何特殊音频需求]

**时长：** [X 秒]
**按提供商估算的成本：**
给出提供商对照表，让用户自己选择：
```
提供商          质量       速度       成本（N 片段）    合计
─────────      ────────   ─────      ──────────────    ─────
VEO 3.1        最高       慢         $X.XX             $X.XX
Kling Pro      高         中         $X.XX             $X.XX
Sora V2        高         中         $X.XX             $X.XX
LTX Distilled  较低       最快       $X.XX             $X.XX
```
+ 图像生成：$X.XX（N 张 × 每张 $X.XX，经 [提供商]）
+ TTS 旁白：$X.XX（N 词，经 [提供商]）
+ 音乐：$X.XX（[来源]）

**不要替用户选定提供商。** 呈现选项与成本，简要说明推荐理由，让用户决定。

**诚实评估：** [最终成片现实上会是什么样——不要夸大]

**Layer 3 技能：** [列出每个工具将用到的 agent_skills。
  写任何生成提示词之前必须先读它们。例如：
  - 视频生成：`ai-video-gen` 技能，获取提供商专属提示模式
  - 图像生成：`flux-best-practices`，用于 FLUX 提示工程
  - TTS：`elevenlabs` 或 `openai-docs`，用于声音调校
  跳过 Layer 3 技能属于治理违规。]
```

**差异化模式：**

| 模式 | 示例 |
|------|------|
| **同结构、不同主题** | 参考：“黑洞如何运作” → 我们：“中子星如何运作”，节奏相同 |
| **同主题、不同角度** | 参考：“Kubernetes 讲解” → 我们：“从安全工程师视角看 Kubernetes” |
| **同语气、不同视觉处理** | 参考：库存素材 + 配音 → 我们：动态图形动画 + 配音 |
| **同内容、不同平台** | 参考：10 分钟 YouTube → 我们：60 秒 Shorts，节奏更快 |
| **反向观点** | 参考：“为什么 AI 会取代工作” → 我们：“为什么 AI 不会取代你的工作” |

**成本透明是强制的。** 每个概念必须包括：
- 在用户要求时长下的逐项成本估算
- 按图像生成、视频生成、TTS、音乐拆分的成本
- 每条成本行的提供商名称
- 诚实说明预算能买到什么、买不到什么

**推荐：** 始终推荐一个选项并给出简短理由。不要让用户在等价选项间瘫痪。

### 第 4b 步：Layer 3 技能关卡（强制）

**在任何素材生成之前**（样片或完整制作），代理必须：

1. 从 `skills/` 目录读取每个工具的 **Layer 2 技能**（使用指引、输入 schema、最佳实践）
2. 检查每个将用工具的 `agent_skills` 字段
3. 读取 `.agents/skills/` 中每个引用的 **Layer 3 技能**（提供商专属提示）
4. 将提供商专属提示指引应用到所有生成提示词

**绝不要读工具源码（*.py）来了解工具用法。** 技能的存在正是为了让代理不必读实现代码。Layer 2 技能说明*是什么*与*何时用*；Layer 3 技能说明*怎么用*。

这不是可选项。AGENT_GUIDE 指出：*“Layer 3 不是可选的。每个生成工具都有 agent_skills 字段。写提示词前先读它们。”*

生成前的示例清单：

```
工具              agent_skills             已读？
────────────      ────────────────────     ─────
video_selector    ai-video-gen             [ ]
flux_image        flux-best-practices      [ ]
elevenlabs_tts    elevenlabs, text-to-speech [ ]
video_compose     remotion-best-practices  [ ]
```

在所有相关 Layer 3 技能读毕之前，不要进入第 5 步。通用提示词与技能指导过的提示词之间的差别，就是“能用”与“电影感”之间的差别。

### 第 5 步：样片优先制作（强制）

用户选定变体后，始终说：

```
“好选择。在我投入完整的 [X] 秒视频之前，我会先做一支 10-15 秒样片——
开头钩子 + 一个中间场景。这样你能先听到声音、看到视觉风格、感受节奏，
再决定是否全量投入。

样片预估成本：$[X.XX]
是否开始制作样片？”
```

样片不是可选项。即使用户说“直接做完整的”，也温和地推回：

```
“我真心建议先做样片——成本极小，可以尽早发现风格偏差。如果你满意，
我会立刻进入完整视频。”
```

只有在用户被提醒后仍坚持时才跳过样片。

**样片内容：**
- 1-2 个代表性场景（钩子 + 一个中间场景）
- 用所选声音的真实 TTS 旁白
- 真实的生成/库存视觉
- 一段音乐床
- 字幕样式预览

**样片检查点：**
呈现样片并说：“这是预览。感觉对吗？可调整项：声音、视觉风格、节奏、音乐、颜色。”

对样片反馈反复迭代直到批准。样片存放于：
`projects/<name>/assets/sample/sample_v{N}.mp4`

### 第 6 步：进入流水线（硬性重定向）

样片获批后，代理必须进入流水线。这不是可选项。

**强制步骤：**
1. 读取流水线清单：`pipeline_defs/animation.yaml`（或匹配制作类型的其他流水线）
2. 按顺序**逐阶段执行**——research → proposal → script → scene_plan → assets → edit → compose → publish
3. 每个阶段之前，从 `skills/pipelines/<pipeline>/<stage>-director.md` 读取该阶段的 director 技能
4. 在每个阶段产出所需产物
5. 在每个 `checkpoint_required: true` 处停下
6. 在每个 `human_approval_default: true` 处获得用户批准

**不要压缩阶段。** 不要从“用户批准提案”直接跳到“生成全部素材”。流水线阶段的存在是为了执行质量关卡、产物依赖与审阅检查点。跳过它们属于治理违规。

**带入流水线的上下文：**
- VideoAnalysisBrief 作为 research/proposal 阶段的基座上下文
- 用户选定的变体作为已批准方向
- 样片反馈并入 brief
- 所有创意差异化决策记入 decision_log
- 第 3 步的音频架构与配音选角决定
- 第 4b 步已读的 Layer 3 技能

流水线从此接管。VideoAnalysisBrief 随标准产物一同流动，在每个阶段提供参考基座。

## 多个参考视频

当用户提供多个参考链接时：

1. 分别分析每个视频（对每个运行 VideoAnalyzer）
2. 呈现对比总结：“视频 A 在 X 方面做得好，视频 B 在 Y 方面做得好”
3. 在提案中注明哪些元素受哪个参考启发
4. 主参考的 VideoAnalysisBrief 随流水线流动；次级参考记入 research_brief

## 错误处理

| 失败 | 处理 |
|------|------|
| URL 下载失败 | 报告错误，建议：换 URL、提供本地文件、或不带参考继续 |
| 无字幕 | 下载视频，本地用 Whisper 转录 |
| 场景检测失败 | 退回均匀帧采样 |
| 全部分析失败 | 请用户口述参考视频，按标准创意录入继续 |

绝不静默跳过分析步骤。若有失败，告知用户发生了什么以及它对分析质量的影响。
