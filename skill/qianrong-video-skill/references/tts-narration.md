# TTS 旁白：让拆书片开口说话

「密度流 + 旁白」形态的核心工序。适用于**非小说类的知识/拆书题材**——没有人物、不需要对口型，
旁白只要「卡在镜头上」就成立。小说/剧情片不适用（需要角色配音和口型同步）。

---

## 一、先讲清那个硬约束

**60s 内「卡片越多」与「旁白越长」互斥。** 这是本工序最重要的一条。

按 `edge-tts` 实测语速 **≈4.3–4.6 字/秒**（云扬，`rate=+18%`），保守按 4.4 算：

| 卡片数 | 每屏停留 | 需要的旁白 | 60s 够吗 |
|---|---|---|---|
| 22 组（纯密度流） | ~2.7s | ≈100s | ❌ 超 40% |
| **17 组 + 1 主张** | ~3.3s | ≈47s | ✅ 刚好 |
| 12 组 | ~4.6s | ≈35s | ✅ 很宽松 |

**正确顺序是「先出旁白、再写分镜」**，不是反过来。用实测时长反推卡片数：

```
全片旁白字数上限 ≈ 片长 × 4.4 × 0.8      # 0.8 是余量系数
```

60s 片 → 上限约 210 字，分 6 段 → 每段 35 字左右。超了就砍卡或拉长片长。

## 二、标准工序（两步脚本）

### 第 1 步：旁白稿 → TTS → 时长实测

```bash
# 生成剧本模板
python scripts/narration.py init --script audio/script.json

# 编辑 audio/script.json，填每镜的 window 和 text
# 快速迭代（不出音频，秒出结果）
python scripts/narration.py plan --script audio/script.json

# 定稿后生成音频 + 实测
python scripts/narration.py run --script audio/script.json
```

`script.json` 结构：

```json
{
  "voice": "zh-CN-YunyangNeural",
  "rate": "+18%",
  "total": 60,
  "segments": [
    {"id": "s1", "window": [0.6, 9.4], "text": "为什么我们越长大，越不敢想象？..."},
    {"id": "s2", "window": [9.8, 20.6], "text": "创造力不是天赋，它是一种可以练习的能力。..."}
  ]
}
```

**判定规则**（脚本内置）：

| 余量 | 标记 | 处置 |
|---|---|---|
| `>= 0.4s` | OK | 通过 |
| `0 ~ 0.4s` | 紧 | 通过，但建议加余量 |
| `< 0` | 超窗! | **exit 1**，必须改稿或改窗口 |

超窗会直接退出码 1 —— 让它挡住流程，别手动绕过。

### 第 2 步：贴轨 + ducking 混音

```bash
python scripts/mix_audio.py --timing audio/timing.json \
  --bgm assets/bgm.wav --total 60 --out film/assets/mix.wav
```

产出两轨：

- `assets/vo.wav` —— 纯旁白轨，**供验收探针检验"人声确实存在"**
- `film/assets/mix.wav` —— 母带（BGM ducking 后的 + 旁白），**交渲染用**

混音逻辑（都在脚本里）：

1. 每段旁白按窗口起点 + **段内居中偏移**落位（`lead ∈ [0.12, 1.2]s`），避免贴脸开头；
2. `start = min(start, w1 - d)` 硬约束，**绝不允许溢出窗口**；
3. BGM 人声包络平滑（两次 box filter ≈ 三角核），有旁白处压到 `0.16`，间隙回 `0.42`
   （ducking ≈ **8.4dB**）；
4. 峰值 > 0.97 自动整体归一；削波率 > 0.0001 则 exit 1。

## 三、把音频接进 hyperframes

分镜 `film/index.html` 里只需把 BGM 换成母带：

```html
<audio src="assets/mix.wav" data-start="0"></audio>
```

**注意**：`references/design-rules.md` 里的「三层运动」「卡点吸附」规则依然适用，
但节拍网格要用**母带**重新生成（`make_beat_grid.py film/assets/mix.wav`），
否则旁白会把人声频段的脉冲算进节拍，卡点会漂。

## 四、验收怎么测旁白

`audit_video.py` 不直接测"有没有人声"，用两个替代信号：

```bash
python scripts/audit_video.py renders/x.mp4 --total 60 --expect-res 1080x1920 \
  --grid-json assets/beat-grid.json --bgm assets/bgm.wav \
  --json evidence/audit.json
```

- **`--bgm` 传的是「无人声的 BGM 原轨」**，auditor 用它的能量包络作为基线，
  与成片音频对比，**差值区域即旁白存在区**。这条能验证旁白真的被混进去了。
- **`head_over_overall`**（开场音频能量比）仍要看 —— 开场 0.6s 内旁白起音不能太猛。

实测《唤醒创造力》（60s，6 段旁白）：
旁白总长 **47.28s（占片长 79%）**，最小余量 0.50s，**削波率 0.00000**，
26 个重拍平均偏移 **0.033s**，活跃帧率 **0.913**。

## 五、踩坑清单（都很关键）

### 音色与语速

- **中文音色**：`zh-CN-YunyangNeural` 云扬（男/新闻专业，拆书推荐）、
  `zh-CN-XiaoxiaoNeural` 晓晓（女/温暖治愈）、`zh-CN-YunxiNeural` 云希（男/活泼）。
- **语速 `+18%` 是本机验证的甜点**。再快就听不清逻辑连接词，再慢 60s 装不下。
- **语速必须实测，不要估算。** 同样的字数和音色，不同稿子的停顿差异能到 15%。

### 采样率

- **edge-tts 输出 24kHz 单声道 mp3**，BGM 通常是 44.1kHz。
  混音前**必须重采样**（`mix_audio.py` 内置线性重采样）。
  忘了这一步会 `assert sr == SR` 直接挂。

### 能力边界（要跟客户讲清楚的）

- **edge-tts 没有逐词时间戳**，所以**做不到"文字逐个亮起跟读"的卡拉OK效果**。
  本工序做的是**整段对位**：每镜一段旁白，卡片同步翻完。
  要逐词同步必须上付费 API（火山、阿里云都有 word-level timestamp）。
- **合成音没有情绪起伏**。要人味就得真人录音。
- **不需要对口型**——这正是它只适合非小说类的原因（片中没有人物）。

### 版面

- **旁白版卡片数少了，必须给卡片 `min-height`**（本机验证 `13.5cqw`），
  否则矮卡导致下半屏大片留白 —— **`check` 测不出留白，抽帧是唯一手段**。
- **stage 顶距要比无旁白版更大**（旁白版用 `padding-top:13cqw`，首镜单独 `20cqw`），
  否则大标题顶到品牌角标 → `content_overlap`。
- **旁白窗口 vs 镜窗要分开**。镜窗可以略宽于旁白窗（留呼吸），但旁白不得溢出镜窗。
- **卡片入场要早**：压在镜窗前 60% 内入完。曾经最后一张卡 47.84s 才入场，
  导致 46.8s 抽帧时下半屏是空的。

### check 的坑（与旁白无关但同批踩到）

- **`visibility:hidden` 会让 check 误报遮挡。** 给未入场卡片加它，check 会把
  "已隐藏但仍在布局中"的元素当遮挡物，刷出上百条 `text_occluded` / `content_overlap`。
  **撤回，改用 section 级 `autoAlpha:0`。**
- **卡片加密后必然跨镜误报。** 上一镜 `data-duration` 到了但元素仍在 DOM 且与
  下一镜卡片位置重叠 → `content_overlap`。**修法**：给每个 section 在 `b-0.02s` 处
  `tl.set('#'+id,{autoAlpha:0})`，让上一镜真正离开布局。
  （注意：不能用 `tl.to(camLayers[id],{autoAlpha})`，会与相机 scale/y tween 冲突。）
- **对比度警告里 1.16:1 那类是"未入场卡"误报**，不是真缺陷；真正要修的是
  已显示文字的对比度（`--muted` 别用 `#8A857C`，用 `#6E6A62`）。

## 六、依赖

```bash
pip install edge-tts soundfile numpy
```

`edge-tts` 依赖微软的在线语音服务，**需要联网**。若网络受限，
`narration.py plan`（只估时长）仍可用，但 `run` 会失败。

## 七、可复用的旁白稿写法（参考）

拆书片六镜的旁白节奏（《唤醒创造力》实测稿）：

| 镜 | 职责 | 旁白句式 | 字数 |
|---|---|---|---|
| S1 | 钩子 | **反问句开场**，用观众自己的话 | 41 |
| S2 | 定义 | 「不是 X，而是 Y」纠正认知 | 48 |
| S3 | 机制 | 「第一…第二…第三…」**显式编号** | 52 |
| S4 | 策略 | 「先…再…」给动作 | 48 |
| S5 | 练习 | 「每天…」具体可执行 | 42 |
| S6 | 收尾 | 短句 + 停顿，落在主张上 | 31 |

**要点**：每段必须**自成一个完整逻辑单元**（因为整段对位，中途不会重来）；
段末留半拍不要连读，让卡片有翻页的时间感。
