# 광고 영상 분석

원본 관찰을 근거로 새 광고의 대사·행동·화면 전환을 구성하고, 최종적으로 Seedance용 프롬프트로 변환한다. 원본 타임라인은 관찰 근거이며 새 영상의 시간을 고정하는 틀이 아니다. 기본 응답 언어는 한국어로 하되 사용자의 언어 요청을 따른다. 단, 복사해 사용할 최종 프롬프트는 사용자의 언어나 요청한 프롬프트 언어와 관계없이 항상 영어로 작성하고, 대사와 화면 속 문구는 영어로 번역하지 않고 실제로 들리거나 보일 언어 그대로 인용한다. 분석과 프롬프트 작성에 유료 서비스나 생성 API 연결을 요구하지 않는다.

분석만 요청하면 관찰 결과와 재창작에 활용할 관계까지 제공한다. 새 제품·인물·멘트로 재창작하거나 프롬프트를 요청하면 [대사 기반 연출과 Seedance 변환](references/semantic-direction.md)을 읽고 새 대본과 화면의 관계를 먼저 설계한다. 입력이 충분하면 프롬프트까지 완성하고, 새 제품의 기능이나 필수 대사가 빠졌으면 분석을 진행하면서 필요한 정보만 확인한다. 미정 내용을 임의의 제품 효능이나 확정 대사로 채우지 않는다.

아래 절차는 정밀 분석의 기준이다. 짧은 질문·일부 구간 확인·빠른 의견 요청에는 필요한 부분만 적용하고, 표·JSON·검사 스크립트는 사용자가 완성된 분석 산출물을 원할 때 갖춘다.

## 입력과 관찰

- 첨부 영상 또는 접근 가능한 로컬 파일을 사용한다. URL은 실제 영상에 접근 가능한 경우에만 분석한다. 썸네일·설명문만으로 영상을 분석했다고 말하지 않는다. 접근할 수 없으면 파일 업로드를 요청한다.
- 원본 길이, 화면 비율, 스트림 시작 시각과 오디오 스트림 존재를 확인한다. 영상·오디오·컨테이너 길이가 다르면 구분하고, 타임라인의 기준은 영상 첫 프레임부터 마지막 프레임의 표시 종료까지로 한다. 확인 불가능한 값은 null로 둔다.
- 실행 환경에서 직접 영상과 음성을 관찰할 수 있으면 그 기능을 먼저 사용한다. 이미지만 읽을 수 있는 환경(예: Claude Code)에서는 영상을 재생할 수 없으므로 프레임·컨택트시트를 추출해 이미지로 읽고, 음성은 전사 초안이 있을 때만 다룬다. 로컬 추출이 필요하면 [로컬 관찰 절차](references/local-observation.md)를 읽고 `scripts/extract_evidence.py`를 사용한다. 보조 스크립트는 프레임·원본 시각·컨택트시트를 준비하며 컷을 판정하지 않는다.
- 전체를 약 1fps로 살핀 뒤, 샘플 사이에서 설명되지 않는 변화에 주목한다. 손에 있던 물체가 사라짐, 손 자세나 배경 위치의 불연속, 빠른 구도 전환, 짧은 텍스트·제품 노출은 재관찰의 단서다. 밀도가 높은 도입부나 시연은 주변 맥락까지 포함해 다시 본다.
- 의심 구간만 4–8fps 또는 직접 재생으로 재확인하고, 정확한 경계가 필요할 때만 원본 프레임 단위로 좁혀 본다. 1fps나 4–8fps만으로 모든 컷을 검출했다고 주장하지 않는다.
- 재관찰한 구간과 판정 근거를 짧게 기록한다. 팬·가림·조명 변화와 실제 컷을 구분하고 남는 불확실성은 유지한다.
- 오디오 스트림 존재, 추출 성공, 실제 청취/전사는 서로 다르다. 음성을 확인할 수 없는 환경이면 시각 분석을 계속하되 음향은 미확인으로 남긴다. 입 움직임이나 자막만으로 발화 유무를 정하지 않는다.
- 음성 전사는 준비된 로컬 WhisperX 환경을 사용한다. [전사 실행·검토 절차](references/speech-transcription.md)에서 현재 기기의 공용 또는 프로젝트별 Python·모델 캐시를 확인하고 `scripts/transcribe_video.py`로 원문과 정렬 결과를 보존한다. 준비된 공용 환경은 재설치하지 않으며 입력·결과는 현재 작업 프로젝트에 둔다. 화자·발화 방식·전사 정확도는 자동 확정하지 않는다. 환경 설치가 필요한 경우 현재 요청의 설치 승인 범위를 확인한다.

## 타임라인 작성

1. 실제 컷을 기본 단위로 나눈다. 한 롱테이크 안에서는 행동·카메라 변화가 재창작에 중요할 때만 하위 비트로 나눈다. 일정한 3초/5초 단위로 억지로 자르지 않는다. 하위 비트를 편집 컷으로 세지 않는다.
2. 각 구간에 다음을 기록한다.
   - **시간:** 원본 시작 기준 시작·종료 초. 각 시간의 측정/추정 여부.
   - **카메라:** 샷 크기, 높이/각도, 움직임의 방향·속도·변화. 피사체 이동과 카메라 이동을 구분한다. 디지털 확대와 실제 전진을 구분할 증거가 없으면 '화면 확대, 방식 불명'으로 쓴다. 렌즈 수치나 촬영 장비를 추측하지 않는다.
   - **행동:** 누가 무엇을 어떤 순서로 하는지, 제품·손·시선이 언제 어떻게 움직이는지. 시연에서는 시작 상태→접촉/이동→눈에 보이는 변화→결과를 확인한다. 재창작에 중요하면 어느 손으로 어디를 잡고 어디로 옮기는지와 세부 시각을 `action_beats`에 적는다. 가려진 과정이나 생략된 설치·결제 완료·구동 원리를 채워 넣지 않는다.
   - **대사:** 실제 들리는 말, 발화 시작·종료, 화자와 화면 안/밖 여부. 음성 인식 결과는 초안이며 불분명한 부분은 명시한다. 화면 자막을 발화로 옮기지 않는다.
   - **연출/편집:** 표정, 제스처, 제품 노출, 하드컷/점프컷/겹침 전환, 속도 변화, 동작·대사와 맞물리는 음향만 간결히 기록한다. 같은 장소·구도에서도 손과 배경의 불연속이 있으면 컷 여부를 확인한다. 겹친 프레임은 전환 구간을 적고 특정 편집 효과로 단정하지 않는다.
3. 대사는 별도 시간축으로 관리하고 컷에서 ID로 참조한다. 여러 컷에 걸친 문장을 컷마다 복제하거나 임의로 끊지 않는다. 타임스탬프 없는 대본은 대사 내용으로 활용할 수 있지만 정확한 발화 시간의 증거로 쓰지 않는다.
4. 자막·로고·그래픽과 후편집 요소는 별도로 적는다. 이미지 생성에 자막을 구워 넣는 지시로 변환하지 않는다. 훅/시연/증거/CTA 등의 역할과 연출 의도는 관찰 사실과 분리해 해석으로 표시한다. 모든 광고를 같은 구조에 끼워 맞추지 않는다.
5. 음성을 확인할 수 없으면 '미확인', 실제로 음성이 없는 경우에만 '없음'으로 구분한다. 확인 불가능한 카메라·대사·시간은 null 또는 unknown으로 둔다.

## 대사와 화면의 관계

- 대화 중심 영상에서는 숏과 별도로 의미가 이어지는 발화 단위를 구분한다. 한 단위는 여러 문장·화자·컷에 걸칠 수 있다. 한 문장=한 숏=한 생성 클립으로 고정하지 않는다.
- 중요한 제품 공개·시연·리액션·컷마다 무엇과 연결되는지 기록한다. 특정 구절이 시작될 때, 설명하는 동안, 질문이 끝난 뒤, 행동 완료 후 등으로 구분하고 원본 대사 ID·숏 ID와 관찰 근거를 붙인다. 단순한 시간상 겹침과 추론한 연출 의도를 구분한다.
- 화면이 바뀌어도 같은 목소리가 계속되는지, 반응하는 인물이 실제 화자인지 확인한다. 발화 전환과 화면 전환을 동일시하지 않는다.
- 말·행동·음악·고정 시간·미확인 중 해당 장면을 이끄는 요소를 선택한다. 무언 시연이나 음악에 맞춘 컷까지 대사에 억지로 연결하지 않는다. 음성 미확인 상태에서는 대사 기반 관계를 확정하지 않는다.
- 새 멘트를 쓰면 원본 구절과 초 단위 위치를 복사하지 말고 의미상 역할을 새 구절·행동에 연결한다. 제품이 바뀌면 시연 자체도 다시 설계한다. 자세한 기록 형식과 변환 예시는 [연출 가이드](references/semantic-direction.md)에 있다.

## 출력

[출력 규격](references/output.md)을 읽고 다음을 제공한다.

- 길이·비율·관찰 범위 및 핵심 패턴 2–3문장.
- 컷/비트별 `시간 | 카메라 | 행동 | 대사·발화 시간 | 연출·편집` 표.
- 같은 관찰을 담은 JSON. 짧으면 코드 블록으로, 길면 환경의 파일 저장 규칙에 따라 파일로 제공한다. 표와 JSON의 시간 및 내용이 일치해야 한다.
- 재창작에 유지할 패턴 3–5개와 교체할 요소(인물·제품·장소 등)를 짧게 제시한다. 이는 원본 사실과 구분한 제안이다. 새 콘셉트가 없다고 분석을 중단하지 않는다.
- 대화 중심 영상은 분석 문서에 `관계 ID | 원본 대사·숏 ID | 관찰된 연결 | 추론한 역할 | 근거·불확실성` 표를 추가한다. 발화 미확인 또는 관계를 판단할 근거가 없으면 그 한계를 적는다. 이 표를 새 광고의 확정 연출과 섞지 않는다.
- 미확인 사항과 시간 정밀도의 한계를 필요한 만큼만 적는다.
- JSON을 저장했다면 `scripts/check_analysis.py <analysis.json>`으로 시간·참조·구간 연결을 검사한다. 표를 JSON에서 만들거나 같은 스크립트의 `--table <timeline.md>`로 생성해 일치를 유지한다. 이 검사는 관찰 내용의 정확성을 보장하지 않는다.

재창작/프롬프트 요청에는 별도의 연출 계획과 Seedance 프롬프트를 제공한다. 원본 분석 JSON을 새 대본으로 덮어쓰지 않는다. 요청하지 않은 영화 평론, 색보정 이론, 마케팅 장문 보고서나 생성 API 호출은 추가하지 않는다.

## 마무리 점검

- 추출물과 분석 결과는 스킬 폴더 밖에 저장한다. 전체 길이에 걸친 샘플 관찰을 전체 프레임 재생이나 음성 청취로 표현하지 않는다.
- 컷과 비트를 혼동하지 않았는지, 한 구간 안의 여러 전환을 뭉개지 않았는지, 대사와 행동의 관계 및 미확인 사항이 사실로 바뀌지 않았는지 검토한다.
- 재창작에 유지할 특징은 실제 관찰한 카메라·행동·편집 패턴에서 고른다. 실제 조회수나 성과 자료 없이 바이럴 효과를 검증했다고 말하지 않는다.
- 프롬프트의 대사는 새 대본과 일치하고, 전환은 새 구절·행동을 참조해야 한다. 예상 길이와 실제 발화 시간을 구분한다. 생성·정렬을 실행하지 않았다면 대사 동기화가 검증되었다고 말하지 않는다.
