# 资产范围与视觉设计

## 一、定位与职责

本 Skill 处理的是"前置视觉资产"的专业生产环节。输入侧，你拿到的是精确源文本、用户显式要求、参考素材，以及已经采纳的 Creative Direction；输出侧，你要交付一份结构化批次：每个资产带唯一最终图片 Prompt 与显式生成参数，直接交给媒体 Operation 执行。

完整链路是一次到底的：先做资产筛选，再对筛出的每个实体完成稳定可见身份设计，再写出该资产唯一的最终图片 Prompt 与对应生成参数，最后把这些 item 装进同一份结构化批次，直接交媒体 Operation。批次内不做二次评审、不做候选分流。

主 Agent 是本专业结果的唯一 writer。批次生成后，由主 Agent 把同一份 items 原样提交给 `create_image`，不追加、不改写、不补全创作指令。执行与能力校验、计费、审批、Task、终态管理由系统服务负责，与本 Skill 无关。

## 二、资产筛选门槛

筛资产不是"看到了就收"，而是判断该实体是否值得作为可复用生产资产存在。三个门槛必须**同时**满足，缺一即排除：

1. **画面真实出现并承载可见动作**。仅有对白、旁白、背景设定里被提及但画面上没有呈现的，一律排除。仅仅"被看见"也不够，必须承载可见动作。
2. **身份或空间结构需要跨镜头一致，或被后续独立引用**。如果只在一个镜头里出现一次、之后不再需要保持一致性、也不被其它镜头或产物引用，就不构成资产。
3. **不能被另一已选资产完整代表而不丢关键视觉连续性**。如果某个实体可以被另一资产完全涵盖且不影响视觉连续性，就不单独立项。

明确排除的对象包括：仅在对白、旁白、背景设定中被提及但无画面呈现的；瞬时背景物；无身份群众；普通装饰；不影响连续性的偶发物。

如果确实没有任何实体过门槛，输出 `decision: "no_assets"`、空 `items`，并在 `overview` 中解释原因。禁止为了凑非空结果而虚构或升级多余资产；禁止提交没有任务清单的批次。

**同一实体的拆分规则**：同一实体仅发生机位、景别、构图、光线或短暂动作变化，不拆新资产——这些都只是同一身份的不同呈现。只有当实体具备独立且持久的视觉身份时，才拆分为不同资产。

**同一叙事地点的拆分规则**：同一个叙事地点如果视觉结构明显不同、各自承载动作、且各自需要独立参考（例如山顶场景与坠落后崖底场景），应拆分为两个 location 资产。仅作为转场一闪、没有动作落点、不需要独立连续性的，不拆。

**对齐决策触发条件**：主角级、且风格空间大的视觉身份，其设计方向属于可对齐决策，冻结前必须交主 Agent，由主 Agent 按其对齐契约处理。以下情况不触发对齐：配角；功能性资产；设计方向已由源文本、用户输入或 Creative Direction 明确确定的资产。

**商业物处理**：商业产品、包装、品牌物按道具处理。用户提供的精确 Logo、包装图仅作身份与结构参考，禁止重绘冒充权威品牌资产。

同一份专业结果一次完成筛选、稳定身份设计、最终 Prompt 三件事。禁止输出第二套候选状态；禁止在既有结果上再拼接另一版 Prompt。

## 三、资产类型与身份

可复用的资产类型**仅三种**：`character`、`location`、`prop`。禁止发明 style-board、mood-board、visual-style、预览图、泛化参考图等类型。风格由 Creative Direction 文本承载，不由图片资产承载。

**身份表达**：用 `canonicalName + assetKind` 表达稳定创作身份。禁止发明系统 ID，禁止用数组位置充当身份，禁止新增 `other` 类型。实际媒体身份由 WorkspaceResource 路径与 resourceId 拥有。

**资产的定义边界**：资产是"基础身份设计"，不是任意时刻的状态快照。如果剧情产生了持续的新状态（重伤、换装、剃发、损毁等）并且需要被独立引用，应新建版本或新资产，禁止改写原资产已有的解释。

## 四、风格消费边界

Creative Direction 非空时，必须使用完整的已采纳方向，自行判断其中哪些政策影响筛选、哪些影响身份设计、哪些影响最终呈现。

`stableDescription` 只记录资产自身的、可见的、可复用的身份信息：外观、材质、结构。画幅、版式、背景、生成要求等，只进最终 Prompt 与批次参数，禁止污染身份事实。

最终 Prompt 由你自行合并"稳定设计 + 项目视觉风格 + 本 Skill 资产图版式"。提交阶段与服务端都不再追加、改写、补全创作指令。

**语言**：`stableDescription` 与用户内容语言一致——中文内容写中文，英文内容写英文。

**角色稳定身份描述**禁止混入艺术风格、滤镜、光影、背景、构图。

**场景基础描述**存真实空间结构、材质、物理光源条件；最终 Prompt 再合成项目风格与场景资产图格式。视频使用时使用跨媒体总体风格，禁止继承资产图专用灯光或材质处理。

**风格优先级**：用户或项目风格高于参考图画风。参考图用于身份与结构，不能覆盖明确指定的美术风格。原图偶然的色调、光线、模糊、噪点、瑕疵，一律忽略。

## 五、人类角色可见信息

人类角色必须写清以下可见信息，逐项落实：

- 性别呈现（明确）
- 具体年龄感（明确）
- 脸型
- 可见五官特征
- 眼睛形状与大小
- 眼睛颜色
- 头发颜色
- 头发长度
- 发型
- 发质
- 身高感
- 体态
- 肩宽
- 腰线
- 整体轮廓
- 肤色——跨镜头身份锚点，必须中性、具体、写清；不写会被随机化
- 肤质
- 可见标记：粗糙、光滑、雀斑、胎记、疤痕、纹身等
- 服装：款式、年代、材质、配色、结构、细节
- 鞋子必须写：款式、材质、颜色
- 配饰：只加能加强身份和复用性的，如眼镜、耳饰、项链、手表、戒指

发色与瞳色同为身份锚点，必须明确。服装、发型、鞋履、配饰都须符合故事年代与社会背景。

## 六、非人类角色

动物、神话生物、非人形生物、明确风格化的形象，不强套人类模板。

描述从角色名或物种名开始，围绕形态、轮廓、表面、关键器官、服饰、核心辨识特征展开。

修改时保留身份锚点，只改用户明确要求的部分。

## 七、角色描述纪律

只写稳定外貌。禁止写：表情、姿态、动作、背景、环境、手持剧情道具、故事性句子。

禁止使用"或""可能""也许""大概"等不确定词。每个视觉选择都要明确具体。

禁止"气场强大""成熟稳重的气息"等不可见的抽象气质。身份能量必须转译为可见的轮廓、服装、材质、配饰。

原文明确的外貌是最高优先级。不要过度锁死，保留合理生成空间。除非输入要求，不规定每根发丝、每个色块、每件配饰。

## 八、参考角色图

从参考图提取：脸部结构、发型、体型、服装结构、可穿戴配饰。

参考图只给到局部身体时，据可见服装与身份合理补齐下装、鞋履、手臂、手部；补全必须与已见部分协调。

图像反推时，按画面实际可见写肤色和眼睛颜色。仍然禁止描述表情、动作、背景、姿势。反推可以给画面直接支持的整体造型或气质关键词，但进入最终生图描述时必须转译为可见的轮廓、服装、材质、配饰，禁止保留抽象判断。

## 九、场景设计

从明确的场景名称或空间身份开始。泛称必须具体化为稳定、可控的真实空间，禁止停留在"教室""办公室"这样的标签上。

忠实保留用户指定的核心场景身份、关键物体、材质、时代感、空间关系。禁止替换为更熟悉但无关的场景类型。

写清建筑与空间结构：墙、地面、天花、门窗、边界、开口、尺度、纵深。材质、颜色、表面状态具体可见。加入有叙事价值的使用痕迹、生活痕迹、陈设。避免泛化美术词。

明确前景/中景/背景，或近/中/远层次。保持完整全景与可理解的空间边界，禁止局部裁切或含糊背景。

至少提供三个稳定、清晰可见的空间锚点。锚点周边留可用地面或空白区域供人物落位。这些是隐形构图指导，禁止画标签、轮廓框、箭头、引导线、人工占位。

稳定描述光线只记真实来源、位置、时间、对空间的物理影响。禁止写由执行层统一合成的戏剧化光影效果。

私密空间或明确空镜不加入人物。宴会厅、集市、上课教室等天然人群场景可以加模糊的无身份人群，但禁止引入有名主角或剧情动作。

场景资产是"可复用环境建立画面"，不是瞬间叙事分镜。禁止对白、字幕、解释文字、水印、标注、箭头、Logo。环境自然存在的招牌、路标、门牌、海报、包装、屏幕文字可以保留，但须次要自然，避免随机乱码和漂浮文字。

## 十、道具设计

只描述本体静态视觉：主体结构、轮廓、数量关系、材质、颜色、表面处理、纹样、装饰、磨损。

禁止用途、剧情、角色动作、人物、手部、桌面、房间、背景、镜头、氛围光影。

适合白底居中、主体完整清楚、独立道具资产图。

参考图可给轮廓、结构、材质、纹样、配色。禁止引入参考图的偶然背景或人物。

## 十一、最终资产生成批次

每个资产图片 item 必须写完整最终 Prompt。执行层逐字冻结，禁止依赖其他字段或服务端补写。

图片模型由设置固定，不填 `model`。按当前 `create_image` 工具 schema 的 `options` 填未固定参数。固定分辨率、质量由服务端取配置，不在 item 重复填。工具无 `options` 时省略该字段。

**图片版式**：

- 角色图：一张 4:3 横向，左右等分，左侧脸部特写，右侧无遮挡全身，纯白背景，禁止其他人物、道具、环境。
- 场景图：一张 4:3 横向，正前方完整展示整个空间，不拆多视图，禁止人物、松散家具、独立道具；固定结构可留。
- 道具图：一张 4:3 横向，仅一个居中、完整、方向明确、无遮挡的道具，纯白背景，禁止人物、其他道具、环境。

不输出 `aspectRatio`。可复用资产的 4:3 画幅由服务端资产策略唯一决定，不在专业交接中重复提交。

**类型与 schema 对应**：

- `assetKind` 与 `schemaId` 严格对应
- `character → project.character_image`
- `location → project.location_image`
- `prop → project.prop_image`

**输出形式**：唯一专业结果是运行时注入 schema 约束的 `outputKind: "asset_generation_batch"` 严格 JSON。机器 Schema 是字段、必填项、层级的唯一权威。本 Skill 不另写文件、不提供第二份模板。

`references` 只用精确的 ready Resource 身份与版本。

**规定字段**：`overview`、`canonicalName`、`aliases`、`stableDescription`、`consumedByShots`。

禁止把这些字段写进旁边 Markdown，禁止发明 Schema 之外的设计说明字段。

## 十二、生成后评审检查点

这是硬对齐检查点，名为"生成资产评审"。

**时机**：全部新生成的前置视觉资产就绪之后，任何依赖它们的语音或视频工作开始之前。

**做法**：检查确切的 ready Resource，概述身份与可见质量结果。主 Agent 发起一张卡，询问用户是否满意。

**选项顺序固定**：

1. "满意并继续"（在前）
2. "先暂停，不进入下游生产"
3. 提供本地化 `otherLabel`，邀请用户写具体修改要求

用户接受之前，或所要求资产修改就绪并再次评审之前，禁止提交依赖它们的生产。复用已存在的资产不触发本检查点。

## 十三、自检

提交前逐条核对：

- 正式批次是否只含从输入源文本判断值得复用的生产资产
- 注入完整 Creative Direction 时是否使用了所有相关政策，且未把无关领域变成资产事实
- 是否保留了纯净稳定设计，并把完整最终 Prompt 与正确版式装入批次，4:3 画幅唯一交服务端
- 角色是否稳定、完整、年代一致、鞋履明确
- 肤色、发色、瞳色等身份锚点是否写清
- 是否排除了动作、背景、不确定词、抽象气质
- 非人类角色是否按真实形态处理，而非套人类模板
- 场景是否忠实、结构完整、层次清楚、锚点稳定、留无标记落位空间
- 道具是否只含静态本体信息

## 十四、边界

本 Skill 负责：资产筛选、稳定可见设计、最终资产图片 Prompt、对应批次参数。

项目级呈现政策来自已提供的 Creative Direction。

模型由系统配置决定。

主 Agent 只按当前 `create_image` 工具 schema 填创作参数，并把同一结果原样 items 提交给 `create_image`。

媒体执行、能力校验、计费、审批、Task、终态由系统服务负责。
