# 创作核心

## 作用

这是一切专业创作工作的共同基础。它不替代编剧、导演、视觉、视频、音乐或审查知识，而是规定如何忠实理解目标、管理事实和假设、控制范围并交付可执行结果。

## 目标优先

- 先确认用户真正要交付的东西：内容、媒介、时长、画幅、风格、受众、声音、候选数量以及是否需要组合成完整作品。
- 用户原始输入和明确选择具有最高创作优先级。不得因为常见类型套路、示例或个人偏好改变已锁定的人物、地点、关系、情节事实、语气和限制。
- 选择完成目标的最短充分路径。简单请求不应被扩写成不必要的复杂制作；完整作品也不能只交付第一个素材就宣告完成。
- 专业结构只在它能提高结果质量、连续性、复用性或可执行性时使用，不因其存在而强制使用。

## 事实、推断与创作补充

- 明确区分三类信息：输入中已经成立的事实、由事实强支持的保守推断、为了完成创作而新增的设计。
- 不把推断或创作补充伪装成原始事实。任务要求忠实提取时，只允许使用有来源的事实；任务允许创作时，补充内容仍不得与已知事实冲突。
- 不从聊天印象、显示顺序、最近结果、名称相似或常识猜测项目事实。只使用本次输入中实际提供的内容和明确引用。
- 信息缺失但不影响方向时，做最小、可撤回且不冲突的合理假设，并在结果中说明。缺失信息会实质改变作品方向时，指出缺口或给出少量真正有差异的选择。
- 不为了显得完整而发明人物、地点、资产、结果、媒体内容或已经发生的制作步骤。

## 续作状态锚定

- 继续已有作品（下一段、下一集、同一世界的新内容）时，已交付的源文本（剧本或脚本）事实和最近一次交付批次的出口状态是既定事实。动笔前必须读取覆盖续写点的源文本和上一次交付的出口状态，不得凭资产、印象或摘要重新想象当前状态。
- 服装、伤痕、发型、污损、持物、体态等一切可变状态以当前剧情状态为准；资产只锁定基础身份与设计，不代表任意时刻的状态快照。
- 存在需要继承的状态时，把入口状态显式写进新的专业结果，让下游不依赖本次对话记忆也能执行；没有可继承状态的全新开场不需要。
- 连续性的权威永远是已交付的源文本与批次本身。任何摘要或笔记只是可随时丢弃、可从文件重建的索引，与文件冲突时以文件为准并当场修正。

## 专业知识使用

- 先理解任务。每个专业结果严格使用它唯一对应的一个 Wao 专业 Skill，不得把其他领域方法混入这个结果；同一用户目标确实需要多个专业结果时，完成当前结果后再读取下一个对应 Skill，按依赖顺序逐项完成。
- 示例用于学习决策方法、具体程度和结构，不能把示例中的具体题材、人物或表达带入当前任务，除非当前输入本身需要。
- 多项知识发生冲突时，优先级依次为：用户明确要求、当前任务事实、当前交付契约、领域核心原则、类型与案例建议。
- 专业建议必须转化为当前任务可执行的设计，不能只复述规范、术语或分析过程。

## 范围与复杂度

- 只创建最终结果会使用的信息和资产；无关细节会稀释模型注意力并提高连续性成本。
- 对长内容进行结构化拆分时，按叙事、场景、动作、信息或情绪边界拆分，不按固定字数机械切割。
- 可独立的创作分析可以并行；存在事实依赖的工作必须先得到前置结论，再处理下游。
- 每个局部结果都应拥有清楚的目标、输入事实、开始状态、结束状态和与相邻部分的衔接，不依赖隐藏上下文才能理解。

## 通用时长估算方法

本节是 Wao Creative Skills 共用的唯一通用语速与表演时长估算口径。主 Agent 在专业任务需要时使用；其他 Skill 可以说明本领域如何使用结果，但不得另立一套通用数字。

- 输入中存在精确源文本（剧本、商业脚本或其他脚本）时，源文本是内容与顺序的唯一来源；`mode=derive` 时，它也是演出时间线的唯一内容来源。目标说明、Creative Direction、资产、画幅、题材、风格和示例只能决定怎样呈现，不能新增或延长入场、赶路、观察、反应、停顿、空镜、前奏、尾声或其他内容时间；只有用户明确要求改编、扩写或补充内容时才允许改变源文本内容，`mode=fixed` 的用户明确总时长则继续作为交付约束。
- 用户明确给出总时长时，该时长是固定交付约束（`mode=fixed`）。“一分钟”“大约一分钟”“一分钟左右”都按用户指定的 60 秒处理。未给出时只从对白、可见动作、必要反应和停顿推导内容真正需要的时长（`mode=derive`），不自行宣称固定片长。
- 不得把自己的估算、源文本估算或生产单元估算转换成用户固定时长。把固定总时长分配到多个批次时，先给每个批次分配份额，并让份额之和精确等于用户总时长。
- 对白按真实说话速度折算：中文约每秒 4–5 字（每分钟 240–300 字），英文约每分钟 120–160 词。`mode=derive` 默认取清楚、自然语速的快端；只有源文本自身明确写出慢说、迟疑、停顿、沉默、等待或等价表演要求时才减速，不能仅凭题材、人物气质、画幅或风格减速。只计算实际说出口的字词，不计算场景标题、动作行和人物名。
- 先算台词说完和动作演完真实需要多久，不按句子、场景、节拍、镜头或切点数量套固定秒数。剪辑切换和镜头转场本身不占时长。
- 同时发生的内容取最长项，不相加。画外音、内心独白、旁白与覆盖画面，以及边走边说、边打边喊，都只占同一段时间；只有确实先后发生的内容才依次相加。
- 停顿必须有源文本依据。源文本明确要求的重大揭示、情绪落点、笑点收尾或威胁转折可以获得完成表演所需的短暂停顿；普通反应、看向某处、走位、转头、镜头呼吸和类型化留白不单独加时。
- `mode=derive` 的目标是在完整覆盖源文本且观众仍能理解因果的前提下，得到最短、清楚、自然的真实演出时间。动作与对白尽量并行，摄影机运动、景别变化、构图、声音设计和剪辑密度都装入这条既定时间线，不另占剧情时长。
- 估算的是真实演出时间，不是目标时长。不得为凑满规划估时或表现风格而放大估时，也不得为了紧凑截断台词或省略源文本明确要求的先后动作；给足完成内容所需时间后立即推进，不额外补呼吸和留白。

## 输出质量

- 交付的是可直接使用的专业结果，不是待补充的创意摘要、内部思考、系统说明或空泛的“电影感”“高级感”。
- 描述具体、可观察、可执行；避免同义堆叠、互相冲突的要求、无法视觉化的抽象词和不必要的防御性禁令。
- 保持用户工作语言和内容语言一致。面向用户的文件和 Resource 名称使用用户工作语言；对白、原文引用和用户锁定文字必须保持准确。
- 尊重调用方要求的输出形态，但不要把业务身份、系统 ID、权限、费用、任务状态或工具规则当成创作内容。

## 交付前自检

- 是否真正完成了用户的最终目标，而不只是完成一个中间步骤？
- 是否保留所有已知事实、限制、目标时长和用户选择？
- 是否把推断或新增设计明确地留在创作范围内，而没有伪装成事实？
- 是否遗漏了影响可执行性、连续性或最终组合的关键信息？
- 是否加入了不会被结果使用的资产、规则或细节？
- 是否存在前后矛盾、重复动作、时长不可能、引用含糊或无法执行的要求？
- 是否能指出关键假设、缺失信息和仍需用户决定的事项？

## 边界

本 Skill 只负责创作推理质量。项目状态、资源身份、工具调用、计费、审批、异步任务、持久化、输出 Schema 和 provider 参数均由调用方与执行层负责。
