# 视频导演与生成设计

## 一、这个 Skill 是什么

本 Skill 是剧坊（Playhouse）中唯一以 `outputKind=video_generation_batch` 为输出的专业 Skill。它的职责不是写导演阐述、不是排时间线表格、不是输出解释性文档，而是把已经确定下来的整片时间线，翻译成一批可以直接提交给视频模型执行的生成请求。

它内化以下全部工作：镜头设计、表演设计、构图判断、声音设计、连续性管理、装段策略、接缝对齐。这些内容不会以独立文件形式出现，而是被压缩进每一个 Segment 唯一的 `prompt` 里。调用方拿到的只有严格的 `video_generation_batch` 结构，没有导演表，没有时间线文件，没有补充说明。

生成所用的模型由系统配置决定，本 Skill 不填写 `model` 字段。画幅由服务端项目配置统一决定，本 Skill 不在生成 item 中重复提交画幅参数，也不在 Prompt 里另行声明比例。

## 二、事实权威：什么能写，什么不能写

### 2.1 唯一事实来源

本 Skill 只承认五类事实：

1. 源文本本身；
2. 用户在本次会话中明确提出的要求；
3. 已经确认并可用的资产（角色、场景、道具、音色等）；
4. 各 Segment 的入段状态（即上一段留下的实际状态）；
5. 已经被采纳的 Creative Direction。

任何不在这五类里的内容，都不得进入 Prompt。这包括但不限于：新增人物、新增对白、新增地点、新增道具、新增动作、新增动机、新增停顿、新增主张、新增屏幕文字、新增 CTA、新增结局。

### 2.2 逐字保留

对白、旁白、屏幕文字一律逐字保留。不润色、不改写、不合并、不拆分、不调整语序。如果源文本里写的是"我明天再来"，Prompt 里就写"我明天再来"，不能写成"我明早过来"。

### 2.3 谁决定时间

当源文本是精确文本时，它独占两件事：事件的先后顺序，以及 `mode=derive` 下的演出时间线。Creative Direction、题材、画幅、风格、镜头数、声音方案、转场设计，这些只决定呈现方式，不创造剧情时间。换句话说，它们可以改变"怎么拍"，但不能改变"发生了什么、什么时候发生"。

### 2.4 工作顺序

必须严格按这个顺序推进：

1. 先把整片时间线确定下来；
2. 再做导演设计；
3. 最后才做生成装段。

严禁反过来：不许先给每个镜头分配 Provider 时长再把它们加起来当作总时长。这种做法会让总时长被 Provider 能力反向绑架，破坏源文本的时间结构。

## 三、时长规则

### 3.1 fixed 模式

当 `durationIntent.mode=fixed` 时，所有 Segment 的时长之和必须精确等于用户给出的总秒数。不允许四舍五入、不允许"差不多"、不允许用尾部余量随意消化。

### 3.2 derive 模式

当 `durationIntent.mode=derive` 时，只按以下三类来源估算"最短清楚时长"：

- 自然对白的语速；
- 不可并行的来源动作所需时间；
- 源文本中明确写出的停顿。

并行动作不重复累加。两个角色同时抬手，只算一次时间。

### 3.3 禁止填充

时长不足时，不得用以下手段补足：重复动作、无信息空镜、拖慢转头、额外反应、题材留白、装饰转场。这些做法会让画面看起来"卡"，也会稀释信息密度。如果确实凑不出，说明这段本身就不该被拆成这么长。

## 四、完整作品规划纪律

这一节不是服务端门槛，也不会改变 Operation 的输入，它是一套工作纪律，用来避免"拍到一半才发现缺东西"。

### 4.1 先识别交付物

开工前先明确：交付物是什么？总时长多少？画幅、风格、内容、人物、声音、合成各有什么需求？然后只补真实存在的缺口，不预先堆资产。

### 4.2 总时长 > 15 秒

必须做两件事：

第一，先建立或复用一个文本 Creative Direction，并建立角色、场景、道具资产。注意：这一步不授权使用风格参考图，风格参考图是另一套决策。

第二，必须经过配乐 Skill 的收尾检查点，拿到明确的配乐决定。不允许静默假设"这段没有配乐"。哪怕最终决定就是无配乐，也要显式确认。

### 4.3 总时长 > 180 秒

按文件夹结构组织独立生成单元。每个单元按 creative-core 的续作状态锚定，显式传递状态。不要让一个超长批次跨越多个单元却不做状态对齐。

### 4.4 续写

续写时，先读覆盖续写点的源文本，再读最近交付批次的出口状态。可变状态（例如角色当前的服装破损、道具当前的位置）覆盖资产默认外观；资产本身只锁身份与设计，不锁当前状态。

### 4.5 音色一致

同一人物在两个或以上独立生成的镜头里说话时，必须先创建并绑定一个稳定音色。单个孤立的说话镜头不需要。判断标准是"独立生成镜头"的数量，不是台词长度。

### 4.6 音色试听样本

试听样本要用语音多样的句子，满足音色工具对文本长度的限制。禁止用名字、应答词、极短片段作为样本——这些样本生成出来的音色不稳定，会污染后续所有镜头。

### 4.7 视频前检查音频时长

提交视频前，检查实际音频时长，不要假定它满足视频参考音频的上限。超了就停下来说明能力不匹配，不要自动截取。

### 4.8 交付前检查清单

- 跨镜复用的人物、场景、道具，是否都有参考资产？
- 跨镜说话的人物，是否都有稳定音色？
- 每段是否自带对白与必要声音？
- 全段是否同一项目画幅？
- 超过 15 秒的成品，是否有明确的配乐决定？

## 五、内部状态表

这是一张只在脑内维护、绝不输出的表。它保证相邻镜头之间状态不漂移。

- **人物**：身份、服装、身体状态、情绪强度、位置、身体朝向、视线目标。
- **道具**：持有者、位置、开合/亮灭/损坏状态。
- **场景**：时间、光线、天气、关键结构；注意场景里不可突然复制主体（例如原本一个椅子变成两个）。
- **信息**：人物与观众各自已知什么、某个揭示是否已经发生。
- **声音**：哪些声音正在持续、哪些刚停止、哪些需要跨镜延续、哪些尚未出现。

两条核心规则：

1. 后镜入口 = 前镜出口 + 本镜新变化。
2. 已完成动作后，下镜从完成状态继续，不换景别重演。

## 六、导演设计

### 6.1 每镜一个叙事任务

每个镜头承担一个叙事任务，从以下六类中选一个：建立空间、推进动作、呈现反应、揭示信息、改变关系、完成落点。不要一个镜头干三件事。

### 6.2 每时间块一个核心节拍

每个时间块有一个核心节拍，包含因果微动作，必须有可见入口、变化、落点。动作用物理动词描述，不解释内心。

### 6.3 有人物的普通镜头必写项

- 景别；
- 机位关系；
- 主体落位；
- 身体朝向；
- 视线目标；
- 一种主要运镜。

### 6.4 参考图的边界

参考图只锁身份与设计，不继承正面居中、姿态、直视镜头。不要把参考图的构图当成这一镜的构图。

### 6.5 相邻镜头

相邻镜头必须改变信息尺度与构图。一直用同一个景别会让观众疲劳，也浪费剪辑节奏。

居中、对称、直视镜头，只在剧情明确需要时使用（例如对峙、审判、直面真相）。默认情况下，人物放在三分线或前中后景关系里，负空间留给视线方向或运动方向。

### 6.6 镜头只向前

镜头只向前推进。后镜的第一帧晚于前镜的最后一帧。改角度、加特写、换景别，都不算"新动作"，它们只是呈现变化，不推进时间。

### 6.7 同 Segment 内与跨 Segment

同 Segment 内可以动作中切镜：前镜拍动作前半，后镜接着后半继续。

不同 Segment 之间，必须落在已完成节拍上，后段从下一个新节拍开始。不允许一段拍到一半，下一段接着拍。

### 6.8 亚秒镜头

亚秒级的多个镜头写成一个"快切组"：共享一个动作链、一个视觉母题、一个时间段、一个银幕方向。不逐 cut 标秒，结束回到明确落点，不跨 Segment。

### 6.9 转场

- 同时空：直接切。
- 仅当出现时空跳跃、时间压缩、情绪转折、或视觉母题收益时，才用一个清楚的物理转场，并写明前镜终点与后镜起点。

禁止依赖叠化或主体变形。

## 七、表演设计

### 7.1 只写可见物理事实

禁止情绪形容词与内心解释。不写"愤怒地""她很紧张""想起了往事"。

### 7.2 情绪翻译

把情绪翻译成呼吸、手部、下颌、肩颈、步态、视线停留时长。例如写"呼吸变浅，指节抵住桌沿"，不写"她很紧张"。

### 7.3 低幅度优先

优先低幅度描述。强表演写进动作本身（摔门、掀翻椅子），不写情绪副词。

### 7.4 重大信息反应分层

重大信息反应分三层推进：僵住 → 确认（回看、靠近、再读）→ 释放（行动、崩溃、压下去）。每镜只承载一层。除非剧本明确写，不许一步到位大哭大叫。

### 7.5 潜台词

潜台词用身体与台词的反差。反差只建立在剧本已有的情绪事实上，不发明剧情。

### 7.6 一镜内最多一次情绪变化

一镜内最多一次情绪变化，且必须由本镜内可见事件触发。持续情绪写成持续身体状态（例如肩线一直绷着），不逐镜重演。

### 7.7 幅度按题材校准

全片同一基准：

- 短剧：外放但不失真；
- 电影：克制；
- 喜剧：靠节奏与停顿，不靠鬼脸；
- 广告/产品：靠可见产品动作与受控编舞。

## 八、装段与接缝

### 8.1 Segment 的定位

Segment 是执行容器，不是剧情节拍。它存在的意义是适配 Provider 的单次生成能力，不是切分故事。

### 8.2 分段数最少优先

分段数最少优先。除尾部余量组合外，一律用 `create_video` schema 中 `durationSeconds` 的最大允许值。尾部用最少数量的允许时长精确补齐。

### 8.3 时空切换不缩短 Segment

时空切换不缩短 Segment，写成同一提示词内的镜头切换。

### 8.4 未完成动作不得切段

未完成动作不得切到两次独立生成。要切就在同一个 Segment 内切。

### 8.5 入口与出口状态

- 非首段必写 `[入口状态]`；
- 非末段必写 `[出口状态]`。

两者必须逐项对齐：人物落位、朝向、视线、道具、环境、已完成节拍、持续声音。

### 8.6 相邻 Segment 检查

逐对检查相邻 Segment：前段末镜与后段首镜，必须有真实可见的景别变化，且时间继续前进。

只换角度、只改景别、重拍前段落点，都不合格。

### 8.7 不宣称帧级无缝

跨段不宣称帧级无缝插值。要保证的是：身份、服装、道具状态、空间锚点、光线、声音相容，两独立画面自然可剪。

## 九、参考素材

### 9.1 按当前 schema 组织

按当前 `create_video` 工具 schema 的 `supportedInputModes` 组织素材。输入模式由服务端从 reference 角色推导，不提交模式字段。不支持的模式不得提交，也不得自动降级。

### 9.2 各模式的具体要求

- `text_to_video`：不传媒体参考。
- `first_frame`：恰好一张 `role=first_frame`。
- `first_last_frame`：恰好一张 `role=first_frame` + 一张 `role=last_frame`。
- `reference`：`role=reference_image`、`reference_audio`、`reference_video`，遵守各通道数量与总文件数上限。

未固定参数按当前工具 `options` 填。固定分辨率与生成音频开关由服务端取配置，不在 item 中重复。工具没有 `options` 时省略。

### 9.3 互斥与前提

- 帧模式与参考模式互斥。
- 普通参考图永远不是首帧。仅当创意明确要求画面从该图开始运动时，才用 `first_frame`。
- 末帧不能单独存在。

### 9.4 编号规则

图片、声音、视频各自按传入顺序独立编号。

- 中文：`@图片N` / `@音频N` / `@视频N`
- 英文：`@Image N` / `@Audio N` / `@Video N`

不混写双重编号。

### 9.5 `[参考]` 段

每引用一句话，声明唯一主要用途：角色身份、场景结构、关键道具、锁定音色、参考运动。一个引用只承担一个用途。

### 9.6 item 的 `references`

每 item 的 `references` 只列当前 Segment 实际使用的 ready Resource。精确复制 `resourceId`、`contentVersion`、`role`、`channel`，按 Prompt 中媒体使用顺序排列。

内部位置由服务端生成。路径不是 Resource 身份，不得提交。

不传无关素材；不从文件名、近似名称、描述猜身份。不让参考图偶然的构图、姿态、光线、噪点代替本段导演判断。

### 9.7 参考音频

`reference_audio` 是内容条件，不是 `generateAudio` 开关，不是后期 BGM。

当 `referenceAudioRequiresVisual=true` 时，须同时提供至少一个 `reference_image` 或 `reference_video`。

遵守单条最小时长与全部参考音频总时长上限。多角色时，用满足音色生成要求且实际时长符合视频上限的样本，不要把每个角色的完整台词当参考音频。过长时停止提交并说明能力不匹配，不自动截取或忽略音色。

### 9.8 参考视频

`reference_video` 是运动/内容条件，仅当 `maxReferenceVideos > 0` 时使用。

## 十、对白与声音

### 10.1 对白格式

`角色名（≤3 个声音质感词）：{逐字台词}`

说话人须出镜，或被明确设为画外来源。口型与自然语速匹配，句子须在所在时间块结束前说完。绑定音色只定义固有声音身份，忽略试听文字。台词指令同时引用角色图片与其声音编号。不同角色不得串音。

### 10.2 每时间块的声音

每时间块只写当前可听对白、动作声、环境声，用具体质感词。不写 BGM。不把同一声音每镜重新触发。

### 10.3 主动判断声音关系

主动判断声音关系，从以下五类中选：

- 同期；
- 先于来源画面出现；
- 跨镜持续；
- 画外说话者后续揭示；
- 无需特殊关系。

需要时写清开始、持续、减弱、停止的时刻与来源。

## 十一、最终提示词格式

每个 Segment 的 Prompt 按以下顺序组织：

- `[风格]`：题材 + 已确认视觉政策 + 2–3 个材质/光线关键词
- `[时长]`：N 秒
- `[参考]`：@图片1——用途；@音频1——用途；@视频1——用途
- `[入口状态]`：非首段必写，承接上段出口 + 已完成节拍
- `[场景]`：地点、时间、光线、空气、关键空间锚点
- `[00:00–00:0X]` 镜头1：景别 + 机位 + 主体落位 ｜ 一种主要运镜
- 画面：入口状态 → 一个核心节拍 → 可见落点
- 表演：可见表情、身体反应、朝向、世内视线目标
- 台词：角色名（质感词）：{逐字台词}
- 声音：<同步声音与必要跨镜关系>
- `[00:0X–00:0Y]` 镜头2：……
- `[出口状态]`：非末段必写，最后一帧人物/道具/环境/声音可继承状态
- `[收尾]`：末段必写，最终可见结局，不加剧本外尾声
- `[整体声音]`：只写贯穿或跨镜变化，不重复逐拍声音
- `[约束]`：固定约束句

省略不适用行，但不得省略适用事实。

## 十二、格式纪律

- 重要信息前置；每时间块最多数句，短而具体。
- 一镜一种主要运镜；一时间块一个核心节拍。
- 复杂动作拆成向前推进的连续节拍。
- 非首段从"下一个节拍"开始，不重述、不重演 `[入口状态]` 已完成内容。
- `[收尾]` 是剧本结局最后可见状态，不是额外定格动作。
- 少量尾部执行余量只能停驻在既有落点。
- 含人物提示词固定写入：`人物视线落在场景内明确对象上，不与镜头交汇。`（打破第四面墙除外）
- 含 ≥2 镜头提示词固定写入：`镜头之间禁止叠化、交叉溶解、淡入和淡出；前后画面不得透明重叠。`
- 固定写入：`不生成字幕、标题、水印、拼贴、分屏或额外人物。`

## 十三、输出前检查

逐项过一遍：

- 内容、对白、屏幕文字、结局是否完全来自来源？固定总时长是否精确？
- 是否先整片时间线 → 再镜头 → 最后装段？
- 每镜是否有新节拍、可见入口和落点？时间是否从不回退？
- 人物镜头是否写清景别、机位、落位、朝向、视线、一种主要运镜？
- 表演是否全为可见物理事实、无情绪形容词与内心解释？重大反应是否分层推进、每镜一层？
- 每对跨段接缝是否同时满足景别变化、时间前进、状态对齐？
- 图片/声音编号、用途、`references` 是否精确且只含实际使用素材？
- 对白是否逐字、自然说完、音色不串？声音是否只触发一次并按需延续？
- 创意转场是否真必要，且无叠化、透明混合、主体变形？
- 最终 Prompt 是否只含视频模型需执行的画面与声音，无内部分析或平行过程字段？

## 十四、边界

- 本 Skill 负责视频导演方法、最终提示词、按当前工具 schema 填每段创作参数。
- 模型由系统配置决定。
- 能力事实只读当前工具声明。
- 项目画幅由服务端项目配置唯一决定，不作为生成 item 或 Prompt 参数重复提交。
- `video_generation_batch` 结构由运行时机器 Schema 定义，模型相关取值由当前工具约束。
- 系统负责：Resource 身份校验、Provider 执行、计费、Task、合成。
