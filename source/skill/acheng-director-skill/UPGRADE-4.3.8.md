# 4.3.8｜专业提问、视觉资料与生产接力修复

本版基于4.3.7开发，保留原工程流程与参考图修复。两份用户原文完整归档并记录SHA-256；原件和已安装版本不在本次修改范围。没有使用子代理或 skill-creator，没有调用付费媒体模型。本说明的“纳入”指提取可用方法并改写，不代表原文全部主张得到验证。

## 采用的结构

**Markdown解释决策，JSON保存可检索条目，真实媒体保持视觉证据，原脚本守工程合同。** 不需要额外数据库服务或向量检索。现有规模下，明确的模块/问题/媒介/表面筛选已经能缩小上下文；以后资料规模或同义表达检索确实成为瓶颈时，再考虑额外检索层。

- 36张问题卡：每张有触发条件、现成输入、两个具体问题、条件分支、原owner/字段、完成条件和不采用的原文硬规则。
- 31个视觉条目：4光学、3影像纹理、3柔化、6光色组织、5动画表现、3渲染观感、7材质。
- 7种材质：皮肤、粗糙铁面、抛光钢、干织物、丝绸、木面、液面；每种区分写实、赛璐璐和水墨表达。
- 问题JSON为唯一编辑源，生成7份人读Markdown视图；包检查拒绝JSON与视图失步。视觉条目直接检索，不再手抄第二份内容表。
- 默认一次检索2张卡，最多4张；没有具体范围只显示目录；无法匹配不偷偷转用其他媒介。多条视觉结果是候选，不是自动组合的全套模板。

当前使用入口：[局部决策](references/115-directed-decisions.md)、[视觉资料手册](references/116-visual-reference-library.md)、[提问数据](data/director-inquiries.json)、[视觉数据](data/visual-style-materials.json)。

原26个局部场景保留，新增群戏、动画变形、材质、风格/曝光、声音、累积状态6个具体场景，共32个。不是新增32道必走工序：已经有答案且输入未变时直接复用；没有对应问题就不读该节。

例：弱模型遇到“丝绸看起来像塑料”，先取已有材质/颜色、光源与景别，问“哪道褶皱朝向光源，亮带是否顺它变化并保留原色”。写实时用表面响应，水墨时用墨面和留白。它不必先回答“如何提升整体高级感”，也不能因为库里提到了雨和金色就自行增加这些事实。

## 从条目到资产、关键帧、H3

1. assets 把选择展开到原 asset_cards：七步第4步光路/材料、第6步可见细节，以及完整 prompt；适用且获准时同步角色/场景登记描述。
2. 角色图守身份，场景图守结构，道具图守物件，关键帧守当前单一相位。资料条目不占参考图槽位；已有STYLE_MOTHER仍按原批准/哈希流程。
3. shots 描述本镜实际可见的部分和真实参考需求；model 在原 style、subjects、references、逐镜正文中消费对应事实，不能只输出MAT/OPT等编号。
4. 动画条目的 terms 路由回原88术语及展开证据；不新增第二套曝光策略或动作字段。
5. 回读磁盘中的图像/H3正文、同源映射和上传卡；原模式锁、媒体签名、版本、状态、哈希和缺图草案机制继续执行。

本次新增的测试包含一次实际文本编译接力：在既有文戏样例副本中选干织物条目，以已有灰色工装、东窗光和当前状态落入原字段，再导出 .image.txt 和 .h3.txt 并回读。它证明描述进入编译结果，不证明真实生成画面达到预期；原样例文件不被改动。

## 有意不照搬的内容

| 原文提法 | 本版处理 |
|---|---|
| 每次必须否定前两个创意、第三个才合格 | 初始方案不满足当前标准时才找替代；直接而合乎人物的动作允许保留 |
| 固定8–12秒反转、每10秒沉思、每击8帧空白 | 根据事件、观看需求和既有时序决定，不增加新计时阈值 |
| 强制公开scratchpad、六轮审问全部执行 | 只交可复核的采用结果、来源和字段；不要求内部思维链或答题全文 |
| 生理五轨全开、微动毫米数、固定乳酸/疲劳阈值 | 选择当前可见/可听且设定支持的少量信号，状态来自真实剧情事件 |
| 所有攻击从脚底发力、所有场景固液气齐备 | 按实际支撑、主体机制、效果family和现场介质处理 |
| 强制闪白、2–3帧停顿、固定慢速比例 | 只有可读性和批准风格需要才使用，仍受原五阶段timing约束 |
| 损坏只能增加、天气必须侵入 | 保留合法清洁、修复、恢复、跳时；不凭资料库新增天气或伤害 |
| 大师/器材/引擎词保证稳定、零畸变、零漂移 | 名称只作来源检索别名，以具体可见目标表达；效果必须后续看真实媒体 |
| 所有镜头强制镜头+胶片+滤镜+大师四件套 | 仅补当前缺口；同时成立的组合也必须服从批准媒介与身份/状态 |
| 字多必然不漂移，YAML自填PASS等于验收 | 原详细度下限继续保留，但不把它当艺术保证；机器状态来自原脚本真实回执 |

原文的“符号化物件”保留为已存在物件的具体使用与关系变化，不自动添加象征道具；“声画对位”保留为有明确观看目的的选择，无配乐、同步情绪或静默也可以成立。

## 技术表述校准的依据

这里只用于校准绝对化主张，不把厂商产品说明变成生成模型能力保证：

- Tiffen官方扩散指南把柔化、高光扩散和反差变化作为不同观感维度，因此本库不沿用“任何条件下绝不影响暗部”的承诺。参见 [Tiffen Diffusion Guide](https://tiffen.com/pages/diffusion-guide)。
- ARRI的Signature说明使用低畸变等相对描述；本库以保留关键几何为设计目标，删除“零畸变”的绝对保证，并把Master/Signature保留为不同来源别名。参见 [ARRI Signature FAQ](https://www.arri.com/en/cine-lenses/signature-lenses/signature-primes-zooms/arri-signature-lenses-faq)。
- Khronos的PBR资料把材质表达建立在具体参数和光照交互上；本库因此要求描述表面响应，器材/引擎名字不当执行回执。参见 [Khronos glTF PBR](https://www.khronos.org/gltf/pbr)。

人物、作者、工作室和胶片归类来自用户资料，仅作为该文启发的检索线索，不声称概括其所有作品或已逐一验证所有品牌特性。更细的适用/拒绝项随每条数据记录保留。

## 验收与限制

原资料库接入增加一个测试文件、五个验收测试；用户随后扩展为全面流程及三条参考链审查，又增加一个工作流测试文件并扩展受影响的既有验收。最终实际数量和结果见 [包验收](reports/package-acceptance-v4.3.8-final.json)、[测试日志](reports/tests-v4.3.8.txt)、[源文件与保留范围](reports/upgrade-integrity-v4.3.8.json)。历史4.3.7及更早报告只对其标明版本有效。

完整功能追溯、实际缺陷、修复和自动化边界见[4.3.8审查报告](reports/v4.3.8-functional-review.md)。本次还修正了示例的重复人物/伤势/道具事实，并重新编译它们；前述库接力测试仍只修改临时副本，不等于整个升级没有修改示例源。

没有进行弱模型对照出片实验，所以“更便于局部执行”是已实现的结构设计，“弱模型必定拍得更好”不是本次验收结论。格式、来源、路由和实际文本消费能被验证；艺术质量、人物稳定性和听觉表现仍需真实媒体与人工审看。
