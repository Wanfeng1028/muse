# 111｜H3 最终格式编译门 v4

## 目的

H3 正文先由 Acheng Director 按剧本、ShotSpec、表演、动作、视效、尺度和连续性事实完整编译，再执行一次最终格式编译门。该步骤只修正可验证的 H3 结构，不重写创意，不删减工程参数，不缩短 `detailed_description`，不把完整镜头改成摘要。

最终格式编译门不是第二个 H3 编译器，也不是新的生产真值。它只负责把已经批准的生产事实装入已安装 `h3-prompt-writing` 要求的最终载体，并在无法安全推断时阻止交付。它必须发生在每个 Segment 的最后：创作与专业增强完成 → 非删减校准 → 原子写入 `.h3.txt` → 回读最终字节与真实参考素材 → 生成哈希绑定回执 → 才能交付。

## 固定处理顺序

1. 先锁定创作正文。角色身份、场景几何、工程参数、受力、速度、镜头路径、声音时序和连续尾态都视为不可丢失事实。
2. 保持已锁定模式，根据真实本地素材完成绑定；不存在时保留拟定映射和明确阻塞草案，不伪造正式引用，也不默改 T2VA。
3. 把内部资产 ID 映射到 H3 标签：`<Subject N>` 表示可复用可见内容，`<Picture N>`、`<Video N>`、`<Audio N>` 只表示真实上传素材或明确的帧、视频、音频来源。内部 `CHAR_*`、`SCENE_*`、`PROP_*` ID 只能保留在 manifest，不能进入模型正文。
4. 保留固定字段顺序。基础模式使用 `integrated_multimodal_description`、`overall_soundscape`、`non_diegetic_music`；Ref2VA 使用六字段，不能增加第七个负向字段。
5. 将镜头标题整理为 `[Shot 1]`、`[Shot 2] At 00:03.500, ...`。第一镜不在标题中放时间范围；时间、镜头参数和工程证据仍保留在正文自然语言中。
6. 将每句对白绑定稳定的本段 `(S1)`、`(S2)` 编号，正文使用 `<d>[Language] 原始对白</d>`。只整理包装，不翻译、改写、补写或删掉用户确认的对白。
7. 把真实屏幕文字写入英文双引号。反引号、内部代码、预留占位符和未解析标签不能进入模型正文。
8. 把全局声音整理为一个连续段落：`overall_soundscape` 保留 1–4 个英文句子，`non_diegetic_music` 保留 1–3 个英文句子。合并句子时使用分号或并列结构保留所有拟音和时序，不删除声音事实。
9. 再次检查 Ref2VA 的 `detailed_description`。新任务按时长与复杂度动态计算最低词数（默认 10 秒段为 2,000）和目标词数（默认约 2,400），工程数值和参数不计作删除理由；不足只能 partial，不能 accepted。
10. 计算最终正文的字段、标签、镜头、对白、声音和长度证据。任一项不能从 production 真值或真实上传清单证明时，返回格式失败和修复路径。

## 磁盘最终文件回读门

`scripts/h3_final_format.py validate_h3_file` 仍是最终文件结构门；4.3.6 另由[114 联合交付门](114-reference-binding-delivery-v4.3.6.md)检查正文、同源绑定、逐段卡与 manifest。最终字节、素材哈希、标签、切点、对白与声音检查不变。无真实媒体只能保存阻塞草案；未经用户明确授权不得换成基础模式。结构 PASS 不单独代表上传交付完整。

标准编译器会为每个文件同时写出同名 `.check.json` 和 `.acceptance.json`。手工或外部生成器必须先建立同样的 revision-bound contract，再运行：

```bash
python scripts/h3_final_format.py path/to/SEG_01.h3.txt --contract path/to/SEG_01.h3.txt.check.json --report path/to/SEG_01.h3.txt.acceptance.json
```

返回 `format_pass=FAILED` 时，该 Segment 只能进入修复或 `partial`，不能被交付视图改写成 PASSED。

## 工程参数保留规则

下列内容属于有效生产事实，格式编译门必须保留：Cartesian 坐标、世界方向、焦段、光圈、帧和时间、速度、加速度、RPM、Hz、Newton、MPa、摩擦系数、材质参数、遮挡关系、质量支撑、受力传递、慢动作比例和退出条件。

它们可以从表格或标题改写成 H3 能读懂的自然语言句子，但不能因为“模型更喜欢自然语言”而删除。工程参数仍必须服务于可见画面、可听声音、动作因果、摄影机路径或验收证据；不能凭空新增未锁定事实。

## 说话清晰度规则

模型无法稳定理解对白时，优先检查以下项目：

- 每个说话人首次发声前有姓名、`(Sx)`、年龄类型、声线、音高、语速和发音状态；
- `<d>` 内只放语言标签和逐字原台词，不放镜头说明、动作说明或括号解释；
- 每句对白只对应一个明确说话人，避免把多个角色的台词塞进同一个 `<d>`；
- 台词周围明确写出嘴型、口腔开合、重音、停顿、呼吸和声音方向；
- 角色高速移动、碰撞、尖叫或同时发声时，写清哪一句先发生、是否重叠、是否被动作声遮盖；
- 不用“说得清楚”“声音自然”这类空泛保证替代具体的发音、节拍和收音事实；
- 不把对白放入 `overall_soundscape` 或 `non_diegetic_music`。

格式编译门只能保证对白结构和可读指令完整，不能宣称生成模型一定产生可用音频。最终口齿清晰度仍需要真实媒体人工听检。

## 失败处理

格式失败时输出 `format_pass=FAILED`、失败字段、证据和修复游标；不得通过压缩正文、删除工程参数、改成 T2VA 或伪造参考标签来绕过门禁。通过后记录 `format_pass=PASSED`、最终字段顺序、引用清单、对白清单、词数和 `visual_status=UNVERIFIED`。
