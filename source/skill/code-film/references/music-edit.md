# 音乐驱动剪辑：拿到一首歌，怎么剪

## 1. 顺序：先音乐，后画面

有音乐的片子，音乐就是骨架。先把音乐分析透，再往上挂画面。反过来做，最后一定要为了对拍大改画面。

你听不到声音，所以要靠分析数据来「听」，再请用户用耳朵确认关键判断（比如高潮到底在哪）。

## 2. 分析音乐

```bash
python <skill>/scripts/analyze_music.py public/music/bgm.mp3 --fps 30 --out docs/music.json
```

输出包含：
- `bpm`、`framesPerBeat`：速度和每拍帧数。
- `beats`：每一拍的时间、帧号、所属小节、在小节中是第几拍（强拍的判断是估算）。
- `sections`：按能量自动切出的段落，带能量等级（low、mid、high）和建议名称（intro、build、peak、break、outro）。
- `energy`：每 0.5 秒一个能量值（0 到 1）。
- `accents`：最突出的重音点（适合放撞击、切换、揭示）。
- `breaks`：能量骤降的小节（空拍、停顿，适合放黑场、静止、单个元素）。

**分析结果的可信度**：节奏稳定的流行、电子、摇滚音乐很准；自由节奏的钢琴、古典、氛围音乐可能不准。BPM 明显不对时（比如差了一倍），用 `--bpm 90` 手动指定速度，脚本只负责找拍子的位置。段落边界拿不准时，把 `sections` 和 `energy` 的摘要讲给用户听，请他确认「高潮是不是从第 X 秒开始」。

## 3. 听懂音乐的结构

常见的流行结构：前奏、主歌、预副歌、副歌（高潮）、间奏、桥段、尾奏。电子音乐常见：前奏、铺垫（build）、爆发（drop）、间歇（break）、再铺垫、再爆发、尾奏。

**映射规则：**

| 音乐 | 画面 |
|---|---|
| 段落边界 | 场景或幕的边界，换环境、换色调、换节奏 |
| 能量曲线 | 画面密度曲线：能量高时镜头短、动作多、画面亮；能量低时长镜头、少元素、留白 |
| 前奏 | 建立世界，钩子，慢慢给信息 |
| 铺垫 / 预副歌 | 蓄力：加速剪辑、画面收缩、元素聚集、张力上升 |
| 爆发 / 副歌第一拍 | 最重要的揭示：片名、核心画面、产品亮相 |
| 间歇 / 空拍 | 黑场、静止、一个孤零零的元素、一句最重要的话 |
| 重音、鼓的重击 | 切换、撞击、震屏、闪白 |
| 持续的长音 | 缓慢的运镜、慢慢展开的画面 |
| 旋律的上行和下行 | 元素上升和下落的方向 |
| 尾奏 | 落版，回声，慢慢收 |

## 4. 剪辑手法

- **切在拍上**：结构切换放在强拍，普通镜头切换放在拍上。
- **按乐句组织**：4 小节或 8 小节是一个完整的「句子」，一组镜头最好在一个乐句内讲完一件事。
- **切的密度随能量变化**：低能量段 2 到 4 小节一个镜头，中能量段 1 到 2 小节，高能量段每 1 到 2 拍一个，最高潮可以每半拍一个。
- **落点对重拍**：动画的落定帧对准重拍，所以要提前开始动（见 `rhythm.md` 第 6 节）。
- **呼吸**：连续卡点一段之后，放一个跨越好几拍的长动作，跟旋律而不是跟鼓。
- **用静音**：音乐本身有停顿的地方，画面也停。这是最爽的卡点。
- **切点手感**：如果看起来总是慢半拍，把切点整体提前 1 到 2 帧。

## 5. 调整音乐长度

音乐和片子的长度不一致时，**在乐句边界上剪**，不要在乐句中间硬切。

```bash
# 截取 12.5 秒到 72.5 秒，结尾 2 秒淡出
ffmpeg -i bgm.mp3 -ss 12.5 -to 72.5 -af "afade=t=out:st=58:d=2" -c:a pcm_s16le bgm_cut.wav

# 把两段在拍点上交叉淡化拼接（第一段的尾和第二段的头各有 0.5 秒重叠）
ffmpeg -i partA.wav -i partB.wav -filter_complex "acrossfade=d=0.5:c1=tri:c2=tri" joined.wav

# 循环一段 4 小节的素材 3 次（-stream_loop 2 表示额外再播 2 次）
ffmpeg -stream_loop 2 -i loop4bars.wav -c copy looped.wav
```

- 缩短：删掉中间一个或几个完整的乐句（比如第二遍主歌），用交叉淡化接起来。
- 加长：重复一个乐句，或者在开头加一段只有铺底的前奏。
- 结尾：在一个乐句结束时淡出 1.5 到 3 秒，或者直接在最后一个重拍上收住。
- 剪完的音乐重新跑一遍 `analyze_music.py`，时间会变。

## 6. 歌词视频

- 需要每句歌词的时间戳。优先向用户要 LRC 歌词文件；没有的话，用分析出的节拍加上用户告诉你的「每句从第几秒开始」来对。
- 一屏一句，按词或按字随节拍出现。副歌的关键词可以放大、换色、震屏。
- 歌词出现要比演唱**提前 2 到 4 帧**，观众的眼睛需要一点时间对焦。

## 7. 没有音乐时

- 照样按情绪选一个 BPM，所有时间落在这个网格上。
- 需要配乐时，用 `synth_music.py` 按同样的 BPM 和段落结构合成一首（见 `pure-code.md`），它会同时输出段落时间图，不需要再分析。
- 或者完全不用音乐，只用音效和静默。紧张、悬疑、极简的片子，这样反而更有力量。

## 8. 音乐剪辑自检

- [ ] 大的结构切换都在段落或乐句边界上。
- [ ] 最重要的揭示在高潮第一拍。
- [ ] 画面密度跟着能量曲线走，高能段更快更满，低能段更慢更空。
- [ ] 音乐的停顿处，画面也有相应的停顿。
- [ ] 结尾在乐句边界上收住或淡出，没有被截断。
- [ ] 请用户听过至少一遍动态预演，确认卡点手感。
