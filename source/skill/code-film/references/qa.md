# 自检与交付：怎么证明片子是对的

## 1. 心态

**不要相信自己一次能写对。** 一部片子一般要迭代两到四轮。保证质量的方法是：把能量化的东西全部变成脚本来检查，把只有人能判断的东西（动感、听感、情绪）明确地交给用户，并且告诉他看什么、听什么。

检查是分层的，从便宜到昂贵：先查数据，再查代码，再看静帧，最后看成片。越早发现的问题，修起来越便宜。

## 2. 分层检查

### 第一层：故事和规划（写代码之前）
- `story.md` 第 8 节和 `planning.md` 第 10 节的清单。
- 分镜数据校验：

  ```bash
  python <skill>/scripts/check_storyboard.py src/storyboard.json --sfx-manifest public/sfx/manifest.json
  ```
  检查：镜头之间的空档和重叠、总时长、切点是否在拍上、文字镜头的阅读时间、每行文字长度、镜头过短或过长、同一场景连续重复、转场种类、音效事件是否越界、音效名是否存在、张力曲线和高潮位置。**错误必须清零，警告逐条确认或说明理由。**

### 第二层：代码
```bash
npm run typecheck
```

### 第三层：静帧
在这些时刻渲染静帧，自己读图检查：
- 每个镜头「停」的阶段中间的一帧（这是观众看得最清楚的时刻）
- 每个转场的中点
- 每个音效事件的落点帧（画面上此刻应该正好是撞击、落定、揭示）
- 第 0 帧和最后一帧

```bash
npx remotion still Film out/check/s03.png --frame=245
```

逐张检查：
- [ ] 文字有没有溢出、被截断、意外换行
- [ ] 中文字体对不对（没有方块、没有回退成宋体）
- [ ] 关键内容在安全区内
- [ ] 对齐：元素边缘对齐到网格或彼此对齐
- [ ] 对比度：文字看得清
- [ ] 层级：一眼能看出主角
- [ ] 没有意外的空白画面、没有元素重叠错位
- [ ] 颜色只用了 `theme.ts` 里的颜色

### 第四层：缩略图墙
渲染出草稿或成片后：

```bash
python <skill>/scripts/contact_sheet.py out/draft.mp4 --every 1 --cols 8
```

一张图看完整部片子，检查：
- [ ] 色彩走向和情绪曲线一致（比如从冷到暖）
- [ ] 构图有变化，没有连续很多格长得一样
- [ ] 高潮部分在视觉上确实最强
- [ ] 没有意外的黑格、白格、空格
- [ ] 视觉风格前后统一

### 第五层：成片技术检查
```bash
python <skill>/scripts/qa_video.py out/film.mp4 --expect-fps 30 --expect-duration 90
```

它会报告：
- 编码参数：编码器、像素格式、分辨率（是否偶数）、帧率、时长、有没有音轨
- **黑帧**：意外的黑屏片段。注意：暗色调的片子（黑底白字）几乎必然触发黑帧警告，`pix_th` 把很暗的画面也算成黑。这些警告只当提示用，确认画面里确实有内容就可以放过
- **冻帧**：画面超过 1.5 秒完全不变的片段。这就是「拖沓」的嫌疑点，逐个核对是不是刻意的留白（落版停留、配合音乐停顿的黑场）。落版和片名停留被报出来通常是正常的
- **静音**：超过 1 秒的完全无声片段
- **响度**：整体响度和真峰值

### 第六层：人（只有用户能做的）
交付时附上这份清单，请用户完整看一遍、戴耳机听一遍：
- 整体节奏：有没有觉得拖、或者太赶的地方？在第几秒？
- 卡点手感：切换和音乐对得上吗？有没有慢半拍的感觉？
- 动作质感：有没有生硬、卡顿、抖动的动作？
- 声音：有没有刺耳、太响、听不清的地方？音乐和画面的情绪对吗？
- 情绪：看完之后的感受，和立意想传达的一致吗？
- 文字：有没有来不及读完的字？有没有错字？

## 3. 修问题的顺序

**故事 > 时间 > 排版 > 细节 > 质感。**

- 故事有问题（立意不清、结构塌、文案差），先改故事，其他的都可能要重做。
- 时间有问题（节奏、卡点、阅读时间），改 `storyboard.json`，这通常会牵动排版。
- 排版有问题（溢出、对齐、层级），改场景组件。
- 细节有问题（曲线、时长、错峰），改动画参数。
- 质感有问题（颗粒、调色、光效），最后改，因为它最便宜也最不影响其他东西。

每轮修改记录在 `docs/brief.md` 末尾的修改记录里：改了什么、为什么。

## 4. 交付清单

- [ ] `check_storyboard.py` 无错误
- [ ] `npm run typecheck` 通过
- [ ] 关键静帧都检查过
- [ ] 缩略图墙检查过
- [ ] `qa_video.py` 的冻帧、黑帧、静音都已核对，响度约 -14 LUFS
- [ ] `finalize.py` 输出了最终文件
- [ ] 片中出现的事实、数字、名字核对过
- [ ] 交付说明写清楚：成片路径、时长、分辨率、用了哪些素材和工具、已知的不足、需要用户亲自确认的地方

交付说明示例：

```
成片：D:/films/sun/out/final.mp4（1920×1080，30fps，92 秒，-14 LUFS）
工程：D:/films/sun（npm run studio 可以预览和修改）
素材：画面全部由代码生成；配乐和音效由脚本合成；字体为思源宋体和 JetBrains Mono
自检：分镜校验、类型检查、静帧、缩略图墙、成片体检均已通过
刻意的静止：第 56 到 60 秒的黑场（冻帧检测会报出，这是设计）
请你重点确认：第 45 到 50 秒的节奏是否太慢；结尾音乐的淡出时机
已知不足：合成配乐的音色比较简单，有条件的话建议换成真实的钢琴配乐
```

## 5. 常见缺陷和修法

| 缺陷 | 修法 |
|---|---|
| 某段觉得拖 | 缩短停留、加微动、让下一个动作提前重叠开始、砍掉这个镜头 |
| 文字来不及读 | 延长镜头，或者删字 |
| 卡点慢半拍 | 让落点对准拍子（提前开始动），或者整体提前 1 到 2 帧 |
| 画面「塑料感」 | 加颗粒、暗角，换更好的字体，降低饱和度，放慢缓动 |
| 画面乱 | 减少同时运动的元素，明确主角，统一对齐，拉开留白 |
| 风格前后不一 | 检查是否所有颜色、字体、动效参数都来自 `theme.ts` |
| 高潮不够高 | 高潮前加一个低谷（静默、黑场、缩小），高潮时配 boom、闪白、大字 |
| 结尾太突然 | 延长最后一帧的停留，音乐在乐句结束时淡出 |
| 转场生硬 | 检查运动方向和视线是否连续，考虑 J 切 |
