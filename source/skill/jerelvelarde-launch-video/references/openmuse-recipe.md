# OpenMuse launch recipe

Use this reference when producing an OpenMuse film or a similar agent-workspace story. Inspect the current product and brand inputs first. This recipe is informed by a historical local film; it is not current evidence of integrations or product availability.

The bundled `OpenMuseLaunch` is a new 36-second Remotion template with eight equal beats. Edit its story in `src/product-stories.ts` and shared layout in `src/ProductLaunch.tsx`.

| Beat | Show | Evidence needed for a real launch |
| --- | --- | --- |
| Reveal | Product name and one clear hook | Approved positioning |
| Protocol | Agent endpoint → AG-UI → app surface | Current connection implementation and supported endpoint requirements |
| Inbox | A concrete source item | Actual supported source or a disclosed illustration |
| Research | Browser context with a visible source | Recorded browsing or implemented capability with disclosure |
| Goal | Steps and an unchecked review item | Current goal/suggestion behavior |
| Artifact | Terminal output and a saved file | Real command/result or a clearly staged example |
| Devices | Readable desktop and phone views | Captures and verified platform availability |
| CTA | Repository or next action | Verified URL, license, and self-hosting instructions |

Protocol compatibility does not prove every named framework has been acceptance-tested. An external agent must provide its own tools; do not imply the app automatically injects browser/terminal capabilities into every endpoint. Browser and Linux workspace capabilities may be separate environments. Match each claim to its actual implementation and setup.

Distinguish mobile source support from store availability. Check open-source and self-hosting claims against the current repository and dependencies. Do not inherit enterprise-readiness, compliance, isolation, performance, or live-integration claims from older film text.

For the framework diagram, use individual cards with consistent logo containers, exact shared connector endpoints, a single draw-on, and a settled read hold. Add official artwork only after reviewing its source and rights. The starter uses neutral text nodes and no framework endorsements.

Keep frame zero useful as a poster. Let the reveal hold before the diagram takes over. For inbox → research → goal scenes, use one short fictional story so the audience can follow the causal path. Preserve the review boundary. Combine real media and illustrative scenes only with a per-scene representation inventory.

The original production used a mascot, named framework artwork, screenshots, and original procedural music. None is bundled. Add approved assets locally and keep source/licensing notes. Use the existing project's soundtrack workflow when available; do not copy another video's music.
