# v1.1.8 分集制作流程

本技能把老版本那套「编剧流水线 + 制作流水线 + 视频工作台」改写成现在 Toonflow 的画布操作方式。每个阶段都按同一节奏推进：**先读取已经确认的输入 → 做完当前这一步 → 写进对应画布 → 回读校验 → 把结果摆出来 → 等用户拍板**。聊天里的一段总结不能顶替画布上的产物，任务被启动也不代表媒体已经产出成功。

技能里既有各个子流程，也带着完成它们所需要的专业知识。动手前先看当前阶段对应的 reference，再顺着它的指引去读 `references/knowledge/` 里的通用方法，以及本项目所选类型与风格的内容；只照流程表填几段摘要就宣称做完是不行的，也不能一次把全部类型和画风都套上去。老版本的依据和迁移时的取舍写在 [来源映射](references/sourceMap.md) 里；不要调用旧数据库、XML 写入或子 Agent 专用接口，也不要自动套用别的 workflow 的模型路由。

阶段是否过关，按 [产出契约对照](references/sourceMap.md#阶段产出契约对照) 去核对内容、数量、来源映射与状态。这里保留旧版的核心产物以及两条制作路线，画布存储、逐步确认、生成验收属于迁移后的要求；阶段名字对得上、文件建出来了，都不能算产出一致，也不能保证两次 AI 生成会逐字或逐帧相同。

## 先定位进度与画布

1. 先弄清当前项目、用户这次想做什么、手上已有哪些输入和已确认结果。如果已经有完整定稿剧本，就按初始化步骤原样放进剧本总画布的正式节点，然后直接进入基础资产或目标集制作，不要倒回去编造小说、事件表或骨架；续作从第一个尚未确认的阶段接着做。
2. 先读 [项目初始化与归档](references/projectSetup.md) 和 [画布执行](references/canvasOperations.md)，把工具、文件位置和当前节点核实一遍。已经确认过的配置继续沿用，只补那些会影响当前步骤的缺项。
3. 所有画布都放在**用户选定的项目工作区**里，而不是技能安装目录。默认结构如下；已有项目可以沿用用户确认过的文件夹和名称，但依然要保持一个剧本总画布、一个资产总画布、每集一个制作画布。

```text
项目工作区/
└─ 画布/
   ├─ 剧本.json
   ├─ 资产.json
   └─ 分集/
      ├─ 第001集.json
      ├─ 第002集.json
      └─ …
```

| 画布 | 唯一正式内容 |
| --- | --- |
| 剧本 | 项目配置、来源索引、章节事件、故事骨架与分集大纲、改编策略、各集正式剧本、画布路径索引 |
| 资产 | 全剧基础与衍生资产、父子关系、视觉设定、提示词、已选图片、使用集数 |
| 第 N 集 | 本集剧本来源/工作快照、导演规划、分镜表、参考素材节点、分镜图、视频、选用与交付记录 |

分集画布里的图片只是对同一份资产文件的本地引用，并不是另建一套正式资产库。跨画布之间不能直接连边；要先切换过去读到真实的资产输出，再回到本集建立引用节点。素材文件保留宿主返回的位置，不能为了让画布文件夹看着整齐就去搬动 `assets/` 里的生成结果。

当前 `addCanvas` 没有目录参数。必须按 [画布归档办法](references/canvasOperations.md#画布创建与归档) 把文件树归位、重新发现真实路径/ID 之后再填入成果，不能把画布全堆在根目录就算归档完成。

## 主流程与确认关口

下表每一行是一个独立阶段，执行前要读该行的 reference 及其指定的知识。已经有明确确认的产出可以复用，同时把来源记下来；要“跳过”必须有站得住的理由，并且用户明确选过。项目不涉及原著改编时，章节事件、骨架或策略可以按已有输入压缩或跳过，但不能凭空编造经历。

| 步骤 | 子流程 | 成果落点与本次需要确认的结果 |
| --- | --- | --- |
| 0 | [项目初始化](references/projectSetup.md) | 剧本画布：项目配置、范围、文件夹与画布索引 |
| 1 | [来源与章节事件](references/sourceEvents.md) | 剧本画布：实际章节与事件表；确认来源覆盖与事实 |
| 2 | [故事骨架](references/storySkeleton.md) | 剧本画布：故事核、人物弧、分集大纲、删减记录；确认分集方案 |
| 3 | [改编策略](references/adaptationStrategy.md) | 剧本画布：改编原则与边界；确认取舍 |
| 4 | [逐集剧本](references/episodeScript.md) | 剧本画布：本集完整剧本；默认一集一确认，再决定续写哪集 |
| 5 | [基础资产提取](references/baseAssets.md) | 资产画布：角色/场景/道具及出场集；确认复用、新建与视觉设定 |
| 6 | [资产图片制作](references/generateAssets.md) | 资产画布：基础资产提示词与图片；先确认生成方案，再确认采用图片 |
| 7 | [导演规划](references/directorPlan.md) | 当前集画布：分场、台词统计、情绪、过渡与注意事项 |
| 8 | [衍生资产分析](references/deriveAssets.md) | 资产画布：本集衍生清单与父资产；确认全部、部分、调整或跳过 |
| 9 | [资产图片制作](references/generateAssets.md) | 资产画布：已选衍生图片；无衍生需求时明确记录跳过 |
| 10 | [分镜表](references/storyboardTable.md) | 当前集画布：场→片段→镜头、真实资产映射及检查结果 |
| 11 | [分镜面板落点](references/storyboardPanel.md) | 当前集画布：按实际模式建立文本、参考、图像/视频节点；确认数量、时长与连线 |
| 12 | [分镜图片](references/storyboardImages.md) | 当前集画布：首帧模式的分镜图；纯文本多参模式可跳过，须记录原因 |
| 13 | [视频与交付](references/videoProduction.md) | 当前集画布：视频提示词/配置 → 生成结果 → 选用与交付，三个独立确认关口 |

第 7–13 步是逐集循环的。一集做完后让用户挑下一集做哪个；不要以为“一集完成”就等于全剧完工。基础资产可以随着剧本确认分批补齐，但跨集时仍然在同一块资产画布里维护。

## 知识如何随流程使用

| 工作内容 | 必须读取的知识 | 必须落实的成果 |
| --- | --- | --- |
| 故事骨架、改编、逐集剧本 | [编剧方法](references/knowledge/scriptCraft.md) + [叙事类型](references/knowledge/narrativeGenres.md) 中本项目类型 | 剧本画布：人物欲望与阻碍、人物弧、情绪推进、信息释放、反转/伏笔及具体改编取舍 |
| 基础/衍生资产设计与提示词 | [资产设计](references/knowledge/assetDesign.md) + [美术风格](references/knowledge/visualStyles.md) 中所选风格 | 资产画布：角色识别锚点、场景空间与色光、道具结构、变体差异、可执行提示词和采用版本 |
| 导演规划与分镜 | [镜头设计](references/knowledge/shotCraft.md) + 本项目叙事类型；涉及视觉表达时读取所选美术风格 | 本集画布：镜头意图、信息可见范围、站位视轴、节奏和连续性，落入导演规划及具体镜头 |
| 分镜图提示词与验收 | [图像提示词](references/knowledge/imagePromptCraft.md) + 所选美术风格 | 本集画布：首帧状态、景别/朝向、实际参考映射、适配模型的提示词与检查结果 |
| 视频提示词与验收 | [视频提示词](references/knowledge/videoPromptCraft.md) + 所选美术风格的视频表现方法 | 本集画布：按所选模式编写的时序/动作/声音、真实参考绑定、动态连续性与逐段验收 |

叙事类型管的是怎么组织信息、情绪和镜头，美术风格管的是形态、材质、色光和表现手法，二者各自独立挑选，别把“悬疑”当成画风，也别把“黏土”当成剧情类型。用户已有明确选择就照用；没选的时候，根据内容给出有理由的方案，确认后写进项目配置。

知识不是额外的剧情许可。编剧阶段可以在用户允许的改编范围内使用结构与反转手法；剧本定稿之后，类型技法只负责指导已确认事件怎么呈现，不能新增红鲱鱼、改结局、调换事件顺序或者自己加戏。风格示例同样不能盖过已经确认的角色身份、世界观和参考图。

当通用方法、类型特例与历史模型模板互相冲突时，优先满足用户已确认的内容以及当前工具的真实能力，然后再选用贴合本项目的方法。旧版那种单线快节奏、固定镜长、肤色/身高模板之类的做法，不要硬套到所有项目上；商业短剧、群像、留白以及特殊变体的适用条件，各自写在对应的知识文件里。

每次只把**本项目实际采用的方法及其结果**写进对应画布：比如这一场藏住了哪条线索、角色为什么保持侧身、场景主光从哪个方向来、父图里哪些特征保持不变。不要把整本知识文档复制成节点，也不要只写一句“已参考某技能”却没有任何可以审阅的制作决策。

## 每一步如何确认

- 先把本阶段完整、可审阅的结果写进画布，用工具回读确认确实保存好了；文本较长时可以按章节、集、场拆成节点，但不能截断正式内容。用 `fitCanvas` 把这次的结果展示出来。
- 在当前画布的「阶段记录」文本节点里写清阶段/集号、输入版本、产出节点 ID、检查结果、状态以及待决策项。状态分为 `草稿`、`待确认`、`已确认`、`生成中`、`失败`、`待复核`、`已跳过`。
- 展示时给出画布名称与相对路径、成果摘要、具体问题、下一步内容。用可用的 `askUser` 让用户在“确认进入下一步 / 修改指定项 / 重做当前步”之间选择；如果没有提问工具，就在对话里发问并等待。用户回复之前，本阶段到此为止，不要提前建下一阶段的制作节点，也不要触发媒体生成。
- 用户答复后把他的决定记下来。只改用户点名的那几项，改完回读修订结果再确认；检查通过、提问被取消、跳过问答、超时或沉默，都不能当成批准。“继续”只推进当前这个待确认的下一阶段。
- 用户已经明确确认过的配置、资产或具体生成批次继续有效，不要为同一件事反复要授权。如果用户明确授权了多集同一阶段的批量执行，可以按该范围做并集中展示；没有这种授权时仍然逐集确认，不能把整个项目的目标当成全流程放行。
- 生成方案要写清实际模型/模式、对象与数量、提示词、参考、时长/画幅/分辨率以及已知费用；费用未知就标注未知。只有在当前批次范围获得确认后才调用生成。失败后先核实真实状态，追加候选、换模型或收费重试都不能超出已确认的范围。

## 续作、修改与失败

每次续作都以画布内容和用户确认记录为准，不能只靠聊天记忆。已有结果如果缺少确认，先把现有结果展示出来补确认，不要重新生成。

上游改动之后，要标出实际受影响的下游：剧本变了就检查本集的导演/分镜/视频，资产版本变了就检查引用该资产的分镜/视频。把它们标记为待复核，保留原有成果和选用记录，不要自动把全剧重做一遍。没有受影响的确认继续有效。

遇到来源缺失、目录没归位、工具缺失或写入失败时，说明具体哪一项没完成以及怎么恢复。不能把聊天文本、空节点、假文件路径、旧输出或者“任务已启动”包装成阶段完成。只处理用户这次要求的范围；仅仅是咨询或编辑技能时，不创建制作项目。
