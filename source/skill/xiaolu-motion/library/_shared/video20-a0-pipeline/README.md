# video20-a0-pipeline

Final-assembly and delivery code for video 20 (the same real, already-published talking-head video the rest of `video20-a0-*`/`a1-*`/`a2-*`/`a3-*` comes from): burning in captions, mixing voice + BGM + SFX, and packaging the rendered picture into deliverable files.

**This is a reference implementation, not a drop-in tool.** All four files are one specific video's production code — hardcoded shot numbers, a hardcoded caption script, hardcoded BGM candidates, hardcoded loudness/timing constants. Read "What's specific to video 20" below before trying to reuse any of it; the point of including it is so a reader can see how a real delivery pipeline was wired together, not to run it as-is on a different project.

## What this pipeline does, end to end

1. **Captions** (`captions.py`, run standalone, ahead of delivery) — takes the corrected, re-timed ASR transcript (`04_captions/words_v2.json`) and a hardcoded list of caption "strips" that must match that transcript word-for-word, breaks it into on-screen strips (width limit, no orphan lines, semantic breaks, `[keyword]` markup for the brushed-highlight effect), works out each strip's display window (lead-in, hold, join adjacent strips if the gap is short, never overlap one of the three inserts or a shot that owns its own on-screen text), and writes the structured plan (`captions_v2.json`) plus `.srt`/`.ass` files.
2. **Mixing** (`mix.py`) — loads the voice master and the three finished-demo-clip inserts' own audio, builds a BGM bed (sliced/crossfaced from a cached Jianying track, then ducked keyed off the voice only), renders an SFX track from a cue list via `audio/xlaudio`, and masters two programme mixes (with BGM, without) to a target LUFS with a true-peak limiter. Also has an `auditions` mode that renders 30-second BGM-candidate previews for picking the bed track before committing.
3. **Delivery, v1** (`deliver.py`) — the un-cut candidate. CLI stages `accept → sfx → mix → render → package → qa → report`: verify every shot's rendered segment (frame count, checksum, no embedded audio, frame-accurate sync against the locked plate) → call `assemble_audio.py` (not ported) to merge SFX cues → call `mix.py` above → call `a0render.py` (not ported) to composite the picture at final quality (`--crf 16` — see the note on low-res/high-res below) → mux picture with each mix into `视频20_候选_v1_{含BGM,无BGM}.mp4`, derive a smaller `_手机预览.mp4`, and copy over the caption files → run technical + custom QA (font-glyph coverage, SFX-to-keyword-onset timing, an Apple Vision OCR sweep for stray platform branding) → write the human QA report (manual, not automated).
4. **Delivery, v2** (`deliver_v2.py`) — a second pass on top of a pause-tightened cut of the same timeline, in two variants: `v2p` (pauses removed) and `v2p110` (same, then sped up 1.1x). Stages `render → audio → package → qa`, delegating the actual cut-list/re-timing/speed-change work to `v2_timeline.py` (not ported) and reusing `mix.py`'s stems for two extra verification passes this file *does* implement: `sync_qa` (samples 5 cuts and 5 sped-up frames, compares picture PSNR and audio cross-correlation against the uncut v1 render) and `av_sync_delivered` (cross-correlates the whole delivered track's level envelope against the reference dialogue, globally and around the sampled cuts, to catch systematic A/V drift introduced by the cut or the speed change).

**Low-res draft vs. final high-res:** `SKILL.md`'s "先低清、后高清" rhythm (draft-resolution render for approval, then a high-res final) is **not** implemented inside these 4 files — both `deliver.py` and `deliver_v2.py` call `a0render.py` directly at `--crf 16` (a final-quality setting), with no lower-quality render call anywhere in either file. The only downscaled output either file produces is a 720×1280 "手机预览" (phone preview) — `deliver.py` makes it at a fixed 2000 kb/s *after* the full-res master already exists; `deliver_v2.py`'s `phone()` instead searches a bitrate to stay under a hard file-size ceiling. That is a lightweight review/sharing copy, not a pre-approval draft gate. If video 20 actually used a low-res-first approval step, it happened upstream of these 4 files (or inside `a0render.py`, which was not part of this port) and isn't visible here.

## The four files

**`deliver.py`** — the v1 delivery driver described above, dispatched from `main()` on `sys.argv[1]` (`accept | sfx | mix | render | package | qa | report | all`), with every heavy step wrapped through a project-local `with_heavy_lock.py` (see "Depends on" below — this is *not* the same file as this repo's `scripts/with_heavy_lock.py`). Its own substantive logic, rather than delegating to sibling scripts: `accept()` (per-shot segment verification, including `sync_check()`'s frame-level PSNR comparison against the locked plate), `font_check()` (every caption/label character exists in all three CJK font weights this project uses), `keyword_sfx_check()` (every caption keyword has an "impact"-type SFX cue within 2 frames of its onset), and `ocr_platforms()` (an Apple Vision OCR sweep of the finished picture for accidental third-party platform names).

**`deliver_v2.py`** — the pause-cut delivery driver described above, dispatched the same way (`render | audio | package | qa | all`, plus `syncqa`/`avsync` as both direct subcommands and steps `qa` re-invokes as its own subprocess under the heavy lock). Its own logic beyond dispatch: `mux()`/`phone()`/`make_phone()` (package picture + a chosen audio stem into a deliverable, including the bitrate-searched phone preview) and the two sync-verification passes, `sync_qa()` and `av_sync_delivered()`, described above.

**`mix.py`** — the programme mixer/master described in "What this pipeline does". Two real entry points, dispatched from `if __name__ == '__main__'`: `auditions()` (BGM-candidate previews) and `programme(sfx_path)` (the actual mix: voice + inserts + BGM + SFX → two mastered WAVs). It also exposes `voice_and_inserts()`, `bgm_bed()`, `place_bgm()` and `master()` as a small library — `deliver_v2.py` imports this module directly (`import mix as M`) to rebuild the same voice/insert stems for its sync checks, rather than re-deriving them.

**`captions.py`** — generates the master caption plan described above. Single entry point, `main()` — no CLI subcommands, it always runs the full pass. It is not invoked by either delivery driver's `main()`; both consume its *output files* instead (`deliver.py` copies `captions_v2_burn.{srt,ass}` directly in `package`; `deliver_v2.py`'s v2 variants get their captions from `v2_timeline.py`'s own `captions` step, which re-times this file's `captions_v2.json` plan onto the cut/sped-up timeline rather than recomputing strips from scratch).

## What's specific to video 20 (read this before reusing anything)

**`deliver.py`**
- `TAG = '视频20_候选_v1'` and filenames like `cand_v1_video.mp4` / `sfx_merged_cand_v1.json` — this video's candidate naming, hardcoded throughout.
- `PLATFORMS` (line ~20) — a hardcoded list of ~25 third-party product/platform names (剪映, CapCut, Claude, Codex, GitHub, 小红书, 抖音, TikTok, …) that `ocr_platforms()` checks the picture against; specific to this video's content-safety concern (don't show a competitor's or unrelated product's name on screen).
- `font_check()`'s `texts` list (line ~107) hardcodes this video's own UI-label strings (`'成片 · vlog'`, `'第二曲线'`, etc.) in addition to reading the caption plan — anything added to a future video's on-screen text needs adding here too.
- `keyword_sfx_check()`'s `impact` cue-id set (line ~87) is this project's own SFX naming vocabulary (`hit`, `stamp`, `tock`, …), and its ±0.35 s search window / ±2-frame tolerance are tuned, not derived.
- `sync_check()`'s PSNR threshold (30 dB) and "meaningful" spread test (>1.0 dB) are heuristic constants tuned for this footage.
- `accept()` assumes the exact shot-table-driven layout `SHOTS_DIR/s{id}/{DONE.json,segment.mp4}` and that every accepted segment has **zero** embedded audio streams — an assumption about how this project's shots were rendered, not a general rule.
- `package()`'s phone-preview encode uses fixed literals (`720:1280`, `2000k`/`2400k`/`4800k`) rather than a size search (contrast with `deliver_v2.py`'s approach to the same problem).
- `ocr_platforms()` reaches into a **private sibling project** for its OCR helper: `XM = Path.home() / 'Projects/xiaolu-motion'` (set in the not-copied `a0common.py`), then `from qa.vision import analyze`. This public repo already ships an equivalent `qa/vision.py` at its own root — a reuse should import that instead of reaching outside the repo.

**`deliver_v2.py`**
- `V` (line ~18) hardcodes the two v2 candidate names (`视频20_候选_v2_删停顿`, `视频20_候选_v2_删停顿1.1倍速`) and their frame-list files.
- `phone()`'s bitrate search (`26.3e6`/`24.5e6` byte budgets, 128 kb/s audio allowance) and 28 MB ceiling are tuned to a specific target file size (reads like a platform upload cap), not derived from anything in this file.
- `sync_qa()` hardcodes `random.seed(20)`, a sample of 5 cuts / 5 sped-up frames, a 0.2 s correlation window and a ±40 ms lag search — all tuned to this video's cut count and expected drift.
- `av_sync_delivered()` hardcodes a 10 ms envelope window / 2.5 ms hop and a ±150 ms (60-hop) lag search.
- Both `sync_qa()` and `av_sync_delivered()` `import v2_timeline as TL` and `import mix as M` — `v2_timeline.py` is **not** part of this port (see "Depends on" below); these functions won't run without it.

**`mix.py`**
- `JY` originally pointed at the local cache directory of the Jianying (剪映) desktop app (`Path.home() / 'Movies/JianyingPro/User Data/Cache/music'`) — unlike `a0common.py`'s `Path.home()` use (a project-root guess that's merely inconvenient to reuse), this one specifically told a reader "your BGM lives in this other app's cache," which a public repo shouldn't do. **Patched** (unlike the rest of this package) to `JY = Path(os.environ.get("XM_BGM_LIBRARY_DIR", "path/to/your_bgm_library"))` — point it at any folder of BGM you have the rights to use.
- `BGM` (line ~50) originally hardcoded 3 candidate tracks by Jianying's content-hash filename (each licensed for the source project's own use via a Jianying membership), plus exact bar-line splice timestamps for looping candidate 3. **Patched**: filenames replaced with `your_bgm_1.mp3`/`your_bgm_2.mp3`/`your_bgm_3.mp3` placeholders; the splice/tempo/key/style fields are left as a worked example of the metadata this system tracks per candidate, not as claims about the placeholder files.
- `VOICE_REF`, `BGM_REL_LU`, `DUCK_DB`, `POCKET_DB`, `INSERT_TARGET`, `TARGET`, `CEIL`, `LIMIT_CEIL` (lines ~39-46) are loudness/limiting targets tuned for this video (the `-14 LUFS` / true-peak numbers match what `audio/README.md` documents for the source project this was distilled from). `LIMIT_CEIL`'s comment ("AAC encoding adds ~0.7 dB true peak, measured on draft v1") is an empirical calibration specific to this delivery.
- `insert_mask()`/`place_bgm()` hardcode the fade durations around the three inserts (0.30 s out, 0.60 s in) and at the programme's own start/end (0.25 s / 1.6 s) — timed to this video's specific structure.
- `N = TOTAL * SPF` and the `assert v.shape[1] == N` checks depend on `TOTAL` (4857 frames, from the not-copied `a0common.py`'s shot table) and on `voice_master_48k.wav`/`inserts_audio_48k.wav` already being exactly that length — both artifacts of this specific video.
- The `NUMBA_CACHE_DIR` default (line 26) is derived from `__file__`'s location two levels up (`.../work/numba_cache`), which assumes this file still lives inside an `a0/src/`-shaped layout with a writable `work/` sibling of `a0/` — true in the source project, not guaranteed wherever this gets reused.

**`captions.py`**
- `STRIPS` (line ~20) is the entire hand-broken caption script for this one video, `[keyword]`-marked, and asserted to match `words_v2.json` token-for-token (`assert got == us`) — this is the least reusable part of the whole pipeline; a new video needs an entirely new list written against its own transcript.
- `NO_BURN_SHOTS = ('01', '06')` hardcodes that shots 1 and 6 own their own on-screen text (the hook's big-type labels, the IP-intro component) and should never get a burned strip — specific to this video's shot table.
- `LEAD` (0.07 s), `HOLD` (0.30 s), `JOIN_GAP` (0.60 s) are pacing constants tuned by ear for this video.
- `cells()`'s character-width table is tuned for one specific font at one specific size (Source Han Sans SC Medium, 66 px) — a different caption style needs a different table.
- The ASS header hardcodes `PlayResX/Y = 1080x1920`, one style block named `C` (this project's "纸条"/paper-strip look), its exact colors, and a `MarginV` computed from `1920 - 1424 + 20` (i.e. this video's specific caption-strip vertical placement, `bottom_max=1424`).

## Environment variables

None were introduced in these 4 files — checking all four for a hardcoded home-directory path or personal username turned up no hits (the one `Path.home()` use, `mix.py`'s `JY`, is documented above instead of parameterized, matching the precedent already set by the existing sanitized `a0common.py`). All path construction in `deliver.py`, `deliver_v2.py`, `mix.py` and `captions.py` instead comes from `from a0common import *`, and `a0common.py` is deliberately **not** duplicated into this package (see below) — so to actually run any of this code, a reader needs that file (or an equivalent) importable next to these four, with its own `XM_VIDEO_PROJECT_ROOT` env var (see `library/_shared/video20-a0-shots/README.md`) pointed at their own project.

## Depends on

- **`audio/xlaudio`** (this repo, `audio/xlaudio/`) — `mix.py` imports it directly (`xlaudio`, `xlaudio.meter`, `xlaudio.dsp`, `xlaudio.mix.duck_envelope`) for oscillators/DSP, loudness metering, limiting, and cue-based SFX rendering, and is tightly coupled to its internals (gain-staging, ducking envelope, and mastering chain are all built from `xlaudio` primitives rather than reimplemented). See `audio/README.md` rather than this file for what that library does.
- **`library/_shared/video20-a0-shots/`** — all four files here import `a0common` (`from a0common import *`) for the project root, the shot table, `TOTAL`, and the small ffmpeg/JSON helpers; that module already lives there, sanitized, and is intentionally not copied a second time into this package. `deliver.py`'s `accept()` also verifies the per-shot output (`segment.mp4`/`DONE.json`) that batch's shots (and the sibling `a1`/`a2`/`a3` batches) produce.
- **`scripts/pause_cuts.py`** (this repo) — its docstring points back here for "that project-specific version, which additionally protects a shot table's own animation windows." That version is now included: `src/pause_cuts.py` below, byte-identical to the source project's file (confirmed clean of personal paths independently of this package's own scan).
- **`scripts/speed.py`** (this repo) — its docstring points back here for "that project-specific version, which times sfx cues and captions to the same speed change." That version is now included: `src/v2_timeline.py` below (also byte-identical to source, also independently confirmed clean) implements both the v2p/v2p110 cut-and-speed timeline **and** consumes `pause_cuts.py`'s output — see the next section.

## Two more files: `pause_cuts.py` and `v2_timeline.py`

Added after the initial 4-file pass above, once the gap this section used to describe (see history) was noticed: `scripts/pause_cuts.py` and `scripts/speed.py` at the repo root both explicitly point back to this directory for "the project-specific version" of what they generalize, so those two source files belong here too.

**`pause_cuts.py`** — produces `a0/cuts/pause_cut_list_v2.json`: for every gap between two spoken phrases longer than 0.25s, computes a shortened keep-time (~0.15s mid-sentence, ~0.22s after a sentence end), subtracts every protected span (three finished-clip inserts, the hook, the IP-intro shot, every shot's own animation/keyword/SFX windows pulled live from that batch's `meta.json` and the merged SFX cue list — all read through `a0common`'s shot table, not hardcoded here), keeps the largest remaining free sub-interval, snaps it to frame boundaries, then shrinks it further frame-by-frame until the locked voice track's peak level in that span is below -66dBFS. Also scores each cut's visual risk (frame-to-frame pixel jump at the splice vs. the local baseline) and writes a top-10-risk contact sheet — a video-specific QA step `scripts/pause_cuts.py` does not include. This is the fuller, shot-table-aware sibling of the generic tool; the generic one only knows about a flat `--protect` JSON list, not a live shot table.

**`v2_timeline.py`** — builds the two delivered variants on top of `pause_cuts.py`'s cut list: `v2p` (pauses removed, same picture/sound otherwise) and `v2p110` (v2p at 1.1x — picture drops frames via nearest-neighbour resampling of the kept-frame list, no interpolation; dialogue time-stretched with ffmpeg's `rubberband` filter, pitch kept, falling back to `atempo`; SFX cues re-placed at `t / 1.1`; BGM laid again at its own, un-stretched speed). Also cuts the audio itself: an equal-power crossfade (`XF_MS = 12.0`) at every join, exactly what `scripts/pause_cuts.py apply` and `scripts/speed.py` do generically. Also re-times the caption plan (`captions()`, using `map_time()` to carry every caption's window through the same cuts and speed change) and calls into `mix.py` above (`place_bgm_cut()`) for the BGM re-lay.

Both are unchanged from source (confirmed independently: no `/Users/`, `maxzhl`, or other absolute path in either file — like the original 4, all their path handling comes from `from a0common import *`). Same caveat as the rest of this package: `SPEED = 1.1` and `XF_MS = 12.0` are hardcoded module constants here (not CLI flags), and `audio()`'s SFX/BGM handling is wired to this project's specific cue-merge file (`a0/work/sfx_merged_cand_v1.json`) and `mix.py`'s specific programme-length global (`M.N`) — reuse means either adapting those or, more simply, using `scripts/pause_cuts.py` + `scripts/speed.py` directly, which is what they were generalized for.
- **`scripts/with_heavy_lock.py`** (this repo's generic heavy-task lock) is a different file from the project-local `with_heavy_lock.py` that `deliver.py`/`deliver_v2.py` reference as `HERE / 'with_heavy_lock.py'` (i.e. sitting next to them in the original `a0/src/`) — same relationship already noted in `library/_shared/video20-a1-shots/README.md` for that batch; the project-local copy was not ported here either.
- **Not ported, referenced only by filename via `subprocess`:** `assemble_audio.py`, `a0render.py`, `qa_draft.py`, `pixel_qa_v20.py`, `contact_sheet.py`, `v2_timeline.py`, `qa_report.py`. None of these are in this repo under those exact project-local implementations; `deliver.py`/`deliver_v2.py` will not actually run end to end without them.
