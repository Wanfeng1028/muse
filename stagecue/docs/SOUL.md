# 舞监台 StageCue · 灵魂一页纸

## 一句话差异化命题
**小剧场演出的"中央控台"**：把现在靠微信群 + Excel + 人肉喊 cue 的演出流程，变成时间轴编排（音频 / 灯光 / 字幕 / 演员提示）+ 导演台 / 返听屏 / 灯光台多端毫秒级同步 + 排练模式 + 离线优先的一体化控台。QLab 只支持 Mac、闭源、贵；开源里没有跨平台、中文友好的演出控台——这是真空位（市场调研已核验）。

## 技术含金量点（不是 CRUD 换皮）
1. **多端时钟同步**：WebSocket 心跳 + NTP 式偏移估算（多次往返取最小 RTT/2 修正），事件触发对齐到毫秒级；断线重连后自动重同步，漂移超阈值告警。
2. **事件广播协议**：自研轻量协议（JSON over WebSocket）：`CUE_TRIGGER` / `CUE_ARMED` / `CLOCK_SYNC` / `STATE_SNAPSHOT`；事件带幂等 ID，乱序到达与重放不会 double-fire。
3. **离线优先操作日志**：本地追加写操作日志（cue 触发记录），重连后按序回放补齐；排练模式支持"如果这里出错就 fallback 到某一段"。
4. **音频 cue 引擎**：多轨音频 cue 预加载、淡入淡出，手动触发与时间轴自动跟随两种模式。

## 视觉概念
"舞监台" = 舞台监督的工作台：暗场 + 场记板 + cue 灯。
UI 走**黑场 + 追光金 + 幕布红**：深炭黑底 `#17130F`、追光金 `#E0A83E`、幕布红 `#9E2B25`、粉笔白 `#F2EDE3`；
时间码与倒计时用等宽字体，像场记板上的粉笔字；时间轴横向排布如演出流程表，当前 cue 高亮如追光打亮；
左对齐信息流，按钮是"推子/开关"的实体感，不做"科技感"。
去 AI 味：无紫渐变、无渐变标题、无一切居中、无三栏特性格、无 emoji 图标、无"赋能/极致体验"类文案。

## 命名理由
- **舞监台**：舞监 = 舞台监督（stage manager），演出时喊 cue 的人；"台"即他的工作台。剧场人一看就懂，非剧场人觉得新鲜好记。
- 英文 **StageCue**：stage + cue，直白点题；GitHub 无重名（dpsk 生成前已要求核验）。
- v1 先做桌面导演台（Compose Multiplatform），KMP 架构为二期 Android 返听屏 / 树莓派灯光网关留好接口——名字不绑定单一形态。

## 自查：用户看了会不会眼前一亮？
- ✅ 名字有记忆点，"舞监"自带剧场味，不是"又一个控台软件"。
- ✅ 一句话讲清跟 QLab 的区别（跨平台 + 中文 + 开源 + 多端同步），差异化真实。
- ✅ 技术点落在协议与同步（时钟同步算法、幂等事件、离线回放），不是 CRUD。
- ⚠️ 风险：Compose Multiplatform 桌面端依赖下载量大、VM 资源紧（2 核 / 低内存）；v1 聚焦桌面导演台 + 同步协议，移动端只留接口——先验证 Gradle 能拉下依赖、Xvfb 能跑出截图，冒烟不过则降级方案。
- 结论：工具链冒烟通过则开工。v1 按"编排器可用 + 双端同步一致 + 截图验收"标准验收。
