

# 敏感数据策略

本产品是单机软件：没有账号体系，也不发任何网络请求。下面说清楚数据存在哪、怎么保护、怎么删。

## 1. 存什么 / 不存什么

| 数据类型 | 位置 | 说明 |
| --- | --- | --- |
| 用户音频 | 用户指定的工程目录 | 原样保存，不转码、不上传 |
| 转写稿 | 工程目录内（随工程保存） | 用户编辑的文本内容 |
| 日志 | 日志目录，JSON 行 | 写入前已脱敏（见第 5 节） |
| 备份 zip | 备份目录 | 含 manifest.json + sha256 sidecar |

不存的东西：不收集遥测，不上传音频/转写稿，不产生任何密钥。

## 2. 怎么存

- 全部落本地文件，路径由用户或配置决定。
- 文件权限遵循操作系统默认（用户主目录下的文件默认仅本人可读写）。
- **备份 zip 未加密，是明文**。这是当前实现的真实情况，不是笔误。如果备份文件被拷走，里面的音频内容就能直接被读出来。需要保密请自行使用系统级磁盘加密（LUKS / FileVault / BitLocker）。加密备份已列入 v2（见 docs/TECH_DEBT.md TD-002）。

## 3. 怎么删

- 删备份：直接删除备份目录下的 zip 及对应 sidecar。
- 清日志：删除日志目录下的日志文件；轮转文件一并删除。
- 卸载：删除 appdir 即删除程序本体与随程序存放的数据；用户自己指定在别处的工程目录不会被自动删，需要手动清理。

## 4. 配置与密钥分离

规则：

- 产品本身不产生密钥。
- ffmpeg 路径等普通配置放 `config.json`。
- **密钥只许走环境变量**（`VOXLOOM_*` 前缀）。

违反时的行为：`config.json` 里出现疑似密钥的键，启动即拒绝，抛 `ConfigValidationException`，进程退出码 2。不会带着可疑配置继续跑。

## 5. 日志脱敏

以下键（递归匹配，大小写不敏感）的值在写日志前替换为 `"***"`：

`password` / `passwd` / `secret` / `token` / `apikey` / `api_key` / `api-key` / `auth` / `credential`

示例（写入日志前）：

```json
{"op_id":"a1b2","token":"***","path":"/home/u/proj","api_key":"***"}
```

嵌套对象同样递归处理，不只看顶层。

## 6. 输入安全

- 音频魔数校验：导入时先验文件头，不信任扩展名。
- Zip Slip 防护：恢复备份时校验解压路径，拒绝逃出目标目录的条目。
- 路径注入：调用外部进程用 `ArgumentList` 逐项传参，不拼接命令行字符串。
- 解码上限：单文件解码上限 1GB，超限直接拒绝（一刀切，见 TD-003）。
