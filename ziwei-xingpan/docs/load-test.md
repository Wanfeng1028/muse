# 负载测试说明（星命盘）

## 1. 架构前提（决定测什么、不测什么）

- 无自建服务器：小程序 + 微信云开发（云函数 + 云数据库 + 云存储）。
  云函数由平台弹性伸缩，无需、也无法做传统服务器压测（无固定
  并发上限可调）；测试重点是单函数超时、数据库索引、缓存命中与
  额度阈值，而不是打满固定机群。
- 排盘在小程序本地完成，不走服务器：排盘并发不消耗云端资源，
  只消耗用户设备算力；云端负载只来自历史、会员、积分、邀请、
  AI、订单 6 类调用。

## 2. 超时与并发策略（已落地，可核查）

| 函数 | 超时建议 | 说明 |
|---|---|---|
| ai | 120 秒 | 对话调用；主备均失败时返回 AI_UNAVAILABLE，不伪造文本 |
| aiImage | 300 秒 | 生图官方建议最长 900 秒；本函数取 300 秒，模型原 URL 仅 24 小时有效，函数内下载转存云存储后才返回 fileID |
| 其余 8 个 | 平台默认 | 纯数据库读写，无外部调用，超时风险低 |

- 幂等与防重：积分账本只增不改；邀请结算是幂等（成功标记 +
  已发阶梯列表防重发）；AI 解读按盘 hash 缓存，命中不重复调模型；
  生图按提示词 / 日期 + 盘 hash 缓存，命中直接返回 fileID。
- 额度降级：当日 CloudBase 用量达配置阈值（种子默认 85%）时，
  AI 调用自动降级到 BotsRouter 并在响应里标注 degraded，不静默失败。

## 3. 实测值（本机已测，不是推导）

| 项目 | 实测值 | 测法 |
|---|---|---|
| 单张命盘 JSON 体积 | 约 8.7 KB（含 12 宫、70 颗星） | 本地引擎生成 1995-06-15 午时男盘并序列化 |
| 出生参数 JSON 体积 | 约 0.24 KB | 同上 |
| 单用户 100 张盘存储 | 约 0.9 MB（推导：8.7 KB × 100 + 参数与索引开销） | 由实测体积推导，非云端实测 |

## 4. 推导值（明确标注，未经真实环境验证，不得当作实测引用）

| 项目 | 推导值 | 依据与待验证点 |
|---|---|---|
| 日 token 预算 | 1,000,000（种子配置 quota.dailyTokenBudget） | 仅为配置默认值；真实 CloudBase 会员额度以控制台为准，上线前必须按控制台额度重设 |
| 降级阈值 | 85%（种子配置） | 逻辑已单测；真实用量曲线需上线后看 quotaLogs |
| 单次 AI 解读 token 消耗 | 未知 | 命盘摘要截断 6000 字符 + 系统提示词；真实值需云端 quotaLogs 实测后填 |
| 单函数冷启动与 P95 延迟 | 未知 | 需真实环境调用统计；ai 与 aiImage 对延迟最敏感 |
| 数据库复合索引 | charts 需 openid + isDefault + updatedAt 复合索引 | 已写入 schema 文档；缺失时 list 查询会报错，部署时必须建 |

## 5. 待实测清单（真实 envId 后执行）

1. 每个函数在真实环境连续调用 20 次，记录成功率与 P95 延迟。
2. AI 解读 10 次：记录 quotaLogs 的 token 分布，验证 85% 阈值降级
   实际触发与 degraded 标注。
3. 同一命盘 AI 解读 2 次：第 2 次必须命中缓存且不产生新的 quotaLogs。
4. 同一生图提示词 2 次：第 2 次必须返回同一 fileID 且不重复生图。
5. 邀请结算重复调用 3 次：积分与阶梯奖励不得重发。
6. 积分日限：同一 openid 同一日签到 2 次，第 2 次必须被拒；
   激励视频 6 次，第 6 次必须被拒。
7. 支付回调重发：同一 outTradeNo 成功回调 2 次，会员不得重复发放
   （订单 status 已为 paid 时跳过发放，见 order 回调逻辑）。
